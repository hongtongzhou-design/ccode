# Ccode 使用手册

> 本文档随产品功能实时更新（改动功能时必须同步本文档，见 AGENTS.md 规则）。
> 最后更新：2026-08-06（P1：官方账号 profile、项目注册与流水线骨架、供应商预设扩充；P2：PDF 预览与整理为笔记；P3：提货单产物登记、图片评审、OS 通知、接力；P4：quarto 渲染脚本；P5：逐 hunk 验收、运行中聚合视图、任务成本、订阅口径；RX1：流水线编辑器 + 步骤资源绑定；RX2：md 阅读版式 + 步骤胶囊对照；RX3：对话步骤化 + 技能新建/编辑/◈ 优化；RX4：docx 预览 + export-docx；界面白话双层与列表精简；Cursor CLI 接入为第八个 agent）

Ccode 是 AI 编码 Agent 的统一工作台：管理八个 CLI agent（Claude Code、Codex、Gemini CLI、Qwen Code、OpenCode、Kimi Code、CodeBuddy Code、Cursor CLI）的 API 配置，内嵌终端一键启动，git worktree 任务工作区，会话历史回放，用量统计，技能分发，以及四处 AI 辅助（提交信息/会话摘要/PR 描述/冲突审查建议）。

开发预览使用 `npm run tauri:dev`，窗口标题为「Ccode Dev - 热更新」；React/样式修改会自动刷新。它与正式版和打包调试版名称不同，验收时以该标题区分。

侧栏七个页面：**配置 / 工作区 / 终端 / 对话 / 技能 / 统计 / 设置**。点击顶部「Ccode」图标可折叠为纯图标栏；「终端」图标在有 agent 运行时会显示数量徽标（任意页面可见）。

**模块是打通的**：配置页建的 profile 在终端页一键启动；终端里跑的会话在对话页以绿点标记（内部标签可点击跳回）；历史会话一键「在终端恢复」；工作区自动完成装依赖、起服务、评审合并；AI 按钮（◈）用你最近使用的 profile 提供辅助。典型动线：**配置 →（工作区）→ 终端 ⇄ 对话**。

## 一、配置页（⇄）：agent 与 API 配置管理

页面 = 可折叠分组列表。顶部筛选（全部/已安装/未安装）+ 搜索 + 「全部折叠/展开」切换；每个 agent 一组（名称 + 版本号 + 右侧更新状态/安装按钮）；分组折叠状态会记住，重开应用保持。

### 1.1 安装与更新

- 未安装的 agent 显示「**安装**」（确认框告知将执行的命令，brew 优先，自动走 TUNA 镜像）
- 已安装的显示版本号，右侧按更新检查结果分三态：「**新版**」（有更新，点击即升级，悬停显示新版本号）/「**已更新**」（已是最新或刚更新完）/「**更新**」（该渠道查不到最新版时的普通按钮，如自更新安装的 claude/kimi）；检查走 brew info / npm view，进程内缓存，更新成功后自动重查。brew 渠道已最新但上游 npm 已有更高版本时，组头显示小字提示「brew 渠道最新；上游 npm 已到 X（渠道通常滞后）」——brew 公式更新慢于 npm 属正常现象，等 brew 跟进即可，勿按 CLI 提示改用 npm 装第二份
- 更新/安装过程是**实时终端**：输出滚动、可输入（`[y/n]` 在下方 `>` 行回答）、2 分钟无输出提醒、失败带诊断建议。渠道与安装方式一致：brew 安装的走 `brew upgrade`（含 opencode，不走其交互式自更新）；npm 安装的用**与目标二进制同目录的 npm**（同机多份 node/npm 时不会装错 prefix）
- **交互式自更新在终端中打开**：kimi 这类自更新（`kimi upgrade`）是方向键选择的交互界面，行输入无法应答，点「新版/更新」会改为在内嵌终端新开标签执行该命令，用方向键选择、回车确认（按钮悬停有提示）；kimi 默认开启启动时自动更新，多数情况下无需手动点更新

### 1.2 创建配置（profile）

一个 profile = 一套 API 配置（端点+密钥+模型列表），一个 agent 可建多个。表单字段：

| 字段 | 说明 |
|---|---|
| Agent | CLI 类型 |
| 名称 | 自定义标记，如「Zeta 中转」 |
| Base URL | 中转地址；「从预设快速填充」可选官方/公开端点 |
| API Key | 存 `keys.json`（0600），界面只显示尾号 |
| 协议 | 仅 Qwen（openai/anthropic）与 Kimi 需要，位于「高级配置」 |
| 模型列表 | **可多个**，首个默认；「获取模型」从端点拉取下拉选。表单上方会提示该 agent 的模型切换页上限：Claude Code 5 个、Gemini/Qwen/Kimi 注入模式仅首个生效（多模型需「设为全局」）、Codex/OpenCode 不限；超出上限会黄色提醒 |
| 附加环境变量 | 每行 `KEY=VALUE`，注入优先级最高，位于「高级配置」 |

辅助：Base URL 行内的**测试**按钮验证端点+密钥并显示延迟和模型数；保存后「⋯ → **验证**」会打开三层结果：① Ccode 字段与当前 CLI 配置文件能否解析；② CLI doctor / 启动预检；③ 最小 API 请求（鉴权、协议、模型是否存在与耗时）。密钥只在后端参与请求，不会进入验证结果或前端日志。**导入/导出**用于 JSON 备份（不含密钥）；行内操作：编辑、⋯（验证/复制/设为全局/恢复备份/删除）。

配置列表每行只保留**名称 / 端点主机名 / 默认模型 / 密钥状态**和「编辑、⋯」；完整模型列表与端点细节保留在编辑页或悬浮提示中。导入/导出在页面顶部「⋯」；有用量的 profile 在行内「⋯ → 用量与费用」打开悬浮卡（按模型近似归属，跨配置共享模型会重复计入）。

**预设清单**：Base URL 的「从预设快速填充」收录官方与公开的兼容端点，新建 profile 选预设 → 粘密钥即可，不必手查端点格式。claude-code 含 Anthropic 官方、智谱 GLM 与 DeepSeek（Anthropic 兼容端点）；codex/qwen/kimi/opencode 含 OpenRouter、DeepSeek、Moonshot、智谱 GLM、阿里云百炼等（kimi 兼容端点会自动带上 openai 协议）；codebuddy 含腾讯官方国际站/中国站与 DeepSeek、智谱（Anthropic 兼容端点）。Gemini 用 Google 官方时 Base URL 留空即可，不设预设。**Cursor 不设预设**——其端点是 Cursor 专有协议（非 OpenAI/Anthropic 兼容），第三方供应商端点接上也不通；Cursor 的模型经 `--model` 参数注入（支持 `claude-opus-4-8[context=1m,effort=high]` 这类 bracket 参数化），API 密钥走 `CURSOR_API_KEY` 注入。

### 1.3 官方账号

除 API 配置外，Claude Code / Codex / Gemini / CodeBuddy / Cursor 支持「**官方账号**」profile：直接用 CLI 自身的订阅账号登录，不需要 API 密钥。

- **建 profile**：表单顶部「账号类型」选「官方账号」——无需填 Base URL 与密钥；模型可留空（= 用 CLI 默认模型）。配置列表端点列显示「官方账号」。目前支持 claude-code / codex / gemini / codebuddy / cursor 五个 agent
- **连接**：支持官方账号的 agent 分组内固定有一行「官方账号」状态行（已连接/未连接，只读检测 CLI 的 auth 文件）。点「**连接**」会在内嵌终端开新标签执行登录命令（`claude auth login` / `codex login` / `cursor-agent login`，OAuth 会弹浏览器授权）；Gemini 没有登录子命令，标签直接拉起 gemini，在 TUI 里选 **Sign in with Google**；CodeBuddy 在 TUI 内 `/login`。登录完成后回本页点状态行的「刷新」重新检测
- **断开**：用 CLI 自己的 logout——`claude auth logout`（或 TUI 内 `/logout`）、`codex logout`、gemini TUI 内 `/auth signout`、codebuddy TUI 内 `/logout`、`cursor-agent logout`。Ccode 只读检测，不替你删除 auth 文件
- **启动行为**：官方账号 profile 启动时不注入端点/密钥，并清除同协议残留的 API 密钥环境变量（防止静默覆盖账号登录）；凭证可能存于系统钥匙串或加密存储（不落文件）时状态行会注明可能漏报（Cursor 凭证默认就在 macOS 钥匙串，仅设 `AGENT_CLI_CREDENTIAL_STORE=file` 时才落 `~/.cursor/auth.json`），以 CLI 自己的 status 命令为准
- **冲突警告**：状态行检测 CLI 自己读取的配置文件（`~/.gemini/.env`、`~/.claude/settings.json` 的 env 块）——其中残留的 API 密钥会覆盖官方账号登录并产生 API 计费，命中时状态行显示黄色「N 项配置冲突」，悬停查看具体变量名，需自行编辑对应文件删除

### 1.4 两种生效方式

- **注入模式（默认）**：终端页「启动」时配置只传给该进程，不改系统文件
- **全局模式**：「⋯ → 设为全局」写入 CLI 配置文件（如 `~/.claude/settings.json`），任何终端生效。同一 CLI 涉及的多个文件会作为一个完整批次写入：全部准备成功才替换，任何一步失败都会自动回滚。「恢复备份」恢复最近一个完整批次；恢复前会先备份当前状态，原恢复点不会被消耗。写入成功后会自动再跑本地解析与对应 CLI 配置检查；失败会直接展开验证结果，不必等到下次启动才发现配置损坏

### 1.5 多模型切换

profile 多个模型时，启动栏下拉选一个启动；CLI 内继续切换：

| CLI | 切换方式 |
|---|---|
| Claude Code | `/model`（前 5 个已注册进选择器） |
| Codex | `/model`（自动生成 model catalog） |
| Qwen / Kimi / OpenCode | `/model`（「设为全局」后列表完整） |
| Gemini | 只能 `/model set <模型id>` 手输（CLI 限制） |

## 二、工作区页（⛁）：任务级 git worktree 隔离

解决多个 agent 在同一目录并行冲突。工作区 = 独立 worktree + 分支 + 端口段。注册项目后，工作区按项目分组展示，组顶部带流水线概览（步骤胶囊）与资源面板。

### 2.1 项目注册与流水线

把一个目录注册为项目后，可以在项目维度定义流水线步骤与资源清单（存于项目目录的 `.ccode/project.toml`，跟着 git 走）。

- **添加项目**：页面顶部主操作「**+ 添加项目**」→ 系统对话框选目录 → 弹窗内命名 → 注册。注册项目即使没有工作区也显示在工作区页（按最近打开排序）；未注册的目录仍按工作区 repo 自动归组，组头「注册项目」打开同一注册弹窗（已预选该目录）。项目组「⋯」可重命名或移除注册（只删注册记录，不动磁盘目录与工作区）
- **课题主题**：「添加项目」与选择模板时都可选填课题主题（存 `project.toml` 顶层 `topic`），显示在项目组头名称旁；组「⋯」→「编辑课题主题」可随时改，一键开步时写进 `TASK.md` 的「课题主题」段供 Agent 围绕执行
- **git 引导**：新注册的目录若还不是 git 仓库，组顶部出现一次性引导横幅，点「初始化 git」一键 init 并生成 `.gitignore`（默认忽略产物目录、`.DS_Store` 与 `*.pdf`——文献 PDF 等大文件登记为资源引用、不进 git；已有 `.gitignore` 不覆盖；已是仓库则提示无需初始化）
- **流水线概览**：组顶部按序展示步骤胶囊（步骤名 + 状态点：待开始 / 进行中 / 待评审 / 已完成 / 阻塞），标题行显示「研究流程 d/t」文字计数与「⚠ N 条提示」校验徽标。状态从绑定工作区自动派生（有冲突 = 阻塞、合并完成无新提交 = 已完成、已提交待合并 = 待评审、有未提交改动 = 进行中），归档工作区回到「待开始」并给出「恢复」入口；纯展示，不需要手动维护状态。每步胶囊只保留一个主按钮（按状态切换：待开始→「开始」、已归档→「恢复」、阻塞→「解决冲突」、待评审→「评审」、其余→「⌨ 终端」）+「产物」+「⋯」；悬浮胶囊可查看步骤名、状态、工作区目录与最近使用的 agent/profile（取自该工作区上次启动配置）；「产物」打开该步骤的产物小面板——进行中/待评审列绑定工作区工作树下的预期产物文件，已完成（已合并）列主文件夹下的同名产物，目录条目列一层文件，未产出显示「尚未产出」，点击文件跳到终端页预览（清单只在打开面板时读取，不自动刷新）
- **空流水线**：新项目还没有步骤时显示「**选择流水线模板**」，打开模板库（名称/描述/步骤数/步骤名预览）选一个写入 `.ccode/project.toml`，也可「编辑流水线」打开同一编辑器从头自建；模板写入后仍可逐步编辑
- **模板库**：内置四套——「英文综述」（检索筛选 → 精读笔记 → 大纲 → 初稿 → 润色定稿）、「科研论文」（选题调研 → 实验设计 → 实验执行 → 结果分析 → IMRaD 初稿 → 投稿准备）、「数据处理」（登记检查 → 清洗整理 → 探索性分析 → 分析报告）、「毕业论文」（开题与综述 → 研究方法 → 实验与结果 → 全文初稿 → 格式与定稿）。胶囊行末尾「重置为模板」打开同一模板库替换现有步骤（绑定的工作区与资源不受影响）；组「⋯」→「另存为模板」把当前流水线存为自定义模板（填名称+描述，同名覆盖会先确认），用户模板在选择器中带「删除」。科研论文/毕业论文模板的初稿与定稿步骤自带 `quarto render` 渲染脚本，开步时自动写入项目 `.ccode/settings.toml`——该工作区行的「运行脚本」菜单随即出现 `render-draft` / `render-final` 一键渲染 PDF，以及 `export-docx` 一键把同一份 Markdown 导出为 docx（与 PDF 渲染并存互不冲突；未安装 quarto/pandoc 时脚本报错会直接显示在终端，安装引导见 `quarto-render` 技能）
- **编辑流水线**：胶囊行末尾「**编辑流水线**」是唯一入口（空流水线面板的同名按钮打开同一编辑器），打开全宽编辑器，每个步骤一张卡片：步骤名与工作区名、大段简报（一键开步时落成 `TASK.md`）、预期产物（逗号分隔）、run 脚本（名称+命令，可增删）、**资源绑定**（勾选项目资源：默认全不勾 = 本步骤使用全部资源；勾选后 `TASK.md` 的「项目资源」段只列选中项，让任务与你准备的资料一一对应；绑定了已移除资源的条目显示「失效」，取消勾选即清理）。卡片可 ↑↓ 排序、删除，底部「+ 添加步骤」；「保存」整体写回 `project.toml`，「取消」放弃，有未保存改动关闭会先确认。配置校验提示（绑定不存在、简报引用与产物不符等）显示在编辑器顶部和概览行的「⚠ N 条提示」徽标（悬停查看）
- **步骤「开始」（一键开步）**：自动确保 git 仓库 → **自动把 `.ccode`（档案卡）与 `.gitignore` 提交进主仓库**（只这两个 Ccode 自有路径，用户其他文件绝不纳入，包括你已自行暂存的文件；无改动则跳过，提交失败只提示不阻断开步——避免工作区合并时被「主文件夹里还有没保存的改动」拦截）→ 建该步骤的绑定工作区 → 把步骤简报落成工作区的 `TASK.md` → 跳到终端预填启动。步骤「⋯」可「◫ 定位目录」（跳到终端页并把文件树根切到该工作区目录，工作区已归档/未创建时禁用）、复制工作区名、删除步骤（不影响已建工作区）
- **资源面板**：组内「资源（N）」折叠区登记 PDF / CSV / parquet / bib 等资料（**只登记路径不复制文件**）；「**发现资源**」自动扫描项目目录列出候选，勾选后一键登记（已登记的标记 ✓）。PDF 资源行有「**查看**」，跳到终端页内嵌预览（可选中文字「◈ 问 AI」，即使文件不在任何文件树根内也能打开）。资源行「⋯」可复制绝对路径（粘贴给 agent 作输入）、移除登记；repo 内登记数据资源后会一次性提示建议加入 `.gitignore`
- **历史**：组「⋯」→「**历史**」打开项目的白话保存时间线（全宽只读视图）——「保存到历史」就是把这一步的成果存进项目时间线。按天分组（今天/昨天/日期），每条一行：✓ 验收合并（工作区任务合回主文件夹，优先显示步骤名）、⚙ 自动保存（Ccode 自动提交的档案卡等）、◔ 保存（你的手动提交，附「N 个文件 +x −y」摘要）；提交 hash 以小字 mono 保留在右侧供技术核对。时间线只展示主线记录：工作区里的过程提交不单独列出，它们的成果通过「✓ 验收合并」体现，保持简洁

### 2.2 创建工作区

「新建工作区」→ 选仓库（只列真实 git 仓库，可手输）→ 填任务名 → 自动：原子预留端口段并写入「创建中」记录 → 拉 `ccode/<任务名>` 分支（基于**本地**主分支，含未推送的提交，工作区 = 你本地项目的现状）→ 建 worktree 到 `~/ccode/workspaces/<仓库>/<任务名>/` → 复制 `.env` 类文件 → 跑 setup 脚本 → 激活工作区。worktree、复制文件或数据库激活任一步失败，应用会补偿删除 worktree/分支/创建中记录并释放端口；复制失败会明确指出具体文件，不会再静默忽略。setup 失败仍保留已创建工作区并标记失败，方便进入终端修复。

成功后「打开终端」自动开标签（目录、端口环境变量已预置）。

### 2.3 项目自动化（.ccode/settings.toml）

```toml
files_to_copy = [".env", ".env.local"]
run_mode = "concurrent"            # nonconcurrent 时脚本互斥
[scripts]
setup = "npm install"               # 创建时执行
archive = "docker compose down"     # 归档前执行（失败阻止归档）
[scripts.run]
web = { command = "npm run dev", default = true }
test = { command = "npm run test" }
```

配了之后行内出现 **▶**（默认脚本）/ **▾**（全部脚本），点击开 shell 标签自动执行。`nonconcurrent` 模式下已有脚本运行时，▾ 菜单里其余脚本显示为禁用项并注明原因，不会静默消失。

### 2.4 行内信息与操作

列表是任务索引：每行只显示**任务名、状态**（可点开看分支、改动和阻塞原因）与高频主路径「⌨ 终端 / 评审」。分支名以小字 mono 次级显示在任务名下方；领先/落后（↑N ↓M）收在状态详情里，悬浮给出白话解释（「比主分支多出 N 个保存点；主分支新增 M 个保存点」）。活跃的 merge 冲突是唯一例外：主操作会直接显示警告色「**解决冲突**」，但仍进入与普通评审相同的终端全宽审阅。会话、运行脚本、复制路径、修复、恢复和删除等低频项位于「⋯」。

PR 与归档也从「⋯」定位到评审页内再确认，避免列表页和评审页各有一套完成流程。**归档不会丢未提交内容**：存在未提交改动时评审页会要求「提交并归档」；正在解冲突或仍有 agent/run 脚本运行时会拒绝归档。普通归档不强制移除工作树；只有明确的「删除」会使用强制删除语义。

如果用户在外部终端移动/删除仓库、worktree 或分支，或者留下未完成 merge，工作区行会显示**状态漂移**并暂停普通危险操作。按实际情况可选择「重新挂载」（重建/修复 worktree 关联）、「重新定位仓库」、「标记归档」或「清理记录」；后两项只改 Ccode 元数据，不删除磁盘目录或分支。已有 merge 现场继续进入统一的全屏冲突审阅。状态诊断本身失败时行内显示「**诊断失败 · 重试**」，点击重新检查，期间按健康状态降级展示、不整体隐藏操作。

### 2.5 评审与合并

- **评审（无冲突）**：行上点「评审」进入终端页的全宽任务审阅；终端标签和进程仍在后台保持运行。中间按文件连续展示左右对照 diff，右侧改动树可快速定位文件；顶部第二工具行可填写或用 ◈ 生成提交信息。默认主按钮「**提交并合并**」一次完成提交和本地合并，工作区继续保留；下拉仍可选「**仅提交**」或「**合并并归档**」。如果改动已提交，主按钮直接变为「合并」。提交后会重新做健康检查，不会因为进入快捷流程而绕过冲突、主仓脏或主仓分支错误等拦截。被「主文件夹里还有没保存的改动」拦截时不用离开评审：展开问题列表，点该行旁的「**提交主文件夹的改动…**」在评审内直接列出主仓文件并勾选提交（默认不勾选、提交信息留空走本地默认信息、不调 AI），提交成功自动重新健康检查。
- **白话术语对照**：**提交** = 把改动保存到项目历史（文件本身不会丢）；**合并** = 把任务成果放回主文件夹（主仓库）；**保存点** = 一次提交产生的历史记录，「多出 N 个保存点」即 git 术语的领先 N；**冲突** = 两边改了同一个地方，需要你逐个文件选一边。技术信息保留在二级位置（悬浮提示/小字 mono），编程用户不受影响。
- **PR 与归档**：从工作区「⋯」选择「在评审中创建 PR / 归档」会直接打开同一评审覆盖层中的对应确认框。创建 PR 仍需在框内填写/确认标题；归档仍会重新检查脏改动、merge 与运行中任务，绝不因入口收口而绕过安全检查。
- **审阅布局**：顶部固定显示任务、分支方向、文件数和总增删量，右上角固定主动作；有未提交改动时，提交信息与 ◈ 生成入口位于第二工具行。主区连续显示双栏 diff，文件标题吸顶，较长的未修改代码默认折叠；右侧仅保留文件搜索、目录树和当前进度，选中项会随主区滚动同步。这样搜索、定位、阅读和完成动作始终在稳定位置，不需要在右栏底部寻找按钮。图片文件（png/jpg/gif/webp/svg/bmp）不再只提示「二进制」，而是直接双栏看图：左基准版、右当前版（透明图带棋盘格底；新增/删除时对应一侧标注为空），单图超过 20 MB 才回落提示。
- **评审（有冲突）**：行上点「**解决冲突**」直接进入与普通评审相同的终端全宽覆盖层，终端标签和进程仍在后台运行。工作区干净时应用会自动在隔离工作区同步**当前最新**基准分支，不再先展示容易被误认为当前 main 的普通累计 diff；有未提交改动时先在顶部填写信息并「先提交改动」，提交后自动继续。准备完成后，中间区按文件连续展示完整双栏对照——左侧任务分支、右侧 main/基准分支，右侧冲突清单可快速定位。每个文件标题下方用紧凑的「选用」控件选择任务版或基准版，并显示已选结果；顶部也支持「全部任务版 / 全部 main 版」，「**◈ AI 建议 → 按建议选择**」为主按钮级（cta 高亮）并附一行小字说明「不确定选哪边时可让 AI 按上下文建议；仍可逐文件手动改选」。如果处理期间 main 又被其他工作区推进，旧对照会立即停止展示和选边，右上角提示「重新同步最新 main」；确认后应用放弃旧冲突现场并重新生成两侧。全部选完默认点「**完成解决并合并**」，应用会提交解决结果、重新检查健康度并合回本地主分支，工作区继续保留且不会推送；下拉可选「**仅保存解决结果**」稍后再合并。选边按整个文件生效；需要逐行混合两侧时，转到预览编辑器手动修改。若解决提交成功但最终合并被主仓脏、分支错误等条件拦截，会明确显示“解决结果已提交，但合并未完成”，处理拦截原因后点普通「合并」即可，不要重复解决冲突
- **改动面板任务视图**：worktree 里自动切换为 vs `merge-base(主分支, 任务分支)` 的累计 diff，头部显示「相对主分支 xxx」（悬浮保留 merge-base 说明），「审阅」可随时展开上述全宽视图；提交区按钮为「**保存到历史 / 保存并推送**」（提交信息留空时「快速保存到历史 / 快速保存并推送」），悬浮标注对应的 git commit / push
- **合并**：「合并」按钮高亮（=可合并）时可用，是拆分按钮——主按钮「**合并**」只合回主分支、**工作区保留**（终端继续用，之后可随时归档）；「**▾**」下拉可选「**合并并归档**」（合并后移除 worktree、自动归档；还留在工作树里的终端标签会自动 cd 回主仓库）。保留的工作区合并完成后，按钮变为禁用的「**已合并**」；继续产生新提交后自动恢复为「合并」。均只合到本地、不自动推送远程（主仓库 git 面板头部 ↑N 即领先远程的提交数）。前置：分支已提交、与基准无冲突、主仓库在主分支且干净，缺一按钮即灰，悬停看原因；合并被拒时报错会列出主仓库的脏文件。若最终 merge 仍失败，应用会自动 `git merge --abort`，主仓库不会停在冲突状态。若代码已合并但归档脚本失败，会明确显示「已合并、归档失败」，此时只需点「归档」重试
- **创建 PR**：弹窗填标题，正文留空自动摘要、或点「**◈ AI 起草**」生成结构化描述（变更点/动机/测试情况，可编辑）→ 推送分支 + `gh` 建 PR（需已登录 gh）。如果分支已推送但 `gh pr create` 失败，弹窗会显示「重试创建 PR」，不会重复推送

## 三、终端页（⌨）：并行工作主界面

三带布局：**左栏（搜索+最近项目+项目区+文件树）｜ 终端标签区 ｜ 右侧面板（对话/预览/改动）**。右侧面板左边缘可拖动调整宽度，普通宽度会在本机记忆；顶部「⇱」进入宽屏分栏，暂时隐藏工作树但保留终端，点「⇲」还原，也可双击「对话 / 预览 / 改动」页签切换。这样查看长 diff 或代码时不需要建立另一套全屏页面，任务审阅覆盖层仍保持独立。标签栏右侧「⤢ 专注」进入专注模式：**只剩终端**——左右栏、顶部标签条、标签内状态条全部隐藏；标签列表移到 App 侧栏（导航图标下方，纵向展示，可切换/关闭/新建），原状态条动作（停止/⟳恢复/⤴对话/对话/◎查找/修改）集成到侧栏的「⋯ 操作」菜单（按当前标签状态裁剪），菜单末项退出专注。

### 3.1 启动与标签

启动栏第一行固定按 agent → profile → 模型 → 目录 → 启动排列，目录会占用剩余宽度；技能数、工作区端口状态与 shell 状态在第二行。启动后启动栏**自动收缩为状态行**（点「修改」展开），只保留「对话 / 修改 / ⋯」；停止、恢复、打开 Shell、查找等按状态出现在「⋯」菜单。选择会记忆，每个工作区也会记住上次用的配置。

- **多标签**：「＋」开标签，各自独立进程；活跃标签为绿色下划线；关闭 × 悬停出现
- **重启恢复**：应用关闭前会在本机保存可恢复标签的名称、目录、agent/profile、模型和关联 sessionId；不会保存 PTY id、滚动输出、密钥、环境变量或 run 脚本命令。重开后标签以「**上次任务，可恢复**」占位出现，不会自动启动进程；点击「恢复任务」才创建新 PTY。上次目录或 profile 已不存在时会保留可编辑启动栏并明确提示，不会偷偷换目录或配置
- **停止/回落**：agent 退出自动回落登录 shell（「shell 模式」，提示「会话已保存，可一键恢复」）；shell 里 `exit` 彻底结束
- **打开 Shell**：纯终端标签（展开的启动栏或收缩状态行的「⋯」中）
- **⟳恢复 / ⤴对话**：收缩状态行的「⋯」按状态显示——⟳恢复 = 用刚才的 sessionId 接回原对话继续聊（shell 模式且可恢复时出现）；⤴对话 = 跳到对话页打开该对话回放（可做标记/保留/归档等整理）
- **◈ 接力到…**：把当前对话交给另一个 Agent 继续干（终端标签收缩状态行「⋯」/ 专注模式侧栏「⋯ 操作」，或对话页回放头部「⋯」进入）。选择目标 Agent 后，应用从当前会话尾部生成一份**结构化接力简报**（任务信息 / 最近对话要点 / 当前 git 状态），脱敏后落到项目目录 `.ccode/handoff-<时间>.md`，再开新终端标签预填同目录与目标 Agent，首条指令自动注入「读简报继续任务」。**接力是简报接力，不是记忆转移**——新 Agent 只看到简报，完整上下文仍留在原 Agent 会话里。Kimi / OpenCode 没有启动注入参数：会先把简报路径复制到剪贴板并提示，启动栏保留指令文本，由你手动发送。接力生成的新会话在对话页显示「**⇄ 接自 <Agent>**」小标，接力链可回溯

> **「进程 vs 会话」心智模型**：进程是标签里正在跑的活的（agent 或 shell），一次一个、不可复活；会话是写在盘上的对话记录，进程死了它还在。停止 agent = 杀进程不杀会话；shell 回落 = 进程空窗期补位；恢复 = 拿盘上的会话开新进程接着聊。
- **注意力标记**：绿点脉冲=工作中，蓝点=已完成等你输入，琥珀点=待确认（显示在标签和运行中面板）；agent 从工作中转为待确认/已完成且 Ccode 窗口未聚焦时另发 **macOS 系统通知**（同一标签 30 秒内最多一条，首次发送需允许系统通知权限；可在设置页「外观 → 长任务 OS 通知」关闭）
- **运行中聚合视图**：运行中面板按「哪个要我管」排序汇总全部终端标签——顶部摘要「N 个待确认 · N 个已完成 · N 个工作中」，列表每项显示注意力点、标签名、agent、模型与目录；待确认 > 已完成（未查看）> 工作中 > shell/已退出（淡显）。点击跳转到对应标签；已完成项跳过后视为已查看，从摘要计数移除（重新变已完成会再计入）

### 3.2 对话联动

启动后点「对话」打开右侧结构化视图。头部显示标题、Agent、会话 ID，以及「识别中 / 同步中 / 已结束 / 等待关联」状态；正文只保留最近 **50 条**，每 3 秒按文件签名增量刷新，不再反复解析整份长会话。点「**完整回放**」可精确跳到对话页继续向前加载历史。

Claude/Qwen 用 `--session-id` 确定性锁定；其余 agent 由后端按 **Agent + 项目 + 启动批次**排他认领，同目录并发标签不会抢到同一条会话，跳转和运行态登记也始终使用 `agent + sessionId` 复合标识。运行中的会话在对话页带绿点「进行中」，可点击跳回对应终端标签。

对话滚动只在你原本位于底部附近时跟随新消息；向上阅读后不会被强制拉回底部，而是在右下角显示「**有新消息 ↓**」。重新切换标签或重新打开对话面板时，才定位到该标签的最新内容。

### 3.3 文件树（左栏）

自上而下：**搜索框 → 最近项目 → 项目区 → 完整树**。

- **搜索框**：当前根目录内按文件名搜索（跳过隐藏目录/构建产物）；结果点击 = 树内定位+高亮
- **最近项目**：按各 Agent 会话的最近更新时间聚合、去重并排序，最多展示 4 个，当前文件树所在项目不重复出现。应用启动时后台预取，并用上次成功结果立即占位展示；首次无缓存时先显示固定骨架，因此进入终端页不会等扫描完成后突然把文件树向下顶开。点击 = 树和终端 cwd 一起切过去（真进入）；↗ 另开标签。缓存中的目录点击前仍会重新验证，已移动或删除时不会切进无效路径
- **项目区**：当前标签 cwd 属于某注册项目或某工作区时，最近项目下方显示「项目」折叠区（默认展开）——主文件夹节点（repo 根名，带「主」标记）下列出该项目的**活跃工作区**（工作区名 + 流水线步骤名 + 注意力点；未创建/已归档不列出）。点击主文件夹或工作区名 = 树和终端 cwd 一起切过去（同「最近项目」真进入语义，右侧对话/预览/改动随之联动）；节点前的 ▸ 只展开显示该节点的**一层目录**（只读，不点不拉取，子目录可点击继续切根）。当前 cwd 落在哪个节点，该节点高亮。agent 正在运行时 cwd 不切换（既有语义），会给出提示但不打断运行中的任务
- **树**：双击钻取；「←」返回上一级；`⌂` 回到当前项目；自动刷新（噪声过滤）；git 状态字母（M/A/?/D）。树根跟随终端的**真实 cwd**——切标签、shell 里 `cd` 都会跟（每 4 秒探测一次；启动栏输入框聚焦时不打扰）。根目录名旁标注归属：绿点「**分支**」= 在工作区工作树里，黄点「**主仓库**」= 在主仓库里（改动不进任何分支）；命中工作区时出现「**⇄**」下拉——列出主项目 + 该仓库全部活跃工作区，任意切换（树和终端 cwd 一起切）
- **右键**：目录 = 打开终端/新建文件夹（内联输入）/删除；文件 = 删除。系统目录、关键用户目录、CLI 配置、.git 等**重要路径一律拒绝删除**
- **预览**：单击文件 → 右侧 Monaco 编辑器（**按扩展名语法高亮**），可编辑（脏标记 ●，保存写回；>256KB/二进制只读）。**Markdown 文件默认进入「阅读版式」**：渲染后的排版视图（标题层级/引用/表格/代码块/列表，配色随主题），工具行可切「**阅读 / 编辑**」（编辑回到 Monaco，切换不丢未保存改动）；点「**⛶ 沉浸阅读 / 沉浸编辑**」打开全宽覆盖层（阅读为大号排版居中、编辑为全宽 Monaco——编辑器实例不变，未保存改动与撤销历史不丢；头部带文件名、保存按钮与「✕ 退出」，Esc 关闭，终端继续在后台运行）；阅读版式（含沉浸阅读）里拖选文字会出现「**◈ 讨论/改写此段**」浮动按钮，点击把「选段引用 + 出处文件名」写入**当前活跃终端标签**的 agent 输入框（不自动发送，接着输入你的意见——讨论、提问或要求改写——后自行回车；无运行中 agent 会提示）；Agent 正在写文件时阅读内容自动刷新，编辑中不覆盖。**PDF 文件走内嵌 pdf.js 预览**：页码导航/跳页/缩放/适配宽度，只渲染当前页与相邻页；在文字上拖选会出现「**◈ 问 AI**」浮动按钮，点击把「选段 + 出处（文件名、页码）」写入**当前活跃终端标签**的 agent 输入框（不自动发送，检查后自行回车；无运行中 agent 会提示）；旁边的「**整理为笔记**」把选段（含文件名/页码/日期出处）追加到归属项目「文献精读与笔记」步骤工作区的 `notes/inbox.md`——没有该工作区时自动一键开步创建，完成后预填终端启动，让 Agent 把选段整理成结构化笔记；PDF 未登记为任何项目资源时会提示并给出「去工作区页登记」入口。**docx 文件走阅读版式预览**：经 mammoth 转成排版视图（标题/正文/列表/表格，图片内嵌显示，配色随主题），只读不可编辑——改内容请编辑对应的 Markdown 源文件再重新导出；超过 50MB 的 docx 不渲染并明确提示。在当前树根内预览保持已打开文件；**切换项目、工作区、终端标签 cwd 或树根时自动清空旧预览**，不会擅自打开新根下的同名文件。未保存时先确认，取消则不切换树根。**磁盘被外部改写（合并/agent 写入等）时自动刷新内容**（编辑中不覆盖）。文件名旁标注路径归属：绿点「分支 ccode/x」= 在工作区工作树里（改动属于该分支）；黄点「**主仓库（非分支）**」= 在主仓库里——此时保存按钮变「**保存到主仓库**」（警示色）且保存前二次确认，防止误改主项目

### 3.4 git 改动面板（右侧「改动」页签）

分支、领先/落后、+/- 行数（含未跟踪）、文件列表，8 秒刷新。文件列表按状态分组显示中文组名（「修改的 N / 新增的 N / 删除的 N」），状态字母（M/A/??/D）保留为文件名前的小号 mono 徽标，悬浮显示「字母 · 中文」说明，方便程序员扫读、新手看白话。**点击任一文件行可在面板内展开/收起单文件 diff**；新增/删除行只使用语义色文字与左侧细线，不再整行铺绿色或红色背景，代码主体保持冷黑底，hunk 标题才使用轻微 inset 底色。未跟踪文本按全新增显示，图片文件展开为「基准 vs 当前」双栏看图，其余二进制文件给出只读提示，超大内容最多读取约 200 KB 并明确标记截断。读取前后都会核对该路径仍属于当前 Git 改动，过期或越界路径会拒绝。工作区任务头部增加「**审阅**」入口，展开全宽 diff 与提交合并闭环；普通仓库不显示。

**按块丢弃/暂存（逐 hunk 验收）**：展开的文件 diff 里，每个改动块（hunk）标题右侧有「**丢弃**」「**暂存**」两个小按钮（只覆盖未提交改动；工作区视图里同样可用，但仅限仍未提交的块，已提交的累计改动请走「审阅」）。「丢弃」把这块改动从工作区抹掉（会二次确认，不可恢复，除非已提交过）；「暂存」把这块改动放进暂存区，随后勾选该文件「**保存到历史**」时就只提交已暂存的块，其余块留在工作区——这就是选块保存。新文件整个文件算一个块：暂存 = 纳入 git 跟踪，丢弃 = 删除该文件。文件已有部分内容暂存时，展开区会提示提交粒度；全部块都暂存后，展开区回落为只读视图并提示「改动已全部暂存」。二进制、非 UTF-8 或超大文件不支持按块操作，保持只读展示。

**普通仓库默认不勾选文件**，可逐文件选择或全选/清空，并明确显示「将保存 N / M 个文件」；提交和 ◈ 生成都只读取所选文件，未选文件保持在工作区。隔离任务工作区仍固定提交全部任务改动，避免把一个任务拆成难以理解的半提交。改动说明可以手动填写（留空自动生成一条），也可点输入框旁的「**◈**」让 AI 按 diff 生成后再审阅。主按钮为「**保存到历史**」（悬浮标注 `git commit`），旁边「**保存并推送**」（悬浮标注 `git commit + push`）；若说明留空，按钮自动变为「**快速保存到历史** / **快速保存并推送**」：应用按文件状态和数量在本地即时生成中性默认信息，不调用 AI，直接提交或推送（无上游自动 `push -u`）。提交阶段失败会把默认信息留在输入框供修改或重试；如果提交已成功但推送失败，会显示「**重试推送**」，只执行 push，不会重复提交。成功时右下角浮出主题绿 toast，展示提交号和实际使用的提交标题。

**产物区（提货单）**：工作区任务视图底部增加「产物（提货单）」区——大型产物（数据/图/PDF）**不进 git**，只有清单 `artifacts.yaml` 随提交传递给下一步。「**登记产物**」打开系统对话框选文件，应用计算 md5 与大小后把工作区根的 `artifacts.yaml` 更新一条（名称/绝对路径/hash/大小/来源工作区/时间；已被 git 跟踪的文件会被拒绝，因为它本来就随分支走；同一路径重复登记会更新而不是重复）。条目显示名称、路径、大小、hash 前 8 位与来源工作区；PDF 条目带「**查看**」按钮，直接在内嵌 PDF 预览中打开。下一步「开始」开步时，项目根的提货单会自动写进新工作区 `TASK.md` 的「上一步产物（提货单）」段，Agent 按路径直接读取产物，不需要手动复制路径。

### 3.5 终端质感

WebGL 渲染（失败时自动回退）、清瘦字形（400/600 字重、行高 1.2、零字距，向 Ghostty 锐利度靠）、盒绘字符对齐、粗体增亮、平滑滚动 150ms、细滚动条。默认字体为打包内置的 JetBrains Mono（woff2，不依赖系统安装），可在设置页换其他字体或调色板预设。后台标签输出只缓存不推流（切回补发），输出 50ms 合帧——十余个标签并行也流畅。

**输出搜索**：⌘/Ctrl+F 或工具栏「◎ 查找」呼出搜索条（输入即增量查找，Enter 下一个、Shift+Enter 上一个、Esc 关闭），只作用于当前活跃标签。

## 四、对话页（◔）：历史回放与整理

- **左栏分类树**：全部 / 按 agent → 按项目；顶部搜索（项目/标题/标签/工作区名/**流水线步骤名**/**AI 摘要内容**）。Ccode 自己发起的 ◈ 无头 AI 会话不混进普通项目，默认归并到单独的「**Ccode 内部 AI**」入口；分类只认后端登记的精确来源，不按临时目录名称猜测
- **归档计数**：「显示已归档」关闭时，全部、Agent、项目和内部 AI 的数字都排除归档项；打开后统一计入，避免左栏数字与列表结果口径不一致
- **列表与标题**：显示标题、相对时间、agent、token 用量；工作区会话的 ⎇ badge 优先显示**流水线步骤名**（工作区名命中项目档案卡 `steps[].workspaceName` 时；不匹配则回落工作区名，悬浮可见两者）；选中项目节点时列表按步骤分组（步骤名小标题，同步骤按时间降序，无工作区会话排在最前）；接力生成的会话带「⇄ 接自 <Agent>」badge（简报接力，非记忆转移）；头部同时显示「当前 N · 搜索命中 M · 总计 T」；Codex resume 链合并（「N 次继续」）；⚑=已保留；绿点「进行中」（内部启动的可点击跳回终端；**外部终端里运行的会话**也按文件活跃度自动标记，仅显示）。标题会折叠换行与多余空格，并忽略 `New Session`、`Untitled`、`未命名对话` 等占位值，优先回落到首条真实用户消息；仍无标题时显示「未命名对话 · ID 前 8 位」
- **对话回放**：首次只读取会话尾部的有界窗口；长会话顶部显示「**加载更早对话**」，逐页向前加载并保持当前阅读位置。OpenCode 每页最多 80 条消息；普通 JSONL 每页最多读取约 192 KB；压缩的旧 Codex 会话只提供有界尾部回放。头部保留「**◈ 摘要**」（AI 概括，缓存）与「**导出**」（整段对话导出 Markdown 到 `~/Downloads/ccode-exports/`）
- **当前项目改动**：「对话 | 当前项目改动」页签中的后者只读展示该项目**此刻磁盘上的 Git 状态**，不是历史会话产生改动的快照；可点击文件展开 diff，但不提供提交或推送，点「前往终端处理」进入正常编辑/提交流程
- **在终端恢复**：行悬停/右键或回放头部 → 自动开标签续聊（claude `-r`、codex `resume`、kimi `-S` 等）
- **⇗ 外部恢复 / ⧉ 复制命令**：不想用内嵌终端时——⇗ 直接在外部终端应用里开窗口续聊（macOS 依次找 Ghostty → iTerm → 系统终端；Windows 开 cmd 新窗口；Linux 找 gnome-terminal/konsole/xterm）；⧉ 复制形如 `codex resume 019fbd46-…` 的恢复命令（含 `cd` 到项目目录），粘贴到任何终端自己执行。两者都用你机器上的全局 CLI 配置（不携带 Ccode profile 注入的密钥）
- **整理**：保留（pin 快照，CLI 自动删除后也能回放）、归档（默认隐藏）、自定义标题/标签、删除会话文件（OpenCode 删除其库中记录；Codex resume 链会连带删除链上成员文件）；项目节点右键批量删除——删除范围含该项目的全部会话：已归档/内部对话即使不在当前列表中也会被一并删除（确认框会明确提示数量）
- **批量删除**：列表头部「批量管理」进入选择模式 → 勾选/全选（当前筛选结果）→「删除 N 项」→ 警示色二次确认「确认删除 N 项（含 pin 快照）？」后逐个删除（pin 快照一并清理，与单个删除同语义）。筛选/搜索无结果时显示「清除筛选」按钮
- **敏感信息保护**：会话标题、回放正文、AI 摘要和 Markdown 导出在后端统一隐藏已保存密钥及常见密钥前缀；脱敏完成后才会送到界面，CLI 的原始会话文件保持只读、不被改写

## 五、技能页（✦）：Skills 统一管理

技能 = 含 `SKILL.md` 的目录（开放标准）。先入库，再分发到各 CLI。

- **分类分组**：可折叠分类头（▸/▾）；修改分类在行内「⋯ → 设置分类」内联输入（回车保存，留空归未分类）
- **应用开关**：每行八个 agent 圆点开关（claude/codex/gemini/qwen/oc/kimi/cb/cur），绿点=已分发到对应 CLI 技能目录（symlink 优先 copy 兜底；cursor 未验证 CLI 是否真读技能目录，固定 copy），灰点=未分发，点击即切换；关闭只清理由 Ccode 分发的。形态不再用药丸文本标注，悬浮在开关上显示完整说明（symlink / copy，copy 带漂移检测）
- **副本漂移**：copy 副本与库不一致时，技能名旁显示黄点（悬浮列出漂移的 agent），行内「⋯ → 重新分发副本」把库里的最新版本重新同步过去
- **导入**：本地目录 / ZIP / GitHub 仓库（`owner/repo` 或完整网址，可另填分支/子目录，预设 anthropics/skills）/「发现未纳管」（页面顶部 ⋯，扫描各 CLI 目录收编）。结果完整分列**新增、覆盖更新、跳过、冲突**四类并逐类列出技能名，不用「已导入 0 个」掩盖冲突；冲突可批量跳过、按右栏名称**全部另存为**、或**备份并覆盖**（覆盖前先备份旧库目录）。ZIP 先在临时目录完整校验再入库，元数据写入失败会回滚库目录
- **新建 / 编辑**：顶部「+ 新建技能」直接把自己的工作方法写成技能（名称即目录名、描述一句话、正文即 SKILL.md 主体，frontmatter 自动生成）；行内「⋯ → 编辑内容」修改描述与正文，保存前自动备份当前版本（保留最近 5 份），SKILL.md 之外的辅助文件不受影响；重名会被拒绝并提示改用编辑
- **◈ 优化**：行内「⋯ → ◈ 优化」写下优化意见后开终端标签（技能库目录为工作目录），Agent 阅读并按意见直接改写库中的 SKILL.md——这是把 skill 交给 Agent 迭代优化的入口；改写结果请审查后再用，之后的保存/覆盖都有旧版本备份兜底
- **步骤推荐技能**：在 `.ccode/project.toml` 的步骤里填 `skills = ["技能名"]`（流水线编辑器会保留该字段），一键开步的 TASK.md 会落成「本步骤推荐技能」段（名称 + 一句话描述，未安装的会标注）；技能本体不进 TASK.md，已分发的技能对启动的 Agent 自动生效，未分发可在本页开启
- **GitHub 更新**：GitHub 来源会记录仓库、子目录与 revision；页面顶部「⋯ → 检查 GitHub 更新」，有可更新时行名旁显示黄点，行内 ⋯ 可「导入 GitHub 更新」带原地址重新打开导入器。重新导入仍经过同名冲突确认，不会静默覆盖
- **导出**：全部打包 ZIP 位于页面顶部 ⋯，单行导出位于行内 ⋯；**查看**：右侧预览 SKILL.md（标注来源与仓库）；**删除**：位于行内 ⋯，取消应用 + 库文件备份（5 份）
- **随 P2 附带四个综述技能**：`lit-search`（检索与筛选）、`lit-notes`（精读笔记）、`review-framework`（综述框架构造：空白清单 + 范式卡片融合出 outline.md）、`review-writing`（英文综述写作）；**随 P3 附带两个数据技能**：`data-clean`（数据清洗规范）、`data-eda`（探索性分析与绘图规范）；**随 P4 附带**：`quarto-render`（quarto 渲染与排错）。均已预装入库，在技能页打开对应 agent 开关即可分发

## 六、统计页（◫）：用量与费用

按消息逐条解析用量、按天聚合（增量更新）。

- **费用口径**：费用均按官方公开价（27 项定价，供应商前缀自动剥离）估算；含未计价模型显示 `≥`，没有可用价格显示 `~`。说明集中在范围工具栏下方，不在每一列表头重复标注。**官方账号**（如 Google 登录）启动产生的用量显示「**订阅**」而非估算金额——不按量计费，token 数仍是实际统计（usage schema 已升 v6，首次打开自动重建索引）

## 七、设置页（⛭）

设置项按「外观 / 统计 / 集成 / 更新 / 诊断」分区，分区可折叠且状态记忆；首次只展开高频的「外观」，其余按需展开。每个设置项的说明文字常驻显示在标签下方（macOS WKWebView 不渲染悬浮提示，不依赖悬停）。

- **更新**：启动时静默检查新版本；有可用更新时该分区自动展开，并在标题显示绿点 + 「vX 可更新」标记；发现更新显示版本号与更新日志，「下载并安装」后自动重启；也可手动「重新检查」
- **诊断**：应用内最近错误/警告日志（前端渲染错误自动上报），支持复制全部/清空——反馈问题时把它发给开发者

- **主题**：七套深色色卡（沉浸黑/陶土/Ayu 琥珀/Catppuccin/极简灰蓝/Dracula/灰蓝正红），各有独立强调色（CTA/选中/「活跃」「可合并」pill 同步换色），点击即时全站切换
- **终端字体**：内置 JetBrains Mono（默认）+ 常用等宽字体候选（Maple Mono NF CN / Sarasa Mono SC / Iosevka / SF Mono / Menlo / Consolas，需系统已装，未装自动回退内置字体），也可填系统已装的任意字体名；选中 Maple/Sarasa/Iosevka 且系统未安装时，下拉旁出现「安装」按钮，一键经 Homebrew 安装（未装 brew 会明确提示），装完即生效；**终端调色板**：VS Code Dark+（默认）等多套预设，8 色无缝色条预览（与终端实际生效色同源），点选即时生效
- **终端字号**：11-18，实时生效；**滚动缓冲行数**：新标签生效
- **长任务 OS 通知**：默认开；agent 从工作中转为待确认/已完成且窗口未聚焦时发系统通知（同一标签 30 秒去抖），关闭后完全不请求权限、不发通知
- **汇率**：USD→CNY，统计页 ¥ 换算
- **brew 镜像开关**：安装/更新是否走 TUNA
- **AI 专用配置**：◈ 生成（提交信息/会话摘要/PR 描述）固定使用的 profile，建议选快模型（生成速度主要取决于它）；默认「自动」= 最近使用的 profile
- **外部终端**：对话页「⇗ 外部恢复」使用的终端应用——默认「自动」按优先级探测（macOS: Ghostty → iTerm → 系统终端；Linux: gnome-terminal/konsole/xterm），也可固定选某一个；选了未安装的会在恢复时报错提示改选
- **自定义定价**：文本框编辑 pricing.json（带校验），下一次统计查询生效

## 八、AI 功能说明（◈）

四处 ◈ 按钮（git 提交信息、会话摘要、PR 描述、冲突审查建议）都通过 **headless 模式调用 agent**：把上下文（diff/会话/提交记录/冲突文件）发给该 CLI 的 print 模式（如 `kimi -p`、`claude -p`），纯文本生成（不依赖工具调用），不产生交互会话。profile 选择顺序：设置页「AI 专用配置」（如已选）→ 最近使用的 profile；生成慢多半是因为自动落到了大模型上，在设置页指定一个快模型即可。专用 profile 被删除时会报错提示重选，不会静默落到别的配置。失败时先检查所选 profile 是否可用。

## 九、常见问题（FAQ）

**Q：macOS 安装后打开提示「已损坏，无法打开」？**
A：不是真损坏——未签名应用从网络下载会带 quarantine 隔离标记，Gatekeeper 因此拦截。终端执行 `xattr -cr /Applications/Ccode.app` 即可。每次重新下载安装都要执行一次，做了签名公证后此问题消失。

**Q：agent 不真正执行操作（不建文件等）？**
A：中转模型不支持工具调用（实测 zetatechs 部分模型只会文字糊弄）。换真 Claude 系模型或支持工具调用的中转。

**Q：配置保存了但调用报空响应/404？**
A：Base URL 的 `/v1` 约定：OpenAI 协议（kimi/codex/qwen/opencode）**必须带** `/v1`；Anthropic 协议（claude/codebuddy）**不要带**。建完先点「测试连接」。

**Q：按钮点了没反应？**
A：macOS WKWebView 不支持 `window.prompt`——需要输入的地方已全部改为内联输入；如仍遇到，把位置报给开发者。

**Q：终端输出黑白？**
A：已内置修复（注入 TERM/COLORTERM、剔除 NO_COLOR）。

**Q：安装/更新卡在下载？**
A：brew 已走 TUNA 镜像（设置页可关）；npm 慢的话在 profile 附加环境变量加 `npm_config_registry=https://registry.npmmirror.com`。

**Q：改了模型列表，CLI 里 /model 没变？**
A：注入配置只在新启动的会话生效，重启该终端标签。

**Q：工作区的会话在历史里归到哪？**
A：所属仓库的项目下，带 `⎇ 任务名` 标签；工作区删除后显示为独立项目（源文件仍在）。
