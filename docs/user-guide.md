# Ccode 使用手册

> 本文档随产品功能实时更新（改动功能时必须同步本文档，见 AGENTS.md 规则）。
> 最后更新：2026-08-01（工作树逻辑统一版）

Ccode 是一个 AI 编码 Agent 的统一工作台：在一个应用里管理多个 CLI agent（Claude Code、Codex、Gemini CLI、Qwen Code、OpenCode、Kimi Code）的 API 配置，内嵌终端一键启动，并行任务工作区（git worktree 隔离），会话历史回放。

侧栏五个页面：**配置 / 工作区 / 终端 / 会话 / 技能**。

**四个页面是打通的**：配置页建的 profile 在终端页一键启动；终端里跑的会话在会话页实时可见（🟢 点一下跳回终端）；会话页的历史可以「在终端恢复」续聊（自动预填目录/agent/profile）；工作区页的任务自动完成装依赖、起服务、评审合并，并记住你上次用的配置。典型动线：**配置 →（工作区）→ 终端 ⇄ 会话**。

## 一、配置页：管理 agent 和 API 配置

页面结构：**可折叠分组列表**。顶部筛选（全部 / 已安装 / 未安装）+ 右侧搜索（按名称/端点/模型过滤）。每个 agent 是一个分组：组头显示名称 + 安装状态 + 版本号 + 右侧更新/安装按钮；有配置的分组默认展开，没有配置的默认收起。配置项是整齐的五列网格：名称 | 端点 | 模型标签 | 密钥状态 | 操作（编辑 + ⋯ 菜单）。

### 1.1 安装与更新 agent

- 每个 agent 标题行显示安装状态：**已安装 · 版本号** 或 **未安装**
- 未安装 → 点「**安装**」（确认框会告诉你将执行什么命令）；已安装 → 点「**更新**」
- 安装/更新过程是**实时终端**：输出滚动显示；遇到 `[y/n]` 提示时在下方的 `>` 输入行回答；超过 2 分钟无输出会出现提示；失败会给出诊断建议

### 1.2 创建配置（profile）

一个 profile = 某 agent 的一套 API 配置（端点 + 密钥 + 模型列表）。一个 agent 可以建多个 profile（如「官方」「中转A」）。

点「**新建配置**」，表单字段：

| 字段 | 说明 |
|---|---|
| Agent | 选 CLI 类型 |
| 名称 | 自己认的标记，如「Zeta 中转」 |
| Base URL | 中转/网关地址；官方端点可留空或用「从预设快速填充」 |
| API Key | 存本地 `keys.json`（0600 权限），界面只显示尾号 |
| 协议 | 仅 Qwen（openai/anthropic）和 Kimi 需要选 |
| 模型列表 | **可多个**，首个为默认。点「获取模型」可从端点自动拉取下拉选 |
| 附加环境变量 | 每行 `KEY=VALUE`，注入优先级最高（如 `HTTPS_PROXY=...`） |

辅助功能：**测试连接**（验证端点+密钥，显示延迟和模型数）；**导入/导出**（JSON 备份，不含密钥）；行内「⋯」菜单有 复制/设为全局/恢复备份/删除。每行还会显示「x 天前使用 / 从未使用」，帮你识别闲置配置。

### 1.3 两种生效方式（重要区别）

- **注入模式（默认）**：在 Ccode 终端页点「启动」时，配置只传给这一次启动的进程，**不改你系统里的任何文件**。其他终端不受影响
- **全局模式**：点 profile 行的「⋯ → 设为全局」，会把配置写进该 CLI 的配置文件（如 `~/.claude/settings.json`），**你在任何终端敲命令都会走这套配置**。写前自动备份，「恢复备份」可还原

### 1.4 多模型切换

profile 里加了多个模型后，启动时在终端页的模型下拉框选一个；进入 CLI 后还能切换：

| CLI | 会话内切换方式 |
|---|---|
| Claude Code | `/model` 选择器（前 5 个模型已注册进去） |
| Codex | `/model` 选择器（我们自动生成了 model catalog） |
| Qwen / Kimi / OpenCode | `/model`（需「设为全局」后才有完整列表） |
| Gemini | 只能手输 `/model set <模型id>`（CLI 本身限制） |

## 二、终端页：并行工作的主界面

三带布局：**左栏（工作树 + 运行中）｜ 中间（终端标签）｜ 右侧面板（会话/预览/改动）**

### 2.1 启动 agent

启动栏：选 agent → 选 profile → 选模型 → 填工作目录 → 「**启动**」。选过的组合会记住，下次免选。

- **启动栏自动收缩**：启动成功后启动栏收拢成一条状态行（agent · profile · 模型 · 目录），点「修改」可重新展开
- **专注模式**：标签栏右侧「⤢ 专注」一键隐藏左栏和右侧面板，终端全宽
- **多标签并行**：标签栏「＋」开新标签，每个标签独立的 agent/目录/会话（活跃标签为绿色下划线）
- **停止与回落**：点「停止」或 agent 自己退出后，终端**自动回落到你的登录 shell**（可继续敲普通命令，显示「shell 模式」）；在 shell 里敲 `exit` 则彻底结束
- **打开 Shell**：不启动 agent，直接开一个纯终端标签
- 性能说明：终端为 GPU（WebGL）渲染；后台标签输出只缓存不推流，切回时补发，10+ 标签并行也流畅

### 2.2 会话联动面板

启动 agent 后，启动栏出现「**会话**」按钮——右侧面板实时显示这次对话的**结构化内容**（消息气泡、思考折叠、工具调用），3 秒刷新，和终端字符流同步。

### 2.3 工作树（左栏）

三段布局：**顶部搜索框 → 最近项目 → 完整文件树**。

- **当前项目为锚**：树根默认是当前终端标签的工作目录。根目录名旁的「←」返回上一级目录（可一直向上）；偏离当前项目时右侧出现 `⌂` 一键回到当前项目
- **顶部搜索框**：在当前根目录内按文件名递归搜索（跳过隐藏目录/node_modules/target/dist），结果点击 = 在树里定位并高亮（不自动打开预览）
- **最近项目**：按最近活跃排序的项目列表，点击 = 树和终端 cwd **一起切过去**（真进入）；悬停 ↗ 才是另开终端标签
- **文件树**：双击文件夹钻取；文件变化自动刷新（监听有噪声过滤，构建产物不触发）；git 状态字母（M 琥珀 / A、? 绿 / D 红）
- **右键操作**：目录 = 在此打开新终端 / 新建文件夹 / 删除目录；文件 = 删除（删除有确认，且系统目录、关键用户目录、CLI 配置、.git 等**重要路径一律拒绝删除**）
- **文件预览（右侧「预览」页签）**：Monaco 编辑器（VS Code 同款内核），**按扩展名自动语法高亮**；可直接编辑，脏标记 ●，点「保存」写回（>256KB 或二进制只读）

### 2.4 运行中面板（左栏底部，默认折叠）

默认折叠为一行「运行中 (N)」，点击展开；有 agent 在跑时会自动展开一次提醒。内容：🟢 agent 运行中（输出活跃时脉冲）/ 🔵 shell 模式 / ⚪ 已退出，附 profile、模型、项目名。点击跳转对应标签。

**注意力标记**：标签和运行中面板会告诉你 agent 的进度——绿点脉冲 = 工作中；蓝点「已完成」= 干完了在等你输入；琥珀点「待确认」= 在等你回答/授权。

### 2.5 git 改动面板（右侧「改动」页签）

跟着当前标签的工作目录走，8 秒刷新：分支、领先/落后、**+增加/−删除** 行数、文件级列表。底部输入提交信息 → 「**提交**」或「**提交并推送**」（无上游分支自动 `push -u`）。页签上的 `+N` 角标提示有改动。

## 三、工作区页：任务级隔离（git worktree）

解决「多个 agent 在同一目录并行干活互相打架」的问题。每个工作区 = 独立 worktree + 独立分支 + 独立端口段。

### 3.1 创建工作区

「新建工作区」→ 选仓库（下拉只列真实 git 仓库，可手输路径）→ 填任务名 → 自动完成：拉 `ccode/<任务名>` 分支（基于 origin 主分支）→ 建 worktree 到 `~/ccode/workspaces/<仓库>/<任务名>/` → 复制 `.env` 等文件 → 跑 setup 脚本（装依赖）→ 分配端口段（4000 起，10 个/工作区）。

成功后点「**打开终端**」→ 自动开标签，目录和端口环境变量都已预置。

### 3.2 项目自动化（.ccode/settings.toml）

在仓库根目录放 `.ccode/settings.toml`（本项目和网页设计仓库各有一份示例）：

```toml
files_to_copy = [".env", ".env.local"]   # 建工作区时复制
run_mode = "concurrent"                   # nonconcurrent = 同时只能跑一个脚本
[scripts]
setup = "npm install"                     # 创建时自动执行
archive = "docker compose down"           # 归档前执行（失败会阻止归档）
[scripts.run]
web = { command = "npm run dev", default = true }   # ▶ 一键运行
test = { command = "npm run test" }
```

配了之后工作区行会出现 **▶**（默认脚本）和 **▾**（全部脚本），点击自动开 shell 标签执行。

**行内其他操作**：「会话」→ 跳到会话页并自动按该工作区名筛选；「打开终端」会记住并预填你上次在这个工作区用的 agent/profile/模型。

### 3.3 生命周期

- **归档**：移除 worktree（分支保留），随时「恢复」
- **删除**：worktree + 分支 + 元数据全清（有确认，不可恢复）
- 在 worktree 里跑第二个实例：见 Ccode 仓库的示范配置（vite 端口用注入的 CCODE_PORT，不与主实例冲突）

### 3.4 评审与合并（W3）

- **任务累计改动**：终端页「改动」面板在 worktree 里自动切换为任务视图——diff 基准是 `merge-base(主分支, 任务分支)`，显示整个任务的累计改动（含已提交），不是只看未提交部分
- **状态判定**：工作区行显示健康状态——「有未提交」「有冲突」「可合并」（无未提交且与主分支无冲突）、`↑领先 ↓落后`
- **合并**：状态到「可合并」后点「合并」→ 把任务分支合并回主分支并自动归档工作区。前置条件：主仓库当前在主分支且工作区干净，否则按提示处理或走 PR
- **创建 PR**：点「创建 PR」→ 填标题（正文留空自动生成提交摘要）→ 自动推送分支并用 `gh` 创建 PR，返回 PR 链接可直接打开。需要机器已登录 `gh`

### 3.5 完整实操演练（新用户跟做版）

以网页设计仓库为例，任务名 `w3-test`，完整走一遍「建 → 干 → 审 → 合」：

**① 建工作区 + 干活**
1. 「工作区」→ 新建工作区，选仓库、填任务名 → 等 setup 装完依赖
2. 点「打开终端」→ 启动 agent，让它做个真实小改动（如「README 末尾加一行，新建一个文件写入当天日期」）
3. 预期：改动发生在 `~/ccode/workspaces/<仓库>/w3-test/`，原目录不受影响

**② 提交改动到任务分支**
1. 右侧「改动」面板确认改动列表正确
2. 底部输入框写提交信息（如 `test: w3`），点「提交」= `git add -A && git commit`
3. 预期：面板显示 `[ccode/w3-test xxxx] test: w3 · N files changed`；**提交按钮随后变灰是正常**——没有剩余改动可提交了
4. 关键观察：提交前后「改动」面板的累计 `+/-` 数字不变（任务 diff 含已提交部分），这是它和普通 git status 的区别

**③ 看健康状态**：回「工作区」页，该行应出现「可合并」绿色标记（可能带 `↑1`）。若显示「有未提交」，回改动面板看漏了什么

**④A 本地合并**（不影响远程，先练这个）
1. 先在系统终端确认主仓库干净：`git -C <主仓库> status`（若不在主分支或有改动，合并会被拦下并提示原因）
2. 点「合并」→ 确认
3. 预期：任务分支合并进主分支，工作区自动变「已归档」；系统终端 `git -C <主仓库> log --oneline -3` 能看到合并提交

**④B 创建 PR**（⚠️ 会在 GitHub 产生真实 PR）
1. 点「创建 PR」→ 标题默认即可，正文留空（自动生成提交摘要）
2. 预期：返回 PR 链接，浏览器打开可见；正文是自动生成的提交列表
3. 在 GitHub 合并或关闭后，回 Ccode 删除该工作区

**⑤ 清理**：「工作区」页删除演练工作区；系统终端 `git -C <主仓库> branch | grep ccode` 应无残留

**常见卡点**
- **提交按钮灰色**：不是坏了——没有可提交的改动（已提交完或没改动）
- **合并被拦**：读提示——主仓库必须停在主分支且工作区干净；有散装改动就先提交或 stash
- **git 提示 Committer 身份**：未配全局用户名邮箱时的提醒，不影响功能；`git config --global user.name/email` 配一次即可

## 四、会话页：历史回放与整理

- **左栏分类树**：全部会话 / 按 agent → 按项目（目录）两层；顶部搜索（项目/标题/标签）
- **会话列表**：标题、相对时间、agent、token 用量；Codex 的多次 resume 自动合并为一条（标「N 次继续」）
- **回放**：点会话全宽显示结构化对话（思考折叠、工具芯片）
- **在终端恢复**：会话行（悬停/右键）或回放页头部的「在终端恢复」→ 自动开终端标签：目录、agent、profile（取该 agent 上次用的）全部预填，并用各 CLI 的恢复参数续上原会话（claude `-r`、codex `resume`、kimi `-S` 等）——**历史一键变回干活现场**
- **进行中标记**：正在终端里运行的会话带 🟢「进行中」，点击直接跳到那个终端标签（反向跳转）
- **整理**：右键或悬停操作——**保留**（pin 快照，CLI 自动删除后也能看）、**归档**（默认隐藏）、自定义标题/标签、**删除会话文件**
- 项目节点右键可**批量删除**该项目的全部会话

## 五、技能页：管理 agent 技能（Skills）

技能 = 一个含 `SKILL.md` 的目录（开放标准），教会 agent 特定能力。本页是技能的统一仓库：先入库，再按需分发到各 CLI。

- **应用开关**：技能行有六个 agent 的药丸开关（claude/codex/gemini/qwen/oc/kimi），点亮即把技能链接/复制到对应 CLI 的技能目录（如 `~/.claude/skills/`），下次启动该 agent 即可用；关闭则移除（只清理由 Ccode 分发的，不碰你自己的目录）
- **导入**（四路）：本地目录（递归找 SKILL.md）/ ZIP 文件 / GitHub 仓库（`owner/repo`，预设 anthropics/skills）/ 「发现未纳管」（扫描各 CLI 目录里还没入库的技能一键收编）
- **导出**：单行导出为 ZIP；顶部导出打包全部
- **查看**：点「查看」右侧预览 SKILL.md 全文
- **删除**：确认后从各 agent 取消应用并删除库文件（自动备份到 `skill-backups/`，保留 5 份）

注意：技能目录的修改不会自动同步——symlink 分发的是实时生效，copy 分发（Windows 或 symlink 失败时）需关闭再打开开关刷新。

## 六、统计页：用量与费用

展示六个 agent 的 token 用量（按消息逐条解析，按天聚合，增量更新）。

- **顶部卡片**：输入/输出/缓存读（含缓存写）tokens、会话数、估算费用
- **时间范围**：今日 / 近 7 天 / 近 30 天 / 全部，右上角切换；「刷新」手动重建索引（首次打开自动建立）
- **分布**：agent 条形图（谁吃 token 最多）、项目排行（哪个项目花得多）、模型明细（哪个模型最贵）
- **费用说明（官方价口径）**：内置 27 项常见模型官方定价（含 grok/glm/qwen/kimi/gemini 系），供应商前缀（如 `zetatechs/xxx`）自动剥离匹配；中转用量也按**官方公开价**估算并标注「费用(官方价)」，页底有免责说明；桶内含未计价模型时显示 `≥`（部分估算）。可自定义：`~/Library/Application Support/ccode/pricing.json` 里按 `{"模型前缀": [输入价, 输出价]}`（每百万 token 美元）覆盖
- **$/¥ 切换**：范围选择器旁的按钮一键切换美元/人民币显示（汇率默认 7.2，`pricing.json` 里 `"_rate": 数字` 可改），选择持久保存

## 七、常见问题（FAQ）

**Q：agent 回复了但不真正执行操作（不创建文件等）？**
A：是中转模型不支持工具调用（实测 zetatechs 的部分模型只会文字糊弄）。换真 Claude 系模型或换个支持工具调用的中转。

**Q：配置保存了但调用报空响应/404？**
A：大概率是 Base URL 的 `/v1` 约定问题：OpenAI 协议（kimi/codex/qwen/opencode）的 SDK 直接在 Base URL 后拼路径，**必须带 `/v1`**（如 `https://xxx.com/v1`）；Anthropic 协议（claude）的 SDK 自己拼 `/v1/messages`，Base URL **不要带** `/v1`。建完配置先点「测试连接」能提前发现。

**Q：终端输出是黑白的？**
A：已内置修复（自动注入 TERM/COLORTERM、剔除 NO_COLOR）。如在 Ccode 外遇到，检查环境的 NO_COLOR 变量。

**Q：安装/更新卡在某个下载？**
A：brew 已自动走清华镜像；npm 慢的话在 profile 的附加环境变量加 `npm_config_registry=https://registry.npmmirror.com`。

**Q：改了模型列表，CLI 里 /model 没变化？**
A：注入的配置只在**新启动**的会话生效，重启该终端标签即可（Codex 的 catalog 也是启动时加载）。

**Q：工作区的会话在历史里归到哪？**
A：归到所属仓库的项目下，带 `⎇ 任务名` 标签。工作区删除后，其历史会话显示为独立项目（数据源文件仍在）。

**Q：修改功能后这份手册去哪更新？**
A：本文档（`docs/user-guide.md`），由开发流程强制同步（AGENTS.md 规则）。
