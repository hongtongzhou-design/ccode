# Ccode 使用手册

> 2026-09-02：快速开聊收口——历史只显示 `~/ccode/scratch` 里的随手聊；弹层上半新开、下半「继续上次」。侧栏记住选择后直接开聊，想每次先选就勾「每次都先问我」。⌘K 和工作台页头仍打开弹层。

> 2026-09-02：快速开聊弹层里的「随手聊历史」打开就在，不再先空着再蹦出来。侧栏右键同一份历史也是马上列出。默认目录一开始就是 `~/ccode/scratch`；弹层里按回车等于点「开聊」。

> 2026-09-02：工作台「继续当前工作」跟真实运行对齐——有 Agent 在跑时，主卡显示那个标签所属的项目（已添加的用项目名）和它自己的状态（正在工作 / 在等你确认），点「继续工作」进运行页并打开该标签。没有运行时才回到上次在项目页选中的项目，并标出研究流程里当前那一步。待你处理没条目时不占右边空栏。

> 2026-09-02：聊天输入框在中文输入法组词还没上屏时按回车，只会确认候选词，不会把半句话发出去。

> 2026-09-02：聊天层可以「窥视」同一会话的终端——聊天下方出现一块真正的终端（Agent 会按这块高度重画界面）。只切聊天/终端时画面大小不变；打开或收起窥视时终端会跟着改高度（Codex 有时会把历史重画一遍）。等待确认、登录卡住、或发出会打开选择器的命令时会自动露出。聊天里也可以切模型/思考档、拖文件进输入框、加载更早的消息。

> 2026-09-02：运行页默认面层从「聊天」改为「终端」——新标签打开直接看到 xterm 终端画面，标签栏同一个按钮单击仍可随时切到聊天层（每个标签独立记住所在层）。「新建聊天」分叉等明确聊天意图的入口仍直接落聊天层，不受影响。

> macOS 浅色主题对比度（2026-08-29）：七套浅色主题的次级文字（时间戳、描述行等浅灰字）在 macOS 上统一加深到中间档——介于原值与 Windows 修复值之间，画面不发闷、正文级灰字达到 WCAG AA 可读线；Windows 与深色主题不受影响。

> Windows 显示清晰度：顶栏改回静态 Segoe UI（不用 Variable），字号字重与正文一致；导航胶囊的毛玻璃模糊与文字分层，避免 WebView2 把字一起栅格化发糊。正文仍用 Segoe UI Variable。macOS/Linux 显示规则不变。此前 2026-08-28：恢复标准 rem 根字号、浅色主题次级文字对比度。

> 模型配置增强（2026-08-27）：连接 Profile 新增请求策略声明、Header 环境变量引用、Agent 能力状态提示和启动计划预览；旧配置文件可无迁移读取，密钥值不进入预览或文档。

> 2026-08-25：MCP 页按设计评审重构——① 页面从满宽收回限宽（约 1080px 居中），宽屏下名称与右侧开关不再分列整页两端；② 整表收进单张带细边浅底的圆角卡片，补了轻量表头（名称 | 类型 | 配置 | 分发 | 启用），各列严格对齐、行间极细分割线；③ 点 ▸ 展开后出现一块独立的浅底深层面板：完整命令/URL 全文、环境变量与请求头（$VAR 引用原样展示）、分发到各 CLI 的开关网格，嵌套内容有了明确落点；④ stdio 紫 / remote 蓝徽章的文字色随主题自适应加深（浅色主题更深、深色主题更亮），识别色相不变。

> 2026-08-25：技能页列表按设计评审重构，解决「树状分组 × 表格列」的视觉冲突——① 分组卡片化：同一分类的技能裹进带细边和浅底的圆角卡片，组与组边界明确；② 子项相对组头加深缩进，悬浮高亮带收进卡片内边距与圆角内，不再通栏切断分组；③ 删除逐行重复的「来源」列：组内来源一致时在组头标一次（如 KKKKhazix/khazix-skills），混合来源不标，具体仓库链接仍在右侧预览面板；④ 描述文字对比度提升（米白底色上不再暗淡），标签与 MCP 徽标同步提亮；⑤ 「0 个 Agent」保持无点灰字、已应用保持绿点，区分闲置与激活。行内 ✎/◈/⋯ 操作仍为悬停淡入的裸图标钮（全站统一口径不变）。

> 2026-08-25：连接页列表整体排版升级——① 五列网格严格对齐（名称/状态 | 域名 | 模型 | 密钥状态 | 操作），「官方账号」行与数据行共用同一网格、行高与分割线，不再有独立行样式；行间改为极细分割线。② 状态标记只在有含义时出现（配置失效 / 已停用）；「默认」「全局生效」收进名称下方的次级小字（与「上次使用」同行）。③ 模型标签去掉灰色底块，改为等宽小字纯文字。④ 组头的包名版本号降为微缩灰字；组内「+ 添加连接」改为次级扁平按钮；行内「在终端使用」「外部终端」改为悬停才现的图标按钮，常驻只留「编辑」与「⋯」。⑤ 「brew 渠道最新但上游 npm 已有更新」的说明不再常驻组头占一整串小字，收成版本区一枚安静的 ⧉ 小图标：悬浮看完整说明，点击复制渠道切换命令（功能不变）。

> 2026-08-25：工作台三处跳转修正——「继续当前工作」主卡与「最近项目」列表此前只跳到项目页首页，现在按落点分流：已在 Ccode 注册的项目跳到项目页并选中该项目详情；未注册的目录（比如只在外部终端干过活的仓库）跳到运行页「真进入」该目录（文件树与终端 cwd 一起切过去，同终端页「最近项目」口径；目录已移动/删除时明确提示而不是卡住）。「最近对话」点击不再只是进对话页，而是直接打开那条对话的回放（同终端页「⤴对话」口径）。2026-09-02 起主卡若对应正在运行的标签，点「继续工作」改为聚焦该标签，不再一律进项目页。

> 2026-08-24：聊天层四项增强——① Agent 等待确认时聊天顶部出现审批卡片：开启「精确注意力标记」的 Agent 会显示在等什么（如「需要 Bash 权限」），卡片上可直接点 ✓ 批准 / ✗ 拒绝 / Esc 取消（按键无效的少数情况仍可一键去终端）；② 聊天头部新增「⏹ 打断」（等效 Ctrl+C）；③ AI 每条消息末尾显示该条 token 用量（Claude/Kimi/Gemini/Qwen/OpenCode 支持）；④ 输入框输入 / 弹出斜杠命令面板（Enter 直接发送选中命令，Tab 只补全；命令表是各家常用子集，没有的命令照常手输）。连续发送多条消息时，未落盘的本地消息全部保留显示（排队语义），不再只留最后一条。

> 2026-08-24：聊天区 AI 回复改为 Markdown 渲染（加粗/列表/表格/代码块生效），消息里的本地图片直接内嵌显示为缩略卡、点击可放大预览，外部图片与外链不自动加载（外链点击走系统浏览器）。聊天⇄终端切换不再丢失输入框草稿与滚动位置。聊天输入框支持直接粘贴截图/图片：粘贴后显示为输入框上方的缩略附件卡（× 可移除），发送时随消息一起发出，发出后消息里显示图片而非路径文本。

开发预览使用 `npm run tauri:dev`，窗口标题为「Ccode Dev - 热更新」；React/样式修改会自动刷新。它与正式版和打包调试版名称不同，验收时以该标题区分。原生下拉、复选框、单选框及日期/数字控件会按当前主题渲染，浅色主题不会出现深色系统弹层。

侧栏按任务层级组织全部页面：**工作（工作台 / 项目 / 运行 / 对话）→ 资源（连接 / 技能 / MCP）→ 管理（用量 / 设置）**，当前页以浅色填充行 + 强调色图标标出，不再叠加左侧色条。首次启动默认进入「工作台」；点击顶部「Ccode」品牌区可在展开侧栏与纯图标栏之间切换（状态会记住），「运行」图标在有 agent 运行时会显示数量徽标（任意页面可见）。需要沉浸工作时可用 ⌘\\ 或命令面板进入完全隐藏。常规页面顶部统一为“标题与当前状态 + 唯一主动作”，搜索和筛选位于下一行工具栏；终端、对话、技能预览继续使用适合连续工作的分栏布局。

**键盘流**：`⌘K`（Windows/Linux 为 `Ctrl+K`）呼出命令面板——可跳九个页面（也可直接 `⌘1`–`⌘9` / `Ctrl+1`–`Ctrl+9`，顺序同侧栏）、切换十四套主题（七深七浅）、隐藏/显示侧栏（同 `⌘\` / `Ctrl+\`，专注干活时界面只剩内容）。命令面板唯一入口在顶栏，键位标签跟随你的自定义绑定；面板内 ↑↓ 选择、回车执行、Esc 关闭。快捷键可在**设置页「快捷键」分区**自定义：命令面板、侧栏显隐与九个页面切换逐条录制——点击绑定按钮后按下新组合键即保存（与其他在用绑定冲突会拒绝），可「恢复默认」；页切另保留整组总开关，关闭后九个页切绑定全部不生效。长任务待确认的系统通知带「**去处理**」按钮：点击聚焦对应终端标签（横幅样式不显示按钮属系统设置行为，点通知正文同样唤回应用收件箱）。

**快速开聊（不建项目直接聊）**：侧栏「工作」组首位与 ⌘K 面板里的「**＋ 快速开聊**」打开同一个弹层——选 agent / 配置 / 目录（默认 `~/ccode/scratch`，三项都会记住上次选择），点「开聊」落到终端页一个干净标签（自动收起工作树与右栏，有可用配置直接启动，没有再降级为预填）：不建项目、不建工作区、不写 `.ccode`。再点「快速开聊」时若 agent/配置/目录与已有随手聊标签相同，**切回那个标签**而不是新开（重启恢复的占位标签不参与复用——会话已断，新开才诚实）；想并行另起一个，换其中任意一项选择即可。**弹层下方是「继续上次」**：只列 `~/ccode/scratch` 里的随手聊（打开即显示）。最近一条是单独按钮，其余在下面；点一条直接**恢复那个对话**。在别的未添加目录（例如 Ccode 源码仓库）里聊过的，请去对话页找，不进这里。已归档/内部任务/进程还活着的不会列出来。「查看全部 →」跳对话页。弹层里按回车等于点「开聊」。**侧栏「快速开聊」**：开过一次、记住选择之后，再点就直接落终端；想每次先选，勾「**每次都先问我**」。右键仍弹出 scratch 历史（直达时左键看不到弹层，右键是回看口）。**⌘K 和工作台页头的「快速开聊」永远打开弹层**，改 Agent/目录从那里进。聊出东西了用标签「⋯ → **转为项目…**」把当前目录登记成项目（只登记、不动磁盘）。

**模块是打通的**：配置页建的 profile 在终端页一键启动；终端里跑的会话在对话页以绿点标记（内部标签可点击跳回）；历史会话一键「在终端恢复」；工作区自动完成装依赖、起服务、评审合并；AI 按钮（◈）用你最近使用的 profile 提供辅助。首次配置完成后的典型动线：**工作区 → 终端 ⇄ 对话 → 评审**；配置和技能作为能力层按需维护。

## 一、连接页（⇄）：Agent、供应商与模型连接管理
页面对用户统一称为「连接」；内部仍使用 profile 数据模型。页头主操作为「**＋ 添加连接**」，导入/导出收在「⋯」。组内行使用留白分隔与 hover 操作，常驻「编辑」，悬停或键盘聚焦后出现「⌨ 在终端使用」，其余低频动作继续收在「⋯」。
页面 = 可折叠分组卡片列表。标题栏右侧是唯一实心主按钮「**＋ 添加连接**」，「⋯」收导入/导出；下一行工具行左侧是筛选胶囊（全部/已安装/未安装，选中实心填充）与「全部折叠/展开」切换，右侧是搜索框。每个 agent 一张卡片（名称 + 连接数量 + 等宽包名/版本号 + 右侧更新状态/安装按钮，「新版」为粉色文字钮；未安装的 agent 卡片无底色、视觉降权）。还没有连接的组首次默认折叠。组内空态是一行说明，不再复制「+ 添加连接」。已安装且支持官方账号的组头有微型芯片：未连接时点「连接」在终端登录，已连接显示「官方已连接」。

### 1.1 安装与更新

- 未安装的 agent 显示「**安装**」（确认框告知将执行的命令，brew 优先，自动走 TUNA 镜像）
- 已安装的显示版本号，右侧按更新检查结果分三态：「**新版**」（有更新，点击即升级，悬停显示新版本号）/「**已更新**」（已是最新或刚更新完）/「**更新**」（该渠道查不到最新版时的普通按钮，如自更新安装的 claude/kimi）；检查走 brew info / npm view，进程内缓存，更新成功后自动重查。brew 渠道已最新但上游 npm 已有更高版本时，组头显示小字提示「brew 渠道最新；上游 npm 已到 X（渠道通常滞后）」——brew 公式更新慢于 npm 属正常现象，等 brew 跟进即可，勿按 CLI 提示改用 npm 装第二份
- 更新/安装过程是**实时终端**：输出滚动、可输入（`[y/n]` 在下方 `>` 行回答）、无输出时持续显示连接状态、失败带诊断建议；包管理器命令最多运行 15 分钟，避免 Windows 慢网络被过早终止。渠道与安装方式一致：brew 安装的走 `brew upgrade`（含 opencode，不走其交互式自更新）；npm 安装的用**与目标二进制同目录的 npm**（同机多份 node/npm 时不会装错 prefix）；Windows 上 claude/codex/opencode/kimi/grok 五家另有 winget 原生渠道（确认框显示 `winget install --id <官方包ID>`，没装 Node.js 也能装），winget 安装的走 `winget upgrade` 更新；gemini/qwen/codebuddy 没有官方 winget 包，需先装 Node.js 走 npm
- **交互式自更新在终端中打开**：kimi 这类自更新（`kimi upgrade`）是方向键选择的交互界面，行输入无法应答，点「新版/更新」会改为在内嵌终端新开标签执行该命令，用方向键选择、回车确认（按钮悬停有提示）；kimi 默认开启启动时自动更新，多数情况下无需手动点更新；在终端里更新完回切配置页会自动强制重查版本与更新状态（其余外部变更由 2 分钟缓存 TTL 自愈）

### 1.2 创建配置（网关 + 绑定）

配置分成两层：**网关**是一把密钥和按协议分槽的端点（Anthropic / OpenAI / Responses / Gemini / Cursor）；**绑定**是某个 Agent 选用这个网关的哪些模型。主列表仍按 Agent 分组；页头「网关库」编辑端点、密钥、五个协议槽。五槽上方有「**Base URL**」主输入：多协议同址的中转只填主输入，空槽与跟随中的槽一起改（槽内手填即脱离跟随）；「全部测速」按 URL 去重，同址槽只探一次。槽行显示上次测速（✓ 245ms / ✗ / 未测），可单槽「测试」。「获取模型」按 OpenAI → Anthropic → Gemini → Responses 顺序试，第一次成功的给目录打标。点模型行展开思考档/温度/输出上限（当前绑了该网关的 Agent 有通道才能改；没通道但存了值显示「已保存在网关，当前 CLI 没有通道」）。网关编辑里可把同一网关绑到其他 Agent。同一把中转密钥绑到 Claude 和 Codex 不必再复制密钥。行上可看本月费用，点开进统计页「按网关」。**用量按网关只统计经 Ccode 内嵌终端启动并记下归属的会话**；外部终端手动跑的不计入。行上「缺槽」表示这个网关还没填该 Agent 要用的协议地址，启动栏不能选。

一条绑定 ≈ 以前的一套连接。表单字段：

| 字段 | 说明 |
|---|---|
| Agent | CLI 类型 |
| 名称 | 自定义标记，如「Zeta 中转」 |
| Base URL | 中转地址；「从预设快速填充」可选官方/公开端点。**Anthropic 通道（Claude Code/CodeBuddy 或 anthropic 协议）不要带末尾 `/v1`**——客户端会自动拼 `/v1/messages`，带 `/v1` 会变成 `/v1/v1/messages` 报 404（此时「测试」仍能成功，是列表接口与运行路径口径不同），界面会行内黄字提醒 |
| API Key | 存 `keys.json`（0600），界面只显示尾号 |
| 协议 | 仅 Qwen（openai/anthropic）与 Kimi 需要，位于「高级配置」；选用已有网关时若网关只填了一个候选槽位则自动确定、只读显示 |
| 模型列表 | **可多个**，首个默认；行式槽位逐个填写（上限内自动给空槽，超上限仍可点「仍要添加」补充）。「获取模型」拉取后按厂商分组折叠选择（带筛选框）；列表拉一次即缓存并标注拉取时间，↻ 强制刷新。表单上方会提示该 agent 的模型切换页上限：Claude Code 5 个（名单 ≥3 时第 3 个 haiku 槽同时复用为子 agent 模型）、Gemini/Qwen/Kimi 注入模式仅首个生效（多模型需「设为全局」；Gemini 设为全局还会把名单登记进 /model 选择器，重启 CLI 生效）、Codex/OpenCode 不限；超出上限会黄色提醒 |
| 附加环境变量 | 每行 `KEY=VALUE`，注入优先级最高，位于「高级配置」 |
| 请求策略声明 | Header 跟网关；思考档/温度/输出上限跟网关里的每个模型。启动只注入**当时选中模型**上、且该 Agent 有通道、且体检未失败的字段。字段标注按通道入口分档：**支持**=启动注入即生效；**仅设为全局**=写入 CLI 配置文件才生效（如 Qwen 的温度/topP）；**会话内命令**=只认 `/effort` 类原生命令（如 Qwen 思考档）；不支持/未知=只存声明不注入。网关体检不是开关：没跑过体检时按 CLI 通道决定；体检明确失败才会关掉对应控件 |
| 无密钥模式 | 仅用于明确无需认证的本地/内网端点；勾选后 Ccode 会清除继承环境中的 API Key，不会静默使用其他账号。 |

辅助：Base URL 行内的**测试**按钮验证端点+密钥并显示延迟和模型数；保存后「⋯ → **验证**」会打开三层结果：① Ccode 字段与当前 CLI 配置文件能否解析；② CLI doctor / 启动预检；③ 最小 API 请求（鉴权、协议、模型是否存在与耗时）。密钥只在后端参与请求，不会进入验证结果或前端日志。配置页的请求策略声明会校验数值范围；不支持或未知的字段会在验证结果中提示，Ccode 不会伪造 HTTP 请求体。可通过「启动计划预览」查看最终二进制、参数、环境变量名称（带来源标注：内置/模型选择器/请求策略/附加环境变量等）、配置 overlay 原文（仅值里无密文的才展示，如 Grok 的 GROK_CONFIG、Claude 的 EXTRA_BODY）与被清理的变量（密钥值永不显示）。**Grok Build 的请求策略**（思考档/温度/输出上限/Header）经 GROK_CONFIG overlay 的 `[models]` 全局默认注入；`api_backend`（API 后端）与 `context_window` 是 grok 逐模型 `[model.*]` 字段、不在 overlay 白名单内，启动注不进——两个渠道：中转在其 `/models` 目录条目里带 `apiBackend`/`contextWindow` 字段（grok 拉目录时自读，首选）；或绑定编辑「高级设置 → **API 后端**」选 responses/messages 后点「设为全局默认」，Ccode 逐模型写 `~/.grok/config.toml` 的 `[model.*]` 段（含显示名；context_window 只在用户覆盖或网关实测确知时随段写入，估值不覆盖目录声明）。**Grok Build 支持「设为全局默认」**（2026-09-01 起）：写入 `~/.grok/config.toml` 的顶层 `api_key`、`[endpoints].models_base_url`、`[models].default` 与请求策略全局默认（与启动注入同口径，Header 存 `$VAR` 引用不落密文）；`[models]` 里的通用键只设不删，你在 config.toml 手写的其他段（如 `[mcp_servers]`）不动，回退走行内「撤销上次写入」或组头「恢复初始状态」。网关库里按槽「测试」绕过 CLI 直连端点发最小请求（max_tokens=16 的 ping）：基础鉴权与模型存在、裸流式是否回 SSE、带请求策略参数是否被接受或触发非流式降级、自定义 Header 接受度——中转「不流式/参数不生效」类问题先用它定位（Cursor 专有协议与 Gemini 暂不支持）。改了端点未保存时测试按钮不可用。**导入/导出**默认网关+绑定 v2（可选含密钥，二次确认）；旧 profiles 数组仍能导入。行内操作：编辑绑定、⋯（停用/设为默认/复制到其他 agent…/设为全局默认/解绑；Codex 绑定多一项「注册到 Codex 客户端（不切换默认）」；分隔线下方是验证与启动计划预览）。网关体检、清除密钥在网关库；撤销上次写入/恢复初始状态在 Agent 组头 ⋯。「复制到其他 agent…」把同一网关绑到同协议族的另一 agent（不复制密钥，共用一把）。「添加连接」可选「选用已有网关」而不是每次新建——选用时模型名单从该网关目录里勾选（与拉取结果同款的厂商分组选择器，目录为空可直接手填）。解绑只删这条绑定，网关和密钥留下。全局生效徽标若磁盘已被外部改过，会变成「全局生效 · 已被外部修改」。**模型能力声明的数据源**（第三方模型接入后上下文窗口/输出上限/视觉/推理等能力按它声明）：点「获取模型」时会顺带沉淀该网关实测的模型元数据（最准，含网关改名模型）；页面顶部 ⋯ 菜单的「**下载模型能力库（models.dev）**」拉公共库兜底（约 400+ 主流模型，不可达时自动换 OpenRouter 源；顺带含官方定价，统计页费用估算随之更新）；再往下是内置表与保守默认，四层都不认识才按保守值声明。想手动修正某个模型，往平台配置目录的 `ccode/model-capabilities.json` 加一条前缀覆盖即可，立即生效（Windows/macOS/Linux 路径由系统配置目录决定）。

配置列表每行只保留**名称 / 端点主机名 / 模型 / 密钥状态**和操作区：常驻「编辑、⋯」，悬停该行（键盘 Tab 聚焦同样）另显现「**⌨ 在终端使用**」——用这套配置直接新开一个终端标签并启动，省去去终端页再选一遍；⋯ 菜单里的「**停用此连接**」是「停用」的准确形态（软停用）：配置与启动行为一字未改、随时可「取消停用」；停用后不再被**自动路径**挑中——终端启动栏的预选/兜底、恢复会话、内置 AI 功能的「最近使用」回落都会跳过它（过期密钥停用后不会被静默选中）；手动指定不受影响：启动栏的配置下拉里它沉到底部「**已停用（可手选）**」分组，选它仍照常启动，你在设置页显式绑定的 AI 专用/功能专属配置也照常生效。名称下方小字显示「上次使用 X 前」（悬浮看绝对时间，从未使用不显示），模型列以代码标签逐个展示（超过 3 个自动折叠为「+N」，悬浮看完整列表），端点细节保留在编辑页或悬浮提示中。行内「⋯」悬停该行才显现（键盘 Tab 聚焦同样显示）；每个 agent 分组是一张带细边框的卡片（未安装的组无底色降权），有更新时组头的「新版」按钮保持常驻。导入/导出在页面顶部「⋯」。用量请看统计页「按网关」或网关库里的近 30 天摘要。

**预设清单**：Base URL 的「从预设快速填充」收录官方与公开的兼容端点，新建 profile 选预设 → 粘密钥即可，不必手查端点格式。claude-code 含 Anthropic 官方、智谱 GLM 与 DeepSeek（Anthropic 兼容端点）；codex/qwen/kimi/opencode/grok 的 OpenAI 兼容预设含 OpenRouter、DeepSeek、Moonshot（月之暗面/Kimi）、智谱 GLM、阿里云百炼（通义千问）等（qwen/kimi 选择兼容端点时会自动带上 `openai` 协议）；codebuddy 含腾讯官方国际站/中国站与 DeepSeek、智谱（Anthropic 兼容端点）。Gemini 用 Google 官方时 Base URL 留空即可，不设预设。**Cursor 不设预设**——其端点是 Cursor 专有协议（非 OpenAI/Anthropic 兼容），第三方供应商端点接上也不通；Cursor 的模型经 `--model` 参数注入（支持 `claude-opus-4-8[context=1m,effort=high]` 这类 bracket 参数化），API 密钥走 `CURSOR_API_KEY` 注入。grok 另含 xAI 官方端点预设（`https://api.x.ai/v1`，OpenAI 兼容）。

连接行的「⇗ 外部终端」会要求明确的 Ccode 连接和最近使用过的目录，不会静默使用其他 profile；外部启动同样复用一次性安全 wrapper。连接编辑时 Agent 已锁定，跨 Agent 请使用「复制到其他 agent」。

### 1.3 官方账号

除 API 配置外，Claude Code / Codex / Gemini / CodeBuddy / Cursor / Grok Build 支持「**官方账号**」profile：直接用 CLI 自身的订阅账号登录，不需要 API 密钥。

- **建 profile**：表单顶部「账号类型」选「官方账号」——无需填 Base URL 与密钥；模型可留空（= 用 CLI 默认模型）。配置列表端点列显示「官方账号」。目前支持 claude-code / codex / gemini / codebuddy / cursor / grok 六个 agent
- **连接**：支持官方账号的 agent 组头（已安装才显示）：未连接是「**登录**」，已连接是绿点「官方」。包名版本收进组名悬浮提示，刷新在组头 ⋯。点「**登录**」会在内嵌终端开新标签执行登录命令（`claude auth login` / `codex login` / `cursor-agent login` / `grok login`，OAuth 会弹浏览器授权）；Gemini 没有登录子命令，标签直接拉起 gemini，在 TUI 里选 **Sign in with Google**；CodeBuddy 在 TUI 内 `/login`。登录完成后用组头 ⋯「刷新官方账号」重新检测。**Codex 注意**：`~/.codex/auth.json` 里只有 `OPENAI_API_KEY` 时显示为「API Key 配置」而非「已连接」——官方 `codex login --api-key` 与 cc-switch 等第三方中转写出的是同一形状，文件层面无法区分，如实显示不算官方账号登录
- **断开**：用 CLI 自己的 logout——`claude auth logout`（或 TUI 内 `/logout`）、`codex logout`、gemini TUI 内 `/auth signout`、codebuddy TUI 内 `/logout`、`cursor-agent logout`。Ccode 只读检测，不替你删除 auth 文件
- **启动行为**：官方账号 profile 启动时不注入端点/密钥，并清除同协议残留的 API 密钥环境变量（防止静默覆盖账号登录）；凭证可能存于系统钥匙串或加密存储（不落文件）时状态行会注明可能漏报（Cursor 凭证默认就在 macOS 钥匙串，仅设 `AGENT_CLI_CREDENTIAL_STORE=file` 时才落 `~/.cursor/auth.json`），以 CLI 自己的 status 命令为准
- **冲突警告**：检测 CLI 自己读取的配置文件（`~/.gemini/.env`、`~/.claude/settings.json` 的 env 块）——其中残留的 API 密钥会覆盖官方账号登录并产生 API 计费。命中时 agent 标题旁直接亮出琥珀色「⚠ N 项配置冲突」胶囊（分组折叠时也可见），点击弹出明细面板列出具体文件与变量名，需自行编辑对应文件删除后点 ⟳ 复检

### 1.4 两种生效方式

- **注入模式（默认）**：终端页「启动」时配置只传给该进程，不改系统文件
- **托盘**：菜单栏/托盘按 Agent 列出绑定，点一下即「设为全局」（只改外部终端用的文件，不改内嵌启动栏的默认绑定）。配置页增删绑定或设为全局后菜单会刷新。对照磁盘文件：对得上才画选中；文件被外改过才提示「已在 Ccode 外改过」（官方账号那一项不算外改）。托盘「退出」走窗口关闭，有 Agent 在跑时会先确认。官方账号那一项会恢复该 CLI 的初始配置。失败发系统通知。
- **全局模式**：「⋯ → 设为全局默认」把默认渠道切到此连接：写入 CLI 配置文件（如 `~/.claude/settings.json`），任何终端与桌面客户端默认都走它。同一 CLI 涉及的多个文件会作为一个完整批次写入：全部准备成功才替换，任何一步失败都会自动回滚。「**撤销上次写入**」（原「恢复备份」）回退最近一个完整批次——写了几遍就要撤销几遍；撤销前会先备份当前状态，原恢复点不会被消耗。**另有「恢复初始状态」**：首次写入时 Ccode 会把写入前的原始配置存成永久快照（不参与批次轮换，连续多次写入也一次回到底），点它即回到 Ccode 第一次动手之前——当时还不存在的文件会被删除，当前状态同样先另存为批次、可用「撤销上次写入」反悔。写入成功后会自动再跑本地解析与对应 CLI 配置检查；失败会直接展开验证结果，不必等到下次启动才发现配置损坏。**写入成功的连接会在名称旁标记绿色「全局生效」徽标**——即「上次由 Ccode 写入该 agent 全局配置的就是它」，给「在 Ccode 配置、去外部终端用」一个一眼可分的标记；对另一个连接再「设为全局默认」徽标随之转移，恢复后徽标自动清除（恢复后全局内容不再是任何连接的快照）。注意该标记只代表「上次由 Ccode 写入」：在 Ccode 之外手改了 CLI 配置文件后标记可能失真（悬浮提示有注明），删除该连接也会同步清除标记。**Codex 特别说明**：写入的自定义 provider 带 `requires_openai_auth = true`，认证直接走 auth.json 的 OPENAI_API_KEY（codex 的自定义 provider 默认只从 `env_key` 环境变量取密钥、不读 auth.json，这个开关让它改用 OpenAI 认证）——外部终端零配置直接可用，无需 export 任何变量；2026-08-25 之前写过的配置带一行旧 `env_key`，重新「设为全局默认」一次即自动迁移。**Codex 另有轻量版「注册到 Codex 客户端（不切换默认）」**：只把 provider 定义写进 codex 的 config.toml（密钥以静态请求头形式写在定义块内，同样先备份、可用「撤销上次写入」回退），顶层默认渠道与 auth.json 都不动，**不影响客户端自己的登录态**——之后 Ccode 里此网关发起的会话可在 Codex 桌面客户端直接打开续聊（客户端按会话记录的 provider 名在 config.toml 查定义，查不到才报 Model provider not found）；已注册的连接在同一位置变为「**移除 Codex 客户端注册**」——只删 config.toml 里的 provider 定义块（块内密钥随块一并清除，同样先备份、可撤销）；移除后此渠道的会话在客户端又无法打开，Ccode 内使用不受影响；官方账号会话无需注册，客户端与 CLI 共享登录态天然可续。2026-09-02 之前注册过的，重新「注册」一次即迁移到新写法（旧写法会把密钥写进 auth.json 的共享槽，客户端用另一把 API 密钥登录时会被顶掉登录）
- **与其他切换工具（cc-switch 等）混用注意**：这类工具普遍有「切换时把当前 live 配置回填进旧 provider 存档」的同步机制——在 Ccode 写入占据 live 期间到对面操作切换，Ccode 的配置会被吸进对面的 provider 存档，之后从对面「启用」该 provider 等于把 Ccode 的配置原样写回（表象是「对面改不动了」）。**建议同一个 agent 的全局写入固定在一侧进行**；已被污染的对侧 provider 记录在该工具里编辑修正（把 config 改回它自己的 model_provider/端点）即可恢复。Ccode 侧写的只是普通文件，不留锁不留后台进程，「撤销上次写入 / 恢复初始状态」后任何工具都可正常接管

### 1.5 多模型切换

一条绑定可以挂多个模型，启动栏下拉选一个启动——思考档/温度只取**这次启动选中的那个模型**。CLI 里 `/model` 换模不会重注策略，要按新模型请重开标签。CLI 内继续切换：

| CLI | 切换方式 |
|---|---|
| Claude Code | `/model`（前 5 个已注册进选择器） |
| Codex | `/model`（自动生成 model catalog） |
| Qwen / Kimi / OpenCode | `/model`（「设为全局」后列表完整） |
| Gemini | 只能 `/model set <模型id>` 手输（CLI 限制） |

- **模型显示名与思考能力（claude / codex / kimi / opencode 四家有能力通道，其余 CLI 无此机制）**：选择器里的显示名统一取「配置名 · 模型名」（不再是裸模型 id 或内部名 ccode）；思考能力与上下文长度由内置**模型能力注册表**判定（收录 kimi/gpt/claude/gemini/glm/qwen/deepseek/grok 主流模型，覆盖文件 `<配置目录>/ccode/model-capabilities.json` 可写 `{"模型前缀": {"thinking": true, "context": 262144}}` 覆盖），表外模型按名称关键词推断（thinking/reasoner/r1/qwq 等）。推断与你的模型不符时：kimi 还可在 profile「高级配置 → 附加环境变量」写 `KIMI_MODEL_CAPABILITIES=tool_use,thinking`（或去掉 thinking）覆盖——附加环境变量优先级最高；kimi 另有两个刻意不自动注入的窄通道变量可在此声明（表单内有提示）：`KIMI_MODEL_ADAPTIVE_THINKING`（Anthropic 通道思考形态开关，注错会 400，默认自动推断已合理）、`KIMI_MODEL_REASONING_KEY`（OpenAI 通道思考字段方言 pin，中转返回异常方言时的修复手段）

## 二、项目页（⛁）：任务级 git worktree 隔离

页面采用双栏工作台：左侧是项目导航（有待处理时显示计数），右侧只展示当前项目的研究流程、资源和任务工作区，避免项目增多后形成超长纵向页面。导航行的「待处理」与顶部收件箱同一口径：除本项目工作区的冲突/可合并外，终端标签的待确认与外部运行会话的待确认也按目录归属摊到对应项目上（终端落在某工作区工作树内的算该项目）——收件箱告诉你总数，导航行告诉你分散在哪。页头右上是全页唯一实心主操作「+ 添加项目」（左侧导航栏头部的「+」图标也有同一入口），注册新目录；「新建工作区」入口收在各项目分组的工作区列表头部（仓库固定为当前分组，不依赖研究流程的手动入口，无步骤的项目与未注册分组同样可用）。切换左侧项目只改变当前详情，不会停止该项目内正在运行的 Agent。

**待你处理（首页收件箱）**：macOS 上收进**窗口标题栏**——有待办时标题文字右侧出一粒圆点 + 数字，点开按类别列出明细（点遮罩 / Esc 收起）；Windows / Linux 上则是项目页顶部同一套「待处理 N」入口。明细每条一个小圆点 + 一句话 + 操作按钮：冲突/可合并点按直接进对应工作区的全宽评审，终端条目点按跳到终端页并激活那个标签。全部处理完自动消失。项目导航行另有按项目摊开的「待处理」计数，告诉你事在哪个项目；侧栏导航不挂任何徽标数字（保持安静，计数只看标题栏入口与项目导航行）。文献雷达的新命中看项目页雷达卡，不进全局 chrome。「已回复」（agent 回合结束、等你输入）不算待办——它每次回复都发生，因此不进收件箱、不打点、不发通知。除冲突/待确认/可合并外，收件箱还覆盖四类「只有你能解锁」的事：**待核验**（任务声明的预期产物已全部产出、但还没有任何提交——PDF 等产物被 git 忽略，git 状态里看不见，点「去核验」跳到该任务所属步骤、展开产物清单并把该行滚动到屏幕中央短暂高亮）、**待发送**（后台提炼的接力简报已生成）、**配置失效**（你手动验证或「设为全局」复检失败的配置，修好前对应 agent 起不来）、**人工请求**（运行中的 agent 把需要你协助的事写进 `.ccode/help-wanted.md`——比如补检索词、某篇文献下不到；每条都附「若未回复则按 ×× 继续」的兜底方案，agent 不会停工等你，你空了点「去查看」会弹出该来源的**完整请求列表**（每条全文 + 回复指引：回到对应终端直接告诉 agent 即可），看完可「忽略此来源」（内容变了会重新出现）；窗口不在前台时出现新的人工请求会发一条系统通知，沿用「长任务 OS 通知」开关）；冲突条目在基准分支已前进时会升级为「需重新同步」，点按自动以最新基准重备冲突两侧。

解决多个 agent 在同一目录并行冲突。工作区 = 独立 worktree + 分支 + 端口段。注册项目后，工作区按项目分组展示，组顶部带研究流程概览（大圆步进器）与资源面板。项目组头部只聚合需要你处理的阻塞数量；进行中/待评审状态由大圆步进器与步骤流程线表达，避免同一状态重复计数。课题主题收进项目名悬浮提示；低频操作（步骤名行的「⋯」、任务行的「⌨ 终端」「产物」「⋯」）默认隐藏、指针悬停才出现（键盘 Tab 聚焦同样显示），每行只保留一个实心主动作。

### 2.1 项目注册与研究流程

把一个目录注册为项目后，可以在项目维度定义研究步骤与资源清单（存于项目目录的 `.ccode/project.toml`，跟着 git 走）。

- **添加项目**：页面顶部主操作「**+ 添加项目**」→ 系统对话框选目录 → 弹窗内命名 → 注册 → **注册成功后弹出研究流程模板选择层**：六套内置模板任选一套即把步骤追加进档案卡（步骤名重复跳过；工作区名冲突自动改名）。底部两个出口语义不同：「**不使用研究流程**」把这个选择显式记进档案卡（`pipeline_opt_out = true`）——项目保持空白、只作为目录与任务的分组管理，模板引导横幅随之隐藏（定时任务与资源面板保留：技能可选后定时巡检不只服务科研）；「**稍后再选**」只关闭不留痕，模板引导照常显示。两条路事后都能反悔：项目组「⋯」→「选择研究流程模板」（空步骤项目的菜单项）随时回到模板库，选一套后标记自动清除。注册项目即使没有工作区也显示在项目页（按最近打开排序）；未注册的目录仍按工作区 repo 自动归组，组头「注册项目」打开同一注册弹窗（已预选该目录）。项目组「⋯」可重命名或移除注册（只删注册记录，不动磁盘目录与工作区）；左侧项目导航行右键菜单提供重命名/复制路径/移除注册/**清除 Ccode 痕迹（保留文件夹）**/**删除项目目录**（红色项，后两个未注册组也可用）——三档命运：**移除注册** = 只摘登记，磁盘全留；**清除 Ccode 痕迹** = 回到没建项目时的样子：文件夹与你的全部文件保留，`.ccode/`（档案卡、任务卡、简报）移入系统回收站（可找回），工作区 worktree 与 `ccode/<名>` 分支、注册记录彻底删除（若 `.ccode` 曾被 git 跟踪，改动面板会显示对应删除，需自行提交——应用不会替你提交仓库）；**删除项目目录…** = 连文件夹一起删：确认框列出目录完整路径与工作区数量，确认后**主目录移入系统回收站**（误删可从废纸篓整个找回）、注册记录移除；但工作区的 worktree 与分支是 git 元数据，只能**彻底删除不可恢复**——这两个操作前请先关闭该项目内正在运行的终端标签；非 Ccode 项目目录与系统/关键目录会被后端拒绝
- **示例课题（演示）**：还没有任何项目时，空态「添加项目」旁有次级按钮「**✦ 创建示例课题（演示）**」——一键在「文档/Ccode 示例课题」生成带演示数据的完整项目：英文综述五步研究流程档案卡、一页示例文献 PDF（程序生成的演示文件，非真实论文）、两条真实示例引文 `references.bib`、README，并自动 git 初始化 + 注册。幂等：重复点不重复建；目录已存在但未注册时只注册、不动磁盘内容。可随意试验开步/编辑研究流程/建工作区，整个目录随时可删（右键项目导航行「删除项目目录…」可连目录带工作区彻底删除；只想从列表移除选「移除注册」）
- **课题主题**：「添加项目」与选择模板时都可选填课题主题（存 `project.toml` 顶层 `topic`），显示在项目组头名称旁；组「⋯」→「编辑课题主题」可随时改，一键开步时写进 `TASK.md` 的「课题主题」段供 Agent 围绕执行
- **全局设定**：贯穿全程的决定（综述角度 / 目标篇幅 / 读者 / 去向），应用模板时预填成建议项（只给问题、答案留空待你补）。**选模板时会先进入「全局设定」填写屏**：逐条给出问题与提示，能定就填、拿不准可「跳过，以后再填」（留空的保留提示行）；填写的答案存进项目配置，已填条目显示在**项目组头第一行**（课题主题旁，「问题：答案 · …」连排，悬浮看全部），点击打开**项目设置抽屉**（组「⋯ → 项目设置…」同一抽屉）随时改：一行一条「问题：答案」，失焦即存。每一步开工时都会写进 `TASK.md` 的「全局设定」段发给 Agent——这正是它挂项目层而不是某一步的原因
- **git 引导**：新注册的目录若还不是 git 仓库，组顶部出现一次性引导横幅，点「初始化 git」一键 init 并生成 `.gitignore`（默认忽略产物目录、`.DS_Store` 与 `*.pdf`——文献 PDF 等大文件登记为资源引用、不进 git；已有 `.gitignore` 不覆盖；已是仓库则提示无需初始化）
- **研究流程概览（大圆步进器）**：组顶部按序展示步骤并按工作区状态着色；点大圆聚焦步骤，下方流程线按「讨论/输入准备 → 人工事项 → AI 执行 → 收尾 → 评审」展示当前动作。窗口装不下全部步骤时才在步进器下方提示可左右滚动，宽屏不显示。agent 节点的「开始 / 恢复工作区 / 去终端看看」不受前置提醒阻挡；评审节点提供「去评审 / 去处理冲突」。人工事项直接显示在流程线中，按步骤设置的完成判定（出现即检测 / 必须人工确认 / 全部目标满足 / 清除占位后完成）展示状态；取消勾选会保留为未完成，需重新勾选确认。长引导先显示摘要，完整内容在「怎么做」展开；文献导入统一跳转「文献与数据」面板。步骤名行「⋯」只显示当前可用操作：编辑步骤；已有工作区时产物核验；活跃工作区时「◫ 定位目录」。配置校验问题以「! N」提示徽标展示，应用模板后有一次性引导带指向第 1 步。
- **流程线节点序号与「确定文献来源」**：主干节点按先后编号，人工事项用复选框表达状态，不占序号；可选事项不抢当前节点。收尾事项在评审前进入主干，是否完成按其完成判定处理。检索类步骤在 AI 节点前提供「确定文献来源」：让 agent 检索 / 我有 Zotero 库 / 我有一堆 PDF·题录；导入动作统一落到「文献与数据」面板。
- **「先定几件事」：确定 TASK.md 的两条路径**：模板预先想好的拍板点（如「实验规模怎么定」）列在这个节点，两条路同形——都是默认折叠的一行，点 ▸ 展开：**直接选择**：展开是选项卡片，点选即答（都不合适点「其他…」自己写一句），答案写进 TASK.md 的「已定方向」；**和 AI 商量（可选）**：展开是「跟 AI 商量一下」，AI 通读 TASK.md、把拿不准的点逐个问你、按回答直接改稿。两条路终点是同一个 TASK.md，都不做也能直接开工（不拦你）。**要先看到数据才定得了的问题不在这里**（如「纳入标准定多严」「精读力度怎么分」「综述骨架借哪篇范式、卖点是什么」——清单规模/全文到位率/候选范式卡片没出来前答了也是猜）：它们写在步骤简报里，开工后 AI 先粗检报数、再拿着数字问你（写进 `.ccode/help-wanted.md`，收件箱会亮），你不答就按它的建议继续，不停工。没有卡片的步骤（如文献检索与筛选、文献精读与笔记）没有直接选择，聊天入口是单按钮「跟 AI 商量一下」（可选 · 结论写入 TASK.md）
- **步骤角色标记**：聚焦卡头步骤名旁的小标「**AI 做 / 你来 / 一起**」标出这一步主要靠谁（模板预填，只影响展示、不参与流程判定）——步骤名保留学术术语，扫一眼标记就知道哪几步要自己出场
- **空研究流程**：新项目还没有步骤时显示「**选择研究流程模板**」，打开模板库（名称/描述/步骤数/步骤名预览）选一个写入 `.ccode/project.toml`，也可「编辑研究流程」打开同一编辑器从头自建；模板写入后仍可逐步编辑
- **模板库**：内置六套——「英文综述」（检索筛选 → 精读笔记 → 大纲 → 初稿 → 润色定稿）、「科研论文」（计算实验向：文献检索与筛选 → 精读与研究空白 → 实验设计 → 实验执行 → 结果分析 → 论文初稿 → 润色与投稿准备）、「数据处理」（登记检查 → 清洗整理 → 探索性分析 → 分析报告）、「毕业论文」（文献检索与筛选 → 精读笔记 → 开题报告与综述 → 研究方法 → 实验执行 → 结果分析与章节 → 论文初稿 → 格式与定稿）、「投稿与返修」（首投：期刊格式适配 → 投稿材料；返修：按轮次生成审稿意见回复、修订稿与再投稿清单）、「LaTeX 论文」（有成稿则转排版，也可从笔记从零写：搭建骨架 → 章节写作 → 编译与排错 → 定稿导出，详见 2.9 节）。每步还会记录结构化输入依赖并在 TASK.md 中列出；后续步骤缺少上游产物或项目资源时，编辑器会给出配置提示。**前五套模板是同一条科研流水线的相邻段，产物路径已对齐、可以一套接一套走**：综述末步产 `manuscript/review-final.md`、科研论文末步产 `manuscript/paper-final.md`、毕业论文末步产 `manuscript/thesis-final.md`，「投稿与返修」首投步的输入就是这三者加 `references.bib`；返修第 1 轮优先读已经按期刊改过的 `submission/formatted.md`。综述攒下的 `notes/` 与 `references.bib` 科研论文/毕业论文可直接复用（有则查漏补缺、不覆盖旧笔记），数据处理的分析报告可接科研论文的实验段。文献 PDF 和渲染成品写在项目根，不进 git。接上游有两种走法，每套模板首步简报里都写明了：同一项目续走（产物随仓库合并自带，用编辑器的「＋ 从模板追加」最顺），或另起项目时先把上游产物文件放进对应目录，抑或在资源面板绑定上游项目目录。模板内容按「讨论种子 → 草稿 → TASK.md → 执行」全链核对过：种子逐条对准真正要你拍板的点（纯执行的步骤不给种子）；技能挂载与 15 个内置技能一一对应（实证论文初稿/投稿准备使用 `research-writing`，综述写作使用 `review-writing`；检索步挂 `lit-search`、精读步挂 `lit-notes`、涉及统计的步挂 `stats-check`、要渲染的步挂 `quarto-render` 等）；涉及文献检索的步骤带「（可选）配置学术检索 MCP」人工事项——到 MCP 页「预设」一键导入 Consensus/Undermind 即可，不配也能跑（OpenAlex/Semantic Scholar 免 key 兜底）；付费墙文献全程有「下载付费墙文献全文」人工事项接应（落点 `papers/*.pdf`）。项目组「⋯」→「更换模板」打开同一模板库替换现有步骤（绑定的工作区与资源不受影响）；同一菜单的「另存为模板」把当前研究流程存为自定义模板（填名称+描述，同名覆盖会先确认），用户模板在选择器中带「删除」。科研论文/毕业论文模板的初稿与定稿步骤自带 `quarto render` 渲染脚本，开步时自动写入项目 `.ccode/settings.toml`——该工作区行的「运行脚本」菜单随即出现 `render-draft` / `render-final` 一键渲染 PDF，以及 `export-docx` 一键把同一份 Markdown 导出为 docx（与 PDF 渲染并存互不冲突；未安装 quarto/pandoc 时脚本报错会直接显示在终端，安装引导见 `quarto-render` 技能）
- **编辑研究流程**：项目组「⋯」→「**编辑研究流程**」是已有研究流程的唯一入口（空研究流程面板的同名按钮打开同一编辑器），打开全宽编辑器，每个步骤一张卡片：步骤名与工作区名、大段简报（一键开步时落成 `TASK.md`）、**本步骤输入**（上游产物/项目资源路径，逗号分隔，开工时原样写入 TASK.md）、预期产物（逗号分隔）、run 脚本（名称+命令，可增删）、**人工事项**（这步里归你做的事：标题 + 交付落点 + 时机（开始前/进行中/收尾）+ 引导说明 + 完成判定，可增删——如「下载付费墙文献全文」落点 `papers/*.pdf`），**资源绑定**（勾选项目资源：默认全不勾 = 本步骤使用全部资源；勾选后 `TASK.md` 的「项目资源」段只列选中项，让任务与你准备的资料一一对应；绑定了已移除资源的条目显示「失效」，取消勾选即清理）。完成判定可选「出现即检测 / 必须人工确认 / 全部目标满足 / 清除占位后完成」；目录/通配落点按 `*` 计数，旧目录写法仍兼容。卡片可 ↑↓ 排序、删除，底部「+ 添加步骤」；「保存」整体写回 `project.toml`，「取消」放弃，有未保存改动关闭会先确认。配置校验提示（输入缺少上游产物/资源、绑定不存在、简报引用与产物不符等）显示在编辑器顶部和概览行的「! N 条提示」徽标（点击逐条查看）。工具区「+ 添加步骤」旁还有「**＋ 从模板追加**」：列出内置六套与你另存的自定义模板，选一个就把它的步骤**追加到当前流程末尾**（与「更换模板」的整体替换不同）；同名步骤仍跳过，但仅工作区名冲突会自动追加 `-2`、`-3` 后缀并在结果中列出，不再静默丢步骤。追加直接写入 `project.toml` 并重读刷新（有未保存改动会先确认放弃）。选择「投稿与返修」时先选首投或返修，返修再填轮次；步骤、分支和流程启用标记一次写入，即使步骤名全部重复跳过也不会丢分支选择。典型用法：科研论文走完 → 追加「投稿与返修」首投或指定返修轮次 → 同一项目里接着走，提货单与资源机制对新步骤直接生效
- **任务卡**：研究流程步进器下方的「任务卡」区——卡片是**对话的归档夹**（讨论的记录容器；v3.72 起不再承担简报供应链——讨论结论直接写进 TASK.md）。卡片区恒为单步骤聚焦视图（聚焦头部「‹ ›」箭头或点大圆切步骤）；未挂步骤的卡收进「未挂步骤」桶（挂在已删除/改名步骤上的卡也并入），该桶为空时整桶不显示，桶头「**＋ 添加想法**」内联起名建卡（未挂步骤的卡无步骤语境，只建卡归档）——「**预览/编辑 TASK.md**」在流程线任务书节点（无任务书节点的步骤挂在 agent 节点）：没编辑过时看到的是模板默认拼装（简报 + 提货单 + 已定方向答案），可以直接改，保存后开工就以这份为准；无卡无工作区也可用。**流程线「任务书」节点上列着讨论种子**——模板预置的「开工前建议想清楚的问题」（如「综述角度怎么收？」「纳入标准定多严？」，只有你能拍板、拍错返工贵的决策点），点一个就开聊（自动以问题建卡归档），**讨论出的结论 Agent 直接写进这一步的 TASK.md 内容**（`.ccode/drafts/<步骤>.md`），开工时这份内容就原样落成工作区的 TASK.md；种子聊不聊随你，不聊直接开工没有任何阻拦。主聊天入口是「**跟 AI 商量一下**」（重复点击切回该步骤已有的讨论终端标签，不会每点一次新开一个；快速开聊同理，同 agent/配置/目录复用旧标签）：**开聊时若 TASK.md 还没编辑过，会先把当前模板拼装（简报/预期产物/提货单等）整份写入作为起点**，Agent 先通读、把拿不准的点逐个问你、按你的回答直接改这份文件——商量改的就是最终落盘的 TASK.md，不会丢模板里的内容；随时可点「预览/编辑 TASK.md」就地检查或再改。这一步的讨论卡以胶囊形式收在流程线「任务书」节点（种子后面，「＋ 自定义话题」可补种子没覆盖的话题），点胶囊 = 续聊：在项目根开终端（不建工作区，想法期不动手），与讨论种子同一口径——Agent 会把聊出的结论直接写进这一步的 TASK.md，**开聊时自动在右侧打开 TASK.md 预览，Agent 写入实时可见**；开工入口在流程线 agent 节点的「开始」（先打开**开始确认弹层**再建工作区）。没挂步骤的卡没有步骤语境，只有只读「**聊想法**」纯聊归档——「**想法期只读保护**」开关（默认开，存设置；聚焦某步骤时在流程线上方的「想法」区标题行）只服务只读纯聊这一路：开 = 聊想法以只读/计划模式启动 Agent（Claude Code / Codex / Gemini / Kimi / CodeBuddy / Cursor / Grok Build 支持，Qwen / OpenCode 只有指令里的口头约束）且预填指令明确「只讨论不动文件，聊到该动手的程度会提醒你回项目页点「开工」或「跟 AI 商量一下」——不会在聊想法会话里产出步骤产物」；卡片「⋯」里的「聊想法（允许改文件）」是不动开关的单次豁免。**从卡片发起的聊天（聊想法/开始/继续）产生的新会话会自动归入该卡片**，无需事后整理（个别落空场景——如启动栏临时换了 Agent——仍可在对话页 ⋯「移到卡片…」手动归卡）。**步骤归属**：从「跟 AI 商量一下」「聊想法」等按步骤上下文发起的**新会话也会自动归入该步骤**——即使它跑在项目根没建工作区，对话页按步骤过滤（或点「本步骤的对话」）也能看到它（个别落空场景如启动栏临时换了 Agent，重新发起一次即归位，或对话页手动处理）。主仓有未提交改动时卡片区标题行右侧显示警告色小字「主仓 N 个未提交改动」（点击直达终端页改动面板看主仓）——「聊想法」在主仓进行、期间 Agent 的改动留在主仓是合法的，只提醒不阻断。讨论时 Agent 会把没定下来的问题记到 TASK.md 的「## 待拍板」小节；这一步里归你做的事不在卡片上——在流程线里（步骤级，一个步骤只出现一次）。「未挂步骤」卡的 ⋯ 里有重命名/删除（删除只移出归置、不删对话文件）
- **想法区与「◈ 融合进任务书」**：聚焦某步骤时，流程线上方多一个独立的「**想法区**」区块——放的是这一步的**自由想法卡**（kind=idea，挂当前步骤）：「＋ 话题」内联起名建卡（还没有话题时，只有「你来」角色步骤常显该入口并带「先聊不改稿，点 ◈ 沉淀才进任务书：」引导——与「跟 AI 商量一下」的「边聊边改 TASK.md」对仗；检索这类纯执行步骤没聊过话题时不显示，聊过之后照常出现），卡行主按钮是只读纯聊「**聊想法**」（受想法期只读保护开关管，会话仍自动归卡），⋯ 里有重命名/删除与「聊想法（允许改文件）」单次豁免。和流程线「任务书」节点上的讨论卡（kind=draft）分工不同：讨论卡的结论随聊随写进 TASK.md，想法卡是**先自由发散、后择优收编**——聊出结果后点「**◈ 融合进任务书**」，AI（沿用设置页「提炼接力/评审沉淀」那份 profile）从**这张卡名下的对话**提炼出结论片段：先弹窗给你预览/可改，点「追加到 TASK.md」才**追加**到 TASK.md 末尾（小节标题「想法：<话题名>」）——已有内容一概不动，不是覆盖重写。步骤开工（有活跃工作区）后融合按钮隐藏，想法卡照常可续聊。旧卡没有 kind 字段也能用：后端按是否挂步骤自动推断（挂步骤 = 讨论卡，未挂 = 想法卡）
- **步骤「开始」（一键开步）**：点流程线 agent 节点的「开始」（归档工作区显示「恢复工作区」）后，经开始确认弹层生成工作区、写入 TASK.md 并跳到终端。弹层可预览/编辑 TASK.md、调整推荐技能、查看人工事项与主仓改动提醒；开始前必办只提醒不阻断，紧邻上一步未完成的必办收尾事项会要求二次确认。步骤名行「⋯」不再承担人工事项、复制工作区名或删除步骤；这些操作分别在聚焦流程线、编辑研究流程中完成，菜单只保留编辑步骤、产物核验和活跃工作区的「◫ 定位目录」。
- **资源面板**：组内「文献与数据（N）」折叠区登记 PDF / CSV / parquet / bib 等资料（**只登记路径不复制文件**）；「**发现资源**」自动扫描项目目录列出候选，勾选后一键登记（已登记的标记 ✓）。旁边的「**导入检索结果**」是文献人肉中转入口——分工是：agent 负责系统检索（OpenAlex / Semantic Scholar 等可程序化库）与 DOI 去重合并，你在 Undermind / Google Scholar / Elicit 网页端做语义发现补漏（哪篇重要你判断更快）；导出 RIS / BibTeX / CSV（可多选）一键复制进主仓 `papers/imports/`——建议文件名带「来源-日期」（如 `consensus-2026-08-13.ris`），开工时 agent 自动解析、去重并合并进筛选清单（lit-search 技能协议），两边结果在 `papers/screening.md` 汇合。PDF 资源行有「**查看**」，跳到终端页内嵌预览（可选中文字「◈ 问 AI」，即使文件不在任何文件树根内也能打开）。资源行「⋯」可复制绝对路径（粘贴给 agent 作输入）、移除登记；repo 内登记数据资源后会一次性提示建议加入 `.gitignore`
- **历史**：组「⋯」→「**历史**」打开项目的白话保存时间线（全宽只读视图）。主文件夹提交会立即进入项目主线；工作区改动先保存到任务分支，合并后才以「✓ 验收合并」进入项目时间线。按天分组（今天/昨天/日期），每条一行：✓ 验收合并、⚙ 自动保存、◔ 保存；提交 hash 以小字 mono 保留在右侧供技术核对。工作区过程提交不单独混入主线，仍保留在对应任务分支中

### 2.2 创建工作区

「新建工作区」在各项目分组的工作区列表头部（页头不再放全局入口）→ 仓库固定为当前分组（未注册分组同样可建），弹窗只填任务名 → 自动：原子预留端口段并写入「创建中」记录 → 拉 `ccode/<任务名>` 分支（基于**本地**主分支，含未推送的提交，工作区 = 你本地项目的现状）→ 建 worktree 到 `~/ccode/workspaces/<仓库>/<任务名>/` → 复制 `.env` 类文件 → 跑 setup 脚本 → 激活工作区。worktree、复制文件或数据库激活任一步失败，应用会补偿删除 worktree/分支/创建中记录并释放端口；复制失败会明确指出具体文件，不会再静默忽略。setup 失败仍保留已创建工作区并标记失败，方便进入终端修复。

成功后「打开终端」自动开标签（目录、端口环境变量已预置）。

### 2.3 项目自动化（.ccode/settings.toml）

```toml
files_to_copy = [".env", ".env.local"]
run_mode = "concurrent"            # nonconcurrent 时脚本互斥
[scripts]
setup = "npm install"               # 创建时执行
archive = "docker compose down"     # 归档前执行（失败阻止归档）
[scripts.run]
web = { command = "npm run dev", default = true }
test = { command = "npm run test" }
```

配了之后行内出现 **▶**（默认脚本）/ **▾**（全部脚本），点击开 shell 标签自动执行。`nonconcurrent` 模式下已有脚本运行时，▾ 菜单里其余脚本显示为禁用项并注明原因，不会静默消失。

### 2.4 行内信息与操作

列表是任务索引：每行主显示只有**任务名、状态**（可点开看分支、改动和阻塞原因）和唯一的实心主动作「**评审**」；「⌨ 终端」「**产物**」与「⋯」默认隐藏、指针悬停该行才出现（键盘 Tab 聚焦同样显示）。「产物」在该行**下方就地展开**产物核验清单（再点收起，展开时按钮保持可见；已合并行同样保留此入口）——活跃任务列绑定工作区工作树下的预期产物文件，已合并任务列主文件夹下的同名产物，目录条目列一层文件，未产出显示「尚未产出」，点击 md/txt/ris/bib 等文本产物就地打开预览层（阅读/编辑两用，Esc 关闭，右上角有「在终端页打开」逃生口），pdf/docx 点击仍跳终端页预览；清单只在展开时读取一次，可点「⟳ 刷新」手动更新，不自动轮询。任务名下方的副行以 10px 灰字显示分支名与**相对时间**（如「5 分钟前」，悬浮看绝对时间与完整目录）；领先/落后（↑N ↓M）收在状态详情里，悬浮给出白话解释（「比主分支多出 N 个保存点；主分支新增 M 个保存点」）；上游步骤晚于本步最后推进时间合并过时，状态详情同样有一行警告色「上游「X」有更新，产物可能过期」（与步进器悬浮卡同口径，只提醒不阻断）。活跃的 merge 冲突是唯一例外：实心主动作直接变为警告色「**解决冲突**」，但仍进入与普通评审相同的终端全宽审阅。已经合并且没有新提交的任务只显示左侧「已合并」状态，右侧不再重复显示「评审」；产生新提交后评审入口自动恢复。会话、运行脚本、复制路径、修复、恢复和删除等低频项位于「⋯」。

PR 与归档也从「⋯」定位到评审页内再确认，避免列表页和评审页各有一套完成流程。**归档不会丢未提交内容**：存在未提交改动时评审页会要求「提交并归档」；正在解冲突或仍有 agent/run 脚本运行时会拒绝归档。普通归档不强制移除工作树；只有明确的「删除」会使用强制删除语义。

如果用户在外部终端移动/删除仓库、worktree 或分支，或者留下未完成 merge，工作区行会显示**状态漂移**并暂停普通危险操作。按实际情况可选择「重新挂载」（重建/修复 worktree 关联）、「重新定位仓库」、「标记归档」或「清理记录」；后两项只改 Ccode 元数据，不删除磁盘目录或分支。已有 merge 现场继续进入统一的全屏冲突审阅。状态诊断本身失败时，状态 pill 上会多一个警告色「⚠」，点开状态详情里的「**诊断失败 · 重新检查**」重试，期间按健康状态降级展示、不整体隐藏操作。

### 2.5 评审与合并

- **评审（无冲突）**：行上点「评审」进入终端页的全宽任务审阅；终端标签和进程仍在后台保持运行。中间按文件连续展示左右对照 diff，右侧改动树可快速定位文件；顶部第二工具行可填写或用 ◈ 生成提交信息——**这栏是可选的：留空也能直接点「提交并合并」，系统自动写一句「更新 N 个文件」**（本地规则生成，不调 AI；想让 AI 看改动内容写就点 ◈）。写作类项目在分支信息行下方还有一条「**可信度**」行：**引用 N/M 可解析**（扫描工作树所有 .md 的 `[@key]` 引用键、对照 `references.bib`——根目录或 `manuscript/` 下；全部可解析为正常色，有缺失变警告色、点击展开缺失键清单）与**产物 X/Y 已产出**摘要（复用产物核验的同一数据机制）；没有 references.bib、全文无引用或未登记预期产物时该行自动不显示，不给非写作类项目添噪声。步骤声明了收尾类人工事项且尚未完成时，同行还有警告色「**收尾事项 N 件待做**」（悬浮可见具体事项）——只提醒不阻断合并。进入评审时读取一次，不轮询。上游步骤晚于本步最后推进时间合并过时，顶部另有一行警告色提醒「上游「X」有更新，产物可能过期」（与步进器悬浮卡同口径；本步合并后消失）。默认主按钮「**提交并合并**」一次完成提交和本地合并，工作区继续保留；下拉仍可选「**仅提交**」或「**合并并归档**」。**合并成功（保留工作区）后，成功横幅会直接给出「→ 去下一步：步骤名」**——如果当前任务属于某个项目研究流程且后面还有未开步的步骤，点它跳到项目页并自动聚焦刚解锁的下一步（流程线、TASK.md、人工事项都在那里，准备好了自己点「开始」；v3.97 起不再直接开步跳终端——那会把不熟流程的用户直接扔进黑窗）；旁边的次级入口「**沉淀到下一步**」把评审结论追加进下一步步骤的 **TASK.md 内容**（`.ccode/drafts/<步骤>.md`，不存在则新建；下一步开工弹层会直接读到它）；编辑区上方有「**◈ AI 起草**」——按本步提交清单、diff 统计与 TASK.md 生成初稿填入编辑框（复用设置页「提炼接力」的 AI 配置，失败行内报错可重试），AI 初稿改完后才会落盘（与提炼接力的初稿编辑同一口径）；没有下一步或项目未注册研究流程时只显示合并成功。如果改动已提交，主按钮直接变为「合并」。提交后会重新做健康检查，不会因为进入快捷流程而绕过冲突、主仓脏或主仓分支错误等拦截。被「主文件夹里还有没保存的改动」拦截时不用离开评审：展开问题列表，点该行旁的「**提交主文件夹的改动…**」在评审内直接列出主仓文件并勾选提交（默认不勾选、提交信息留空走本地默认信息、不调 AI），提交成功自动重新健康检查。
- **白话术语对照**：**提交** = 把改动保存到项目历史（文件本身不会丢）；**合并** = 把任务成果放回主文件夹（主仓库）；**保存点** = 一次提交产生的历史记录，「多出 N 个保存点」即 git 术语的领先 N；**冲突** = 两边改了同一个地方，需要你逐个文件选一边。技术信息保留在二级位置（悬浮提示/小字 mono），编程用户不受影响。
- **PR 与归档**：从工作区「⋯」选择「在评审中创建 PR / 归档」会直接打开同一评审覆盖层中的对应确认框。创建 PR 仍需在框内填写/确认标题；归档仍会重新检查脏改动、merge 与运行中任务，绝不因入口收口而绕过安全检查。
- **审阅布局**：顶部固定显示任务、分支方向、文件数和总增删量，右上角固定主动作；有未提交改动时，提交信息与 ◈ 生成入口位于第二工具行。主区连续显示双栏 diff，文件标题吸顶，较长的未修改代码默认折叠；右侧仅保留文件搜索、目录树和当前进度，选中项会随主区滚动同步。这样搜索、定位、阅读和完成动作始终在稳定位置，不需要在右栏底部寻找按钮。图片文件（png/jpg/gif/webp/svg/bmp）不再只提示「二进制」，而是直接双栏看图：左基准版、右当前版（透明图带棋盘格底；新增/删除时对应一侧标注为空），单图超过 20 MB 才回落提示。
- **评审（有冲突）**：行上点「**解决冲突**」直接进入与普通评审相同的终端全宽覆盖层，终端标签和进程仍在后台运行。工作区干净时应用会自动在隔离工作区同步**当前最新**基准分支，不再先展示容易被误认为当前 main 的普通累计 diff；有未提交改动时先在顶部填写信息并「先提交改动」，提交后自动继续。准备完成后，中间区按文件连续展示完整双栏对照——左侧任务分支、右侧 main/基准分支，右侧冲突清单可快速定位。每个文件标题下方用紧凑的「选用」控件选择任务版或基准版，并显示已选结果；顶部也支持「全部任务版 / 全部 main 版」，「**◈ AI 建议 → 按建议选择**」为主按钮级（cta 高亮）并附一行小字说明「不确定选哪边时可让 AI 按上下文建议；仍可逐文件手动改选」。如果处理期间 main 又被其他工作区推进，旧对照会立即停止展示和选边，右上角提示「重新同步最新 main」；确认后应用放弃旧冲突现场并重新生成两侧。全部选完默认点「**完成解决并合并**」，应用会提交解决结果、重新检查健康度并合回本地主分支，工作区继续保留且不会推送；下拉可选「**仅保存解决结果**」稍后再合并。选边按整个文件生效；需要逐行混合两侧时，转到预览编辑器手动修改。若解决提交成功但最终合并被主仓脏、分支错误等条件拦截，会明确显示“解决结果已提交，但合并未完成”，处理拦截原因后点普通「合并」即可，不要重复解决冲突
- **改动面板任务视图**：worktree 里自动切换为 vs `merge-base(主分支, 任务分支)` 的累计 diff，头部显示「相对主分支 xxx」（悬浮保留 merge-base 说明），「审阅」可随时展开上述全宽视图；提交区按钮为「**提交 / 提交并推送**」（提交信息留空时「快速提交（⌘Enter）」），悬浮标注对应的 git commit / push
- **合并**：「合并」按钮高亮（=可合并）时可用，是拆分按钮——主按钮「**合并**」只合回主分支、**工作区保留**（终端继续用，之后可随时归档）；「**▾**」下拉可选「**合并并归档**」（合并后移除 worktree、自动归档；还留在工作树里的终端标签会自动 cd 回主仓库）。保留的工作区合并完成后，按钮变为禁用的「**已合并**」；继续产生新提交后自动恢复为「合并」。均只合到本地、不自动推送远程（主仓库 git 面板头部 ↑N 即领先远程的提交数）。前置：分支已提交、与基准无冲突、主仓库在主分支且干净，缺一按钮即灰，悬停看原因；合并被拒时报错会列出主仓库的脏文件。若最终 merge 仍失败，应用会自动 `git merge --abort`，主仓库不会停在冲突状态。若代码已合并但归档脚本失败，会明确显示「已合并、归档失败」，此时只需点「归档」重试
- **创建 PR**：弹窗填标题，正文留空自动摘要、或点「**◈ AI 起草**」生成结构化描述（变更点/动机/测试情况，可编辑）→ 推送分支 + `gh` 建 PR（需已登录 gh）。如果分支已推送但 `gh pr create` 失败，弹窗会显示「重试创建 PR」，不会重复推送

### 2.6 定时任务（◔）：每日/每周自动巡检

每个已注册项目的分组里（资源面板下方）有「**◔ 定时任务**」区块：点「**＋ 定时巡检**」建一条定时任务——技能（默认 `lit-watch` 文献监控，下拉可选技能库里的其他技能，按各自技能的既定规范执行）、名称（默认跟随技能：lit-watch 为「文献雷达」，其他为技能名；手改过的名称切换技能时不覆盖）、周期（每天 / 每周几）、时间、profile（默认「自动」，跟随设置页 AI 专用配置或最近使用；**建成后在任务行的配置下拉里随时可改**，绑定配置被删除时会显示「原配置已删除（自动回落中）」并自动按回落链继续跑）。到点后应用在后台无头拉起对应 Agent 到项目目录执行一次巡检（lit-watch 写 `notes/inbox.md`、`papers/watch-seen.md` 等，与手动「执行 lit-watch」完全同路径；其他技能的 prompt 为通用模板——按技能自身规范产出），单次最长 10 分钟。列表行显示「名称 · 周期 · 技能」，可启停、「▶ 立即跑」、「▸ 历史」看最近运行（状态 + 简报，**点击简报行展开全文**）、「⋯」删除；跑完弹系统通知（复用设置页「长任务 OS 通知」开关），通知正文即简报首行。**应用没开就不会跑**：下次打开时自动补跑一次当天/本周漏掉的（多次漏跑只补一次）。改检索关键词/来源永远改 `papers/watchlist.md`，任务只管「什么时候跑」。跑出的新命中在哪看、怎么攒着读，见 2.7 文献雷达。

### 2.7 文献雷达（◔）：新文献追踪与精读清单

定时巡检跑出的新文献在哪看、怎么攒着读，都收在项目详情工作段的「**◔ 文献雷达**」卡片里（任务卡区下方）。

- **是什么**：定时任务（见 2.6）到点自动让 Agent 按你的订阅关键词巡检新文献，精选后写进 `notes/inbox.md`；雷达卡片把这份结果变成可直接扫读的清单，不用自己想起来去翻文件。最近一次巡检有新命中时（24 小时内），顶部「待处理」里会出现文献条目——「文献雷达 · 项目名：N 条新命中」，点击直达该项目的雷达卡片；卡头同时显示「上次巡检 × 前」。项目已经从 Ccode 移除或删除后，这条提示不会再出现（定时任务随项目清掉）。
- **怎么订阅**：卡头「**订阅**」打开弹层，一行一条订阅：**关键词 + 来源（可多选 arXiv / OpenAlex / Crossref / web）+ 备注**（备注可写时间窗口；写 `+bib` 时推荐条目会同步生成 BibTeX 进 references.bib）；「**＋ 加一行**」新增订阅，「**编辑源文件**」可直接改 `papers/watchlist.md` 原文（注释行会保留）。保存即生效，下一次巡检就按新清单跑。还没有订阅时只留一行「文献雷达 · 还没订阅读」和「添加」，点添加打开订阅弹层。卡头另有「**◔ 定时**」直达项目设置抽屉的定时巡检区块（建/改任务）；已有任务时卡头还显示「**⟳ 立即跑**」
- **怎么看新命中**：默认「**新命中**」页签——顶部是近 8 周每周新命中数的迷你趋势，下方可按「**按日期**」（今天 / 昨天 / 更早）或「**按关键词**」（每条归入它命中的第一个订阅关键词，无关键词的归「未分类」）两种视图分组，组内按 推荐 > 相关 > 待确认 排序。条目带**期刊徽章**：`IF 29.1`（JCR 影响因子）、`1区`（中科院大类分区）、`TOP`（中科院 Top 期刊）——数据来自本机期刊指标表（JCR2025 + 中科院分区表升级版 2025，按期刊名匹配，匹配不上就不显示，绝不虚构）；还没装表时卡头按钮是「**↓ 期刊指标表**」一键下载（约 7MB，下载后徽章自动出现，旧条目同样生效）；装好后它变为「**↻ 期刊指标表**」常驻，悬浮可看到表是什么时候下载的；打开雷达卡片时应用会顺带查一次上游 ShowJCR 仓库，若上游已更新按钮变成「**↻ 期刊指标表（有新表）**」，点它重新下载即更新（只提示不自动下载，查询失败就静默保持原样）。卡头「**筛选**」可按期刊指标过滤新命中：IF 下限（如只看 IF≥10）、中科院大类分区（仅 1 区 / 2 区及以上 / 3 区及以上）、仅 TOP 期刊，三条可组合；生效后「新命中」列表只显示符合的条目（被隐藏的几条可点「查看全部」临时展开），定时巡检跑完的推送提醒与收件箱计数也只算符合筛选的——查不到指标的条目（表未装、期刊未收录）一律照常显示不误伤，所以筛选要等装好指标表才真正生效（弹层里会提醒）；精读清单是你自己选的，不受筛选影响。**数据来源与版权说明**：指标表由第三方开源仓库 [ShowJCR](https://github.com/hitfyd/ShowJCR) 整理自 JCR / 中科院分区表，数据版权归原数据方（Clarivate / 中科院文献情报中心）所有，仅供个人科研参考——Ccode 不内置、不转发该数据，下载动作完全由你发起、只存本机；若你所在单位订阅了分区表或 JCR，也可以把自己导出的同名 CSV 放进指标表目录（`~/Library/Application Support/ccode/journal-metrics/`）使用，来源更干净。每条三行：标题（配相关性标记，「推荐」最醒目，整行放开不挤）+ 出处行（期刊名与 IF/分区/TOP 徽章）+ 一句中文摘要（每条都有，扫读用）。想深看单篇，悬停该行点「**◈ 解读**」：AI 用三行说清「做了什么 / 为什么重要 / 和本课题的关系」（围绕项目课题主题；结果会缓存，失败可重试）——默认只给中文一句话，不为每篇都调 AI。开放获取的文献显示「**↓ 全文**」（悬停提示免费直接下载），点击把 PDF 直接下载进 `papers/` 并自动登记进项目资源清单；没有免费直链的（DOI、出版商落地页）不摆下载钮，直接显示「**↗ 来源**」一键打开来源页面——手动下好后用「⋯」里的「**关联本地 PDF…**」选中文件，自动复制进 `papers/` 并按标题登记，一步到位。「⋯」里还有打开来源 / 忽略 / 复制标题
- **精读清单（先攒后读）**：遇到想细读的，点条目常驻主按钮「**→ 精读**」攒进清单（重复标题自动去重）。切到「**精读清单**」页签：每行 = 状态点 + 标题 + 作者年份——绿点 = 已读（`notes/` 里已有这篇的笔记，不用手动标记），灰点 = 未读。主按钮「**开读**」直接进入**沉浸阅读区**读已下载的 PDF（笔记 · PDF · 对话三栏，见 3.7）；还没下载的行主按钮按可得性分流——免费直链是「↓ 全文」，没有直链的是「↗ 来源」打开来源页，先拿全文再开读；「⋯」里有「获取全文 / 关联本地 PDF…（手动下载的付费墙文献选这个，选中即复制进 `papers/` 并登记）/ 移出清单」
- **付费墙文献怎么办**：下不到全文的条目由巡检自动记入跟进队列，卡片底部折叠区显示「**待人工下载（N）**」——展开看清单，自己从图书馆 / 出版商渠道下载后把 PDF 放进 `papers/` 即可（与模板里「下载付费墙文献全文」人工事项同一落点）。**用 Zotero 管文献的话**：检索步产出 `papers/to-fetch.md` 时会同步产出 `papers/to-fetch.ris`——在产物核验清单里按住该行的「⠿」手柄直接拖进 Zotero（或从访达拖入），Zotero 会自动建成一个待获取列表；往里拖 PDF 后回「文献与数据」面板重新「从 Zotero 导入」即登记（只读引用不复制），再回人工事项手动勾一下。**文件名不用操心**：人工补投的 PDF 命名随意，下一步精读开工时 agent 会对照清单统一改成「作者年份-短标题.pdf」并勾掉已补行
- **关联步骤**：建定时任务时可（可选）挂一个「**关联步骤**」，任务行回显「→ 步骤名」。挂了之后，若雷达又有了新命中、且时间晚于该步骤工作区的最后一次推进，雷达卡片会出现警告色小字「雷达有新命中，「X」步的产物可能过期」——和「上游有更新」同一口径，只提醒不阻断：要不要回那一步补收新文献由你判断

### 2.8 端口监控

页面尾部「**端口**」折叠区（默认收起，展开才读取，配合「刷新」手动更新，不自动轮询）列出本机全部监听中的 TCP 端口：端口号、进程名、归属和工作目录。归属按进程工作目录判定：落在某工作区工作树内显示「**工作区 · 任务名**」（绿点），落在注册项目内显示「**项目 · 项目名**」（绿点）；cwd 不在任何已知目录但端口号落在某活跃工作区的分配段（如 4000–4009）内时显示「**端口段 … · 任务名**」（琥珀点）；其余显示「系统/其他」。列表按归属分两段展示——「**本应用**」（工作区/项目/端口段归属）与「**系统/其他**」。典型用途：工作区里跑了 jupyter / quarto preview / 本地服务后，查谁占了哪个端口。「**终止**」向进程发送退出信号（SIGTERM，进程不退出时可稍候刷新再试）：「本应用」段点击即直接终止、不弹确认，「系统/其他」段终止前需二次确认；终止前都会重新确认该进程仍在监听，防止进程号被复用后误杀无关进程。

### 2.9 LaTeX 论文与公式显示

用 LaTeX 写论文的一整套：第六套研究流程模板 + 编译脚本 + 界面里的公式显示。

- **模板从哪选**：注册项目后的模板选择层、空流程面板的「选择研究流程模板」、编辑器「＋ 从模板追加」三处都有「**LaTeX 论文**」。四步各干什么：**搭建骨架**——开工前先定文档类（elsarticle / IEEEtran / achemso / ctexart / 学位论文通用架）和参考文献宏包（natbib / biblatex）；项目里已有 `paper-final.md` / `review-final.md` / `thesis-final.md` / `draft.md` 时按成稿转成 TeX，不改观点和数据，没有成稿才从笔记从零搭；如果目标期刊有官方模板 zip，按可选人工事项解压到 `manuscript/template/`，agent 会先读模板说明再搭骨架。**章节写作**——引用写 `\cite{bib键}`、键必须存在于 `references.bib`；从成稿转写时只补结构和引用；**编译与排错**——报错先读 `manuscript/main.log` 对症改，不绕路（不删报错命令、不换文档类）；**定稿导出**——引用闭环核对 + 终编译，源稿仍在 `manuscript/`，定稿 PDF 统一写入 `output/main.pdf`
- **编译环境**：每一步都带 `render-pdf` 运行脚本（工作区行「运行脚本」菜单里点）——优先 tectonic（轻量，编译时自动下载宏包），没有则试 latexmk，两个都没有会打印安装提示并以失败退出。**应用不替你装 LaTeX**：没环境时装环境是「编译与排错」步的可选人工事项（`brew install tectonic`，或装 MacTeX/TeXLive 获得 latexmk），agent 检测不到编译器时也会把安装提示写进人工请求转给你
- **公式直接显示**：笔记、TASK.md 预览、产物核验的文本预览里，`$...$` 行内公式和 `$$...$$` 块级公式直接排版显示（KaTeX，用到时才加载，不占启动速度）；`$5` 这类金额和代码块里的 `$` 不会误判成公式，公式语法写错了就显示原始源码、不会把页面弄坏
- **截图转公式**：阅读区（或 PDF 预览）里「▦ 圈选」把书上的公式框下来、「◈ 发给 agent」，再补一句「写成 LaTeX」即可
- **数据转三线表**：对话里直接说「把这组数据做成三线表 LaTeX」就行——没有专门按钮，一句话的事

## 三、终端页（⌨）：并行工作主界面

### 当前使用方式：聊天 / 终端

终端顶部的 Ghostty 式标签胶囊内保留当前终端标签和「＋」；旁边的聊天/终端图标只切换显示方式，不切换会话：

- **终端**：默认模式（2026-09-02 起）。显示原来的 xterm 画面，登录、权限确认、模型选择器等交互直接可见可操作。
- **聊天**：消息列表显示当前会话最近 50 条消息，底部输入框支持 Enter 发送、Shift+Enter 换行；技能/MCP 菜单点击只插入一条可编辑提示，不会跳过用户确认直接发送；按 Enter 后才写入同一终端。Agent 已结束时会自动恢复原会话，空标签发送第一条消息会自动启动。
- 切换不会销毁 PTY、xterm 或滚动缓冲；进入聊天会自动退出分屏，切回终端不自动恢复分屏。
- 右侧工作台只保留「文件 / 改动」。对话不再同时出现在右侧，避免重复。

### 从当前会话新建聊天

当前会话已关联文件和 session ID 后，聊天头部会启用「＋ 新建聊天」。它生成一份脱敏结构化分叉简报（任务信息、最近消息、最后回复、Git 状态），新标签继承 Agent、连接、模型和目录，但使用独立 PTY/session，默认标记为「只读分叉」。这不是完整历史复制，而是摘要接力。

点击「允许修改」前会明确提示原会话仍运行时可能覆盖同一目录；确认后当前只读 PTY 会停止，并以同一摘要重启可写会话。没有原生只读参数的 Agent 会标注「提示约束」，不能把它当作强制沙箱。

会话同步优先使用文件事件监听，通常在文件写入后很快刷新；若监听不可用，界面会显示兜底同步并继续用签名轮询。同步按消息刷新，不承诺逐 token 流式显示。

> 下面的旧版“三段布局”说明保留作历史背景；当前实现以上一节「聊天 / 终端」规则为准，右侧不再承载实时对话。

### 3.1 启动与标签

> 当前接力注入口径：Kimi 仍没有交互式首条指令参数，需要启动后粘贴；OpenCode 1.18.x 已核实支持 `--prompt`，Ccode 会自动注入首条指令。下文较早版本记录中的「Kimi / OpenCode 均需手动」仅是历史说明，不代表当前行为。

启动栏第一行固定按 agent → profile → 模型 → 运行排列（**v3.91 起目录输入框移出启动栏**——改目录用中带底部状态栏的「**📂 目录**」胶囊：点击弹出浮层输入新路径，仅未启动时可改；运行中或 shell 里目录跟随终端真实 cwd 每 4 秒回写，shell 里 `cd` 即可）；技能数（◈ N 技能）、MCP 数（⌗ M MCP）胶囊作为运行时快捷入口常驻在第一行右侧，工作区端口状态与 shell 状态在第二行。**未启动时终端画布中央有一张引导卡**：终端图标 + 当前 agent 与配置胶囊，点「**运行**」（或按 `⌘↵`）直接开跑，「**>_ 打开普通 Shell 终端**」一键切成纯终端；卡片在场时启动栏右上角的「运行」自动降级为线框按钮，同一视野只留一个高亮主按钮。输入框统一 inset 浮起底；「运行」是启动栏唯一的实心主按钮，「停止」等其余按钮为深色描边次要样式。运行后启动栏**自动收缩为状态行**（点「修改」展开），技能/MCP 仍常驻，首条指令等低频启动项收进「⋯」的「高级启动选项」；实时聊天在主工作区显示，右侧工作台只保留文件/改动，停止、恢复、打开 Shell、查找等按状态出现在「⋯」菜单。选择会记忆，每个工作区也会记住上次用的配置。

- **◈ 技能 / ⌗ MCP pill**：两个入口在展开启动栏（第一行右端）与收缩状态行都可用。「◈ N 技能」展开该 agent 已启用的技能清单，点击一键使用（运行中注入终端输入框不自动发送，未启动写进首条指令）；「⌗ M MCP」展开该 agent 已分发的 MCP server 清单，点击一键提及（注入「使用 X 提供的工具：」提示词，agent 会调用其工具），清单底部「管理 MCP 分发 →」直达 MCP 页——分发变更对新会话生效。

- **高级启动选项**：从启动栏「⋯」打开后，仅显示「启动后自动发送」首条指令。首条指令可编辑，留空 = 不注入，注入成功即清除；技能/MCP 继续从常驻入口使用。

- **首条指令（启动后自动发送）**：开步/接力/技能注入的首条指令显示在启动栏「启动后自动发送」一行，可编辑，留空 = 不注入，注入成功即清除。**Kimi 没有交互式启动注入参数**：启动后指令不会自动发出——此时指令**自动复制到剪贴板**并提示，启动栏保留指令文本（运行中输入框不可编辑，旁边有「⧉」一键复制兜底），到终端里粘贴回车即可。OpenCode 使用 `--prompt` 自动注入首条指令。

- **空白标签落在家目录**：第一次点进运行、关掉最后一个标签、或点「＋」开的空标签，目录是**家目录**（不预填当前项目主仓，也不沿用上次开步留下的 `search` 等工作树）。点进某个项目后，文件树和启动目录才切到该项目。上次没关就退出的任务标签仍会按原目录恢复。
- **多标签**：「＋」开标签，各自独立进程；标签固定宽度、超出可横向滚动；活跃标签为绿色下划线；关闭 × 与注意力点悬停、激活或键盘聚焦时才显现——注意力点只在 工作中 / 待确认 时出现（无状态的空闲标签不显示；「已回复」不打点——回合结束每次回复都发生，不是待办）
- **分屏对比**：标签栏右侧「◧ 分屏」把中间终端区分为左右两个 pane（至少两个标签时可用）——左侧固定当前活跃标签，右侧 pane 头部下拉选择任意其他标签做对照（如 analysis-a/b 并行盯梢）。两个 pane 都有 32px 小头：左侧显示「当前」标签名，右侧是「对照」下拉，各带一个 × 关闭该 pane（关左 = 退出分屏并切到对照标签，关右 = 退出分屏保留当前标签）。两侧终端同时保持挂载、互不影响（xterm 不重建、进程不断）；中间分隔条平时极细透明、悬停才显色，可拖动调比例（本机记忆，双击恢复对半）。点击某个 pane 即把它设为活跃 pane，右侧工作台（对话/文件/改动）与左侧文件树跟随活跃 pane；标签条上对照标签带 ◧ 小标，点它会交换到左侧。再点「◧ 分屏」或任一 pane 小头 × 退出分屏；分屏状态不随重启恢复
- **关闭守卫**：关闭 Agent 还在运行的标签时会弹出 Ccode 应用内确认框「该标签的 Agent 还在运行，确认关闭并终止？」；shell/已退出的标签直接关闭不打扰。关闭整个窗口时同理——还有在跑 Agent 的标签会先统一确认一次，取消则保持运行，确认后终止 Agent 并退出应用
- **重启恢复**：应用关闭前会在本机保存可恢复标签的名称、目录、agent/profile、模型和关联 sessionId；不会保存 PTY id、滚动输出、密钥、环境变量或 run 脚本命令。重开后标签以「**上次任务，可恢复**」占位出现，不会自动启动进程；点击「恢复任务」才创建新 PTY。上次目录或 profile 已不存在时会保留可编辑启动栏并明确提示，不会偷偷换目录或配置。目录失效时可在空态卡选择新目录、回到主目录或重新检查；选定新目录后仍需再次点击「恢复任务」，原会话和配置元数据不会丢失。
- **停止/回落**：agent 退出自动回落登录 shell（「shell 模式」，提示「会话已保存，可一键恢复」）；shell 里 `exit` 彻底结束
- **运行 / 打开 Shell**：运行页主按钮使用「运行」启动 Agent；「打开 Shell」只打开纯终端标签（展开的启动栏或收缩状态行的「⋯」中）。
- **⟳恢复 / ⤴对话**：收缩状态行的「⋯」按状态显示——⟳恢复 = 用刚才的 sessionId 接回原对话继续聊（shell 模式且可恢复时出现）；⤴对话 = 跳到对话页打开该对话回放（可做标记/保留/归档等整理）
- **◈ 接力到…**：把当前对话交给另一个 Agent 继续干（终端标签收缩状态行「⋯」/ 专注模式侧栏「⋯ 操作」，或对话页回放头部「⋯」进入）。选择目标 Agent 后，应用从当前会话尾部生成一份**结构化接力简报**（任务信息 / 最近对话要点 / 当前 git 状态），脱敏后落到项目目录 `.ccode/handoff-<时间>.md`（过程文件，生成时会自动把 `.ccode/handoff-*.md` 补进仓库 .gitignore，不进版本库），再开新终端标签预填同目录与目标 Agent，首条指令自动注入「读简报继续任务」。**接力是简报接力，不是记忆转移**——新 Agent 只看到简报，完整上下文仍留在原 Agent 会话里。Kimi 没有启动注入参数：会先把简报路径复制到剪贴板并提示，启动栏保留指令文本，由你手动发送；OpenCode 使用 `--prompt` 自动注入。接力生成的新会话在对话页显示「**⇄ 接自 <Agent>**」小标，接力链可回溯
- **◈ 提炼接力…**：长会话的续作方式——「恢复」会把整个旧上下文原样带回，容易污染；提炼接力则用 AI 把**全会话**蒸馏成一份紧凑简报（任务目标 / 关键决策与结论 / 已完成的改动 / 当前状态与待办 / 下一步建议 / 环境与约束），脱敏后同样落到 `.ccode/handoff-<时间>.md`，新会话只需读这一份简报即可续作（入口同「接力到…」，另在对话页行内 ⋯ 菜单）。目标列表里**来源 Agent 置顶**（标注「同 Agent · 新会话」）——同一 CLI 开新会话读简报，不带旧上下文；选其他 Agent 即跨 Agent 接力（同样登记接力链、显示「⇄ 接自」小标）。行悬停还有两个外部路径：**⧉ 复制外部续作命令**（形如 `cd <项目> && claude '读 .ccode/handoff-… 接力简报，…'`，粘贴到任意终端执行；用的是机器上的全局 CLI 配置，不携带 Ccode 注入的密钥）与 **⇗ 外部终端打开**。Kimi 没有启动注入参数：⧉ 对 Kimi 改为复制简报指令文本，启动后手动粘贴发送；OpenCode 使用 `--prompt` 自动注入。提炼需要可用的 AI profile（设置页「AI 辅助」可按功能单独指定「提炼接力」用的 profile）；没有配置或调用失败时会行内报错，可重试，也可以退回免 AI 的「◈ 接力到…」快速简报。**提炼在后台进行**：弹窗可以随时关闭去做别的事，不会中断也不会重复生成；完成后简报在「待你处理」收件箱出现「接力简报已生成，待发送」条目，点击直接回到发送界面；选定目标发送后条目自动消失（也可以点「暂不发送」手动摘除，简报文件保留在磁盘）。**AI 初稿就绪后同页就是「初稿编辑框 + 发送目标列表」**：不改动就直接点目标发送（用的就是 AI 初稿）；改过再点目标，会先把改动写回简报文件再发送；「暂不发送」= 改过的内容落盘保留、关闭弹窗（没改过则直接关闭）。简报统一是 `.ccode/handoff-<时间>.md` 一份——不再另存定稿副本，也不再钉到任务卡

> **「进程 vs 会话」心智模型**：进程是标签里正在跑的活的（agent 或 shell），一次一个、不可复活；会话是写在盘上的对话记录，进程死了它还在。停止 agent = 杀进程不杀会话；shell 回落 = 进程空窗期补位；恢复 = 拿盘上的会话开新进程接着聊。
- **注意力标记**：绿点短暂脉冲=工作中（几秒后静止，不会一直闪），琥珀点=待确认（标签上的点悬停/激活才显现、无状态不渲染）；「已回复」（回合结束等你输入）不打点不通知。agent 转为待确认且 Ccode 窗口未聚焦时另发 **macOS 系统通知**（同一标签 30 秒内最多一条，首次发送需允许系统通知权限；可在设置页「外观 → 长任务 OS 通知」关闭）。另可选**精确注意力标记**（设置页「集成」区按 agent 逐个开启，默认关）：开启后向该 CLI 的 hooks 配置写入事件钩子，由 agent 事件实时驱动注意力点，比默认的会话尾部推断更准；状态文件超过 10 分钟无更新自动回退推断，关闭开关即移除 hooks 并完全回退。支持 Claude Code / Codex / Gemini / Qwen / Kimi / CodeBuddy / Grok Build 七家（Cursor 与 OpenCode 暂不支持，设置页置灰并注明原因）

### 3.2 对话联动

窗口聚焦、页面轮询和跳转刷新由同一入口协调：并发普通刷新会复用在途请求；删除、归档、归置等会话变更使用强制刷新，较早返回的结果不会覆盖较新的列表。

主工作区默认进入「终端」（2026-09-02 起），也可在顶部终端标签旁切到「聊天」。聊天头部显示当前会话状态、实时同步状态、「↺ 历史」和「＋ 新建聊天」；正文只保留最近 **50 条**，会话文件事件触发整段替换，签名轮询仅作兜底，不再反复解析整份长会话。右侧工作台不再显示重复的实时对话。

Claude/Qwen 用 `--session-id` 确定性锁定；其余 agent 由后端按 **Agent + 项目 + 启动批次**排他认领，同目录并发标签不会抢到同一条会话，跳转和运行态登记也始终使用 `agent + sessionId` 复合标识。运行中的会话在对话页带绿点「进行中」，可点击跳回对应终端标签。

对话滚动只在你原本位于底部附近时跟随新消息；向上阅读后不会被强制拉回底部，而是在右下角显示「**有新消息 ↓**」。重新切换标签或重新打开对话面板时，才定位到该标签的最新内容。

### 3.3 文件树（左栏）

文件树默认完全收起（画布优先，不留窄条）。打开按钮在标签栏左侧。打开后左栏自上而下：**工作树标题行（`.*` 显隐隐藏文件 / ⟳ 刷新 / 收起）→ 项目区（常驻，固定列出所有建有活跃工作区的项目，当前项目置顶标注）→ 文件树（搜索框 + 完整树）**；「最近项目」收进文件树搜索行的 ⌄ 下拉浮层，左栏不再设「打开的标签」区；区间靠留白分层。成果面板用标签栏右侧按钮打开或收起；文件树与成果面板的显隐都会记住。

- **搜索框**：当前根目录内按文件名或后缀搜索（跳过 `.git` / `node_modules` 等构建产物）。`pdf`、`.pdf`、`*.docx` 都能按扩展名找，`doc` 同时包含 `.doc`/`.docx`（ppt/xls/jpg 同理）；纯后缀写法（`.pdf` / `*.pdf`）只返回该类型。带后缀的命中排在文件名碰巧包含这些字母的结果前面。点开头的配置目录（如 `.kimi-code`、`.claude`）在搜它的名字、或以 `.` 开头的查询、或已打开「显示隐藏文件」时会出现；点结果会在树里定位并高亮，若该路径默认隐藏会自动打开眼睛按钮。根目录下的 `.env` 一类隐藏文件本来就能搜到
- **折叠**：点行左侧箭头只展开或收起；点文件夹名字单击同样折叠，双击才进入该目录（文件树浏览根，不改 Agent 运行目录）
- **最近项目**：收进文件树搜索框旁的 ⌄ 下拉浮层（Esc/点外部关闭）。按各 Agent 会话的最近更新时间聚合、去重并排序，最多展示 4 个，当前文件树所在项目不重复出现。应用启动时后台预取，并用上次成功结果立即占位展示；首次无缓存时先显示固定骨架，因此进入终端页不会等扫描完成后突然把文件树向下顶开。点击 = 树和终端 cwd 一起切过去（真进入）；↗ 另开标签。缓存中的目录点击前仍会重新验证，已移动或删除时不会切进无效路径
- **项目区**：最近项目下方显示「项目」折叠区（默认展开），**固定列出所有建有活跃工作区的项目**——每个仓库一个小节（组头标仓库名），主文件夹节点（repo 根名，带「主」标记）下列出该项目的**活跃工作区**（工作区名 + 研究步骤名 + 注意力点；未创建/已归档不列出）；当前标签 cwd 命中的项目**置顶并标注「当前」**（还没有活跃工作区也保留显示）。点击主文件夹或工作区名 = 树和终端 cwd 一起切过去（同「最近项目」真进入语义，右侧对话/预览/改动随之联动）；节点前的 ▸ 只展开显示该节点的**一层目录**（只读，不点不拉取，子目录可点击继续切根）。当前 cwd 落在哪个节点，该节点高亮。agent 正在运行时 cwd 不切换（既有语义），会给出提示但不打断运行中的任务
- **树**：双击钻取；「←」返回上一级；`⌂` 回到当前项目；自动刷新（噪声过滤）；git 状态字母（M/A/?/D，小号 mono 徽标）、文件夹图标随主题着色；**根为家目录（~）时，系统目录（macOS 的 Library、Applications 等）自动置灰降噪**（交互不受影响，普通目录不受影响）。树根跟随终端的**真实 cwd**——切标签、shell 里 `cd` 都会跟（每 4 秒探测一次）。根目录名旁标注归属：绿点「**分支**」= 在工作区工作树里，黄点「**主仓库**」= 在主仓库里（改动不进任何分支）；命中工作区时出现「**⇄**」下拉——列出主项目 + 该仓库全部活跃工作区，任意切换（树和终端 cwd 一起切）
- **右键**：目录 = 打开终端/新建文件夹（内联输入）/删除；文件 = 删除。**删除 = 移入系统回收站**（废纸篓/回收站可找回，不是永久删除）；系统目录、关键用户目录、CLI 配置、.git 等**重要路径一律拒绝删除**
- **预览**：单击文件 → 右侧 Monaco 编辑器（**按扩展名语法高亮**），可编辑（脏标记 ●，保存写回；>256KB/二进制只读）。**Markdown 文件默认进入「阅读版式」**：渲染后的排版视图（标题层级/引用/表格/代码块/列表，配色随主题），工具行可切「**阅读 / 编辑**」（编辑回到 Monaco，切换不丢未保存改动）；点「**⛶ 沉浸阅读 / 沉浸编辑**」打开全宽覆盖层（md 阅读态除外——它会配对本篇 PDF 直接进 3.7 的三栏沉浸阅读区；阅读为大号排版居中、编辑为全宽 Monaco——编辑器实例不变，未保存改动与撤销历史不丢；头部带文件名、保存按钮与「✕ 退出」，Esc 关闭，终端继续在后台运行）；阅读版式（含沉浸阅读）里拖选文字会出现「**◈ 讨论/改写此段**」浮动按钮，点击把「选段引用 + 出处文件名」写入**当前活跃终端标签**的 agent 输入框（不自动发送，接着输入你的意见——讨论、提问或要求改写——后自行回车；无运行中 agent 会提示）；Agent 正在写文件时阅读内容自动刷新，编辑中不覆盖。**PDF 文件走内嵌 pdf.js 预览**：页码导航/跳页/缩放/适配宽度，只渲染当前页与相邻页（Windows 深色主题下不再闪白屏）；在文字上拖选会出现「**◈ 问 AI**」浮动按钮，点击把「选段 + 出处（文件名、页码）」写入**当前活跃终端标签**的 agent 输入框（不自动发送，检查后自行回车；无运行中 agent 会提示）；旁边的「**整理为笔记**」把选段（含文件名/页码/日期出处）追加到归属项目「文献精读与笔记」步骤工作区的 `notes/inbox.md`——没有该工作区时自动一键开步创建，完成后预填终端启动，让 Agent 把选段整理成结构化笔记；PDF 未登记为任何项目资源时会提示并给出「去项目页登记」入口。**docx 文件走阅读版式预览**：经 mammoth 转成排版视图（标题/正文/列表/表格，图片内嵌显示，配色随主题），只读不可编辑——改内容请编辑对应的 Markdown 源文件再重新导出；超过 50MB 的 docx 不渲染并明确提示。旧版 `.doc` 不能预览，请另存为 `.docx`。**Excel / 表格（`.xlsx` / `.xls` / `.ods`）按工作表预览**（列字母与行号冻结，宽表可横滑；点格子在顶栏看全文。最多 200 行 × 256 列，只读；多工作表可切换；超过 20MB 不渲染；复杂公式/图/宏以 Excel 打开为准）。**图片（png / jpg / gif / webp / svg）单击内嵌显示**（棋盘格底，超过 20MB 不渲染）。Markdown 阅读版式里的本地图会显示：相对路径、`/Users/...` 绝对路径、中文文件名都可以；https 图（如 README 徽章）会显示，http 图不加载。在当前树根内预览保持已打开文件；**切换项目、工作区、终端标签 cwd 或树根时自动清空旧预览**，不会擅自打开新根下的同名文件。未保存时先确认，取消则不切换树根。**磁盘被外部改写（合并/agent 写入等）时自动刷新内容**（编辑中不覆盖）。文件名旁标注路径归属：绿点「分支 ccode/x」= 在工作区工作树里（改动属于该分支）；黄点「**主仓库（非分支）**」= 在主仓库里——此时保存按钮变「**保存到主仓库**」（警示色）且保存前二次确认，防止误改主项目。**md 阅读版式与 PDF 预览的选段浮动条均有「✦ 沉淀为技能」**：把选段（比如你纠正 agent 做法的那段交互）交给 AI 提炼成技能草稿（名称/描述/正文规则清单），自动跳到技能页打开新建表单预填，检查修改后保存即入库（重名会被拒绝，改名再存即可）

### 3.4 git 改动面板（右侧「改动」页签）

面板跟随**左栏文件树的当前根**（你在文件树里双击钻取、返回上级、或从项目区/最近项目切根，改动面板就看到哪；切换终端标签时回到该标签的目录）。分支、领先/落后、+/- 行数（含未跟踪）、文件列表，8 秒刷新。文件列表按状态分组显示中文组名（「修改的 N / 新增的 N / 删除的 N」），状态字母（M/A/??/D）保留为文件名前的小号 mono 徽标，悬浮显示「字母 · 中文」说明，方便程序员扫读、新手看白话；文件名前另有**文件类型小徽标**（固定识别色的短标签，如 M↓/⚛/TS/R，随扩展名识别，未收录类型留空槽位对齐）。**点击任一文件行切换为主从分栏：左栏是该文件的 diff 主区（图片为「基准 vs 当前」双栏看图），右栏收成紧凑文件列（状态徽标 + 文件名）方便连续翻看，再点当前行或 diff 头部的 × 收起回全宽列表**；新增/删除行整行铺语义底色（深色主题为深底浅字、浅色主题为 GitHub 式浅绿/浅红底深字，十四主题通用），代码文字保持高对比，hunk 标题使用 inset 底色。未跟踪文本按全新增显示，其余二进制文件给出只读提示，超大内容最多读取约 200 KB 并明确标记截断。读取前后都会核对该路径仍属于当前 Git 改动，过期或越界路径会拒绝。若面板目录本身已不存在（如工作区合并归档后旧标签页仍指着它），会明确提示「目录不存在（可能已被归档或删除）」，而不是误报「不是 git 仓库」。工作区任务头部增加「**审阅**」入口，展开全宽 diff 与提交合并闭环；普通仓库不显示。

**按块丢弃/暂存（逐 hunk 验收）**：diff 主区里，每个改动块（hunk）标题右侧有「**丢弃**」「**暂存**」两个小按钮（只覆盖未提交改动；工作区视图里同样可用，但仅限仍未提交的块，已提交的累计改动请走「审阅」）。「丢弃」把这块改动从工作区抹掉（会二次确认，不可恢复，除非已提交过）；「暂存」把这块改动放进暂存区，随后勾选该文件「**保存到历史**」时就只提交已暂存的块，其余块留在工作区——这就是选块保存。新文件整个文件算一个块：暂存 = 纳入 git 跟踪，丢弃 = 删除该文件。文件已有部分内容暂存时，diff 主区会提示提交粒度；全部块都暂存后回落为只读视图并提示「改动已全部暂存」。二进制、非 UTF-8 或超大文件不支持按块操作，保持只读展示。

**普通仓库默认不勾选文件**，可逐文件选择或全选/清空，并明确显示「已选择 N / M 个文件」；提交和 ◈ 生成都只读取所选文件，未选文件保持在工作区。隔离任务工作区仍固定提交全部任务改动，避免把一个任务拆成难以理解的半提交。文件列表的路径做了分级（目录段浅灰、文件名加粗），文件状态（修改/新增/删除）以文件名颜色表达（黄/绿/红），不再有独立徽标块。改动说明可以手动填写（留空自动生成一条），也可点输入框旁的「**◈**」让 AI 按 diff 生成后再审阅。主按钮为「**提交（⌘Enter）**」（悬浮标注 `git commit`），旁边「**提交并推送**」（悬浮标注 `git commit + push`，激活时翡翠绿）；若说明留空，按钮自动变为「**快速提交（⌘Enter）**」：应用按文件状态和数量在本地即时生成中性默认信息，不调用 AI，直接提交或推送（无上游自动 `push -u`）。提交阶段失败会把默认信息留在输入框供修改或重试；如果提交已成功但推送失败，会显示「**重试推送**」，只执行 push，不会重复提交。成功时右下角浮出主题绿 toast，展示提交号和实际使用的提交标题。

**产物区（提货单）**：工作区任务视图底部增加「产物（提货单）」区——大型产物（数据/图/PDF）**不进 git**，只有清单 `artifacts.yaml` 随提交传递给下一步。「**登记产物**」打开系统对话框选文件，应用计算 md5 与大小后把工作区根的 `artifacts.yaml` 更新一条（名称/绝对路径/hash/大小/来源工作区/时间；已被 git 跟踪的文件会被拒绝，因为它本来就随分支走；同一路径重复登记会更新而不是重复）。条目显示名称、路径、大小、hash 前 8 位与来源工作区；PDF 条目带「**查看**」按钮，直接在内嵌 PDF 预览中打开。下一步「开始」开步时，项目根的提货单会自动写进新工作区 `TASK.md` 的「上一步产物（提货单）」段，Agent 按路径直接读取产物，不需要手动复制路径。

### 3.5 终端质感

运行页左栏分为「项目与工作区」和「文件树」两种上下文：点击项目或工作区会切换当前终端目录；文件树中双击目录只进入浏览，不会偷偷改变 Agent 的运行目录。浏览根与终端目录不一致时会明确显示两者，并可一键回到当前终端目录。Agent 正在运行时切换项目，会自动在新标签打开目标目录，不打断当前任务。每个终端标签独立记住「聊天 / 终端」显示层，标签栏里同一个按钮单击切换；顶部「布局」菜单管理分屏和专注终端。成果面板用标签栏右侧按钮打开。

项目 rail 中主项目使用文件夹图标；已绑定研究流程的工作区显示流程序号，未绑定流程的手动工作区显示分支图标。图标只表达归属和顺序，不改变工作区切换或运行逻辑。

WebGL 渲染（创建失败或探测到软件渲染时自动回退，防 Windows 上 GPU 被拉黑后的闪烁）、清瘦字形（400/600 字重、行高 1.2、零字距，向 Ghostty 锐利度靠）、盒绘字符对齐、粗体增亮、平滑滚动 150ms、细滚动条。默认字体为打包内置的 JetBrains Mono（woff2，不依赖系统安装），可在设置页换其他字体或调色板预设。后台标签输出只缓存不推流（切回补发），输出 50ms 合帧——十余个标签并行也流畅。

**输出搜索**：⌘/Ctrl+F 或工具栏「◎ 查找」呼出搜索条（输入即增量查找，Enter 下一个、Shift+Enter 上一个、Esc 关闭），只作用于当前活跃标签。

### 3.6 图片与文件输入

九家 CLI 都内建图片输入，终端画布有三种给法：

- **粘贴截图/图片**：macOS 按 **Cmd+V 或 Ctrl+V**（Chromium 内核下 Ctrl+V 等效）。剪贴板里有图片数据时，应用自动把图片存成临时文件、把**绝对路径写进终端输入框**（不自动发送，检查后自行回车），右下角浮出「已粘贴图片路径：…」轻提示；剪贴板只有文字时就是普通文本粘贴，行为不变。**Windows 上各家 CLI 的贴图键是 Alt+V**（按键原样透传给 CLI，由 CLI 自读剪贴板）。Ctrl+V 在 macOS 上会原样透传给 CLI（各家 CLI 的贴图键就是 Ctrl+V），想贴图片路径用 Cmd+V 或右键「粘贴」即可
- **拖入任意文件**：把文件从访达/资源管理器拖进终端画布，自动变成 shell 转义后的绝对路径（空格/引号/中文名都会处理好），多个文件以空格拼接，同样不自动发送。图片、数据文件、PDF 都可以这样给。**在访达里「拷贝文件」再 Cmd+V 粘贴的只是文件名字符串，不是路径——拷贝文件请改用拖入**
- **右键菜单**：终端画布上右键 = 复制（有选区时可用）/ 粘贴（剪贴板有图片自动走落盘转路径，否则纯文本写入；不支持读剪贴板时静默忽略）/ 全选 / 清屏 / 查找输出

各家 CLI 对路径的处理分两派（细节见 docs/agent-integration-matrix.md §11）：claude/codex/qwen/grok/opencode 会把图片路径**自动升级为真附件**（模型直接看图）；gemini/kimi/codebuddy/cursor 是路径原文进上下文、模型用工具读图。两派体验等价，你只管把图给它。粘贴产生的临时图片存在应用配置目录 `tmp/paste-*`，7 天前的会在下次粘贴时自动清理。终端输出里的 **http(s) 链接可直接点击**，在系统浏览器打开。

### 3.7 沉浸阅读区（⛶）：笔记 · PDF · 终端 三栏

读论文的专注形态：对一份 PDF 打开**全屏阅读区**——左边笔记、中间 PDF、右边 Agent 终端，三栏并排，没有底部终端；底下的终端与对话照常运行，`Esc` 退出回到原样（中文输入法组词中按 Esc 是取消候选，不会误退；**焦点在右侧终端里时 Esc 归终端自己**——打断生成等终端内语义，此时退出点「← 返回」或先点别处）。入口：PDF 内嵌预览工具条「**⛶ 沉浸阅读**」、文献雷达「精读清单」页签的「**开读**」、文件树里 PDF 右键「⛶ 沉浸阅读」；**md 笔记也有三个入口**——文件树里 md 右键「⛶ 沉浸阅读」、md 预览工具条的「⛶ 沉浸阅读」（阅读态）、产物核验清单里 md 预览弹层的「⛶ 沉浸阅读」，都会自动配对本篇 PDF 并把左栏定位到这份笔记本身（找不到配对 PDF 会说明原因；工作区里尚未合并进主仓的笔记会提示先合并）。三栏分隔条可拖并记住宽度，左右两栏可收起；右栏「翻译面板 × 终端」之间的横分割线同样可拖动调整高度（记住高度，双击分割线恢复内容自适应）。

- **笔记栏（左）**：第一次打开某篇 PDF 时自动建档 `notes/<标题>.md`——固定小节与 lit-notes 技能的精读笔记同一结构（一句话总结 / 研究问题 / 方法 / 主要结果 / 局限 / 可引用点 / 与本课题的关系 / 疑问与待跟进，外加阅读区自维护的「译段」「我的想法」两节），已存在的笔记不会被覆盖；**建档前会先认「来源行」**——`notes/` 里已有笔记在头部声明了 `> 来源 PDF：<路径>`（精读步骤的笔记按新规范都带这行）时，「开读」直接打开那份笔记，不再按 PDF 文件名另建重复笔记（此前误建的空模板笔记会顺手清进回收站）。**从产物核验清单的 md 笔记进入时不再另建档**：左栏就是这份笔记本身（精读步骤产出的 `<序号-短标题>.md` 原样可编），配对 PDF 按笔记标题与项目已登记 PDF（type=paper 资源）的标题互相包含自动查找，找不到会在弹层里提示「需 papers/ 内有已登记的本篇 PDF」。与文件预览同一套「阅读 / 编辑」双态：阅读是排版视图（笔记里的本地图片直接显示；https 图会显示，**http 图片不加载**、只显示链接文本；相对链接在笔记栏原地打开、顶栏「← 回笔记」退回）；编辑态下**粘贴图片**自动存进 `notes/assets/` 并在光标处插入图片引用。Agent 改笔记时阅读内容自动刷新
- **PDF 栏（中）**：连续滚动整本翻看（只渲染可视附近的页，大文件不卡），支持缩放 / 适配宽度。拖选文字出现浮动条：**「译」** = 就地翻译选段（选段旁浮卡显示译文，可「保存译段到笔记」收进笔记「译段」小节）；**「◈ 问 AI」** = 把选段写进右侧终端的输入行（不自动发送，检查后自行回车；⋯ 菜单里的「↵ 直接发送」免确认直发）；**「＋ 生词」** = 选中的词存进生词本（释义自动预填可改）。工具条「**▦ 圈选**」进入截图模式：在一页里拖框，定格后两个去向——「**◈ 发给 agent**」把截图路径与说明写进右侧终端输入行（不自动发送；扫描件没有文字层，就靠它让会看图的模型读图），「**＋ 插入笔记**」把图存进 `notes/assets/` 并追加到笔记「我的想法」小节。**⌘/Ctrl + 点击某一段** = 整段对照翻译（自动识别段落边界，译文浮在点击位置旁，可保存进笔记）。**生词本里已有的术语在正文里淡高亮**（点状下划线），悬停看释义。顶栏「护眼」反色显示（按文件记忆）；**读到哪页自动记**（停稳 2 秒才记），下次打开自动回到那一页并短暂提示
- **终端栏（右）**：就是本项目的阅读会话终端本体（真实终端画面，不是对话列表）——进阅读区自动拉起一个属于本项目的会话（退出再进接着上次聊；还没有可用 API 配置时显示引导卡，点它去配置页建一个；会话标签被手动关掉时给「重新启动会话」入口）。直接在终端里敲命令、提问；顶部一行小字显示 agent · 模型 · 运行状态

## 四、对话页（◔）：历史回放与整理

- **布局**：应用导航外的两栏——**会话列表栏**（固定宽，含标题「对话」、计数副题「当前 N · 总计 M」（搜索时透出命中数）、「导入」与「批量管理」次按钮与搜索框；其下一行是快筛胶囊（常驻 保留/进行中/今天，近 7 天/内部 AI/已归档收进「更多 ▾」，激活的自动提到行内）+ 右端当前分类下拉（默认「全部对话 ▾」））｜**回放区**（常驻，未选中时为空态）；选中行浅填充标记当前回放的对话；**按 ↑ / ↓ 可在列表中快速切换对话**（选中行自动滚进视野）
- **分类筛选**：快筛下方整行「范围」显示当前分类（默认「全部对话」）。点开后列表变成选择面——「全部对话 / Ccode 内部 AI / 各 Agent」及计数，Agent 列表下方是「**按项目**」分组（跨 Agent，按最近更新排）。点 Agent 展开或收起它名下的项目（再点一次收回去）；点「全部项目」只看这一家，点「按项目」里的目录则筛这个项目里所有 Agent 的对话。点项目或「全部项目」即筛完并回到会话列表；「完成」或 Esc 取消选择面。Agent 下的项目行右键仍可批量删除该 Agent 在该项目的全部对话。顶部搜索（项目/标题/标签/工作区名/**研究步骤名**/**AI 摘要内容**，以及**对话正文**里说过的话）。多个词用空格分开，按相关程度和时间排序；正文命中会在该行下面显示一句摘录，点开后回放滚到那一段并标出来。Ccode 自己发起的 ◈ 无头 AI 会话不混进普通项目，默认归并到单独的「**Ccode 内部 AI**」入口（包括临时目录名 `ccode-ai-…` 的那些，它们不是你的课题）。用量统计仍只按后端登记的来源计，不会把你在临时目录里自己跑的任务算成内部活动
- **归档计数**：快筛「已归档」（更多 ▾ 里）关闭时，全部、Agent、项目和内部 AI 的数字都排除归档项；打开后统一计入，避免分类数字与列表结果口径不一致
- **列表与标题**：双行行式——标题行（标题 + 右侧相对时间，相对时间主显、悬浮查看绝对时间）+ meta 行（agent 名 · token 用量 mono 小字 + ⎇步骤/⇄接力/标签 chip，AI 摘要截断尾随）；工作区会话的 ⎇ badge 优先显示**研究步骤名**（工作区名命中项目档案卡 `steps[].workspaceName` 时；不匹配则回落工作区名，悬浮可见两者）；选中项目节点时列表**按任务卡分组**（卡片名小标题，组内按时间降序，组按最近活跃排序，未归置卡片的会话收「未归置」组排在最前；**搜索时改按相关度平铺**，不再分组）；已归置的会话 meta 行带「▤ 卡片名」chip（点击跳到项目页对应项目），行 ⋯ 菜单的「**移到卡片…**」在项目筛选下可把对话归入/移出卡片；接力生成的会话带「⇄ 接自 <Agent>」badge（简报接力，非记忆转移）；Codex resume 链合并（「N 次继续」）；⚑=已保留；绿点「进行中」（内部启动的可点击跳回终端；**外部终端里运行的会话**也按文件活跃度自动标记，仅显示）。行悬停（或键盘聚焦）才显示「恢复 / ⋯」操作。标题会折叠换行与多余空格，并忽略 `New Session`、`Untitled`、`未命名对话` 等占位值，优先回落到首条真实用户消息；仍无标题时显示「未命名对话 · ID 前 8 位」。Gemini 若因重启/恢复留下多个同 `sessionId` 文件，列表只显示最新文件对应的一条会话
- **对话回放**：首次只读取会话尾部的有界窗口；长会话顶部显示「**加载更早对话**」，逐页向前加载并保持当前阅读位置。OpenCode 每页最多 80 条消息；普通 JSONL 每页最多读取约 192 KB；压缩的旧 Codex 会话只提供有界尾部回放。回放排版：你的消息为右对齐气泡，AI 回复直接排版；正文中的围栏代码块以独立代码块展示（hover 显现 ⧉ 复制）；连续工具调用折叠为「▸ N 次工具调用」一行，点击展开逐条明细；右上角 `继续` 是唯一的应用内继续入口，底部只读操作条提供「在外部继续」，并且仅在会话路径属于已注册项目时显示「查看项目」。头部保留「**◈ 摘要**」（AI 概括，缓存）与「**导出**」（整段对话导出 Markdown 到 `~/Downloads/ccode-exports/`）
- **当前项目改动**：「对话 | 当前项目改动」页签中的后者只读展示该项目**此刻磁盘上的 Git 状态**，不是历史会话产生改动的快照；可点击文件展开 diff，但不提供提交或推送，点「前往终端处理」进入正常编辑/提交流程
- **在终端恢复**：行悬停/右键或回放头部 → 自动开标签续聊（claude `-r`、codex `resume`、kimi `-S` 等）
- **⇗ 外部恢复 / ⧉ 复制命令**：不想用内嵌终端时——⇗ 直接在外部终端应用里开窗口续聊（macOS 依次找 Ghostty → iTerm → 系统终端；Windows 按设置打开命令提示符或 PowerShell 续聊；Linux 找 gnome-terminal/konsole/xterm）。⇗ 会读取当前兼容的 Ccode profile 和模型，在后端生成一次性权限收紧 wrapper；密钥和 Agent 特殊参数只在该次进程环境中生效，不进入命令行、剪贴板、前端 payload 或普通日志，wrapper 启动后自删。⧉ 复制形如 `codex resume 019fbd46-…` 的恢复命令仍是**全局配置模式**，不携带 Ccode 密钥，适合你确认全局 CLI 配置已准备好的场景。Windows 上复制的是 PowerShell 语法（`Set-Location '…'; & 'claude' -r 'id'`），请粘贴到 PowerShell，不要粘到 cmd。Codex 自定义接入的复制命令会补 provider 定义；**应用内恢复（会话行「恢复」）也按会话记录自动挑兼容配置**。
- **在客户端打开 · Codex**：Codex 会话有两处入口——回放区**底部操作条**（「在外部继续」旁）与行 ⋯「继续」组——唤起 Codex 桌面客户端（ChatGPT.app 内嵌）直接打开这条对话接着聊。桌面端与 CLI 共享同一份本地会话库，CLI/Ccode 里发起的对话也能跳过去；仅 macOS / Windows 显示此入口（Linux 无桌面客户端）。**会话记录的渠道在客户端 config.toml 里没有定义时**（Ccode 内联渠道 `ccode` 发起的会话就是这种）按钮置灰并注明原因——客户端打开它会报「Model provider not found」，这类会话用「继续/恢复」在终端续聊即可，Ccode 会自动补渠道定义
- **整理**：保留（pin 快照，CLI 自动删除后也能回放）、归档（默认隐藏）、自定义标题/标签、删除会话文件（源文件进系统回收站，可从回收站找回；OpenCode 删除其库中记录无法进回收站；Codex resume 链会连带删除链上成员文件）；项目节点右键批量删除——删除范围含该项目的全部会话：已归档/内部对话即使不在当前列表中也会被一并删除（确认框会明确提示数量）
- **批量删除**：列表头部「批量管理」进入选择模式 → 勾选/全选（当前筛选结果）→「删除 N 项」→ 警示色二次确认「确认删除 N 项（含 pin 快照）？」后逐个删除（pin 快照一并清理，与单个删除同语义）。筛选/搜索无结果时显示「清除筛选」按钮
- **会话包导出 / 导入**：换电脑时把对话带走。列表头部「**导入**」选 `.ccode-sessions.zip`；单条 ⋯ 或批量管理里「**导出会话包**」（系统保存对话框）。**导出是会话文件原文拷贝**，可能含密钥或路径，弹层会说明，分享前请自查；密钥、网关和连接配置不会进包。导入向导列出每条对话的状态：原目录在本机还在即可导入；不在则选一个本机文件夹（已添加的项目里同名文件夹会优先填上）；本机已有同一条对话则跳过、不覆盖。OpenCode 不能进包（会话在 SQLite 里）。工作区里开的对话，列表显示主仓库，导入时改写的是会话文件里的工作区路径——原工作区在本机没有时要选目录，不会把主仓库路径误写进会话。导入后列表自动刷新，保留标记/自定义标题/标签/摘要一并带上。Codex 用 Ccode 渠道发起的会话可勾选「注册到 Codex 客户端」（默认开，有可用连接时），用本机连接补上另一台机器记下的渠道名，桌面客户端才能打开；官方账号会话不用注册
- **敏感信息保护**：会话标题、回放正文、AI 摘要和 Markdown 导出在后端统一隐藏已保存密钥及常见密钥前缀；脱敏完成后才会送到界面，CLI 的原始会话文件保持只读、不被改写。会话包导出是原文拷贝（见上条），不走这段脱敏

## 五、技能页（✦）：Skills 统一管理

技能 = 含 `SKILL.md` 的目录（开放标准）。先入库，再分发到各 CLI。

页面顶部标题旁显示计数副题「N 个 · 已应用 N」；右上主操作只有实心「+ 创建技能」，「导入技能」为次级描边按钮，导出全部 / 发现未纳管 / 检查 GitHub 更新收在「⋯」。主列表为表格化呈现：小字灰表头（技能 / 来源 / 应用）+ 可折叠分类分组头（▾ 分类名加粗深色 + 「N 个技能」微型胶囊，「未分类」固定排在最后并附「⋯ → 设置分类」归档引导），固定展示技能（名称 + 次行简介，名称后可带 1-4 个自定义标签 pill；正文提及 MCP 工具的技能另带「⌗ MCP」微型标记）、来源和「● N 个 Agent」（未应用为浅灰「0 个 Agent」不画点；悬浮列出具体 agent 名称），不再为每个 Agent 永久占一列；点击技能或应用计数后，右侧详情面板集中展示描述全文、全部 Agent 开关与 SKILL.md。以后新增 Agent 只会在右侧开关区增加一项，列表宽度和阅读结构保持不变。悬停该行（Tab 聚焦同样）行尾浮出微型操作栏「✎ 编辑 / ◈ 优化 / ⋯」，采用细边 raised 层而不使用大阴影；分类、标签、导出、删除等低频项仍在 ⋯；技能描述同时上收到列表次行（为空或纯符号的异常值不渲染，详情面板显示「—」）；副本过期与 GitHub 可更新合并为技能名旁的一个警示点（悬浮看明细）；技能行按分类以卡间留白组织，避免满屏横线。

- **标签与分类分组**：标签是用户自定义的展示层——名称后最多 4 个小 pill，行内「⋯ → 设置标签」内联输入（逗号/空格分隔，回车保存，超 4 个截断，留空=清除全部标签）；分类仍是列表分组依据，可折叠分类头（▸/▾），修改分类在「⋯ → 设置分类」内联输入（回车保存，留空归未分类）；两者相互独立
- **应用开关**：点击技能后，在右侧详情的 Agent 网格中管理九个 agent（Claude Code / Codex / Gemini CLI / Qwen Code / OpenCode / Kimi Code / CodeBuddy / Cursor / Grok Build）；绿点=已分发到对应 CLI 技能目录（symlink 优先、copy 兜底；Cursor / Grok 未验证 CLI 是否真读技能目录，固定 copy），灰点=未分发，点击即切换；关闭只清理由 Ccode 分发的。有未启用项时标题行出现「**一键应用**」按钮，顺序分发到全部剩余 agent（逐个走与单点相同的 apply_skill，失败即停并显示错误）；**未安装的 agent 自动跳过并提示**（CLI 不在时分发只会留下没人读的副本，如 Cursor 在 Windows 暂无安装渠道）；全部启用后按钮消失。悬浮在开关上显示 symlink / copy 方式，copy 副本同时参与漂移检测。
- **副本漂移**：copy 副本与库不一致时，技能名旁显示黄点（悬浮列出漂移的 agent），行内「⋯ → 重新分发副本」把库里的最新版本重新同步过去
- **导入**：本地目录 / ZIP / GitHub 仓库（`owner/repo` 或完整网址，可另填分支/子目录，预设 anthropics/skills）/「发现未纳管」（页面顶部 ⋯，扫描各 CLI 目录收编）。结果完整分列**新增、覆盖更新、跳过、冲突**四类并逐类列出技能名，不用「已导入 0 个」掩盖冲突；冲突可批量跳过、按右栏名称**全部另存为**、或**备份并覆盖**（覆盖前先备份旧库目录）。ZIP 先在临时目录完整校验再入库，元数据写入失败会回滚库目录
- **新建 / 编辑**：顶部「+ 新建技能」直接把自己的工作方法写成技能（名称即目录名、描述一句话、正文即 SKILL.md 主体，frontmatter 自动生成）；也可以从 md 阅读版式 / PDF 预览的选段浮动条点「**✦ 沉淀为技能**」，让 AI 把选段提炼成草稿预填本表单再保存；行内「⋯ → 编辑内容」修改描述与正文，保存前自动备份当前版本（保留最近 5 份），SKILL.md 之外的辅助文件不受影响；重名会被拒绝并提示改用编辑
- **◈ 优化**：行内「⋯ → ◈ 优化」写下优化意见后开终端标签（技能库目录为工作目录），Agent 阅读并按意见直接改写库中的 SKILL.md——这是把 skill 交给 Agent 迭代优化的入口；改写结果请审查后再用，之后的保存/覆盖都有旧版本备份兜底
- **◈ 适配到流水线（外部技能推荐第一步）**：行内「⋯ → ◈ 适配到流水线」让 AI 按流水线路径约定（papers/、notes/、references.bib 等）改写技能的读取/产出落点，并补写 frontmatter 的 `inputs`/`outputs` 接口声明——弹层里可预览和再编辑，确认后才写回技能库（覆盖前有备份）。从 GitHub 下载的科研技能常自带一套产出路径，与流水线接口对不上时用它一键对齐，比手改省事
- **挂载到步骤（反向入口）**：行内「⋯ → 挂载到步骤」或详情面板「哪些步骤在用」区的「＋ 挂载到步骤」——选项目、选步骤即挂进研究流程（写回 project.toml，已挂载的步骤置灰）；下次开工 TASK.md 的「本步骤技能」段会列出它
- **步骤推荐技能**：在 `.ccode/project.toml` 的步骤里填 `skills = ["技能名"]`（研究流程编辑器会保留该字段），一键开步的 TASK.md 会落成「本步骤推荐技能」段（名称 + 一句话描述，未安装的会标注）；技能本体不进 TASK.md，已分发的技能对启动的 Agent 自动生效，未分发可在本页开启。步骤级「预览 TASK.md」弹层与开工确认弹层都有「推荐技能」chip 区（点击看一句话说明）；开工确认弹层里可直接增删（chip × 移除 /「＋ 添加技能」下拉），**增删写回步骤定义**（project.toml，影响以后所有开工），不是只对本次生效；chip 还标出归处：技能未安装有标记，内容含「推荐 MCP」的技能带 MCP 标记、点击跳到 MCP 页配置；**一步挂多个技能时，若它们的声明产物路径相撞（同目录/同文件），chip 区下方会出现 ⚠ 提示**，确认简报里写清分工即可，只提醒不拦截。**链路校验**：技能声明（或正文推断出）的 inputs 在上游产物/本步骤输入/项目资源里找不到来源、或 outputs 不在本步骤预期产物里时，chip 区下方也会逐条 ⚠ 提示（推断结果标「供参考」）——挂外部技能时照它核对上下游接口即可。另外 TASK.md「本步骤技能」段固定带一句「技能正文路径与本文件不一致时以本文件为准」，即使技能没适配，Agent 也会把产物写到流水线约定的落点
- **GitHub 更新**：GitHub 来源会记录仓库、子目录与 revision；页面顶部「⋯ → 检查 GitHub 更新」，有可更新时行名旁显示黄点。此时详情面板出现「**应用更新**」按钮、行内 ⋯ 也有「一键应用 GitHub 更新」——按原地址下载最新版并覆盖该技能（覆盖前自动备份，同仓库其他技能不受影响）；若上游已改名/移动会明确提示，可改用行内 ⋯ 的「导入 GitHub 更新」带原地址打开导入器手动处理（仍经过同名冲突确认，不会静默覆盖）。GitHub 导入的技能会自动按仓库名归组分类；早期导入没有分类的存量，用顶部「⋯ → **无分类 GitHub 技能按仓库归组**」一次性补齐（已有分类不动）
- **导出**：全部打包 ZIP 位于页面顶部 ⋯，单行导出位于行内 ⋯；**查看**：右侧预览 SKILL.md（标注来源与仓库，GitHub 来源显示为可点链接直达仓库），详情面板带「**◈ 翻译为中文**」——AI 译文随会话缓存展示，不改写库文件；**删除**：位于行内 ⋯，取消应用 + 库文件备份（5 份）
- **内置技能（15 个，启动自动播种）**：文献线 `lit-search`（检索与筛选：多库检索清单 + 闭源检索站「人肉中转」规范——网页端导出 RIS/BibTeX/CSV 放入 `papers/imports/` 由 Agent 解析去重合并，带 key 的库一律环境变量引用 + 推荐 MCP 配置片段）、`lit-notes`（精读笔记）、`lit-watch`（新文献监控：arXiv/OpenAlex/Crossref 三路官方 API 确定性检索 + WebSearch 兜底，DOI 优先跨源去重合并，精选 Top 3–5 标「推荐」，无摘要/付费墙进 `papers/watch-followup.md` 跟进队列，订阅行备注 `+bib` 时推荐条目同步生成 BibTeX 进 references.bib）、`review-framework`（综述框架构造：空白清单 + 范式卡片融合出 outline.md）、`review-writing`（英文综述写作）；数据线 `data-clean`（数据清洗规范）、`data-eda`（探索性分析与绘图规范，统计结论先过 stats-check 口径）；论文线 `research-writing`（实证科研论文 IMRaD 写作）、`quarto-render`（quarto 渲染与排错）、`bib-check`（引用闭环只读校验，联网时可加做 Crossref/arXiv 外部元数据核验）、`rebuttal-crafter`（审稿意见逐条回复 + 修改对照表）、`stats-check`（统计用法审查 + 实验设计功效自查）、`figure-forge`（投稿级出图生产规范）、`proposal-writer`（开题报告/研究方案）、`slides-deck`（组会/答辩幻灯片大纲或单文件 HTML）。**首次启动自动入库（来源标「内置」），只补没有的、不覆盖你改过的、你删掉的不复活**；研究流程模板的对应步骤已挂载这些技能，开步 TASK.md 会带「本步骤推荐技能」段。**内置技能出新版时**（Ccode 升级带的种子增强，你库里的旧副本不会自动追平），页面顶部出现「内置技能有新版」提示条，逐个点「更新」即可用官方最新版覆盖库内副本——覆盖前原文件自动备份为同目录 `SKILL.md.bak-<日期>`（你自己改过的差异同样会提示，更不换由你定，更新失败会行内报错）
- **文献监控用法**：`lit-watch` 订阅清单是项目里的 `papers/watchlist.md`（一行一条 `关键词 — 来源 — 备注`，来源 `arxiv`/`openalex`/`crossref`/`web` 可多选，备注可写时间窗口与 `+bib`）。手动跑：在项目终端对 Agent 说「执行 lit-watch」。**自动跑（推荐）**：项目页项目分组里「◔ 定时任务 → ＋ 定时巡检」建一条每日/每周任务（见 §2.6），到点无头拉起 Agent 自动巡检，跑完发系统通知、新命中落在 `notes/inbox.md`（项目详情「◔ 文献雷达」卡片直接扫读与处置，见 2.7）

## 六、MCP 页（⌗）：MCP 统一清单与分发

统一管理 MCP 清单，按开关一键写进各 CLI 的用户级配置，九个 agent 共用一份（Grok Build 首版只读展示其已有配置、不支持分发）：

- **添加 MCP**：右上「+ 添加 MCP」，填名称（字母/数字/连字符，不含下划线）、类型（stdio = 本地命令 / remote = 远程 URL）；stdio 填命令 + 参数 + 可选工作目录 + 环境变量，remote 填 URL + 请求头
- **粘贴导入**：右上「⋯ → 粘贴导入」直接粘贴 MCP 文档里的标准 JSON 片段（`{"mcpServers": {...}}`），解析后逐条入库，同名自动跳过——不用对着表单逐项抄
- **收编现有配置**：右上「⋯ → 收编现有配置」扫描九个 CLI 的用户级配置，列出不在清单里的 server，点「收编」进统一清单并标记已分发到来源 agent——之前在各 CLI 里零散配过的一次性归一
- **内置预设**：右上「预设 ▾」一键预填官方 server 表单，目前收两个学术检索 server：**Consensus**（官方 hosted MCP，需 Consensus API key——先设好环境变量 `CONSENSUS_API_KEY`，请求头以 `Bearer ${CONSENSUS_API_KEY}` 引用不落明文）与 **Undermind**（官方 hosted MCP，文献语义搜索；认证走 OAuth 没有 API key——保存分发后在对应 CLI 里登录一次，如 `claude mcp login undermind`，浏览器授权即可，免费账号可用），确认或调整后保存，再按开关分发
- **密钥不落明文**：环境变量/请求头的值可填 `$VAR` 或 `${VAR}` 引用系统环境变量（如 `Authorization` 填 `Bearer ${MY_TOKEN}`），分发时自动转成各家支持的引用写法，密钥本身不会写进任何配置文件
- **分发**：点 server 行或「已分发 N」计数展开各 agent 的开关（Grok Build 位置显示「只读」标记，不可开关），打开即写入该 CLI 的用户级 MCP 配置（只改动配置里的 MCP 一个键/段，写前自动备份）；关闭即移除同名条目。编辑 server 后已开启的 agent 会自动更新为新内容
- **行内信息**：类型徽章按传输层着色（stdio 紫 / remote 蓝）；stdio 的完整启动命令做路径缩略（家目录折 `~`、长路径砍中段留首尾，悬浮看全文）；每行最右侧是**全局启用开关**——停用会把条目从各 agent 配置移除但不删清单、分发映射保留，重新启用时按原样重投，适合临时关掉某个服务
- **连通性检测**：hover 行尾点「⚡」现场检测（stdio = 实际拉起进程做 MCP `initialize` 握手；remote = POST 探活，8 秒上限）；检测过名称左侧才出现状态点（绿 = 正常并带耗时，红 = 失败），悬浮状态点看 serverInfo / HTTP 状态或失败原因（路径失效、node 缺失、超时、stderr 末尾片段），点击红点重新检测。检测不会进页面自动全量跑，避免一次拉起一堆进程。行尾 hover 还会露出「✎ 编辑 / ✕ 删除」轻量图标钮（tooltip 挂在按钮上方）
- **注意**：只写用户级配置（项目级配置各 CLI 都要逐个批准，体验差故不分发）；分发到 Cursor 会同时影响 Cursor IDE（两者共享同一配置）；kimi 不支持环境变量引用（需填字面值，保存时会明确提示）；stdio 命令是相对路径（`./…`）的 server 不能跨 agent 分发——相对路径的基准是来源 CLI 自己的运行目录，换家必找不到，分发时会直接报错提示改为绝对路径；检测到企业托管 MCP 配置时会拒绝写入并提示；Grok Build 的 MCP 配置要增删请用 `grok mcp add` 或手工编辑 `~/.grok/config.toml`
- **安全保护**：粘贴导入会先列出解析出的完整命令清单（stdio 命令会被 agent 直接执行，确认来源可信再点「确认导入」）；填了疑似明文密钥（如 `sk-` 开头）时保存/导入会要求二次确认，建议改用 `$VAR` 引用；关闭开关或删除时，如果该 agent 配置里的条目被你在外部改过（比如在 CLI 里手调过），会先提示确认而不是静默删掉手调版本

## 七、统计页（◫）：用量与费用

按消息逐条解析用量、按天聚合（增量更新）。

- **总览**：一页两块。上面一块是费用和 tokens（含输入/输出比例），一行带对话次数、场均和缓存命中（有定价才写「若无缓存约 ¥X」，即实付+缓存相对全价少付的那截，便于和费用对上）。折线用「花费 / 用量」切换，不再并排两张图。费用数字、折线和最贵会话都跟随页顶范围（今日 / 近 7 天 / 近 30 天 / 全部）。「本周 ¥… · 较上周 ▲/▼N%」仍是滚动近 7 天对前 7 天，上周没用量、或当前范围盖不住上周（今日 / 近 7 天）就不出。Ccode 自己的无头调用（摘要、提交信息等）不进花费折线和最贵榜；定时雷达跑在项目目录里，按该项目正常活动计费。
- **范围**：今日/近 7 天/近 30 天/全部，均按本机日期计算；「刷新」手动重建索引。普通 JSONL 与 Codex 压缩会话采用逐行流式解析，大于 10 MB 的长会话也会进入统计，不会因文件体积整份跳过
- **分布**：同一组滑块切换「最贵 / Agent / 项目 / 网关 / 任务」，一次只看一张表。最贵是当前范围费用前 5 个会话（点进对话回放）。Agent 进度条仍用品牌色。网关库跳过来会先落到「网关」并高亮该网关。任务按工作区归因。
- **按模型**：默认折起，点标题展开。明细表费用列固定宽度，过长省略，悬浮看全。
- **内部活动**：Ccode 在发起自身的 ◈ 无头 AI 调用前，由后端登记精确的 agent 与临时任务来源，usage 事件及项目/模型聚合都携带 `source/internal`。默认把这些已确认的内部活动归并，勾选「显示内部活动」可查看原始条目，选择会在本机记忆。不会再按 `/tmp` 路径、目录名或模型名猜测，因此用户主动在临时目录运行 agent 仍属于普通活动
- **费用口径**：费用按三层定价链估算——设置页「自定义定价」（pricing.json）> 连接页 ⋯ 菜单下载的**模型能力库**（models.dev/OpenRouter 快照，内含官方定价，数百个模型随下载更新）> 应用内置价目（2026-08-31 各官方定价页口径）；按模型名前缀匹配、供应商前缀自动剥离，高层写短前缀即覆盖低层一切细分代（如自定义「claude-sonnet」盖过内置的 sonnet 全代价目）。含未计价模型显示 `≥`，没有可用价格显示 `~`。说明集中在范围工具栏下方，不在每一列表头重复标注。**官方账号**（如 Google 登录）启动产生的用量显示「**订阅**」而非估算金额——不按量计费，token 数仍是实际统计（usage schema 已升 v6，首次打开自动重建索引）
- **$/¥ 切换**：范围旁的按钮一键换算（汇率默认 7.2，设置页可改）

## 八、设置页（⛭）

设置项按左侧子导航「外观 / 启动行为 / 快捷键 / 统计 / 集成 / 更新 / 诊断 / 数据与存储 / 关于」分区，右侧一次只显示当前分区；点击分区时始终展开，折叠记忆只影响下次进入的默认值。每个设置项的说明文字常驻显示在标签下方（macOS WKWebView 不渲染悬浮提示，不依赖悬停）；「诊断」分区行内的刷新 / 复制全部 / 导出 / 清空为低频操作，悬停该行才显现（Tab 聚焦同样显示）。

- **更新**：启动时静默检查新版本；有可用更新时该分区自动展开，并在标题显示绿点 + 「vX 可更新」标记；发现更新显示版本号与更新日志，「下载并安装」后自动重启；也可手动「重新检查」
- **诊断包**：点「导出诊断包」会在 `~/Downloads/ccode-exports/` 生成 `ccode-diagnostics-<时间>.zip`，包含 Windows 与 WebView2 版本、显卡/驱动、WebGL Renderer、语言/输入法、当前功能开关、最近 500 条应用日志，以及自本次启动后 Ccode 子进程的程序/脱敏参数/PID/父 PID/开始与结束时间；同时记录 Ccode 相关的 Git、cmd、conhost、WebView2 和系统 CTF/TextInputHost 活动。包内均为 UTF-8 JSON/TXT，可直接带回 Mac 解压离线分析，不需要安装 Ccode 或 Windows 工具。不会采集子进程环境变量，已保存密钥与常见密钥前缀会在 Rust 层脱敏；路径和普通参数仍保留，发送前可先解压检查
- **生效配置快照**：诊断包下方「生效配置快照」一键导出当前实际生效的配置到 `~/Downloads/ccode-exports/ccode-effective-config-<时间戳>.json`——包含应用版本、全部应用设置（合并缺省值后）、各 agent 能力支持面（设为全局/MCP 写入/技能分发/hooks 注意力）、hooks 开关状态，以及全部 profile 的非敏感字段（只留密钥尾号提示，绝不含密钥本体与自定义环境变量）；排查「配置到底生没生效」时不用逐个文件翻。整份 JSON 导出前经 Rust 层脱敏，导出后提示完整路径
- **依赖体检**：「生效配置快照」下方「依赖体检」行显示 Git / Node.js / 安装渠道三项状态（✓ 版本与路径，或 ✗ 缺失说明），右侧「重新检测」手动刷新；缺失且渠道可用时行内出现「一键安装」（macOS 走 Homebrew，Windows 走 winget `Git.Git` / `OpenJS.NodeJS.LTS`，装完自动复检生效）；渠道不可用时给本平台指引（macOS 无 Homebrew 时 Git 改走系统弹窗装 Xcode 命令行工具，Windows 无 winget 时指 git-scm.com / nodejs.org，Linux 给 apt/dnf/pacman 命令）。缺 Git 时收件箱会出现「依赖」类提醒，点「去处理」直达这里；改动面板遇到「找不到 git」报错时旁边也会出现「一键安装 Git」
- **单独日志**：下方仍展示最近 100 条应用日志（前端渲染错误自动上报），支持刷新、复制全部、导出 txt 与清空

- **主题**：七套深色 + 七套对应浅色色卡（沉浸黑/陶土/Ayu 琥珀/Catppuccin/极简灰蓝/Dracula/灰蓝正红，浅色排在对应深色正下方一列对齐），各有独立强调色（CTA/选中/「活跃」「可合并」pill 同步换色），点击即时全站切换；原生下拉列表、滚动条等系统控件同步跟随主题明暗；**终端配色随主题明暗自动成对**——切到浅色主题时终端的 ANSI 十六色、光标和选区一并换成浅色专用配色，不再出现白底上「白色文字看不见、黄色读不了、选中文字发黑」的情况。注意：**运行中的 Agent 会话不随切换热改配色**——Gemini 等 TUI 只在启动时探测一次终端底色并显式上色，切换后其输入框/消息行保持旧配色属预期，重启会话即与新主题一致（主题色卡下方与 ⌘K 命令面板「外观」分组下常驻这条说明）

- **长任务 OS 通知**：默认开；agent 转为待确认且窗口未聚焦时发系统通知（同一标签 30 秒去抖；「已回复」不通知），关闭后完全不请求权限、不发通知

- **汇率**：USD→CNY，统计页 ¥ 换算
- **brew 镜像开关**：安装/更新是否走 TUNA
- **AI 专用配置**：内置 AI 功能默认使用的 profile，建议选快模型（生成速度主要取决于它）；默认「自动」= 最近使用的 profile。其下七行可**按功能单独指定**（提交信息/会话摘要/PR 描述/沉淀为技能/提炼接力·评审沉淀/冲突建议/翻译），「跟随默认」即回落到专用配置；功能专属 profile 被删除时自动回落，不会静默落到别的配置

- **精确注意力标记**：默认关。「集成」区按 agent 逐个开关——开启后向该 CLI 的 hooks 配置写入三个事件钩子（用户提交/轮次结束/等待确认；写入前自动备份到应用备份目录，只合并 hooks 段、不动其他配置，已有 hooks 保留），事件实时驱动终端注意力点与系统通知；关闭即移除 hooks 条目并回退为会话尾部推断模式，可随时开关。支持 Claude Code / Codex / Gemini / Qwen / Kimi / CodeBuddy / Grok Build 七家，各家的配置文件路径显示在开关旁。两个生效条件：**Codex 首次生效需在其 /hooks 面板信任该 hook**（Codex 的安全机制，hook 命令变动后需重新信任）；**CodeBuddy 已运行的会话需重启后才生效**（hooks 配置是启动时加载的快照）。Cursor（无「等待确认」原生事件、机制未验证）与 OpenCode（无 shell hooks 形态）置灰不可开关并注明原因
- **自定义定价**：表格化编辑（每行 = 模型前缀 + 输入价 + 输出价，「+ 添加模型」增行），保存时仍写成 pricing.json 并经后端校验，下一次统计查询生效；定价链最高层——覆盖模型能力库与内置价目；缓存读/写按输入价 0.1/1.0 统一系数计价
- **数据与存储**：展开时统计一次应用数据占用（会话索引与用量 `app.db` / 配置 `profiles.json` / 技能库 / 会话快照 / 配置改写备份 / 模型目录缓存），逐行列出完整路径与占用大小，点「定位」在系统文件管理器中显示；快照 / 备份 / 缓存可以直接删，配置与索引别手动删

## 九、AI 功能说明（◈）

各处 ◈ 按钮（git 提交信息、会话摘要、PR 描述、冲突审查建议、沉淀为技能、技能文档翻译、提炼接力、评审沉淀起草）都通过 **headless 模式调用 agent**：把上下文（diff/会话/提交记录/冲突文件/选段/技能正文）发给该 CLI 的 print 模式（如 `kimi -p`、`claude -p`），纯文本生成（不依赖工具调用），不产生交互会话。profile 选择顺序：显式指定 → 功能专属配置（设置页按功能单独指定，如已选）→ 设置页「AI 专用配置」→ 最近使用的 profile；生成慢多半是因为自动落到了大模型上，在设置页指定一个快模型即可。专用 profile 被删除时会报错提示重选，不会静默落到别的配置。失败时先检查所选 profile 是否可用。

## 十、常见问题（FAQ）

**Q：macOS 安装后打开提示「已损坏，无法打开」？**
A：不是真损坏——未签名应用从网络下载会带 quarantine 隔离标记，Gatekeeper 因此拦截。终端执行 `xattr -cr /Applications/Ccode.app` 即可。每次重新下载安装都要执行一次，做了签名公证后此问题消失。

**Q：agent 不真正执行操作（不建文件等）？**
A：中转模型不支持工具调用（部分中转商的模型只会输出文字、不真正执行工具调用）。换真 Claude 系模型或明确支持工具调用的中转。

**Q：配置保存了但调用报空响应/404？**
A：Base URL 的 `/v1` 约定：OpenAI 协议（kimi/codex/qwen/opencode）**必须带** `/v1`；Anthropic 协议（claude/codebuddy）**不要带**。建完先点「测试连接」。

**Q：按钮点了没反应？**
A：macOS WKWebView 不支持原生 JS 对话框——需要输入的地方已全部改为内联输入框，确认弹窗也已全部改为应用内对话框；如仍遇到，把位置报给开发者。

**Q：终端输出黑白？**
A：已内置修复（注入 TERM/COLORTERM、剔除 NO_COLOR）。

**Q：Windows 上切了浅色主题，但 agent 的输入框还是深色？**
A：gemini / qwen 已内置修复。这两个 CLI 靠启动时查询终端底色来选浅/深配色，而 Windows 的 ConPTY 会把
这个查询吞掉，它们探不到底色就回落深色；Ccode 现在会在浅色主题下主动告知，**新开的**标签即为浅色
（已在跑的会话不受影响，配色只在启动时定，重开标签即可）。
**codex 与 Claude Code 无解**：codex 当前版本不再根据终端底色选配色（它的 `/theme` 只管代码块语法
高亮），Claude Code 用自己配置文件里的 theme——两者都不看终端底色，Ccode 这边无从干预。
Claude Code 可在其 `~/.claude/settings.json` 里自行设 theme。

**Q：安装/更新卡在下载？**
A：brew 已走 TUNA 镜像（设置页可关）；npm 慢或不可达时，可先在系统终端执行 `npm config get registry` 检查源，必要时临时使用 `npm_config_registry=https://registry.npmmirror.com`；Ccode 的 npm 单次请求超时为 30 秒、整体安装最多 15 分钟。若仍失败，请查看实时输出中的 `npm ERR!` 原因，不要只根据“超时”判断包不存在。

API 连接默认必须有 Ccode 密钥；只有明确勾选「本地端点无密钥」才允许无 key 启动，并会清理继承环境中的其他 API Key。连接创建后 Agent 不可直接改，跨 Agent 请用「复制到其他 agent」。

**Q：改了模型列表，CLI 里 /model 没变？**
A：注入配置只在新启动的会话生效，重启该终端标签。

**Q：工作区的会话在历史里归到哪？**
