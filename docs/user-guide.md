Ccode 是 AI 编码 Agent 的统一工作台：管理八个 CLI agent（Claude Code、Codex、Gemini CLI、Qwen Code、OpenCode、Kimi Code、CodeBuddy Code、Cursor CLI）的 API 配置，内嵌终端一键启动，git worktree 任务工作区，会话历史回放，用量统计，技能分发，以及多处 ◈ AI 辅助（提交信息/会话摘要/PR 描述/冲突审查建议/沉淀为技能/技能文档翻译/提炼接力/评审沉淀起草）。

开发预览使用 `npm run tauri:dev`，窗口标题为「Ccode Dev - 热更新」；React/样式修改会自动刷新。它与正式版和打包调试版名称不同，验收时以该标题区分。

侧栏按任务层级组织全部页面：**工作（工作区 / 终端 / 对话）→ 能力（配置 / 技能 / MCP / 统计）**，底部只保留「设置」，当前页以浅色填充行 + 左侧彩色指示条标出。首次启动默认进入「工作区」，它同时承担项目首页职责；点击顶部「Ccode」品牌区可折叠为纯图标栏（折叠状态会记住），「终端」图标在有 agent 运行时会显示数量徽标（任意页面可见）。常规页面顶部统一为“标题与当前状态 + 唯一主动作”，搜索和筛选位于下一行工具栏；终端、对话、技能预览继续使用适合连续工作的分栏布局。

**键盘流**：`⌘K` 呼出命令面板——可跳八个页面（也可直接 `⌘1`–`⌘8`，顺序同侧栏）、切换十四套主题（七深七浅）、隐藏/显示侧栏（同 `⌘\`，专注干活时界面只剩内容）；侧栏底部「设置」上方有常驻的「⌘K 命令面板」小入口（键位标签跟随你的自定义绑定），点击同效。面板内 ↑↓ 选择、回车执行、Esc 关闭。快捷键可在**设置页「快捷键」分区**自定义：命令面板、侧栏显隐与八个页面切换逐条录制——点击绑定按钮后按下新组合键即保存（与其他在用绑定冲突会拒绝），可「恢复默认」；页切另保留整组总开关，关闭后八个页切绑定全部不生效。长任务待确认的系统通知带「**去处理**」按钮：点击聚焦对应终端标签（横幅样式不显示按钮属系统设置行为，点通知正文同样唤回应用进收件箱）。

**模块是打通的**：配置页建的 profile 在终端页一键启动；终端里跑的会话在对话页以绿点标记（内部标签可点击跳回）；历史会话一键「在终端恢复」；工作区自动完成装依赖、起服务、评审合并；AI 按钮（◈）用你最近使用的 profile 提供辅助。首次配置完成后的典型动线：**工作区 → 终端 ⇄ 对话 → 评审**；配置和技能作为能力层按需维护。

## 一、配置页（⇄）：agent 与 API 配置管理
页面 = 可折叠分组列表。标题栏右侧是唯一实心主按钮「**＋ 新建配置**」，「⋯」收导入/导出；下一行工具行左侧是筛选胶囊（全部/已安装/未安装，选中实心填充）与「全部折叠/展开」切换，右侧是搜索框。每个 agent 一组（名称 + 等宽包名/版本号 + 右侧更新状态/安装按钮，「新版」为粉色文字钮）；分组折叠状态会记住，重开应用保持。

### 1.1 安装与更新

- 未安装的 agent 显示「**安装**」（确认框告知将执行的命令，brew 优先，自动走 TUNA 镜像）
- 已安装的显示版本号，右侧按更新检查结果分三态：「**新版**」（有更新，点击即升级，悬停显示新版本号）/「**已更新**」（已是最新或刚更新完）/「**更新**」（该渠道查不到最新版时的普通按钮，如自更新安装的 claude/kimi）；检查走 brew info / npm view，进程内缓存，更新成功后自动重查。brew 渠道已最新但上游 npm 已有更高版本时，组头显示小字提示「brew 渠道最新；上游 npm 已到 X（渠道通常滞后）」——brew 公式更新慢于 npm 属正常现象，等 brew 跟进即可，勿按 CLI 提示改用 npm 装第二份
- 更新/安装过程是**实时终端**：输出滚动、可输入（`[y/n]` 在下方 `>` 行回答）、2 分钟无输出提醒、失败带诊断建议。渠道与安装方式一致：brew 安装的走 `brew upgrade`（含 opencode，不走其交互式自更新）；npm 安装的用**与目标二进制同目录的 npm**（同机多份 node/npm 时不会装错 prefix）
- **交互式自更新在终端中打开**：kimi 这类自更新（`kimi upgrade`）是方向键选择的交互界面，行输入无法应答，点「新版/更新」会改为在内嵌终端新开标签执行该命令，用方向键选择、回车确认（按钮悬停有提示）；kimi 默认开启启动时自动更新，多数情况下无需手动点更新

### 1.2 创建配置（profile）

一个 profile = 一套 API 配置（端点+密钥+模型列表），一个 agent 可建多个。表单字段：

| 字段 | 说明 |
|---|---|
| Agent | CLI 类型 |
| 名称 | 自定义标记，如「Zeta 中转」 |
| Base URL | 中转地址；「从预设快速填充」可选官方/公开端点 |
| API Key | 存 `keys.json`（0600），界面只显示尾号 |
| 协议 | 仅 Qwen（openai/anthropic）与 Kimi 需要，位于「高级配置」 |
| 模型列表 | **可多个**，首个默认；「获取模型」从端点拉取下拉选。表单上方会提示该 agent 的模型切换页上限：Claude Code 5 个、Gemini/Qwen/Kimi 注入模式仅首个生效（多模型需「设为全局」）、Codex/OpenCode 不限；超出上限会黄色提醒 |
| 附加环境变量 | 每行 `KEY=VALUE`，注入优先级最高，位于「高级配置」 |

辅助：Base URL 行内的**测试**按钮验证端点+密钥并显示延迟和模型数；保存后「⋯ → **验证**」会打开三层结果：① Ccode 字段与当前 CLI 配置文件能否解析；② CLI doctor / 启动预检；③ 最小 API 请求（鉴权、协议、模型是否存在与耗时）。密钥只在后端参与请求，不会进入验证结果或前端日志。**导入/导出**用于 JSON 备份（不含密钥）；行内操作：编辑、⋯（验证/复制/复制到其他 agent…/设为全局/恢复备份/删除）——「复制到其他 agent…」把配置复制到同协议族的另一 agent，密钥由后端内部复制、不出站。

配置列表每行只保留**名称 / 端点主机名 / 默认模型 / 密钥状态**和「编辑、⋯」；名称下方小字显示「上次使用 X 前」（悬浮看绝对时间，从未使用不显示），模型列全量展示完整模型列表（「·」连排，仅极端超长才截断），端点细节保留在编辑页或悬浮提示中。行内「⋯」悬停该行才显现（键盘 Tab 聚焦同样显示）；agent 分组不再套卡片外框，靠分隔线与左侧缩进线分层，有更新时组头的「新版」按钮保持常驻。导入/导出在页面顶部「⋯」；有用量的 profile 在行内「⋯ → 用量与费用」打开悬浮卡（按模型近似归属，跨配置共享模型会重复计入）。

**预设清单**：Base URL 的「从预设快速填充」收录官方与公开的兼容端点，新建 profile 选预设 → 粘密钥即可，不必手查端点格式。claude-code 含 Anthropic 官方、智谱 GLM 与 DeepSeek（Anthropic 兼容端点）；codex/qwen/kimi/opencode 含 OpenRouter、DeepSeek、Moonshot、智谱 GLM、阿里云百炼等（kimi 兼容端点会自动带上 openai 协议）；codebuddy 含腾讯官方国际站/中国站与 DeepSeek、智谱（Anthropic 兼容端点）。Gemini 用 Google 官方时 Base URL 留空即可，不设预设。**Cursor 不设预设**——其端点是 Cursor 专有协议（非 OpenAI/Anthropic 兼容），第三方供应商端点接上也不通；Cursor 的模型经 `--model` 参数注入（支持 `claude-opus-4-8[context=1m,effort=high]` 这类 bracket 参数化），API 密钥走 `CURSOR_API_KEY` 注入。

### 1.3 官方账号

除 API 配置外，Claude Code / Codex / Gemini / CodeBuddy / Cursor 支持「**官方账号**」profile：直接用 CLI 自身的订阅账号登录，不需要 API 密钥。

- **建 profile**：表单顶部「账号类型」选「官方账号」——无需填 Base URL 与密钥；模型可留空（= 用 CLI 默认模型）。配置列表端点列显示「官方账号」。目前支持 claude-code / codex / gemini / codebuddy / cursor 五个 agent
- **连接**：支持官方账号的 agent 分组内固定有一行「官方账号」状态行（已连接/未连接，只读检测 CLI 的 auth 文件）。点「**连接**」会在内嵌终端开新标签执行登录命令（`claude auth login` / `codex login` / `cursor-agent login`，OAuth 会弹浏览器授权）；Gemini 没有登录子命令，标签直接拉起 gemini，在 TUI 里选 **Sign in with Google**；CodeBuddy 在 TUI 内 `/login`。登录完成后回本页点状态行的「刷新」重新检测。**Codex 注意**：`~/.codex/auth.json` 里只有 `OPENAI_API_KEY` 时显示为「API Key 配置」而非「已连接」——官方 `codex login --api-key` 与 cc-switch 等第三方中转写出的是同一形状，文件层面无法区分，如实显示不算官方账号登录
- **断开**：用 CLI 自己的 logout——`claude auth logout`（或 TUI 内 `/logout`）、`codex logout`、gemini TUI 内 `/auth signout`、codebuddy TUI 内 `/logout`、`cursor-agent logout`。Ccode 只读检测，不替你删除 auth 文件
- **启动行为**：官方账号 profile 启动时不注入端点/密钥，并清除同协议残留的 API 密钥环境变量（防止静默覆盖账号登录）；凭证可能存于系统钥匙串或加密存储（不落文件）时状态行会注明可能漏报（Cursor 凭证默认就在 macOS 钥匙串，仅设 `AGENT_CLI_CREDENTIAL_STORE=file` 时才落 `~/.cursor/auth.json`），以 CLI 自己的 status 命令为准
- **冲突警告**：状态行检测 CLI 自己读取的配置文件（`~/.gemini/.env`、`~/.claude/settings.json` 的 env 块）——其中残留的 API 密钥会覆盖官方账号登录并产生 API 计费，命中时状态行显示黄色「N 项配置冲突」，悬停查看具体变量名，需自行编辑对应文件删除

### 1.4 两种生效方式

- **注入模式（默认）**：终端页「启动」时配置只传给该进程，不改系统文件
- **全局模式**：「⋯ → 设为全局」写入 CLI 配置文件（如 `~/.claude/settings.json`），任何终端生效。同一 CLI 涉及的多个文件会作为一个完整批次写入：全部准备成功才替换，任何一步失败都会自动回滚。「恢复备份」恢复最近一个完整批次；恢复前会先备份当前状态，原恢复点不会被消耗。写入成功后会自动再跑本地解析与对应 CLI 配置检查；失败会直接展开验证结果，不必等到下次启动才发现配置损坏

### 1.5 多模型切换

profile 多个模型时，启动栏下拉选一个启动；CLI 内继续切换：

| CLI | 切换方式 |
|---|---|
| Claude Code | `/model`（前 5 个已注册进选择器） |
| Codex | `/model`（自动生成 model catalog） |
| Qwen / Kimi / OpenCode | `/model`（「设为全局」后列表完整） |
| Gemini | 只能 `/model set <模型id>` 手输（CLI 限制） |

## 二、工作区页（⛁）：任务级 git worktree 隔离

页面采用双栏工作台：左侧是项目导航（有待处理时显示计数），右侧只展示当前项目的研究流程、资源和任务工作区，避免项目增多后形成超长纵向页面。导航行的「待处理」与顶部收件箱同一口径：除本项目工作区的冲突/可合并外，终端标签的待确认与外部运行会话的待确认也按目录归属摊到对应项目上（终端落在某工作区工作树内的算该项目）——收件箱告诉你总数，导航行告诉你分散在哪。页头右上是全页唯一实心主操作「+ 添加项目」（左侧导航栏头部的「+」图标也有同一入口），注册新目录；其旁的「新建工作区」为次级描边按钮，保留不依赖研究流程的手动入口。切换左侧项目只改变当前详情，不会停止该项目内正在运行的 Agent。

**待你处理（首页收件箱）**：macOS 上收进**窗口标题栏**——标题文字右侧按类别出现一排胶囊（「● 冲突 2」「● 待确认 1」「● 人工请求 1」……），点某个胶囊向下展开该类明细（点遮罩 / Esc 收起）；Windows / Linux 上则是工作区页顶部的单行条，同样按类别出胶囊、点击展开。明细每条一个小圆点 + 一句话 + 操作按钮：冲突/可合并点按直接进对应工作区的全宽评审，终端条目点按跳到终端页并激活那个标签。全部处理完自动消失。项目导航行另有按项目摊开的「待处理」计数，告诉你事在哪个项目；侧栏导航不挂任何徽标数字（保持安静，计数只看标题栏胶囊/页内条与项目导航行）。「已回复」（agent 回合结束、等你输入）不算待办——它每次回复都发生，因此不进收件箱、不打点、不发通知。除冲突/待确认/可合并外，收件箱还覆盖四类「只有你能解锁」的事：**待核验**（任务声明的预期产物已全部产出、但还没有任何提交——PDF 等产物被 git 忽略，git 状态里看不见，点「去核验」直接展开该任务的产物清单）、**待发送**（后台提炼的接力简报已生成）、**配置失效**（你手动验证或「设为全局」复检失败的配置，修好前对应 agent 起不来）、**人工请求**（运行中的 agent 把需要你协助的事写进 `.ccode/help-wanted.md`——比如补检索词、某篇文献下不到；每条都附「若未回复则按 ×× 继续」的兜底方案，agent 不会停工等你，你空了点「去查看」跳到对应项目处理即可；条目可点 ✕ 暂时忽略，请求内容变了会重新出现；窗口不在前台时出现新的人工请求会发一条系统通知，沿用「长任务 OS 通知」开关）；冲突条目在基准分支已前进时会升级为「需重新同步」，点按自动以最新基准重备冲突两侧。

解决多个 agent 在同一目录并行冲突。工作区 = 独立 worktree + 分支 + 端口段。注册项目后，工作区按项目分组展示，组顶部带研究流程概览（大圆步进器）与资源面板。项目组头部在名称旁直接聚合同一项目内的任务状态（「●N 进行中 ●N 待评审 ●N 阻塞」小圆点计数，全为零时不显示），课题主题收进项目名悬浮提示；低频操作（步骤名行的「⋯」、任务行的「⌨ 终端」「产物」「⋯」）默认隐藏、指针悬停才出现（键盘 Tab 聚焦同样显示），每行只保留一个实心主动作。

### 2.1 项目注册与研究流程

把一个目录注册为项目后，可以在项目维度定义研究步骤与资源清单（存于项目目录的 `.ccode/project.toml`，跟着 git 走）。

- **添加项目**：页面顶部主操作「**+ 添加项目**」→ 系统对话框选目录 → 弹窗内命名 → 注册。注册项目即使没有工作区也显示在工作区页（按最近打开排序）；未注册的目录仍按工作区 repo 自动归组，组头「注册项目」打开同一注册弹窗（已预选该目录）。项目组「⋯」可重命名或移除注册（只删注册记录，不动磁盘目录与工作区）；左侧项目导航行右键菜单提供重命名/复制路径/移除注册/**清除 Ccode 痕迹（保留文件夹）**/**删除项目目录**（红色项，后两个未注册组也可用）——三档命运：**移除注册** = 只摘登记，磁盘全留；**清除 Ccode 痕迹** = 回到没建项目时的样子：文件夹与你的全部文件保留，`.ccode/`（档案卡、任务卡、简报）移入系统回收站（可找回），工作区 worktree 与 `ccode/<名>` 分支、注册记录彻底删除（若 `.ccode` 曾被 git 跟踪，改动面板会显示对应删除，需自行提交——应用不会替你提交仓库）；**删除项目目录…** = 连文件夹一起删：确认框列出目录完整路径与工作区数量，确认后**主目录移入系统回收站**（误删可从废纸篓整个找回）、注册记录移除；但工作区的 worktree 与分支是 git 元数据，只能**彻底删除不可恢复**——这两个操作前请先关闭该项目内正在运行的终端标签；非 Ccode 项目目录与系统/关键目录会被后端拒绝
- **示例课题（演示）**：还没有任何项目时，空态「添加项目」旁有次级按钮「**✦ 创建示例课题（演示）**」——一键在「文档/Ccode 示例课题」生成带演示数据的完整项目：英文综述五步研究流程档案卡、一页示例文献 PDF（程序生成的演示文件，非真实论文）、两条真实示例引文 `references.bib`、README，并自动 git 初始化 + 注册。幂等：重复点不重复建；目录已存在但未注册时只注册、不动磁盘内容。可随意试验开步/编辑研究流程/建工作区，整个目录随时可删（右键项目导航行「删除项目目录…」可连目录带工作区彻底删除；只想从列表移除选「移除注册」）
- **课题主题**：「添加项目」与选择模板时都可选填课题主题（存 `project.toml` 顶层 `topic`），显示在项目组头名称旁；组「⋯」→「编辑课题主题」可随时改，一键开步时写进 `TASK.md` 的「课题主题」段供 Agent 围绕执行
- **git 引导**：新注册的目录若还不是 git 仓库，组顶部出现一次性引导横幅，点「初始化 git」一键 init 并生成 `.gitignore`（默认忽略产物目录、`.DS_Store` 与 `*.pdf`——文献 PDF 等大文件登记为资源引用、不进 git；已有 `.gitignore` 不覆盖；已是仓库则提示无需初始化）
- **研究流程概览（大圆步进器）**：组顶部按序展示步骤，一条小方块节律的 hairline 虚线横贯整条流程，每个步骤一个大圆坐在线上（等分列，窗口不足时整条横向滚动不换行）。大圆为纯色实心圆（内部无字符），按状态填色：**已完成/已合并** = 绿；**进行中/检查中** = 主色（状态刚变化时短暂呼吸脉冲几秒，之后静止——不会一直闪）；**待评审** = 主色浅底；**阻塞** = 黄；**未开始** = 实心灰。状态从绑定工作区自动派生（有冲突 = 阻塞、合并完成无新提交 = 已完成、已提交待合并 = 待评审、有未提交改动 = 进行中），不需要手动维护；圆上不写状态文字，悬浮大圆可查看步骤名、白话状态、工作区目录、最近使用的 agent/profile（取自该工作区上次启动配置）与点击动作提示（应用内悬浮卡，移动/点击即消失）；**上游步骤晚于本步最后推进时间（已合并取合并时间、未合并取开步时间）又发生合并时，悬浮卡多一行警告色小字「上游「X」有更新，产物可能过期」**——启发式提醒，只提示不阻断，本步再次合并后自动恢复；**大圆右上角出现小圆点 = 该工作区里的终端需要你处理**（黄点 = 待确认，悬浮卡里有对应文字；「已回复」不打点）。**点大圆 = 聚焦这一步**：下方卡片区只看该步骤——顶部是**步骤内协同流程线**（这一步里人和 agent 的动作按先后排成的节点链：开工前聊聊（种子就列在节点上，点击即聊；种子没覆盖到的话题点「＋ 自定义话题」起名开聊，同一口径——自动建卡归档、结论直接写进任务书草稿）→ 开始前归你做的事 → agent 执行 → agent 干活期间可随时做的事 → 收尾归你做的事 → 评审合并；当前轮到谁一目了然——第一个未完成的节点高亮标「← 当前」并就地展开操作：提交产物/开始/去终端看看/去评审（阻塞时为「去处理冲突」，直达冲突解决；工作区已归档时 agent 节点主入口换成「恢复工作区」）；**轮到你做的人工事项条目右侧有「等你做」小标签**（醒目色，一眼可辨）；完成的打勾划线），下方是该步骤的卡片；流程线上方的**聚焦头部**显示步骤名 + 白话状态（待开始且还没有定稿简报时提示「建议先点下方种子聊聊」，已有简报则「想法已就位，可以开始」），右侧「**总览全部步骤**」还原——总览态下所有步骤桶展开，没卡也没种子的桶显示「该步骤还没开始」；没点过任何圆时默认聚焦当前步骤（第一个未完成）。**聚焦同时作用于下方工作区列表**：标题变为「{步骤名} · 工作区（N）」，点右侧「全部」回到项目全量（再点「按步骤」切回）；该步骤还没有工作区时会提示点流程线里的「开始」一键开步。推进动作不在圆上：开步/跳终端/去评审/恢复工作区都在流程线节点或卡片行/任务行。步骤名居中显示在大圆正上方（截断、悬浮看全称），「⋯」悬停步骤名才现：编辑步骤（打开研究流程编辑器并定位到该步骤）、人工事项（等同点圆聚焦；清单里完成判定全自动——交付文件放到落点目录自动勾上显示「✓ 已见到文件」，纯脑力事项可手动勾选显示「✓ 已确认」；「**提交产物**」按钮选文件、或直接把文件拖到条目上，复制进落点目录并登记提货单（落在主仓的交付导入成功后会追问一句「要登记为项目资源吗」，点「登记」一键进资源清单，点「不了」不纠缠）；落点在 `papers/` 的事项（如「补充你已知的关键文献」）旁边还有「**导入检索结果**」入口——从 Undermind / Consensus / Elicit 导出 RIS/BibTeX/CSV 一键复制进 `papers/imports/`，开工时 agent 自动解析、去重并合并进筛选清单）、产物核验（就地展开预期产物清单；已合并读主文件夹，其余读工作区工作树）、◫ 定位目录、复制工作区名、删除步骤。不知道现在该干嘛时看聚焦头部 + 流程线：状态短语告诉你卡在哪，「等你做」标签告诉你哪件事归你，主按钮就在当前节点上；应用模板成功的瞬间还有一条一次性引导带（可关）把你引到第 1 步的种子。有配置校验问题时流程条右上角显示「⚠ N 条提示」徽标，点击展开小浮层逐条查看全文。评审、合并、解决冲突等任务动作统一在下方工作区任务行执行（见 2.4），产物核验在任务行与步骤 ⋯ 菜单两处同一面板。
- **空研究流程**：新项目还没有步骤时显示「**选择研究流程模板**」，打开模板库（名称/描述/步骤数/步骤名预览）选一个写入 `.ccode/project.toml`，也可「编辑研究流程」打开同一编辑器从头自建；模板写入后仍可逐步编辑
- **模板库**：内置五套——「英文综述」（检索筛选 → 精读笔记 → 大纲 → 初稿 → 润色定稿）、「科研论文」（选题调研 → 实验设计 → 实验执行 → 结果分析 → IMRaD 初稿 → 投稿准备）、「数据处理」（登记检查 → 清洗整理 → 探索性分析 → 分析报告）、「毕业论文」（开题与综述 → 研究方法 → 实验与结果 → 全文初稿 → 格式与定稿）、「投稿与返修」（期刊格式适配 → cover letter 与投稿清单 → 审稿意见逐条回复与修订稿；审稿意见需先粘贴保存为 `reviews/round-1.md`）。项目组「⋯」→「更换模板」打开同一模板库替换现有步骤（绑定的工作区与资源不受影响）；同一菜单的「另存为模板」把当前研究流程存为自定义模板（填名称+描述，同名覆盖会先确认），用户模板在选择器中带「删除」。科研论文/毕业论文模板的初稿与定稿步骤自带 `quarto render` 渲染脚本，开步时自动写入项目 `.ccode/settings.toml`——该工作区行的「运行脚本」菜单随即出现 `render-draft` / `render-final` 一键渲染 PDF，以及 `export-docx` 一键把同一份 Markdown 导出为 docx（与 PDF 渲染并存互不冲突；未安装 quarto/pandoc 时脚本报错会直接显示在终端，安装引导见 `quarto-render` 技能）
- **编辑研究流程**：项目组「⋯」→「**编辑研究流程**」是已有研究流程的唯一入口（空研究流程面板的同名按钮打开同一编辑器），打开全宽编辑器，每个步骤一张卡片：步骤名与工作区名、大段简报（一键开步时落成 `TASK.md`）、预期产物（逗号分隔）、run 脚本（名称+命令，可增删）、**人工事项**（这步里归你做的事：标题 + 交付落点 + 时机（开始前/进行中/收尾）+ 引导说明，可增删——比如「下载付费墙文献全文」落点 `papers/*.pdf`）、**资源绑定**（勾选项目资源：默认全不勾 = 本步骤使用全部资源；勾选后 `TASK.md` 的「项目资源」段只列选中项，让任务与你准备的资料一一对应；绑定了已移除资源的条目显示「失效」，取消勾选即清理）。卡片可 ↑↓ 排序、删除，底部「+ 添加步骤」；「保存」整体写回 `project.toml`，「取消」放弃，有未保存改动关闭会先确认。配置校验提示（绑定不存在、简报引用与产物不符等）显示在编辑器顶部和概览行的「⚠ N 条提示」徽标（点击逐条查看）
- **任务卡**：研究流程步进器下方的「任务卡」区——卡片是**对话的归档夹**（讨论的记录容器；v3.72 起不再承担简报供应链——讨论结论直接写进任务书草稿）。卡片按所挂步骤分桶展示（挂在已删除/改名步骤上的卡与未挂步骤的卡收进「未挂步骤」桶，该桶为空时整桶不显示）；总览态下没卡也没种子的步骤桶显示一行占位「该步骤还没开始」（聚焦态无卡时不显示桶头——讨论入口已并入流程线「任务书」节点）；桶头只有「**＋ 添加想法**」（内联命名；总览态悬停才现）——挂步骤的话题与种子同一口径：建卡归档 + 直接开聊写任务书草稿（未挂步骤的卡无步骤语境，只建卡归档）——「**预览 TASK.md**」全页唯一入口在流程线的 agent 节点（只读弹出该步骤当前拼装结果：模板简报 + 默认来源简报 + 提货单，无卡无工作区也可预览）。**每个步骤桶里有「开工前聊聊：」讨论种子**——模板预置的「开工前建议想清楚的问题」（如「综述角度怎么收？」「纳入标准定多严？」，只有你能拍板、拍错返工贵的决策点），点一个就开聊（自动以问题建卡归档），**讨论出的结论 Agent 直接写进这一步的任务书草稿**（`.ccode/drafts/<步骤>.md`），开工时草稿就是 TASK.md 的内容；种子聊不聊随你，不聊直接开工没有任何阻拦。卡片行 = 名称 + meta 小字（「简报 N · 最新 x 分钟前」）+ 主按钮。新卡片的主按钮是「**聊想法**」：在项目根开终端（不建工作区，想法期不动手），预填「我想跟你探讨：<卡片名>」帮你开口；卡片区标题行有「**想法期只读保护**」开关（默认开，存设置）——开 = 聊想法以只读/计划模式启动 Agent（Claude Code / Codex / Gemini / Kimi / CodeBuddy / Cursor 支持，Qwen / OpenCode 只有指令里的口头约束）且预填指令明确「只讨论不动文件」（注意：种子与「跟 Agent 聊任务书」是另一口径——需要 Agent 写草稿，只读保护不适用）；卡片「⋯」里的「聊想法（允许改文件）」是不动开关的单次豁免。**从卡片发起的聊天（聊想法/开始/继续）产生的新会话会自动归入该卡片**，无需事后整理（个别落空场景——如启动栏临时换了 Agent——仍可在对话页 ⋯「移到卡片…」手动归卡）。已有简报的卡片主按钮为**开始**（挂步骤的卡可用，与点步骤大圆同一入口：先打开**开始确认弹层**再建工作区）与**继续**（有定稿简报时可用：开终端新会话，预填「阅读 <简报> 并继续任务」首条指令，目录为卡片绑定工作区的工作树、无绑定则项目根；Kimi/OpenCode 无注入参数时指令文本留在启动栏手动发送）。主仓有未提交改动时卡片区标题行右侧显示警告色小字「主仓 N 个未提交改动」（点击直达终端页改动面板看主仓）——「聊想法」在主仓进行、期间 Agent 的改动留在主仓是合法的，只提醒不阻断。点卡片名就地展开：**待拍板**列表（最新定稿简报里「## 待拍板」小节的问题，点一条就带它去「聊想法」）+ 简报列表（相对时间 + 路径，点击跳到终端页预览）；这一步里归你做的事不在卡片上——在流程线里（步骤级，一个步骤只出现一次）。聊想法（已有简报的卡）/重命名/删除收在行悬停才现的「⋯」（删除只移出归置、不删对话与简报文件）
- **步骤「开始」（一键开步）**：点未开始步骤的大圆（或卡片行的「开始」）先打开**开始确认弹层**，「确认开始」才执行：自动确保 git 仓库 → **自动把 `.ccode`（档案卡）与 `.gitignore` 提交进主仓库**（只这两个 Ccode 自有路径，用户其他文件绝不纳入，包括你已自行暂存的文件；无改动则跳过，提交失败只提示不阻断开步——避免工作区合并时被「主文件夹里还有没保存的改动」拦截）→ 建该步骤的绑定工作区 → 把步骤简报落成工作区的 `TASK.md` → 跳到终端预填启动。确认弹层里：步骤声明了**人工事项**时先看到「这一步需要你做的事」清单（可直接勾选或提交产物；「开始前」档的事没做完会有警告色提醒——做完再开始更顺，但现在开始也可以，只提醒不拦你）；能预览并**编辑 TASK.md 全文**——**这一步已有任务书草稿（`.ccode/drafts/`）时，编辑区直接就是草稿内容**（草稿是聊出来的合同，所见即所得；「恢复默认拼装」可回到模板拼装）；没有草稿则默认由模板简报 + 勾选简报 + 提货单拼装，可手改；勾选简报非空时可点「**◈ 融合为连贯 TASK.md**」让 AI 把模板与简报融合成一份连贯文档填入再改——模板交付要求为主干、卡片思想融入对应段落、已否决方向保留为约束、提货单段原样保留），「确认开始」落盘的就是编辑区最终内容（人从看预览升级为定稿 TASK.md）；本步骤与未挂步骤下含简报的卡片逐个列出可勾选（默认勾选点开始的那张卡；多选 = 多份简报按卡片名分小节进「任务简报（定稿）」段）；勾选 ≥2 张时出现「**◈ 融合所选简报**」——AI 把多份简报融合成一份初稿（保留各来源关键决策/思路/已否决方向，冲突显式列出），弹层内改完「定稿并采用」（落盘钉到目标卡，可换卡或新建），TASK.md 改用这份融合简报；主仓有未提交改动时弹层顶部有警告色提醒（不阻断）；打开弹层时还会只读扫描一次项目目录，**有未登记的 PDF/CSV/parquet/bib 等文件时简报区下方出现「发现 N 个未登记文件」小节**（默认不勾选，勾了才「登记选中」写回资源清单，不登记也能开工）。步骤「⋯」（悬停步骤名才现）有「◫ 定位目录」（跳到终端页并把文件树根切到该工作区目录，工作区已归档/未创建时禁用）、复制工作区名、删除步骤（不影响已建工作区）
- **资源面板**：组内「资源（N）」折叠区登记 PDF / CSV / parquet / bib 等资料（**只登记路径不复制文件**）；「**发现资源**」自动扫描项目目录列出候选，勾选后一键登记（已登记的标记 ✓）。旁边的「**导入检索结果**」是文献人肉中转入口：从 Undermind / Consensus / Elicit 等闭源检索站导出 RIS / BibTeX / CSV（可多选），一键复制进主仓 `papers/imports/`——建议文件名带「来源-日期」（如 `consensus-2026-08-13.ris`），开工时 agent 会自动解析、去重并合并进筛选清单（lit-search 技能协议）。PDF 资源行有「**查看**」，跳到终端页内嵌预览（可选中文字「◈ 问 AI」，即使文件不在任何文件树根内也能打开）。资源行「⋯」可复制绝对路径（粘贴给 agent 作输入）、移除登记；repo 内登记数据资源后会一次性提示建议加入 `.gitignore`
- **历史**：组「⋯」→「**历史**」打开项目的白话保存时间线（全宽只读视图）——「保存到历史」就是把这一步的成果存进项目时间线。按天分组（今天/昨天/日期），每条一行：✓ 验收合并（工作区任务合回主文件夹，优先显示步骤名）、⚙ 自动保存（Ccode 自动提交的档案卡等）、◔ 保存（你的手动提交，附「N 个文件 +x −y」摘要）；提交 hash 以小字 mono 保留在右侧供技术核对。时间线只展示主线记录：工作区里的过程提交不单独列出，它们的成果通过「✓ 验收合并」体现，保持简洁

### 2.2 创建工作区

「新建工作区」→ 选仓库（只列真实 git 仓库，可手输）→ 填任务名 → 自动：原子预留端口段并写入「创建中」记录 → 拉 `ccode/<任务名>` 分支（基于**本地**主分支，含未推送的提交，工作区 = 你本地项目的现状）→ 建 worktree 到 `~/ccode/workspaces/<仓库>/<任务名>/` → 复制 `.env` 类文件 → 跑 setup 脚本 → 激活工作区。worktree、复制文件或数据库激活任一步失败，应用会补偿删除 worktree/分支/创建中记录并释放端口；复制失败会明确指出具体文件，不会再静默忽略。setup 失败仍保留已创建工作区并标记失败，方便进入终端修复。

成功后「打开终端」自动开标签（目录、端口环境变量已预置）。

### 2.3 项目自动化（.ccode/settings.toml）

```toml
files_to_copy = [".env", ".env.local"]
run_mode = "concurrent"            # nonconcurrent 时脚本互斥
[scripts]
setup = "npm install"               # 创建时执行
archive = "docker compose down"     # 归档前执行（失败阻止归档）
[scripts.run]
web = { command = "npm run dev", default = true }
test = { command = "npm run test" }
```

配了之后行内出现 **▶**（默认脚本）/ **▾**（全部脚本），点击开 shell 标签自动执行。`nonconcurrent` 模式下已有脚本运行时，▾ 菜单里其余脚本显示为禁用项并注明原因，不会静默消失。

### 2.4 行内信息与操作

列表是任务索引：每行主显示只有**任务名、状态**（可点开看分支、改动和阻塞原因）和唯一的实心主动作「**评审**」；「⌨ 终端」「**产物**」与「⋯」默认隐藏、指针悬停该行才出现（键盘 Tab 聚焦同样显示）。「产物」在该行**下方就地展开**产物核验清单（再点收起，展开时按钮保持可见；已合并行同样保留此入口）——活跃任务列绑定工作区工作树下的预期产物文件，已合并任务列主文件夹下的同名产物，目录条目列一层文件，未产出显示「尚未产出」，点击文件跳到终端页预览；清单只在展开时读取一次，可点「⟳ 刷新」手动更新，不自动轮询。任务名下方的副行以 10px 灰字显示分支名与**相对时间**（如「5 分钟前」，悬浮看绝对时间与完整目录）；领先/落后（↑N ↓M）收在状态详情里，悬浮给出白话解释（「比主分支多出 N 个保存点；主分支新增 M 个保存点」）；上游步骤晚于本步最后推进时间合并过时，状态详情同样有一行警告色「上游「X」有更新，产物可能过期」（与步进器悬浮卡同口径，只提醒不阻断）。活跃的 merge 冲突是唯一例外：实心主动作直接变为警告色「**解决冲突**」，但仍进入与普通评审相同的终端全宽审阅。已经合并且没有新提交的任务只显示左侧「已合并」状态，右侧不再重复显示「评审」；产生新提交后评审入口自动恢复。会话、运行脚本、复制路径、修复、恢复和删除等低频项位于「⋯」。

PR 与归档也从「⋯」定位到评审页内再确认，避免列表页和评审页各有一套完成流程。**归档不会丢未提交内容**：存在未提交改动时评审页会要求「提交并归档」；正在解冲突或仍有 agent/run 脚本运行时会拒绝归档。普通归档不强制移除工作树；只有明确的「删除」会使用强制删除语义。

如果用户在外部终端移动/删除仓库、worktree 或分支，或者留下未完成 merge，工作区行会显示**状态漂移**并暂停普通危险操作。按实际情况可选择「重新挂载」（重建/修复 worktree 关联）、「重新定位仓库」、「标记归档」或「清理记录」；后两项只改 Ccode 元数据，不删除磁盘目录或分支。已有 merge 现场继续进入统一的全屏冲突审阅。状态诊断本身失败时，状态 pill 上会多一个警告色「⚠」，点开状态详情里的「**诊断失败 · 重新检查**」重试，期间按健康状态降级展示、不整体隐藏操作。

### 2.5 评审与合并

- **评审（无冲突）**：行上点「评审」进入终端页的全宽任务审阅；终端标签和进程仍在后台保持运行。中间按文件连续展示左右对照 diff，右侧改动树可快速定位文件；顶部第二工具行可填写或用 ◈ 生成提交信息。写作类项目在分支信息行下方还有一条「**可信度**」行：**引用 N/M 可解析**（扫描工作树所有 .md 的 `[@key]` 引用键、对照 `references.bib`——根目录或 `manuscript/` 下；全部可解析为正常色，有缺失变警告色、点击展开缺失键清单）与**产物 X/Y 已产出**摘要（复用产物核验的同一数据机制）；没有 references.bib、全文无引用或未登记预期产物时该行自动不显示，不给非写作类项目添噪声。步骤声明了收尾类人工事项且尚未完成时，同行还有警告色「**收尾事项 N 件待做**」（悬浮可见具体事项）——只提醒不阻断合并。进入评审时读取一次，不轮询。上游步骤晚于本步最后推进时间合并过时，顶部另有一行警告色提醒「上游「X」有更新，产物可能过期」（与步进器悬浮卡同口径；本步合并后消失）。默认主按钮「**提交并合并**」一次完成提交和本地合并，工作区继续保留；下拉仍可选「**仅提交**」或「**合并并归档**」。**合并成功（保留工作区）后，成功横幅会直接给出「▶ 开始下一步：步骤名」**——如果当前任务属于某个项目研究流程且后面还有未开步的步骤，点它就按同一套开步链路（不经确认弹层——连续流，简报已沉淀到下一步卡）建好下一步工作区、写好 TASK.md 并跳到终端预填简报，确认配置点「启动」即可，无需回到工作区页；旁边的次级入口「**沉淀到下一步**」把评审结论追加进下一步步骤的**任务书草稿**（`.ccode/drafts/<步骤>.md`，不存在则新建；下一步开工弹层会直接读到它）；编辑区上方有「**◈ AI 起草**」——按本步提交清单、diff 统计与 TASK.md 生成初稿填入编辑框（复用设置页「提炼接力」的 AI 配置，失败行内报错可重试），AI 初稿改完定稿后才会落盘（与提炼接力定稿页同一口径）；没有下一步或项目未注册研究流程时只显示合并成功。如果改动已提交，主按钮直接变为「合并」。提交后会重新做健康检查，不会因为进入快捷流程而绕过冲突、主仓脏或主仓分支错误等拦截。被「主文件夹里还有没保存的改动」拦截时不用离开评审：展开问题列表，点该行旁的「**提交主文件夹的改动…**」在评审内直接列出主仓文件并勾选提交（默认不勾选、提交信息留空走本地默认信息、不调 AI），提交成功自动重新健康检查。
- **白话术语对照**：**提交** = 把改动保存到项目历史（文件本身不会丢）；**合并** = 把任务成果放回主文件夹（主仓库）；**保存点** = 一次提交产生的历史记录，「多出 N 个保存点」即 git 术语的领先 N；**冲突** = 两边改了同一个地方，需要你逐个文件选一边。技术信息保留在二级位置（悬浮提示/小字 mono），编程用户不受影响。
- **PR 与归档**：从工作区「⋯」选择「在评审中创建 PR / 归档」会直接打开同一评审覆盖层中的对应确认框。创建 PR 仍需在框内填写/确认标题；归档仍会重新检查脏改动、merge 与运行中任务，绝不因入口收口而绕过安全检查。
- **审阅布局**：顶部固定显示任务、分支方向、文件数和总增删量，右上角固定主动作；有未提交改动时，提交信息与 ◈ 生成入口位于第二工具行。主区连续显示双栏 diff，文件标题吸顶，较长的未修改代码默认折叠；右侧仅保留文件搜索、目录树和当前进度，选中项会随主区滚动同步。这样搜索、定位、阅读和完成动作始终在稳定位置，不需要在右栏底部寻找按钮。图片文件（png/jpg/gif/webp/svg/bmp）不再只提示「二进制」，而是直接双栏看图：左基准版、右当前版（透明图带棋盘格底；新增/删除时对应一侧标注为空），单图超过 20 MB 才回落提示。
- **评审（有冲突）**：行上点「**解决冲突**」直接进入与普通评审相同的终端全宽覆盖层，终端标签和进程仍在后台运行。工作区干净时应用会自动在隔离工作区同步**当前最新**基准分支，不再先展示容易被误认为当前 main 的普通累计 diff；有未提交改动时先在顶部填写信息并「先提交改动」，提交后自动继续。准备完成后，中间区按文件连续展示完整双栏对照——左侧任务分支、右侧 main/基准分支，右侧冲突清单可快速定位。每个文件标题下方用紧凑的「选用」控件选择任务版或基准版，并显示已选结果；顶部也支持「全部任务版 / 全部 main 版」，「**◈ AI 建议 → 按建议选择**」为主按钮级（cta 高亮）并附一行小字说明「不确定选哪边时可让 AI 按上下文建议；仍可逐文件手动改选」。如果处理期间 main 又被其他工作区推进，旧对照会立即停止展示和选边，右上角提示「重新同步最新 main」；确认后应用放弃旧冲突现场并重新生成两侧。全部选完默认点「**完成解决并合并**」，应用会提交解决结果、重新检查健康度并合回本地主分支，工作区继续保留且不会推送；下拉可选「**仅保存解决结果**」稍后再合并。选边按整个文件生效；需要逐行混合两侧时，转到预览编辑器手动修改。若解决提交成功但最终合并被主仓脏、分支错误等条件拦截，会明确显示“解决结果已提交，但合并未完成”，处理拦截原因后点普通「合并」即可，不要重复解决冲突
- **改动面板任务视图**：worktree 里自动切换为 vs `merge-base(主分支, 任务分支)` 的累计 diff，头部显示「相对主分支 xxx」（悬浮保留 merge-base 说明），「审阅」可随时展开上述全宽视图；提交区按钮为「**保存到历史 / 保存并推送**」（提交信息留空时「快速保存到历史 / 快速保存并推送」），悬浮标注对应的 git commit / push
- **合并**：「合并」按钮高亮（=可合并）时可用，是拆分按钮——主按钮「**合并**」只合回主分支、**工作区保留**（终端继续用，之后可随时归档）；「**▾**」下拉可选「**合并并归档**」（合并后移除 worktree、自动归档；还留在工作树里的终端标签会自动 cd 回主仓库）。保留的工作区合并完成后，按钮变为禁用的「**已合并**」；继续产生新提交后自动恢复为「合并」。均只合到本地、不自动推送远程（主仓库 git 面板头部 ↑N 即领先远程的提交数）。前置：分支已提交、与基准无冲突、主仓库在主分支且干净，缺一按钮即灰，悬停看原因；合并被拒时报错会列出主仓库的脏文件。若最终 merge 仍失败，应用会自动 `git merge --abort`，主仓库不会停在冲突状态。若代码已合并但归档脚本失败，会明确显示「已合并、归档失败」，此时只需点「归档」重试
- **创建 PR**：弹窗填标题，正文留空自动摘要、或点「**◈ AI 起草**」生成结构化描述（变更点/动机/测试情况，可编辑）→ 推送分支 + `gh` 建 PR（需已登录 gh）。如果分支已推送但 `gh pr create` 失败，弹窗会显示「重试创建 PR」，不会重复推送

### 2.6 定时任务（◔）：每日/每周自动巡检

每个已注册项目的分组里（资源面板下方）有「**◔ 定时任务**」区块：点「**＋ 定时巡检**」建一条定时任务——名称（默认「文献雷达」）、周期（每天 / 每周几）、时间、profile（默认「自动」，跟随设置页 AI 专用配置或最近使用）；技能固定为 `lit-watch` 文献监控。到点后应用在后台无头拉起对应 Agent 到项目目录执行一次巡检（写 `notes/inbox.md`、`papers/watch-seen.md` 等，与手动「执行 lit-watch」完全同路径），单次最长 10 分钟。列表行可启停、「▶ 立即跑」、「▸ 历史」看最近运行（状态 + 简报）、「⋯」删除；跑完弹系统通知（复用设置页「长任务 OS 通知」开关），通知正文即简报首行。**应用没开就不会跑**：下次打开时自动补跑一次当天/本周漏掉的（多次漏跑只补一次）。改关键词/来源永远改 `papers/watchlist.md`，任务只管「什么时候跑」。

### 2.7 端口监控

页面尾部「**端口**」折叠区（默认收起，展开才读取，配合「刷新」手动更新，不自动轮询）列出本机全部监听中的 TCP 端口：端口号、进程名、归属和工作目录。归属按进程工作目录判定：落在某工作区工作树内显示「**工作区 · 任务名**」（绿点），落在注册项目内显示「**项目 · 项目名**」（绿点）；cwd 不在任何已知目录但端口号落在某活跃工作区的分配段（如 4000–4009）内时显示「**端口段 … · 任务名**」（琥珀点）；其余显示「系统/其他」。列表按归属分两段展示——「**本应用**」（工作区/项目/端口段归属）与「**系统/其他**」。典型用途：工作区里跑了 jupyter / quarto preview / 本地服务后，查谁占了哪个端口。「**终止**」向进程发送退出信号（SIGTERM，进程不退出时可稍候刷新再试）：「本应用」段点击即直接终止、不弹确认，「系统/其他」段终止前需二次确认；终止前都会重新确认该进程仍在监听，防止进程号被复用后误杀无关进程。

## 三、终端页（⌨）：并行工作主界面

三段布局：**左侧上下文（项目/工作区/文件树）｜ 中间 Agent 终端｜ 右侧成果工作台（对话/文件/改动）**。右侧成果工作台默认可见，顶部一行即是三个稳定模式页签：「◔ 对话」「▤ 文件」「⌘ 改动」（带计数徽标：对话 = 实时视图消息数、改动 = +N 增删行数；面板整体为浮起层底色），行尾按页签透出对应上下文——对话页签显示当前会话状态小字与「完整回放」入口，文件/改动页签的上下文由各自内容头部承担——并固定专注/收起按钮，不再单设面板标题行；文件树单击文件仍直接切到「文件」，改动页继续承载 Git 状态和提交，工作区任务仍从改动页进入全宽评审。右侧左边缘可拖动调整宽度（分隔条平时极细透明，悬停才显色），普通宽度会在本机记忆；顶部「⇱ 专注内容」让右栏铺满（暂时隐藏工作树，中带不加遮罩、保持挂载），点「⇲」或 Esc 还原，也可双击模式页签切换。顶部标签栏有唯一的「◫ 工作台」入口，终端启动栏不再重复放「对话」按钮；标签栏右侧在当前项目存在可合并工作区时显示「● 可合并」状态 pill（纯状态提示，悬浮列出工作区名，没有则不显示）。任务审阅覆盖层仍保持独立。标签栏右侧「⤢ 专注终端」进入专注模式：**只剩终端**——左右栏与标签内状态条隐藏，顶部标签条保留在原位（切换/关闭/新建标签照常），标签动作（停止/⟳恢复/⤴对话/◎查找/修改）收进标签条右端的「⋯」菜单，Esc 或再点一次退出专注。

### 3.1 启动与标签

启动栏第一行固定按 agent → profile → 模型 → 目录 → 启动排列，目录会占用剩余宽度；技能数（◈ N 技能）、MCP 数（⌗ M MCP）、工作区端口状态与 shell 状态在第二行。输入框统一 inset 浮起底；「启动」是启动栏唯一的实心主按钮，「停止」等其余按钮为深色描边次要样式。启动后启动栏**自动收缩为状态行**（点「修改」展开），保留「◈ 技能 / ⌗ MCP 入口 pill + 修改 / ⋯」；实时对话统一在右侧「对话」工作台查看，停止、恢复、打开 Shell、查找等按状态出现在「⋯」菜单。选择会记忆，每个工作区也会记住上次用的配置。

- **◈ 技能 / ⌗ MCP pill**：两个入口在展开启动栏与收缩状态行（运行中）都可用。「◈ N 技能」展开该 agent 已启用的技能清单，点击一键使用（运行中注入终端输入框不自动发送，未启动写进首条指令）；「⌗ M MCP」展开该 agent 已分发的 MCP server 清单，点击一键提及（注入「使用 X 提供的工具：」提示词，agent 会调用其工具），清单底部「管理 MCP 分发 →」直达 MCP 页——分发变更对新会话生效

- **多标签**：「＋」开标签，各自独立进程；标签固定宽度、超出可横向滚动；活跃标签为绿色下划线；关闭 × 与注意力点悬停、激活或键盘聚焦时才显现——注意力点只在 工作中 / 待确认 时出现（无状态的空闲标签不显示；「已回复」不打点——回合结束每次回复都发生，不是待办）
- **分屏对比**：标签栏右侧「◧ 分屏」把中间终端区分为左右两个 pane（至少两个标签时可用）——左侧固定当前活跃标签，右侧 pane 头部下拉选择任意其他标签做对照（如 analysis-a/b 并行盯梢）。两个 pane 都有 32px 小头：左侧显示「当前」标签名，右侧是「对照」下拉，各带一个 × 关闭该 pane（关左 = 退出分屏并切到对照标签，关右 = 退出分屏保留当前标签）。两侧终端同时保持挂载、互不影响（xterm 不重建、进程不断）；中间分隔条平时极细透明、悬停才显色，可拖动调比例（本机记忆，双击恢复对半）。点击某个 pane 即把它设为活跃 pane，右侧工作台（对话/文件/改动）与左侧文件树跟随活跃 pane；标签条上对照标签带 ◧ 小标，点它会交换到左侧。再点「◧ 分屏」或任一 pane 小头 × 退出分屏；分屏状态不随重启恢复
- **关闭守卫**：关闭 Agent 还在运行的标签时会弹出 Ccode 应用内确认框「该标签的 Agent 还在运行，确认关闭并终止？」；shell/已退出的标签直接关闭不打扰。关闭整个窗口时同理——还有在跑 Agent 的标签会先统一确认一次，取消则保持运行，确认后终止 Agent 并退出应用
- **重启恢复**：应用关闭前会在本机保存可恢复标签的名称、目录、agent/profile、模型和关联 sessionId；不会保存 PTY id、滚动输出、密钥、环境变量或 run 脚本命令。重开后标签以「**上次任务，可恢复**」占位出现，不会自动启动进程；点击「恢复任务」才创建新 PTY。上次目录或 profile 已不存在时会保留可编辑启动栏并明确提示，不会偷偷换目录或配置
- **停止/回落**：agent 退出自动回落登录 shell（「shell 模式」，提示「会话已保存，可一键恢复」）；shell 里 `exit` 彻底结束
- **打开 Shell**：纯终端标签（展开的启动栏或收缩状态行的「⋯」中）
- **⟳恢复 / ⤴对话**：收缩状态行的「⋯」按状态显示——⟳恢复 = 用刚才的 sessionId 接回原对话继续聊（shell 模式且可恢复时出现）；⤴对话 = 跳到对话页打开该对话回放（可做标记/保留/归档等整理）
- **◈ 接力到…**：把当前对话交给另一个 Agent 继续干（终端标签收缩状态行「⋯」/ 专注模式侧栏「⋯ 操作」，或对话页回放头部「⋯」进入）。选择目标 Agent 后，应用从当前会话尾部生成一份**结构化接力简报**（任务信息 / 最近对话要点 / 当前 git 状态），脱敏后落到项目目录 `.ccode/handoff-<时间>.md`（过程文件，生成时会自动把 `.ccode/handoff-*.md` 补进仓库 .gitignore，不进版本库），再开新终端标签预填同目录与目标 Agent，首条指令自动注入「读简报继续任务」。**接力是简报接力，不是记忆转移**——新 Agent 只看到简报，完整上下文仍留在原 Agent 会话里。Kimi / OpenCode 没有启动注入参数：会先把简报路径复制到剪贴板并提示，启动栏保留指令文本，由你手动发送。接力生成的新会话在对话页显示「**⇄ 接自 <Agent>**」小标，接力链可回溯
- **◈ 提炼接力…**：长会话的续作方式——「恢复」会把整个旧上下文原样带回，容易污染；提炼接力则用 AI 把**全会话**蒸馏成一份紧凑简报（任务目标 / 关键决策与结论 / 已完成的改动 / 当前状态与待办 / 下一步建议 / 环境与约束），脱敏后同样落到 `.ccode/handoff-<时间>.md`，新会话只需读这一份简报即可续作（入口同「接力到…」，另在对话页行内 ⋯ 菜单）。目标列表里**来源 Agent 置顶**（标注「同 Agent · 新会话」）——同一 CLI 开新会话读简报，不带旧上下文；选其他 Agent 即跨 Agent 接力（同样登记接力链、显示「⇄ 接自」小标）。行悬停还有两个外部路径：**⧉ 复制外部续作命令**（形如 `cd <项目> && claude '读 .ccode/handoff-… 接力简报，…'`，粘贴到任意终端执行；用的是机器上的全局 CLI 配置，不携带 Ccode 注入的密钥）与 **⇗ 外部终端打开**。Kimi / OpenCode 无启动注入参数：⧉ 改为复制简报指令文本，启动后手动粘贴发送。提炼需要可用的 AI profile（设置页「AI 辅助」可按功能单独指定「提炼接力」用的 profile）；没有配置或调用失败时会行内报错，可重试，也可以退回免 AI 的「◈ 接力到…」快速简报。**提炼在后台进行**：弹窗可以随时关闭去做别的事，不会中断也不会重复生成；完成后简报在「待你处理」收件箱出现「接力简报已生成，待发送」条目，点击直接回到发送界面；选定目标发送后条目自动消失（也可以点「暂不发送」手动摘除，简报文件保留在磁盘）。**提炼结果先经「定稿页」人工把关**：AI 初稿全文放在可编辑文本框（「AI 初稿，改完定稿后才会落盘」），「定稿并继续」把定稿落盘为 `.ccode/brief-<时间>.md` 并自动钉入该会话所属的任务卡（未归置则只落盘），之后发送页的三个路径一律使用这份定稿；「暂不发送」= 仅定稿落盘钉卡、关闭弹窗。已定的稿重开弹窗直达发送页

> **「进程 vs 会话」心智模型**：进程是标签里正在跑的活的（agent 或 shell），一次一个、不可复活；会话是写在盘上的对话记录，进程死了它还在。停止 agent = 杀进程不杀会话；shell 回落 = 进程空窗期补位；恢复 = 拿盘上的会话开新进程接着聊。
- **注意力标记**：绿点短暂脉冲=工作中（几秒后静止，不会一直闪），琥珀点=待确认（标签上的点悬停/激活才显现、无状态不渲染）；「已回复」（回合结束等你输入）不打点不通知。agent 转为待确认且 Ccode 窗口未聚焦时另发 **macOS 系统通知**（同一标签 30 秒内最多一条，首次发送需允许系统通知权限；可在设置页「外观 → 长任务 OS 通知」关闭）。Claude Code 会话另可选**精确注意力标记**（设置页「集成」区开启，默认关）：开启后向 `~/.claude/settings.json` 写入 hooks 配置，由 Claude 事件实时驱动注意力点，比默认的会话尾部推断更准；状态文件超过 10 分钟无更新自动回退推断，关闭开关即移除 hooks 并完全回退

### 3.2 对话联动

启动后点「对话」打开右侧结构化视图。页签行右侧显示标题、Agent、会话 ID，以及「识别中 / 同步中 / 已结束 / 等待关联」状态（空间不足时截断，悬浮可见完整会话 ID）；正文只保留最近 **50 条**，每 3 秒按文件签名增量刷新，不再反复解析整份长会话。点「**完整回放**」可精确跳到对话页继续向前加载历史。

Claude/Qwen 用 `--session-id` 确定性锁定；其余 agent 由后端按 **Agent + 项目 + 启动批次**排他认领，同目录并发标签不会抢到同一条会话，跳转和运行态登记也始终使用 `agent + sessionId` 复合标识。运行中的会话在对话页带绿点「进行中」，可点击跳回对应终端标签。

对话滚动只在你原本位于底部附近时跟随新消息；向上阅读后不会被强制拉回底部，而是在右下角显示「**有新消息 ↓**」。重新切换标签或重新打开对话面板时，才定位到该标签的最新内容。

### 3.3 文件树（左栏）

左栏自上而下：**工作树标题行（`.*` 显隐隐藏文件 / ⟳ 刷新）→ 项目区（常驻，固定列出所有建有活跃工作区的项目，当前项目置顶标注）→ 文件树（搜索框 + 完整树）**；「最近项目」收进文件树搜索行的 ⌄ 下拉浮层，左栏不再设「打开的标签」区；区间靠留白分层。

- **搜索框**：当前根目录内按文件名搜索（跳过隐藏目录/构建产物）；结果点击 = 树内定位+高亮
- **最近项目**：收进文件树搜索框旁的 ⌄ 下拉浮层（Esc/点外部关闭）。按各 Agent 会话的最近更新时间聚合、去重并排序，最多展示 4 个，当前文件树所在项目不重复出现。应用启动时后台预取，并用上次成功结果立即占位展示；首次无缓存时先显示固定骨架，因此进入终端页不会等扫描完成后突然把文件树向下顶开。点击 = 树和终端 cwd 一起切过去（真进入）；↗ 另开标签。缓存中的目录点击前仍会重新验证，已移动或删除时不会切进无效路径
- **项目区**：最近项目下方显示「项目」折叠区（默认展开），**固定列出所有建有活跃工作区的项目**——每个仓库一个小节（组头标仓库名），主文件夹节点（repo 根名，带「主」标记）下列出该项目的**活跃工作区**（工作区名 + 研究步骤名 + 注意力点；未创建/已归档不列出）；当前标签 cwd 命中的项目**置顶并标注「当前」**（还没有活跃工作区也保留显示）。点击主文件夹或工作区名 = 树和终端 cwd 一起切过去（同「最近项目」真进入语义，右侧对话/预览/改动随之联动）；节点前的 ▸ 只展开显示该节点的**一层目录**（只读，不点不拉取，子目录可点击继续切根）。当前 cwd 落在哪个节点，该节点高亮。agent 正在运行时 cwd 不切换（既有语义），会给出提示但不打断运行中的任务
- **树**：双击钻取；「←」返回上一级；`⌂` 回到当前项目；自动刷新（噪声过滤）；git 状态字母（M/A/?/D，小号 mono 徽标）、文件夹图标随主题着色。树根跟随终端的**真实 cwd**——切标签、shell 里 `cd` 都会跟（每 4 秒探测一次；启动栏输入框聚焦时不打扰）。根目录名旁标注归属：绿点「**分支**」= 在工作区工作树里，黄点「**主仓库**」= 在主仓库里（改动不进任何分支）；命中工作区时出现「**⇄**」下拉——列出主项目 + 该仓库全部活跃工作区，任意切换（树和终端 cwd 一起切）
- **右键**：目录 = 打开终端/新建文件夹（内联输入）/删除；文件 = 删除。**删除 = 移入系统回收站**（废纸篓/回收站可找回，不是永久删除）；系统目录、关键用户目录、CLI 配置、.git 等**重要路径一律拒绝删除**
- **预览**：单击文件 → 右侧 Monaco 编辑器（**按扩展名语法高亮**），可编辑（脏标记 ●，保存写回；>256KB/二进制只读）。**Markdown 文件默认进入「阅读版式」**：渲染后的排版视图（标题层级/引用/表格/代码块/列表，配色随主题），工具行可切「**阅读 / 编辑**」（编辑回到 Monaco，切换不丢未保存改动）；点「**⛶ 沉浸阅读 / 沉浸编辑**」打开全宽覆盖层（阅读为大号排版居中、编辑为全宽 Monaco——编辑器实例不变，未保存改动与撤销历史不丢；头部带文件名、保存按钮与「✕ 退出」，Esc 关闭，终端继续在后台运行）；阅读版式（含沉浸阅读）里拖选文字会出现「**◈ 讨论/改写此段**」浮动按钮，点击把「选段引用 + 出处文件名」写入**当前活跃终端标签**的 agent 输入框（不自动发送，接着输入你的意见——讨论、提问或要求改写——后自行回车；无运行中 agent 会提示）；Agent 正在写文件时阅读内容自动刷新，编辑中不覆盖。**PDF 文件走内嵌 pdf.js 预览**：页码导航/跳页/缩放/适配宽度，只渲染当前页与相邻页；在文字上拖选会出现「**◈ 问 AI**」浮动按钮，点击把「选段 + 出处（文件名、页码）」写入**当前活跃终端标签**的 agent 输入框（不自动发送，检查后自行回车；无运行中 agent 会提示）；旁边的「**整理为笔记**」把选段（含文件名/页码/日期出处）追加到归属项目「文献精读与笔记」步骤工作区的 `notes/inbox.md`——没有该工作区时自动一键开步创建，完成后预填终端启动，让 Agent 把选段整理成结构化笔记；PDF 未登记为任何项目资源时会提示并给出「去工作区页登记」入口。**docx 文件走阅读版式预览**：经 mammoth 转成排版视图（标题/正文/列表/表格，图片内嵌显示，配色随主题），只读不可编辑——改内容请编辑对应的 Markdown 源文件再重新导出；超过 50MB 的 docx 不渲染并明确提示。在当前树根内预览保持已打开文件；**切换项目、工作区、终端标签 cwd 或树根时自动清空旧预览**，不会擅自打开新根下的同名文件。未保存时先确认，取消则不切换树根。**磁盘被外部改写（合并/agent 写入等）时自动刷新内容**（编辑中不覆盖）。文件名旁标注路径归属：绿点「分支 ccode/x」= 在工作区工作树里（改动属于该分支）；黄点「**主仓库（非分支）**」= 在主仓库里——此时保存按钮变「**保存到主仓库**」（警示色）且保存前二次确认，防止误改主项目。**md 阅读版式与 PDF 预览的选段浮动条均有「✦ 沉淀为技能」**：把选段（比如你纠正 agent 做法的那段交互）交给 AI 提炼成技能草稿（名称/描述/正文规则清单），自动跳到技能页打开新建表单预填，检查修改后保存即入库（重名会被拒绝，改名再存即可）

### 3.4 git 改动面板（右侧「改动」页签）

分支、领先/落后、+/- 行数（含未跟踪）、文件列表，8 秒刷新。文件列表按状态分组显示中文组名（「修改的 N / 新增的 N / 删除的 N」），状态字母（M/A/??/D）保留为文件名前的小号 mono 徽标，悬浮显示「字母 · 中文」说明，方便程序员扫读、新手看白话。**点击任一文件行切换为主从分栏：左栏是该文件的 diff 主区（图片为「基准 vs 当前」双栏看图），右栏收成紧凑文件列（状态徽标 + 文件名）方便连续翻看，再点当前行或 diff 头部的 × 收起回全宽列表**；新增/删除行整行铺语义深底（绿底/红底，七主题通用），代码文字保持浅色高对比，hunk 标题使用 inset 底色。未跟踪文本按全新增显示，其余二进制文件给出只读提示，超大内容最多读取约 200 KB 并明确标记截断。读取前后都会核对该路径仍属于当前 Git 改动，过期或越界路径会拒绝。工作区任务头部增加「**审阅**」入口，展开全宽 diff 与提交合并闭环；普通仓库不显示。

**按块丢弃/暂存（逐 hunk 验收）**：diff 主区里，每个改动块（hunk）标题右侧有「**丢弃**」「**暂存**」两个小按钮（只覆盖未提交改动；工作区视图里同样可用，但仅限仍未提交的块，已提交的累计改动请走「审阅」）。「丢弃」把这块改动从工作区抹掉（会二次确认，不可恢复，除非已提交过）；「暂存」把这块改动放进暂存区，随后勾选该文件「**保存到历史**」时就只提交已暂存的块，其余块留在工作区——这就是选块保存。新文件整个文件算一个块：暂存 = 纳入 git 跟踪，丢弃 = 删除该文件。文件已有部分内容暂存时，diff 主区会提示提交粒度；全部块都暂存后回落为只读视图并提示「改动已全部暂存」。二进制、非 UTF-8 或超大文件不支持按块操作，保持只读展示。

**普通仓库默认不勾选文件**，可逐文件选择或全选/清空，并明确显示「将保存 N / M 个文件」；提交和 ◈ 生成都只读取所选文件，未选文件保持在工作区。隔离任务工作区仍固定提交全部任务改动，避免把一个任务拆成难以理解的半提交。改动说明可以手动填写（留空自动生成一条），也可点输入框旁的「**◈**」让 AI 按 diff 生成后再审阅。主按钮为「**保存到历史**」（悬浮标注 `git commit`），旁边「**保存并推送**」（悬浮标注 `git commit + push`）；若说明留空，按钮自动变为「**快速保存到历史** / **快速保存并推送**」：应用按文件状态和数量在本地即时生成中性默认信息，不调用 AI，直接提交或推送（无上游自动 `push -u`）。提交阶段失败会把默认信息留在输入框供修改或重试；如果提交已成功但推送失败，会显示「**重试推送**」，只执行 push，不会重复提交。成功时右下角浮出主题绿 toast，展示提交号和实际使用的提交标题。

**产物区（提货单）**：工作区任务视图底部增加「产物（提货单）」区——大型产物（数据/图/PDF）**不进 git**，只有清单 `artifacts.yaml` 随提交传递给下一步。「**登记产物**」打开系统对话框选文件，应用计算 md5 与大小后把工作区根的 `artifacts.yaml` 更新一条（名称/绝对路径/hash/大小/来源工作区/时间；已被 git 跟踪的文件会被拒绝，因为它本来就随分支走；同一路径重复登记会更新而不是重复）。条目显示名称、路径、大小、hash 前 8 位与来源工作区；PDF 条目带「**查看**」按钮，直接在内嵌 PDF 预览中打开。下一步「开始」开步时，项目根的提货单会自动写进新工作区 `TASK.md` 的「上一步产物（提货单）」段，Agent 按路径直接读取产物，不需要手动复制路径。

### 3.5 终端质感

WebGL 渲染（创建失败或探测到软件渲染时自动回退，防 Windows 上 GPU 被拉黑后的闪烁）、清瘦字形（400/600 字重、行高 1.2、零字距，向 Ghostty 锐利度靠）、盒绘字符对齐、粗体增亮、平滑滚动 150ms、细滚动条。默认字体为打包内置的 JetBrains Mono（woff2，不依赖系统安装），可在设置页换其他字体或调色板预设。后台标签输出只缓存不推流（切回补发），输出 50ms 合帧——十余个标签并行也流畅。

**输出搜索**：⌘/Ctrl+F 或工具栏「◎ 查找」呼出搜索条（输入即增量查找，Enter 下一个、Shift+Enter 上一个、Esc 关闭），只作用于当前活跃标签。

## 四、对话页（◔）：历史回放与整理

- **布局**：应用导航外的两栏——**会话列表栏**（固定宽，含标题「对话」、计数副题「当前 N · 总计 M」（搜索时透出命中数）、「显示已归档 / 批量管理」次按钮与搜索框）｜**回放区**（常驻，未选中时为空态）；选中行浅填充标记当前回放的对话
- **分类筛选**：列表栏「分类筛选」行展开**单列纵向手风琴**（默认收起）——「全部对话 / Ccode 内部 AI / 各 agent」及计数纵向排开；「全部对话」「内部 AI」点击即筛选；点 agent 只**展开/收起它的项目子列表**（缩进线表达层级，不改变当前列表、不关闭正在看的回放），点子列表里「全部项目」或某个项目才切换筛选，**面板保持展开可连续浏览，只有选中某条具体会话时才自动收起**；选中行浅填充，计数弱化显示；项目行右键仍可批量删除该项目全部对话。顶部搜索（项目/标题/标签/工作区名/**研究步骤名**/**AI 摘要内容**）。Ccode 自己发起的 ◈ 无头 AI 会话不混进普通项目，默认归并到单独的「**Ccode 内部 AI**」入口；分类只认后端登记的精确来源，不按临时目录名称猜测
- **归档计数**：「显示已归档」关闭时，全部、Agent、项目和内部 AI 的数字都排除归档项；打开后统一计入，避免分类数字与列表结果口径不一致
- **列表与标题**：双行行式——标题行（标题 + 右侧相对时间，相对时间主显、悬浮查看绝对时间）+ meta 行（agent 名 · token 用量 mono 小字 + ⎇步骤/⇄接力/标签 chip，AI 摘要截断尾随）；工作区会话的 ⎇ badge 优先显示**研究步骤名**（工作区名命中项目档案卡 `steps[].workspaceName` 时；不匹配则回落工作区名，悬浮可见两者）；选中项目节点时列表**按任务卡分组**（卡片名小标题，组内按时间降序，组按最近活跃排序，未归置卡片的会话收「未归置」组排在最前）；已归置的会话 meta 行带「▤ 卡片名」chip（点击跳到工作区页对应项目），行 ⋯ 菜单的「**移到卡片…**」在项目筛选下可把对话归入/移出卡片；接力生成的会话带「⇄ 接自 <Agent>」badge（简报接力，非记忆转移）；Codex resume 链合并（「N 次继续」）；⚑=已保留；绿点「进行中」（内部启动的可点击跳回终端；**外部终端里运行的会话**也按文件活跃度自动标记，仅显示）。行悬停（或键盘聚焦）才显示「恢复 / ⋯」操作。标题会折叠换行与多余空格，并忽略 `New Session`、`Untitled`、`未命名对话` 等占位值，优先回落到首条真实用户消息；仍无标题时显示「未命名对话 · ID 前 8 位」
- **对话回放**：首次只读取会话尾部的有界窗口；长会话顶部显示「**加载更早对话**」，逐页向前加载并保持当前阅读位置。OpenCode 每页最多 80 条消息；普通 JSONL 每页最多读取约 192 KB；压缩的旧 Codex 会话只提供有界尾部回放。回放排版：你的消息为右对齐气泡，AI 回复直接排版；正文中的围栏代码块以独立代码块展示（hover 显现 ⧉ 复制）；连续工具调用折叠为「▸ N 次工具调用」一行，点击展开逐条明细；底部为只读展示态的圆角输入条（提示如何恢复续聊）。头部保留「**◈ 摘要**」（AI 概括，缓存）与「**导出**」（整段对话导出 Markdown 到 `~/Downloads/ccode-exports/`）
- **当前项目改动**：「对话 | 当前项目改动」页签中的后者只读展示该项目**此刻磁盘上的 Git 状态**，不是历史会话产生改动的快照；可点击文件展开 diff，但不提供提交或推送，点「前往终端处理」进入正常编辑/提交流程
- **在终端恢复**：行悬停/右键或回放头部 → 自动开标签续聊（claude `-r`、codex `resume`、kimi `-S` 等）
- **⇗ 外部恢复 / ⧉ 复制命令**：不想用内嵌终端时——⇗ 直接在外部终端应用里开窗口续聊（macOS 依次找 Ghostty → iTerm → 系统终端；Windows 开 cmd 新窗口；Linux 找 gnome-terminal/konsole/xterm）；⧉ 复制形如 `codex resume 019fbd46-…` 的恢复命令（含 `cd` 到项目目录），粘贴到任何终端自己执行。两者都用你机器上的全局 CLI 配置（不携带 Ccode profile 注入的密钥）
- **整理**：保留（pin 快照，CLI 自动删除后也能回放）、归档（默认隐藏）、自定义标题/标签、删除会话文件（OpenCode 删除其库中记录；Codex resume 链会连带删除链上成员文件）；项目节点右键批量删除——删除范围含该项目的全部会话：已归档/内部对话即使不在当前列表中也会被一并删除（确认框会明确提示数量）
- **批量删除**：列表头部「批量管理」进入选择模式 → 勾选/全选（当前筛选结果）→「删除 N 项」→ 警示色二次确认「确认删除 N 项（含 pin 快照）？」后逐个删除（pin 快照一并清理，与单个删除同语义）。筛选/搜索无结果时显示「清除筛选」按钮
- **敏感信息保护**：会话标题、回放正文、AI 摘要和 Markdown 导出在后端统一隐藏已保存密钥及常见密钥前缀；脱敏完成后才会送到界面，CLI 的原始会话文件保持只读、不被改写

## 五、技能页（✦）：Skills 统一管理

技能 = 含 `SKILL.md` 的目录（开放标准）。先入库，再分发到各 CLI。

页面顶部标题旁显示计数副题「N 个 · 已应用 N」；右上主操作只有实心「+ 新建技能」，「导入」为次级描边按钮，导出全部 / 发现未纳管 / 检查 GitHub 更新收在「⋯」。主列表为表格化呈现：小字灰表头（技能 / 来源 / 应用）+ 可折叠分类分组头（▾ 分类名 + 计数，「未分类」固定排在最后），固定展示技能（名称后可带 1-4 个自定义标签 pill）、来源和“已应用 N / Agent 总数”，不再为每个 Agent 永久占一列；点击技能或应用计数后，右侧详情面板集中展示描述全文、全部 Agent 开关与 SKILL.md。以后新增 Agent 只会在右侧开关区增加一项，列表宽度和阅读结构保持不变。行内「⋯」悬停该行才显现（Tab 聚焦同样显示）；技能列只显示名称与标签，描述收进右侧详情面板（为空或纯符号的异常值显示「—」）；副本过期与 GitHub 可更新合并为技能名旁的一个警示点（悬浮看明细）；未应用的技能只显示计数、不画灰点；来源与应用计数弱化为灰字，列表平铺 hairline 分行、不套卡片外框。

- **标签与分类分组**：标签是用户自定义的展示层——名称后最多 4 个小 pill，行内「⋯ → 设置标签」内联输入（逗号/空格分隔，回车保存，超 4 个截断，留空=清除全部标签）；分类仍是列表分组依据，可折叠分类头（▸/▾），修改分类在「⋯ → 设置分类」内联输入（回车保存，留空归未分类）；两者相互独立
- **应用开关**：点击技能后，在右侧详情的 Agent 网格中管理八个 agent（Claude Code / Codex / Gemini CLI / Qwen Code / OpenCode / Kimi Code / CodeBuddy / Cursor）；绿点=已分发到对应 CLI 技能目录（symlink 优先、copy 兜底；Cursor 未验证 CLI 是否真读技能目录，固定 copy），灰点=未分发，点击即切换；关闭只清理由 Ccode 分发的。有未启用项时标题行出现「**一键应用**」按钮，顺序分发到全部剩余 agent（逐个走与单点相同的 apply_skill，失败即停并显示错误）；全部启用后按钮消失。悬浮在开关上显示 symlink / copy 方式，copy 副本同时参与漂移检测。
- **副本漂移**：copy 副本与库不一致时，技能名旁显示黄点（悬浮列出漂移的 agent），行内「⋯ → 重新分发副本」把库里的最新版本重新同步过去
- **导入**：本地目录 / ZIP / GitHub 仓库（`owner/repo` 或完整网址，可另填分支/子目录，预设 anthropics/skills）/「发现未纳管」（页面顶部 ⋯，扫描各 CLI 目录收编）。结果完整分列**新增、覆盖更新、跳过、冲突**四类并逐类列出技能名，不用「已导入 0 个」掩盖冲突；冲突可批量跳过、按右栏名称**全部另存为**、或**备份并覆盖**（覆盖前先备份旧库目录）。ZIP 先在临时目录完整校验再入库，元数据写入失败会回滚库目录
- **新建 / 编辑**：顶部「+ 新建技能」直接把自己的工作方法写成技能（名称即目录名、描述一句话、正文即 SKILL.md 主体，frontmatter 自动生成）；也可以从 md 阅读版式 / PDF 预览的选段浮动条点「**✦ 沉淀为技能**」，让 AI 把选段提炼成草稿预填本表单再保存；行内「⋯ → 编辑内容」修改描述与正文，保存前自动备份当前版本（保留最近 5 份），SKILL.md 之外的辅助文件不受影响；重名会被拒绝并提示改用编辑
- **◈ 优化**：行内「⋯ → ◈ 优化」写下优化意见后开终端标签（技能库目录为工作目录），Agent 阅读并按意见直接改写库中的 SKILL.md——这是把 skill 交给 Agent 迭代优化的入口；改写结果请审查后再用，之后的保存/覆盖都有旧版本备份兜底
- **步骤推荐技能**：在 `.ccode/project.toml` 的步骤里填 `skills = ["技能名"]`（研究流程编辑器会保留该字段），一键开步的 TASK.md 会落成「本步骤推荐技能」段（名称 + 一句话描述，未安装的会标注）；技能本体不进 TASK.md，已分发的技能对启动的 Agent 自动生效，未分发可在本页开启。步骤级「预览 TASK.md」弹层与开工确认弹层都有「推荐技能」chip 区（点击看一句话说明）；开工确认弹层里可直接增删（chip × 移除 /「＋ 添加技能」下拉），**增删写回步骤定义**（project.toml，影响以后所有开工），不是只对本次生效
- **GitHub 更新**：GitHub 来源会记录仓库、子目录与 revision；页面顶部「⋯ → 检查 GitHub 更新」，有可更新时行名旁显示黄点。此时详情面板出现「**应用更新**」按钮、行内 ⋯ 也有「一键应用 GitHub 更新」——按原地址下载最新版并覆盖该技能（覆盖前自动备份，同仓库其他技能不受影响）；若上游已改名/移动会明确提示，可改用行内 ⋯ 的「导入 GitHub 更新」带原地址打开导入器手动处理（仍经过同名冲突确认，不会静默覆盖）。GitHub 导入的技能会自动按仓库名归组分类；早期导入没有分类的存量，用顶部「⋯ → **无分类 GitHub 技能按仓库归组**」一次性补齐（已有分类不动）
- **导出**：全部打包 ZIP 位于页面顶部 ⋯，单行导出位于行内 ⋯；**查看**：右侧预览 SKILL.md（标注来源与仓库，GitHub 来源显示为可点链接直达仓库），详情面板带「**◈ 翻译为中文**」——AI 译文随会话缓存展示，不改写库文件；**删除**：位于行内 ⋯，取消应用 + 库文件备份（5 份）
- **内置技能（14 个，启动自动播种）**：文献线 `lit-search`（检索与筛选：多库检索清单 + 闭源检索站「人肉中转」规范——网页端导出 RIS/BibTeX/CSV 放入 `papers/imports/` 由 Agent 解析去重合并，带 key 的库一律环境变量引用 + 推荐 MCP 配置片段）、`lit-notes`（精读笔记）、`lit-watch`（新文献监控：arXiv/OpenAlex/Crossref 三路官方 API 确定性检索 + WebSearch 兜底，DOI 优先跨源去重合并，精选 Top 3–5 标「推荐」，无摘要/付费墙进 `papers/watch-followup.md` 跟进队列，订阅行备注 `+bib` 时推荐条目同步生成 BibTeX 进 references.bib）、`review-framework`（综述框架构造：空白清单 + 范式卡片融合出 outline.md）、`review-writing`（英文综述写作）；数据线 `data-clean`（数据清洗规范）、`data-eda`（探索性分析与绘图规范，统计结论先过 stats-check 口径）；论文线 `quarto-render`（quarto 渲染与排错）、`bib-check`（引用闭环只读校验，联网时可加做 Crossref/arXiv 外部元数据核验）、`rebuttal-crafter`（审稿意见逐条回复 + 修改对照表）、`stats-check`（统计用法审查 + 实验设计功效自查）、`figure-forge`（投稿级出图生产规范）、`proposal-writer`（开题报告/研究方案）、`slides-deck`（组会/答辩幻灯片大纲或单文件 HTML）。**首次启动自动入库（来源标「内置」），只补没有的、不覆盖你改过的、你删掉的不复活**；研究流程模板的对应步骤已挂载这些技能，开步 TASK.md 会带「本步骤推荐技能」段

## 六、MCP 页（⌗）：MCP server 统一清单与分发

统一管理 MCP server 清单，按开关一键写进各 CLI 的用户级配置，八个 agent 共用一份：

- **添加 server**：右上「+ 添加 server」，填名称（字母/数字/连字符，不含下划线）、类型（stdio = 本地命令 / remote = 远程 URL）；stdio 填命令 + 参数 + 可选工作目录 + 环境变量，remote 填 URL + 请求头
- **粘贴导入**：右上「⋯ → 粘贴导入」直接粘贴 MCP 文档里的标准 JSON 片段（`{"mcpServers": {...}}`），解析后逐条入库，同名自动跳过——不用对着表单逐项抄
- **收编现有配置**：右上「⋯ → 收编现有配置」扫描八个 CLI 的用户级配置，列出不在清单里的 server，点「收编」进统一清单并标记已分发到来源 agent——之前在各 CLI 里零散配过的一次性归一
- **内置预设**：右上「预设 ▾」一键预填官方 server 表单，目前收两个学术检索 server：**Consensus**（官方 hosted MCP，需 Consensus API key——先设好环境变量 `CONSENSUS_API_KEY`，请求头以 `Bearer ${CONSENSUS_API_KEY}` 引用不落明文）与 **Undermind**（官方 hosted MCP，文献语义搜索；认证走 OAuth 没有 API key——保存分发后在对应 CLI 里登录一次，如 `claude mcp login undermind`，浏览器授权即可，免费账号可用），确认或调整后保存，再按开关分发
- **密钥不落明文**：环境变量/请求头的值可填 `$VAR` 或 `${VAR}` 引用系统环境变量（如 `Authorization` 填 `Bearer ${MY_TOKEN}`），分发时自动转成各家支持的引用写法，密钥本身不会写进任何配置文件
- **分发**：点开任意 server 行展开八个 agent 的开关，打开即写入该 CLI 的用户级 MCP 配置（只改动配置里的 MCP 一个键/段，写前自动备份）；关闭即移除同名条目。编辑 server 后已开启的 agent 会自动更新为新内容
- **注意**：只写用户级配置（项目级配置各 CLI 都要逐个批准，体验差故不分发）；分发到 Cursor 会同时影响 Cursor IDE（两者共享同一配置）；kimi 不支持环境变量引用（需填字面值，保存时会明确提示）；检测到企业托管 MCP 配置时会拒绝写入并提示
- **安全保护**：粘贴导入会先列出解析出的完整命令清单（stdio 命令会被 agent 直接执行，确认来源可信再点「确认导入」）；填了疑似明文密钥（如 `sk-` 开头）时保存/导入会要求二次确认，建议改用 `$VAR` 引用；关闭开关或删除时，如果该 agent 配置里的条目被你在外部改过（比如在 CLI 里手调过），会先提示确认而不是静默删掉手调版本

## 七、统计页（◫）：用量与费用

按消息逐条解析用量、按天聚合（增量更新）。

- **概览**：输入/输出/缓存读（含写）tokens、会话数、估算费用（官方价）——大数字 + 小号灰标签两档呈现，不堆卡片
- **范围**：今日/近 7 天/近 30 天/全部，均按本机日期计算；「刷新」手动重建索引。普通 JSONL 与 Codex 压缩会话采用逐行流式解析，大于 10 MB 的长会话也会进入统计，不会因文件体积整份跳过
- **分布**：连续分区（无卡片边框）：agent 占比进度条（每 agent 专属色相、随主题联动，条宽=token 占比，含百分比列 + 「N 模型」不同模型数）、项目排行、**任务成本**（按工作区/任务归因：工作区名 + 所属项目 + tokens + 费用，回答"这篇综述/这个课题花了多少钱"；usage schema 已升 v5，首次打开自动重建索引）、模型明细
- **内部活动**：Ccode 在发起自身的 ◈ 无头 AI 调用前，由后端登记精确的 agent 与临时任务来源，usage 事件及项目/模型聚合都携带 `source/internal`。默认把这些已确认的内部活动归并，勾选「显示内部活动」可查看原始条目，选择会在本机记忆。不会再按 `/tmp` 路径、目录名或模型名猜测，因此用户主动在临时目录运行 agent 仍属于普通活动
- **费用口径**：费用均按官方公开价（27 项定价，供应商前缀自动剥离）估算；含未计价模型显示 `≥`，没有可用价格显示 `~`。说明集中在范围工具栏下方，不在每一列表头重复标注。**官方账号**（如 Google 登录）启动产生的用量显示「**订阅**」而非估算金额——不按量计费，token 数仍是实际统计（usage schema 已升 v6，首次打开自动重建索引）
- **$/¥ 切换**：范围旁的按钮一键换算（汇率默认 7.2，设置页可改）

## 八、设置页（⛭）

设置项按「外观 / 统计 / 集成 / 更新 / 诊断」分区，分区可折叠且状态记忆；首次只展开高频的「外观」，其余按需展开。每个设置项的说明文字常驻显示在标签下方（macOS WKWebView 不渲染悬浮提示，不依赖悬停）；「诊断」分区行内的刷新 / 复制全部 / 导出 / 清空为低频操作，悬停该行才显现（Tab 聚焦同样显示）。

- **更新**：启动时静默检查新版本；有可用更新时该分区自动展开，并在标题显示绿点 + 「vX 可更新」标记；发现更新显示版本号与更新日志，「下载并安装」后自动重启；也可手动「重新检查」
- **诊断包**：点「导出诊断包」会在 `~/Downloads/ccode-exports/` 生成 `ccode-diagnostics-<时间>.zip`，包含 Windows 与 WebView2 版本、显卡/驱动、WebGL Renderer、语言/输入法、当前功能开关、最近 500 条应用日志，以及自本次启动后 Ccode 子进程的程序/脱敏参数/PID/父 PID/开始与结束时间；同时记录 Ccode 相关的 Git、cmd、conhost、WebView2 和系统 CTF/TextInputHost 活动。包内均为 UTF-8 JSON/TXT，可直接带回 Mac 解压离线分析，不需要安装 Ccode 或 Windows 工具。不会采集子进程环境变量，已保存密钥与常见密钥前缀会在 Rust 层脱敏；路径和普通参数仍保留，发送前可先解压检查
- **单独日志**：下方仍展示最近 100 条应用日志（前端渲染错误自动上报），支持刷新、复制全部、导出 txt 与清空

- **主题**：七套深色 + 七套对应浅色色卡（沉浸黑/陶土/Ayu 琥珀/Catppuccin/极简灰蓝/Dracula/灰蓝正红，浅色排在对应深色正下方一列对齐），各有独立强调色（CTA/选中/「活跃」「可合并」pill 同步换色），点击即时全站切换；原生下拉列表、滚动条等系统控件同步跟随主题明暗；浅色模式下终端 ANSI 调色板仍偏深色向，可在「调色板」设置里另行选择
- **终端字体**：内置 JetBrains Mono（默认）+ 常用等宽字体候选（Maple Mono NF CN / Sarasa Mono SC / Iosevka / SF Mono / Menlo / Consolas，需系统已装，未装自动回退内置字体），也可填系统已装的任意字体名；选中 Maple/Sarasa/Iosevka 且系统未安装时，下拉旁出现「安装」按钮，一键经 Homebrew 安装（未装 brew 会明确提示），装完即生效；**终端调色板**：VS Code Dark+（默认）等多套预设，8 色无缝色条预览（与终端实际生效色同源），点选即时生效
- **终端字号**：11-18，实时生效；**滚动缓冲行数**：新标签生效
- **长任务 OS 通知**：默认开；agent 转为待确认且窗口未聚焦时发系统通知（同一标签 30 秒去抖；「已回复」不通知），关闭后完全不请求权限、不发通知
- **汇率**：USD→CNY，统计页 ¥ 换算
- **brew 镜像开关**：安装/更新是否走 TUNA
- **AI 专用配置**：内置 AI 功能默认使用的 profile，建议选快模型（生成速度主要取决于它）；默认「自动」= 最近使用的 profile。其下七行可**按功能单独指定**（提交信息/会话摘要/PR 描述/沉淀为技能/提炼接力·评审沉淀/冲突建议/翻译），「跟随默认」即回落到专用配置；功能专属 profile 被删除时自动回落，不会静默落到别的配置
- **外部终端**：对话页「⇗ 外部恢复」使用的终端应用——默认「自动」按优先级探测（macOS: Ghostty → iTerm → 系统终端；Linux: gnome-terminal/konsole/xterm），也可固定选某一个；选了未安装的会在恢复时报错提示改选
- **精确注意力标记（Claude Code）**：默认关。开启后向 `~/.claude/settings.json` 的 hooks 段写入三个事件钩子（写入前自动备份到应用备份目录，只合并 hooks 段、不动其他配置，已有 hooks 保留），Claude 提交/完成/等待确认事件实时驱动终端注意力点与系统通知；关闭即移除 hooks 条目并回退为会话尾部推断模式，可随时开关
- **自定义定价**：表格化编辑（每行 = 模型前缀 + 输入价 + 输出价，「+ 添加模型」增行），保存时仍写成 pricing.json 并经后端校验，下一次统计查询生效；缓存读/写按输入价 0.1/1.0 统一系数计价

## 九、AI 功能说明（◈）

各处 ◈ 按钮（git 提交信息、会话摘要、PR 描述、冲突审查建议、沉淀为技能、技能文档翻译、提炼接力、评审沉淀起草）都通过 **headless 模式调用 agent**：把上下文（diff/会话/提交记录/冲突文件/选段/技能正文）发给该 CLI 的 print 模式（如 `kimi -p`、`claude -p`），纯文本生成（不依赖工具调用），不产生交互会话。profile 选择顺序：显式指定 → 功能专属配置（设置页按功能单独指定，如已选）→ 设置页「AI 专用配置」→ 最近使用的 profile；生成慢多半是因为自动落到了大模型上，在设置页指定一个快模型即可。专用 profile 被删除时会报错提示重选，不会静默落到别的配置。失败时先检查所选 profile 是否可用。

## 十、常见问题（FAQ）

**Q：macOS 安装后打开提示「已损坏，无法打开」？**
A：不是真损坏——未签名应用从网络下载会带 quarantine 隔离标记，Gatekeeper 因此拦截。终端执行 `xattr -cr /Applications/Ccode.app` 即可。每次重新下载安装都要执行一次，做了签名公证后此问题消失。

**Q：agent 不真正执行操作（不建文件等）？**
A：中转模型不支持工具调用（部分中转商的模型只会输出文字、不真正执行工具调用）。换真 Claude 系模型或明确支持工具调用的中转。

**Q：配置保存了但调用报空响应/404？**
A：Base URL 的 `/v1` 约定：OpenAI 协议（kimi/codex/qwen/opencode）**必须带** `/v1`；Anthropic 协议（claude/codebuddy）**不要带**。建完先点「测试连接」。

**Q：按钮点了没反应？**
A：macOS WKWebView 不支持原生 JS 对话框——需要输入的地方已全部改为内联输入框，确认弹窗也已全部改为应用内对话框；如仍遇到，把位置报给开发者。

**Q：终端输出黑白？**
A：已内置修复（注入 TERM/COLORTERM、剔除 NO_COLOR）。

**Q：安装/更新卡在下载？**
A：brew 已走 TUNA 镜像（设置页可关）；npm 慢的话在 profile 附加环境变量加 `npm_config_registry=https://registry.npmmirror.com`。

**Q：改了模型列表，CLI 里 /model 没变？**
A：注入配置只在新启动的会话生效，重启该终端标签。

**Q：工作区的会话在历史里归到哪？**
A：所属仓库的项目下，带 `⎇ 任务名` 标签；工作区删除后显示为独立项目（源文件仍在）。
