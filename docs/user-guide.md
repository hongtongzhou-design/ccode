# Ccode 使用手册

> 本文档随产品功能实时更新（改动功能时必须同步本文档，见 AGENTS.md 规则）。
> 最后更新：2026-08-03（工作区审阅闭环 + 本地快速提交版）

Ccode 是 AI 编码 Agent 的统一工作台：管理六个 CLI agent（Claude Code、Codex、Gemini CLI、Qwen Code、OpenCode、Kimi Code）的 API 配置，内嵌终端一键启动，git worktree 任务工作区，会话历史回放，用量统计，技能分发，以及四处 AI 辅助（提交信息/会话摘要/PR 描述/冲突审查建议）。

开发预览使用 `npm run tauri:dev`，窗口标题为「Ccode Dev - 热更新」；React/样式修改会自动刷新。它与正式版和打包调试版名称不同，验收时以该标题区分。

侧栏七个页面：**配置 / 工作区 / 终端 / 会话 / 技能 / 统计 / 设置**。点击顶部「Ccode」图标可折叠为纯图标栏；「终端」图标在有 agent 运行时会显示数量徽标（任意页面可见）。

**模块是打通的**：配置页建的 profile 在终端页一键启动；终端里跑的会话在会话页以绿点标记（内部标签可点击跳回）；历史会话一键「在终端恢复」；工作区自动完成装依赖、起服务、评审合并；AI 按钮（◈）用你最近使用的 profile 提供辅助。典型动线：**配置 →（工作区）→ 终端 ⇄ 会话**。

## 一、配置页（⇄）：agent 与 API 配置管理

页面 = 可折叠分组列表。顶部筛选（全部/已安装/未安装）+ 搜索 + 「全部折叠/展开」切换；每个 agent 一组（名称 + 版本号 + 右侧更新状态/安装按钮）；分组折叠状态会记住，重开应用保持。

### 1.1 安装与更新

- 未安装的 agent 显示「**安装**」（确认框告知将执行的命令，brew 优先，自动走 TUNA 镜像）
- 已安装的显示版本号，右侧按更新检查结果分三态：「**新版**」（有更新，点击即升级，悬停显示新版本号）/「**已更新**」（已是最新或刚更新完）/「**更新**」（该渠道查不到最新版时的普通按钮，如自更新安装的 claude/kimi）；检查走 brew info / npm view，进程内缓存，更新成功后自动重查
- 更新/安装过程是**实时终端**：输出滚动、可输入（`[y/n]` 在下方 `>` 行回答）、2 分钟无输出提醒、失败带诊断建议。渠道与安装方式一致：brew 安装的走 `brew upgrade`（含 opencode，不走其交互式自更新）；npm 安装的用**与目标二进制同目录的 npm**（同机多份 node/npm 时不会装错 prefix）

### 1.2 创建配置（profile）

一个 profile = 一套 API 配置（端点+密钥+模型列表），一个 agent 可建多个。表单字段：

| 字段 | 说明 |
|---|---|
| Agent | CLI 类型 |
| 名称 | 自定义标记，如「Zeta 中转」 |
| Base URL | 中转地址；「从预设快速填充」可选官方/公开端点 |
| API Key | 存 `keys.json`（0600），界面只显示尾号 |
| 协议 | 仅 Qwen（openai/anthropic）与 Kimi 需要，位于「高级配置」 |
| 模型列表 | **可多个**，首个默认；「获取模型」从端点拉取下拉选。表单上方会提示该 agent 的模型切换页上限：Claude Code 5 个、Gemini/Qwen/Kimi 注入模式仅首个生效（多模型需「设为全局」）、Codex/OpenCode 不限；超出上限会黄色提醒 |
| 附加环境变量 | 每行 `KEY=VALUE`，注入优先级最高，位于「高级配置」 |

辅助：Base URL 行内的**测试**按钮验证端点+密钥并显示延迟和模型数；**导入/导出**（JSON 备份，不含密钥）；行内操作：编辑、⋯（复制/设为全局/恢复备份/删除）。

行内显示：配置的**模型标签**（最多 4 个，超出 +N 悬浮看全部）、端点**主机名**（不显示路径、查询参数或完整 URL）、**上次使用时间**；有用量的 profile 名称旁有「**▸用量**」按钮 → 悬浮卡显示输入/输出 token 和官方价费用（按模型近似归属，跨配置共享模型会重复计入，悬停有说明）。

### 1.3 两种生效方式

- **注入模式（默认）**：终端页「启动」时配置只传给该进程，不改系统文件
- **全局模式**：「⋯ → 设为全局」写入 CLI 配置文件（如 `~/.claude/settings.json`），任何终端生效；写前自动备份（保留 5 份），「恢复备份」可还原

### 1.4 多模型切换

profile 多个模型时，启动栏下拉选一个启动；CLI 内继续切换：

| CLI | 切换方式 |
|---|---|
| Claude Code | `/model`（前 5 个已注册进选择器） |
| Codex | `/model`（自动生成 model catalog） |
| Qwen / Kimi / OpenCode | `/model`（「设为全局」后列表完整） |
| Gemini | 只能 `/model set <模型id>` 手输（CLI 限制） |

## 二、工作区页（⛁）：任务级 git worktree 隔离

解决多个 agent 在同一目录并行冲突。工作区 = 独立 worktree + 分支 + 端口段。

### 2.1 创建

「新建工作区」→ 选仓库（只列真实 git 仓库，可手输）→ 填任务名 → 自动：拉 `ccode/<任务名>` 分支（基于**本地**主分支，含未推送的提交，工作区 = 你本地项目的现状）→ 建 worktree 到 `~/ccode/workspaces/<仓库>/<任务名>/` → 复制 `.env` 类文件 → 跑 setup 脚本 → 分配端口段（4000 起 10 个）。

成功后「打开终端」自动开标签（目录、端口环境变量已预置）。

### 2.2 项目自动化（.ccode/settings.toml）

```toml
files_to_copy = [".env", ".env.local"]
run_mode = "concurrent"            # nonconcurrent 时脚本互斥
[scripts]
setup = "npm install"               # 创建时执行
archive = "docker compose down"     # 归档前执行（失败阻止归档）
[scripts.run]
web = { command = "npm run dev", default = true }
test = { command = "npm run test" }
```

配了之后行内出现 **▶**（默认脚本）/ **▾**（全部脚本），点击开 shell 标签自动执行。

### 2.3 行内信息与操作

状态 pill：灰底小点——**活跃**（绿点）/ 已归档 / **已合并**（绿字，「合并（保留工作区）」后出现，继续提交后自动消失）；健康 pill：**有冲突**（红点）/ 有未提交 / **主仓有改动**（黄点）/ ↑↓领先落后；**仓库节点标题行**同样显示「主仓有改动」黄点（任一活跃工作区的主仓库脏即亮）。可合并状态不用 pill，由「合并」按钮本身的强调色高亮表达（不可合并时悬停列出具体原因）；**有冲突时「评审」按钮亮成警告色**，提醒你点进去处理。
操作：打开终端（记住上次用的 profile）、**评审**（打开全宽任务审阅，见下；有冲突时在当前页展开冲突处理）、会话（跳到会话页筛选）、归档 / 恢复 / 删除（分支也删，有确认）。

### 2.4 评审与合并

- **评审（无冲突）**：行上点「评审」进入终端页的全宽任务审阅；终端标签和进程仍在后台保持运行。中间按文件连续展示左右对照 diff，右侧改动树可快速定位文件；底部可填写或用 ◈ 生成提交信息。默认主按钮「**提交并合并**」一次完成提交和本地合并，工作区继续保留；下拉仍可选「**仅提交**」或「**合并并归档**」。如果改动已提交，主按钮直接变为「合并」。提交后会重新做健康检查，不会因为进入快捷流程而绕过冲突、主仓脏或主仓分支错误等拦截。
- **评审（有冲突）**：保留在工作区当前页展开原冲突面板。顶部列出冲突文件并提供「**开始解决冲突**」；应用会在隔离工作区同步主分支并准备两边内容，不改动主仓库。随后**逐文件列出两边实际内容**，点「选『分支内容』/ 选『main 内容』」按钮解决；「**◈ AI 建议**」逐文件审查给出选侧+理由（确认后「按建议」执行或「全部按 AI 建议执行」，建议人工的留给你）；多文件时还有「**全部选分支版 / 全部选 main 版**」一键搞定（后者会放弃分支改动，有确认）。全部选完默认点「**完成解决并合并**」，应用会依次提交解决结果、重新检查健康度并合回本地主分支，工作区继续保留且不会推送；也可选「**仅保存解决结果**」稍后再合并。若解决提交成功但最终合并被主仓脏、分支错误等条件拦截，会明确显示“解决结果已提交，但合并未完成”，此时只需处理拦截原因后点普通「合并」，不要重复解决冲突。需要逐行取舍时去预览编辑器手动改（文件树标 U，「改动」提交）。**其他路径**：改动方向错了可「归档/删除」从最新 main 重来；想在网页端解冲突走「创建 PR」
- **改动面板任务视图**：worktree 里自动切换为 vs `merge-base(主分支, 任务分支)` 的累计 diff，头部「审阅」可随时展开上述全宽视图；原「提交 / 提交并推送」按钮保持不变
- **合并**：「合并」按钮高亮（=可合并）时可用，是拆分按钮——主按钮「**合并**」只合回主分支、**工作区保留**（终端继续用，之后可随时归档）；「**▾**」下拉可选「**合并并归档**」（合并后移除 worktree、自动归档；还留在工作树里的终端标签会自动 cd 回主仓库）。保留的工作区合并完成后，按钮变为禁用的「**已合并**」；继续产生新提交后自动恢复为「合并」。均只合到本地、不自动推送远程（主仓库 git 面板头部 ↑N 即领先远程的提交数）。前置：分支已提交、与基准无冲突、主仓库在主分支且干净，缺一按钮即灰，悬停看原因；合并被拒时报错会列出主仓库的脏文件
- **创建 PR**：弹窗填标题，正文留空自动摘要、或点「**◈ AI 起草**」生成结构化描述（变更点/动机/测试情况，可编辑）→ 推送分支 + `gh` 建 PR（需已登录 gh）

## 三、终端页（⌨）：并行工作主界面

三带布局：**左栏（搜索+最近项目+文件树）｜ 终端标签区 ｜ 右侧面板（会话/预览/改动）**。标签栏右侧「⤢ 专注」进入专注模式：**只剩终端**——左右栏、顶部标签条、标签内状态条全部隐藏；标签列表移到 App 侧栏（导航图标下方，纵向展示，可切换/关闭/新建），原状态条动作（停止/⟳恢复/⤴对话/会话/◎查找/修改）集成到侧栏的「⋯ 操作」菜单（按当前标签状态裁剪），菜单末项退出专注。

### 3.1 启动与标签

启动栏第一行固定按 agent → profile → 模型 → 目录 → 启动排列，目录会占用剩余宽度；技能数、工作区端口状态与「打开 Shell / 会话 / ◎ 查找」在第二行，避免与启动主流程混排。启动后启动栏**自动收缩为状态行**（点「修改」展开）。选择会记忆，每个工作区也会记住上次用的配置。

- **多标签**：「＋」开标签，各自独立进程；活跃标签为绿色下划线；关闭 × 悬停出现
- **停止/回落**：agent 退出自动回落登录 shell（「shell 模式」，提示「会话已保存，可一键恢复」）；shell 里 `exit` 彻底结束
- **打开 Shell**：纯终端标签（在展开的启动栏里）
- **⟳恢复 / ⤴对话**：收缩状态行「会话」「修改」左侧的两个按钮——⟳恢复 = 用刚才的 sessionId 接回原对话继续聊（shell 模式且可恢复时出现）；⤴对话 = 跳转到会话页打开该对话回放（可做标记/保留/归档等整理）

> **「进程 vs 会话」心智模型**：进程是标签里正在跑的活的（agent 或 shell），一次一个、不可复活；会话是写在盘上的对话记录，进程死了它还在。停止 agent = 杀进程不杀会话；shell 回落 = 进程空窗期补位；恢复 = 拿盘上的会话开新进程接着聊。
- **注意力标记**：绿点脉冲=工作中，蓝点=已完成等你输入，琥珀点=待确认（显示在标签和运行中面板）

### 3.2 会话联动

启动后启动栏出现「会话」按钮 → 右侧面板实时显示结构化对话（3 秒刷新）。Claude/Qwen 用 `--session-id` 确定性锁定，其他 agent 按（agent+目录+启动时间）探测。补充：运行中的会话在会话页带绿点「进行中」，点击跳回终端标签；终端标签也可经 ⤴对话 跳到会话页。

### 3.3 文件树（左栏）

三段：**搜索框 → 最近项目 → 完整树**。

- **搜索框**：当前根目录内按文件名搜索（跳过隐藏目录/构建产物）；结果点击 = 树内定位+高亮
- **最近项目**：按活跃排序，点击 = 树和终端 cwd 一起切过去（真进入）；↗ 另开标签
- **树**：双击钻取；「←」返回上一级；`⌂` 回到当前项目；自动刷新（噪声过滤）；git 状态字母（M/A/?/D）。树根跟随终端的**真实 cwd**——切标签、shell 里 `cd` 都会跟（每 4 秒探测一次；启动栏输入框聚焦时不打扰）。根目录名旁标注归属：绿点「**分支**」= 在工作区工作树里，黄点「**主仓库**」= 在主仓库里（改动不进任何分支）；命中工作区时出现「**⇄**」下拉——列出主项目 + 该仓库全部活跃工作区，任意切换（树和终端 cwd 一起切）
- **右键**：目录 = 打开终端/新建文件夹（内联输入）/删除；文件 = 删除。系统目录、关键用户目录、CLI 配置、.git 等**重要路径一律拒绝删除**
- **预览**：单击文件 → 右侧 Monaco 编辑器（**按扩展名语法高亮**），可编辑（脏标记 ●，保存写回；>256KB/二进制只读）。在当前树根内预览保持已打开文件；**切换项目、工作区、终端标签 cwd 或树根时自动清空旧预览**，不会擅自打开新根下的同名文件。未保存时先确认，取消则不切换树根。**磁盘被外部改写（合并/agent 写入等）时自动刷新内容**（编辑中不覆盖）。文件名旁标注路径归属：绿点「分支 ccode/x」= 在工作区工作树里（改动属于该分支）；黄点「**主仓库（非分支）**」= 在主仓库里——此时保存按钮变「**保存到主仓库**」（警示色）且保存前二次确认，防止误改主项目

### 3.4 git 改动面板（右侧「改动」页签）

分支、领先/落后、+/- 行数（含未跟踪）、文件列表，8 秒刷新。工作区任务头部增加「**审阅**」入口，展开全宽 diff 与提交合并闭环；普通仓库不显示。提交信息可以手动填写，也可点输入框旁的「**◈**」让 AI 按 diff 生成后再审阅。若直接留空，按钮自动变为「**快速提交** / **快速提交并推送**」：应用按文件状态和数量在本地即时生成中性默认信息，不调用 AI，直接提交或推送（无上游自动 `push -u`）。Git 阶段失败会把默认信息留在输入框供修改或重试。成功时右下角浮出主题绿 toast，展示提交号和实际使用的提交标题；失败才显示红字输出详情。

### 3.5 终端质感

WebGL 渲染（GPU）、清瘦字形（400/600 字重、行高 1.2、零字距，向 Ghostty 锐利度靠）、盒绘字符对齐、粗体增亮、平滑滚动 150ms、细滚动条。默认字体为打包内置的 JetBrains Mono（woff2，不依赖系统安装），可在设置页换其他字体或调色板预设。后台标签输出只缓存不推流（切回补发），输出 50ms 合帧——十余个标签并行也流畅。

**输出搜索**：⌘/Ctrl+F 或工具栏「◎ 查找」呼出搜索条（输入即增量查找，Enter 下一个、Shift+Enter 上一个、Esc 关闭），只作用于当前活跃标签。

## 四、会话页（◔）：历史回放与整理

- **左栏分类树**：全部 / 按 agent → 按项目；顶部搜索（项目/标题/标签/工作区名/**AI 摘要内容**）
- **列表**：标题、相对时间、agent、token 用量；头部同时显示当前结果、搜索命中与总数；Codex resume 链合并（「N 次继续」）；⚑=已保留；绿点「进行中」（内部启动的可点击跳回终端；**外部终端里运行的会话**也按文件活跃度自动标记，仅显示）
- **回放**：「对话 | 改动」页签切换——对话 = 结构化对话（思考折叠、工具芯片）+ 头部「**◈ 摘要**」（AI 概括，缓存）+「**导出**」（整段对话导出 Markdown 到 `~/Downloads/ccode-exports/`）；改动 = 该会话项目的 git diff（复用改动面板，支持手写信息、◈ 先生成及留空快速提交），**外部会话的改动也能直接提交/推送**（提交前留意「进行中」标记，避免和 agent 撞车）
- **在终端恢复**：行悬停/右键或回放头部 → 自动开标签续聊（claude `-r`、codex `resume`、kimi `-S` 等）
- **⇗ 外部恢复 / ⧉ 复制命令**：不想用内嵌终端时——⇗ 直接在外部终端应用里开窗口续聊（macOS 依次找 Ghostty → iTerm → 系统终端；Windows 开 cmd 新窗口；Linux 找 gnome-terminal/konsole/xterm）；⧉ 复制形如 `codex resume 019fbd46-…` 的恢复命令（含 `cd` 到项目目录），粘贴到任何终端自己执行。两者都用你机器上的全局 CLI 配置（不携带 Ccode profile 注入的密钥）
- **整理**：保留（pin 快照，CLI 自动删除后也能回放）、归档（默认隐藏）、自定义标题/标签、删除会话文件；项目节点右键批量删除
- **批量删除**：列表头部「批量管理」进入选择模式 → 勾选/全选（当前筛选结果）→「删除 N 项」→ 警示色二次确认「确认删除 N 项（含 pin 快照）？」后逐个删除（pin 快照一并清理，与单个删除同语义）。筛选/搜索无结果时显示「清除筛选」按钮
- **敏感信息保护**：会话标题、回放正文、AI 摘要和 Markdown 导出在后端统一隐藏已保存密钥及常见密钥前缀；脱敏完成后才会送到界面，CLI 的原始会话文件保持只读、不被改写

## 五、技能页（✦）：Skills 统一管理

技能 = 含 `SKILL.md` 的目录（开放标准）。先入库，再分发到各 CLI。

- **分类分组**：可折叠分类头（▸/▾），行内「分类: xxx」按钮内联改名（回车保存，留空归未分类）
- **应用开关**：每行六个 agent 药丸开关（claude/codex/gemini/qwen/oc/kimi），点亮即分发到对应 CLI 技能目录（symlink 优先 copy 兜底），关闭只清理由 Ccode 分发的；已分发的开关带形态标记（**·s**=symlink / **·c**=copy，悬停显示完整说明）；copy 副本与库不一致时显示「副本过期」+ 一键「重新分发」
- **导入**：本地目录 / ZIP / GitHub 仓库（`owner/repo` 或完整网址，预设 anthropics/skills）/ 「发现未纳管」（扫描各 CLI 目录收编）
- **导出**：全部打包 ZIP，单行导出位于「⋯」菜单；**查看**：右侧预览 SKILL.md；**删除**：位于「⋯」菜单，取消应用 + 库文件备份（5 份）

设置项按「外观 / 统计 / 集成 / 更新 / 诊断」分区，分区可折叠且状态记忆（默认全展开）。

## 八、AI 功能说明（◈）

四处 ◈ 按钮（git 提交信息、会话摘要、PR 描述、冲突审查建议）都通过 **headless 模式调用 agent**：把上下文（diff/会话/提交记录/冲突文件）发给该 CLI 的 print 模式（如 `kimi -p`、`claude -p`），纯文本生成（不依赖工具调用），不产生交互会话。profile 选择顺序：设置页「AI 专用配置」（如已选）→ 最近使用的 profile；生成慢多半是因为自动落到了大模型上，在设置页指定一个快模型即可。专用 profile 被删除时会报错提示重选，不会静默落到别的配置。失败时先检查所选 profile 是否可用。

## 九、常见问题（FAQ）

**Q：macOS 安装后打开提示「已损坏，无法打开」？**
A：不是真损坏——未签名应用从网络下载会带 quarantine 隔离标记，Gatekeeper 因此拦截。终端执行 `xattr -cr /Applications/Ccode.app` 即可。每次重新下载安装都要执行一次，做了签名公证后此问题消失。

**Q：agent 不真正执行操作（不建文件等）？**
A：中转模型不支持工具调用（实测 zetatechs 部分模型只会文字糊弄）。换真 Claude 系模型或支持工具调用的中转。

**Q：配置保存了但调用报空响应/404？**
A：Base URL 的 `/v1` 约定：OpenAI 协议（kimi/codex/qwen/opencode）**必须带** `/v1`；Anthropic 协议（claude）**不要带**。建完先点「测试连接」。

**Q：按钮点了没反应？**
A：macOS WKWebView 不支持 `window.prompt`——需要输入的地方已全部改为内联输入；如仍遇到，把位置报给开发者。

**Q：终端输出黑白？**
A：已内置修复（注入 TERM/COLORTERM、剔除 NO_COLOR）。

**Q：安装/更新卡在下载？**
A：brew 已走 TUNA 镜像（设置页可关）；npm 慢的话在 profile 附加环境变量加 `npm_config_registry=https://registry.npmmirror.com`。

**Q：改了模型列表，CLI 里 /model 没变？**
A：注入配置只在新启动的会话生效，重启该终端标签。

**Q：工作区的会话在历史里归到哪？**
A：所属仓库的项目下，带 `⎇ 任务名` 标签；工作区删除后显示为独立项目（源文件仍在）。
