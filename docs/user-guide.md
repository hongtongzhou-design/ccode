# Ccode 使用手册

> 本文档随产品功能实时更新（改动功能时必须同步本文档，见 AGENTS.md 规则）。
> 最后更新：2026-08-04（UI 重构：侧栏「会话」更名「对话页」、技能页行内收口）

Ccode 是 AI 编码 Agent 的统一工作台：管理六个 CLI agent（Claude Code、Codex、Gemini CLI、Qwen Code、OpenCode、Kimi Code）的 API 配置，内嵌终端一键启动，git worktree 任务工作区，会话历史回放，用量统计，技能分发，以及四处 AI 辅助（提交信息/会话摘要/PR 描述/冲突审查建议）。

开发预览使用 `npm run tauri:dev`，窗口标题为「Ccode Dev - 热更新」；React/样式修改会自动刷新。它与正式版和打包调试版名称不同，验收时以该标题区分。

侧栏七个页面：**配置 / 工作区 / 终端 / 对话 / 技能 / 统计 / 设置**。点击顶部「Ccode」图标可折叠为纯图标栏；「终端」图标在有 agent 运行时会显示数量徽标（任意页面可见）。

**模块是打通的**：配置页建的 profile 在终端页一键启动；终端里跑的会话在对话页以绿点标记（内部标签可点击跳回）；历史会话一键「在终端恢复」；工作区自动完成装依赖、起服务、评审合并；AI 按钮（◈）用你最近使用的 profile 提供辅助。典型动线：**配置 →（工作区）→ 终端 ⇄ 对话**。

## 一、配置页（⇄）：agent 与 API 配置管理

页面 = 可折叠分组列表。顶部筛选（全部/已安装/未安装）+ 搜索 + 「全部折叠/展开」切换；每个 agent 一组（名称 + 版本号 + 右侧更新状态/安装按钮）；分组折叠状态会记住，重开应用保持。

### 1.1 安装与更新

- 未安装的 agent 显示「**安装**」（确认框告知将执行的命令，brew 优先，自动走 TUNA 镜像）
- 已安装的显示版本号，右侧按更新检查结果分三态：「**新版**」（有更新，点击即升级，悬停显示新版本号）/「**已更新**」（已是最新或刚更新完）/「**更新**」（该渠道查不到最新版时的普通按钮，如自更新安装的 claude/kimi）；检查走 brew info / npm view，进程内缓存，更新成功后自动重查
- 更新/安装过程是**实时终端**：输出滚动、可输入（`[y/n]` 在下方 `>` 行回答）、2 分钟无输出提醒、失败带诊断建议。渠道与安装方式一致：brew 安装的走 `brew upgrade`（含 opencode，不走其交互式自更新）；npm 安装的用**与目标二进制同目录的 npm**（同机多份 node/npm 时不会装错 prefix）

### 1.2 创建配置（profile）

一个 profile = 一套 API 配置（端点+密钥+模型列表），一个 agent 可建多个。表单字段：

| 字段 | 说明 |
|---|---|
| Agent | CLI 类型 |
| 名称 | 自定义标记，如「Zeta 中转」 |
| Base URL | 中转地址；「从预设快速填充」可选官方/公开端点 |
| API Key | 存 `keys.json`（0600），界面只显示尾号 |
| 协议 | 仅 Qwen（openai/anthropic）与 Kimi 需要，位于「高级配置」 |
| 模型列表 | **可多个**，首个默认；「获取模型」从端点拉取下拉选。表单上方会提示该 agent 的模型切换页上限：Claude Code 5 个、Gemini/Qwen/Kimi 注入模式仅首个生效（多模型需「设为全局」）、Codex/OpenCode 不限；超出上限会黄色提醒 |
| 附加环境变量 | 每行 `KEY=VALUE`，注入优先级最高，位于「高级配置」 |

辅助：Base URL 行内的**测试**按钮验证端点+密钥并显示延迟和模型数；保存后「⋯ → **验证**」会打开三层结果：① Ccode 字段与当前 CLI 配置文件能否解析；② CLI doctor / 启动预检；③ 最小 API 请求（鉴权、协议、模型是否存在与耗时）。密钥只在后端参与请求，不会进入验证结果或前端日志。**导入/导出**用于 JSON 备份（不含密钥）；行内操作：编辑、⋯（验证/复制/设为全局/恢复备份/删除）。

配置列表每行只保留**名称 / 端点主机名 / 默认模型 / 密钥状态**和「编辑、⋯」；完整模型列表与端点细节保留在编辑页或悬浮提示中。导入/导出在页面顶部「⋯」；有用量的 profile 在行内「⋯ → 用量与费用」打开悬浮卡（按模型近似归属，跨配置共享模型会重复计入）。

### 1.3 两种生效方式

- **注入模式（默认）**：终端页「启动」时配置只传给该进程，不改系统文件
- **全局模式**：「⋯ → 设为全局」写入 CLI 配置文件（如 `~/.claude/settings.json`），任何终端生效。同一 CLI 涉及的多个文件会作为一个完整批次写入：全部准备成功才替换，任何一步失败都会自动回滚。「恢复备份」恢复最近一个完整批次；恢复前会先备份当前状态，原恢复点不会被消耗。写入成功后会自动再跑本地解析与对应 CLI 配置检查；失败会直接展开验证结果，不必等到下次启动才发现配置损坏

### 1.4 多模型切换

profile 多个模型时，启动栏下拉选一个启动；CLI 内继续切换：

| CLI | 切换方式 |
|---|---|
| Claude Code | `/model`（前 5 个已注册进选择器） |
| Codex | `/model`（自动生成 model catalog） |
| Qwen / Kimi / OpenCode | `/model`（「设为全局」后列表完整） |
| Gemini | 只能 `/model set <模型id>` 手输（CLI 限制） |

## 二、工作区页（⛁）：任务级 git worktree 隔离

解决多个 agent 在同一目录并行冲突。工作区 = 独立 worktree + 分支 + 端口段。

### 2.1 创建

「新建工作区」→ 选仓库（只列真实 git 仓库，可手输）→ 填任务名 → 自动：原子预留端口段并写入「创建中」记录 → 拉 `ccode/<任务名>` 分支（基于**本地**主分支，含未推送的提交，工作区 = 你本地项目的现状）→ 建 worktree 到 `~/ccode/workspaces/<仓库>/<任务名>/` → 复制 `.env` 类文件 → 跑 setup 脚本 → 激活工作区。worktree、复制文件或数据库激活任一步失败，应用会补偿删除 worktree/分支/创建中记录并释放端口；复制失败会明确指出具体文件，不会再静默忽略。setup 失败仍保留已创建工作区并标记失败，方便进入终端修复。

成功后「打开终端」自动开标签（目录、端口环境变量已预置）。

### 2.2 项目自动化（.ccode/settings.toml）

```toml
files_to_copy = [".env", ".env.local"]
run_mode = "concurrent"            # nonconcurrent 时脚本互斥
[scripts]
setup = "npm install"               # 创建时执行
archive = "docker compose down"     # 归档前执行（失败阻止归档）
[scripts.run]
web = { command = "npm run dev", default = true }
test = { command = "npm run test" }
```

配了之后行内出现 **▶**（默认脚本）/ **▾**（全部脚本），点击开 shell 标签自动执行。`nonconcurrent` 模式下已有脚本运行时，▾ 菜单里其余脚本显示为禁用项并注明原因，不会静默消失。

### 2.3 行内信息与操作

列表是任务索引：每行只显示**任务名、状态**（可点开看分支、改动和阻塞原因）与高频主路径「⌨ 终端 / 评审」。活跃的 merge 冲突是唯一例外：主操作会直接显示警告色「**解决冲突**」，但仍进入与普通评审相同的终端全宽审阅。会话、运行脚本、复制路径、修复、恢复和删除等低频项位于「⋯」。

PR 与归档也从「⋯」定位到评审页内再确认，避免列表页和评审页各有一套完成流程。**归档不会丢未提交内容**：存在未提交改动时评审页会要求「提交并归档」；正在解冲突或仍有 agent/run 脚本运行时会拒绝归档。普通归档不强制移除工作树；只有明确的「删除」会使用强制删除语义。

如果用户在外部终端移动/删除仓库、worktree 或分支，或者留下未完成 merge，工作区行会显示**状态漂移**并暂停普通危险操作。按实际情况可选择「重新挂载」（重建/修复 worktree 关联）、「重新定位仓库」、「标记归档」或「清理记录」；后两项只改 Ccode 元数据，不删除磁盘目录或分支。已有 merge 现场继续进入统一的全屏冲突审阅。状态诊断本身失败时行内显示「**诊断失败 · 重试**」，点击重新检查，期间按健康状态降级展示、不整体隐藏操作。

### 2.4 评审与合并

- **评审（无冲突）**：行上点「评审」进入终端页的全宽任务审阅；终端标签和进程仍在后台保持运行。中间按文件连续展示左右对照 diff，右侧改动树可快速定位文件；顶部第二工具行可填写或用 ◈ 生成提交信息。默认主按钮「**提交并合并**」一次完成提交和本地合并，工作区继续保留；下拉仍可选「**仅提交**」或「**合并并归档**」。如果改动已提交，主按钮直接变为「合并」。提交后会重新做健康检查，不会因为进入快捷流程而绕过冲突、主仓脏或主仓分支错误等拦截。
- **PR 与归档**：从工作区「⋯」选择「在评审中创建 PR / 归档」会直接打开同一评审覆盖层中的对应确认框。创建 PR 仍需在框内填写/确认标题；归档仍会重新检查脏改动、merge 与运行中任务，绝不因入口收口而绕过安全检查。
- **审阅布局**：顶部固定显示任务、分支方向、文件数和总增删量，右上角固定主动作；有未提交改动时，提交信息与 ◈ 生成入口位于第二工具行。主区连续显示双栏 diff，文件标题吸顶，较长的未修改代码默认折叠；右侧仅保留文件搜索、目录树和当前进度，选中项会随主区滚动同步。这样搜索、定位、阅读和完成动作始终在稳定位置，不需要在右栏底部寻找按钮。
- **评审（有冲突）**：行上点「**解决冲突**」直接进入与普通评审相同的终端全宽覆盖层，终端标签和进程仍在后台运行。工作区干净时应用会自动在隔离工作区同步**当前最新**基准分支，不再先展示容易被误认为当前 main 的普通累计 diff；有未提交改动时先在顶部填写信息并「先提交改动」，提交后自动继续。准备完成后，中间区按文件连续展示完整双栏对照——左侧任务分支、右侧 main/基准分支，右侧冲突清单可快速定位。每个文件标题下方用紧凑的「选用」控件选择任务版或基准版，并显示已选结果；顶部也支持「全部任务版 / 全部 main 版」和「**◈ AI 建议 → 按建议选择**」。如果处理期间 main 又被其他工作区推进，旧对照会立即停止展示和选边，右上角提示「重新同步最新 main」；确认后应用放弃旧冲突现场并重新生成两侧。全部选完默认点「**完成解决并合并**」，应用会提交解决结果、重新检查健康度并合回本地主分支，工作区继续保留且不会推送；下拉可选「**仅保存解决结果**」稍后再合并。选边按整个文件生效；需要逐行混合两侧时，转到预览编辑器手动修改。若解决提交成功但最终合并被主仓脏、分支错误等条件拦截，会明确显示“解决结果已提交，但合并未完成”，处理拦截原因后点普通「合并」即可，不要重复解决冲突
- **改动面板任务视图**：worktree 里自动切换为 vs `merge-base(主分支, 任务分支)` 的累计 diff，头部「审阅」可随时展开上述全宽视图；原「提交 / 提交并推送」按钮保持不变
- **合并**：「合并」按钮高亮（=可合并）时可用，是拆分按钮——主按钮「**合并**」只合回主分支、**工作区保留**（终端继续用，之后可随时归档）；「**▾**」下拉可选「**合并并归档**」（合并后移除 worktree、自动归档；还留在工作树里的终端标签会自动 cd 回主仓库）。保留的工作区合并完成后，按钮变为禁用的「**已合并**」；继续产生新提交后自动恢复为「合并」。均只合到本地、不自动推送远程（主仓库 git 面板头部 ↑N 即领先远程的提交数）。前置：分支已提交、与基准无冲突、主仓库在主分支且干净，缺一按钮即灰，悬停看原因；合并被拒时报错会列出主仓库的脏文件。若最终 merge 仍失败，应用会自动 `git merge --abort`，主仓库不会停在冲突状态。若代码已合并但归档脚本失败，会明确显示「已合并、归档失败」，此时只需点「归档」重试
- **创建 PR**：弹窗填标题，正文留空自动摘要、或点「**◈ AI 起草**」生成结构化描述（变更点/动机/测试情况，可编辑）→ 推送分支 + `gh` 建 PR（需已登录 gh）。如果分支已推送但 `gh pr create` 失败，弹窗会显示「重试创建 PR」，不会重复推送

## 三、终端页（⌨）：并行工作主界面

三带布局：**左栏（搜索+最近项目+文件树）｜ 终端标签区 ｜ 右侧面板（对话/预览/改动）**。右侧面板左边缘可拖动调整宽度，普通宽度会在本机记忆；顶部「⇱」进入宽屏分栏，暂时隐藏工作树但保留终端，点「⇲」还原，也可双击「对话 / 预览 / 改动」页签切换。这样查看长 diff 或代码时不需要建立另一套全屏页面，任务审阅覆盖层仍保持独立。标签栏右侧「⤢ 专注」进入专注模式：**只剩终端**——左右栏、顶部标签条、标签内状态条全部隐藏；标签列表移到 App 侧栏（导航图标下方，纵向展示，可切换/关闭/新建），原状态条动作（停止/⟳恢复/⤴对话/对话/◎查找/修改）集成到侧栏的「⋯ 操作」菜单（按当前标签状态裁剪），菜单末项退出专注。

### 3.1 启动与标签

启动栏第一行固定按 agent → profile → 模型 → 目录 → 启动排列，目录会占用剩余宽度；技能数、工作区端口状态与 shell 状态在第二行。启动后启动栏**自动收缩为状态行**（点「修改」展开），只保留「对话 / 修改 / ⋯」；停止、恢复、打开 Shell、查找等按状态出现在「⋯」菜单。选择会记忆，每个工作区也会记住上次用的配置。

- **多标签**：「＋」开标签，各自独立进程；活跃标签为绿色下划线；关闭 × 悬停出现
- **重启恢复**：应用关闭前会在本机保存可恢复标签的名称、目录、agent/profile、模型和关联 sessionId；不会保存 PTY id、滚动输出、密钥、环境变量或 run 脚本命令。重开后标签以「**上次任务，可恢复**」占位出现，不会自动启动进程；点击「恢复任务」才创建新 PTY。上次目录或 profile 已不存在时会保留可编辑启动栏并明确提示，不会偷偷换目录或配置
- **停止/回落**：agent 退出自动回落登录 shell（「shell 模式」，提示「会话已保存，可一键恢复」）；shell 里 `exit` 彻底结束
- **打开 Shell**：纯终端标签（展开的启动栏或收缩状态行的「⋯」中）
- **⟳恢复 / ⤴对话**：收缩状态行的「⋯」按状态显示——⟳恢复 = 用刚才的 sessionId 接回原对话继续聊（shell 模式且可恢复时出现）；⤴对话 = 跳到对话页打开该对话回放（可做标记/保留/归档等整理）

> **「进程 vs 会话」心智模型**：进程是标签里正在跑的活的（agent 或 shell），一次一个、不可复活；会话是写在盘上的对话记录，进程死了它还在。停止 agent = 杀进程不杀会话；shell 回落 = 进程空窗期补位；恢复 = 拿盘上的会话开新进程接着聊。
- **注意力标记**：绿点脉冲=工作中，蓝点=已完成等你输入，琥珀点=待确认（显示在标签和运行中面板）

### 3.2 对话联动

启动后点「对话」打开右侧结构化视图。头部显示标题、Agent、会话 ID，以及「识别中 / 同步中 / 已结束 / 等待关联」状态；正文只保留最近 **50 条**，每 3 秒按文件签名增量刷新，不再反复解析整份长会话。点「**完整回放**」可精确跳到对话页继续向前加载历史。

Claude/Qwen 用 `--session-id` 确定性锁定；其余 agent 由后端按 **Agent + 项目 + 启动批次**排他认领，同目录并发标签不会抢到同一条会话，跳转和运行态登记也始终使用 `agent + sessionId` 复合标识。运行中的会话在对话页带绿点「进行中」，可点击跳回对应终端标签。

对话滚动只在你原本位于底部附近时跟随新消息；向上阅读后不会被强制拉回底部，而是在右下角显示「**有新消息 ↓**」。重新切换标签或重新打开对话面板时，才定位到该标签的最新内容。

### 3.3 文件树（左栏）

三段：**搜索框 → 最近项目 → 完整树**。

- **搜索框**：当前根目录内按文件名搜索（跳过隐藏目录/构建产物）；结果点击 = 树内定位+高亮
- **最近项目**：按各 Agent 会话的最近更新时间聚合、去重并排序，最多展示 4 个，当前文件树所在项目不重复出现。应用启动时后台预取，并用上次成功结果立即占位展示；首次无缓存时先显示固定骨架，因此进入终端页不会等扫描完成后突然把文件树向下顶开。点击 = 树和终端 cwd 一起切过去（真进入）；↗ 另开标签。缓存中的目录点击前仍会重新验证，已移动或删除时不会切进无效路径
- **树**：双击钻取；「←」返回上一级；`⌂` 回到当前项目；自动刷新（噪声过滤）；git 状态字母（M/A/?/D）。树根跟随终端的**真实 cwd**——切标签、shell 里 `cd` 都会跟（每 4 秒探测一次；启动栏输入框聚焦时不打扰）。根目录名旁标注归属：绿点「**分支**」= 在工作区工作树里，黄点「**主仓库**」= 在主仓库里（改动不进任何分支）；命中工作区时出现「**⇄**」下拉——列出主项目 + 该仓库全部活跃工作区，任意切换（树和终端 cwd 一起切）
- **右键**：目录 = 打开终端/新建文件夹（内联输入）/删除；文件 = 删除。系统目录、关键用户目录、CLI 配置、.git 等**重要路径一律拒绝删除**
- **预览**：单击文件 → 右侧 Monaco 编辑器（**按扩展名语法高亮**），可编辑（脏标记 ●，保存写回；>256KB/二进制只读）。在当前树根内预览保持已打开文件；**切换项目、工作区、终端标签 cwd 或树根时自动清空旧预览**，不会擅自打开新根下的同名文件。未保存时先确认，取消则不切换树根。**磁盘被外部改写（合并/agent 写入等）时自动刷新内容**（编辑中不覆盖）。文件名旁标注路径归属：绿点「分支 ccode/x」= 在工作区工作树里（改动属于该分支）；黄点「**主仓库（非分支）**」= 在主仓库里——此时保存按钮变「**保存到主仓库**」（警示色）且保存前二次确认，防止误改主项目

### 3.4 git 改动面板（右侧「改动」页签）

分支、领先/落后、+/- 行数（含未跟踪）、文件列表，8 秒刷新。**点击任一文件行可在面板内展开/收起单文件 diff**；新增/删除行只使用语义色文字与左侧细线，不再整行铺绿色或红色背景，代码主体保持冷黑底，hunk 标题才使用轻微 inset 底色。未跟踪文本按全新增显示，二进制文件给出只读提示，超大内容最多读取约 200 KB 并明确标记截断。读取前后都会核对该路径仍属于当前 Git 改动，过期或越界路径会拒绝。工作区任务头部增加「**审阅**」入口，展开全宽 diff 与提交合并闭环；普通仓库不显示。

**普通仓库默认不勾选文件**，可逐文件选择或全选/清空，并明确显示「将提交 N / M 个文件」；提交和 ◈ 生成都只读取所选文件，未选文件保持在工作区。隔离任务工作区仍固定提交全部任务改动，避免把一个任务拆成难以理解的半提交。提交信息可以手动填写，也可点输入框旁的「**◈**」让 AI 按 diff 生成后再审阅。若直接留空，按钮自动变为「**快速提交** / **快速提交并推送**」：应用按文件状态和数量在本地即时生成中性默认信息，不调用 AI，直接提交或推送（无上游自动 `push -u`）。提交阶段失败会把默认信息留在输入框供修改或重试；如果提交已成功但推送失败，会显示「**重试推送**」，只执行 push，不会重复提交。成功时右下角浮出主题绿 toast，展示提交号和实际使用的提交标题。

### 3.5 终端质感

WebGL 渲染（失败时自动回退）、清瘦字形（400/600 字重、行高 1.2、零字距，向 Ghostty 锐利度靠）、盒绘字符对齐、粗体增亮、平滑滚动 150ms、细滚动条。默认字体为打包内置的 JetBrains Mono（woff2，不依赖系统安装），可在设置页换其他字体或调色板预设。后台标签输出只缓存不推流（切回补发），输出 50ms 合帧——十余个标签并行也流畅。

**输出搜索**：⌘/Ctrl+F 或工具栏「◎ 查找」呼出搜索条（输入即增量查找，Enter 下一个、Shift+Enter 上一个、Esc 关闭），只作用于当前活跃标签。

## 四、对话页（◔）：历史回放与整理

- **左栏分类树**：全部 / 按 agent → 按项目；顶部搜索（项目/标题/标签/工作区名/**AI 摘要内容**）。Ccode 自己发起的 ◈ 无头 AI 会话不混进普通项目，默认归并到单独的「**Ccode 内部 AI**」入口；分类只认后端登记的精确来源，不按临时目录名称猜测
- **归档计数**：「显示已归档」关闭时，全部、Agent、项目和内部 AI 的数字都排除归档项；打开后统一计入，避免左栏数字与列表结果口径不一致
- **列表与标题**：显示标题、相对时间、agent、token 用量；工作区会话另带 ⎇ 任务名 badge；头部同时显示「当前 N · 搜索命中 M · 总计 T」；Codex resume 链合并（「N 次继续」）；⚑=已保留；绿点「进行中」（内部启动的可点击跳回终端；**外部终端里运行的会话**也按文件活跃度自动标记，仅显示）。标题会折叠换行与多余空格，并忽略 `New Session`、`Untitled`、`未命名对话` 等占位值，优先回落到首条真实用户消息；仍无标题时显示「未命名对话 · ID 前 8 位」
- **对话回放**：首次只读取会话尾部的有界窗口；长会话顶部显示「**加载更早对话**」，逐页向前加载并保持当前阅读位置。OpenCode 每页最多 80 条消息；普通 JSONL 每页最多读取约 192 KB；压缩的旧 Codex 会话只提供有界尾部回放。头部保留「**◈ 摘要**」（AI 概括，缓存）与「**导出**」（整段对话导出 Markdown 到 `~/Downloads/ccode-exports/`）
- **当前项目改动**：「对话 | 当前项目改动」页签中的后者只读展示该项目**此刻磁盘上的 Git 状态**，不是历史会话产生改动的快照；可点击文件展开 diff，但不提供提交或推送，点「前往终端处理」进入正常编辑/提交流程
- **在终端恢复**：行悬停/右键或回放头部 → 自动开标签续聊（claude `-r`、codex `resume`、kimi `-S` 等）
- **⇗ 外部恢复 / ⧉ 复制命令**：不想用内嵌终端时——⇗ 直接在外部终端应用里开窗口续聊（macOS 依次找 Ghostty → iTerm → 系统终端；Windows 开 cmd 新窗口；Linux 找 gnome-terminal/konsole/xterm）；⧉ 复制形如 `codex resume 019fbd46-…` 的恢复命令（含 `cd` 到项目目录），粘贴到任何终端自己执行。两者都用你机器上的全局 CLI 配置（不携带 Ccode profile 注入的密钥）
- **整理**：保留（pin 快照，CLI 自动删除后也能回放）、归档（默认隐藏）、自定义标题/标签、删除会话文件（OpenCode 删除其库中记录；Codex resume 链会连带删除链上成员文件）；项目节点右键批量删除——删除范围含该项目的全部会话：已归档/内部对话即使不在当前列表中也会被一并删除（确认框会明确提示数量）
- **批量删除**：列表头部「批量管理」进入选择模式 → 勾选/全选（当前筛选结果）→「删除 N 项」→ 警示色二次确认「确认删除 N 项（含 pin 快照）？」后逐个删除（pin 快照一并清理，与单个删除同语义）。筛选/搜索无结果时显示「清除筛选」按钮
- **敏感信息保护**：会话标题、回放正文、AI 摘要和 Markdown 导出在后端统一隐藏已保存密钥及常见密钥前缀；脱敏完成后才会送到界面，CLI 的原始会话文件保持只读、不被改写

## 五、技能页（✦）：Skills 统一管理

技能 = 含 `SKILL.md` 的目录（开放标准）。先入库，再分发到各 CLI。

- **分类分组**：可折叠分类头（▸/▾）；修改分类在行内「⋯ → 设置分类」内联输入（回车保存，留空归未分类）
- **应用开关**：每行六个 agent 圆点开关（claude/codex/gemini/qwen/oc/kimi），绿点=已分发到对应 CLI 技能目录（symlink 优先 copy 兜底），灰点=未分发，点击即切换；关闭只清理由 Ccode 分发的。形态不再用药丸文本标注，悬浮在开关上显示完整说明（symlink / copy，copy 带漂移检测）
- **副本漂移**：copy 副本与库不一致时，技能名旁显示黄点（悬浮列出漂移的 agent），行内「⋯ → 重新分发副本」把库里的最新版本重新同步过去
- **导入**：本地目录 / ZIP / GitHub 仓库（`owner/repo` 或完整网址，可另填分支/子目录，预设 anthropics/skills）/「发现未纳管」（页面顶部 ⋯，扫描各 CLI 目录收编）。结果完整分列**新增、覆盖更新、跳过、冲突**四类并逐类列出技能名，不用「已导入 0 个」掩盖冲突；冲突可批量跳过、按右栏名称**全部另存为**、或**备份并覆盖**（覆盖前先备份旧库目录）。ZIP 先在临时目录完整校验再入库，元数据写入失败会回滚库目录
- **GitHub 更新**：GitHub 来源会记录仓库、子目录与 revision；页面顶部「⋯ → 检查 GitHub 更新」，有可更新时行名旁显示黄点，行内 ⋯ 可「导入 GitHub 更新」带原地址重新打开导入器。重新导入仍经过同名冲突确认，不会静默覆盖
- **导出**：全部打包 ZIP 位于页面顶部 ⋯，单行导出位于行内 ⋯；**查看**：右侧预览 SKILL.md（标注来源与仓库）；**删除**：位于行内 ⋯，取消应用 + 库文件备份（5 份）

按消息逐条解析用量、按天聚合（增量更新）。

## 八、AI 功能说明（◈）

四处 ◈ 按钮（git 提交信息、会话摘要、PR 描述、冲突审查建议）都通过 **headless 模式调用 agent**：把上下文（diff/会话/提交记录/冲突文件）发给该 CLI 的 print 模式（如 `kimi -p`、`claude -p`），纯文本生成（不依赖工具调用），不产生交互会话。profile 选择顺序：设置页「AI 专用配置」（如已选）→ 最近使用的 profile；生成慢多半是因为自动落到了大模型上，在设置页指定一个快模型即可。专用 profile 被删除时会报错提示重选，不会静默落到别的配置。失败时先检查所选 profile 是否可用。

## 九、常见问题（FAQ）

**Q：macOS 安装后打开提示「已损坏，无法打开」？**
A：不是真损坏——未签名应用从网络下载会带 quarantine 隔离标记，Gatekeeper 因此拦截。终端执行 `xattr -cr /Applications/Ccode.app` 即可。每次重新下载安装都要执行一次，做了签名公证后此问题消失。

**Q：agent 不真正执行操作（不建文件等）？**
A：中转模型不支持工具调用（实测 zetatechs 部分模型只会文字糊弄）。换真 Claude 系模型或支持工具调用的中转。

**Q：配置保存了但调用报空响应/404？**
A：Base URL 的 `/v1` 约定：OpenAI 协议（kimi/codex/qwen/opencode）**必须带** `/v1`；Anthropic 协议（claude）**不要带**。建完先点「测试连接」。

**Q：按钮点了没反应？**
A：macOS WKWebView 不支持 `window.prompt`——需要输入的地方已全部改为内联输入；如仍遇到，把位置报给开发者。

**Q：终端输出黑白？**
A：已内置修复（注入 TERM/COLORTERM、剔除 NO_COLOR）。

**Q：安装/更新卡在下载？**
A：brew 已走 TUNA 镜像（设置页可关）；npm 慢的话在 profile 附加环境变量加 `npm_config_registry=https://registry.npmmirror.com`。

**Q：改了模型列表，CLI 里 /model 没变？**
A：注入配置只在新启动的会话生效，重启该终端标签。

**Q：工作区的会话在历史里归到哪？**
A：所属仓库的项目下，带 `⎇ 任务名` 标签；工作区删除后显示为独立项目（源文件仍在）。
