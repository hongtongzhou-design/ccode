# Ccode 使用手册

> 本文档随产品功能实时更新（改动功能时必须同步本文档，见 AGENTS.md 规则）。
> 最后更新：2026-08-01（AI 三件套 + 设置/主题版）

Ccode 是 AI 编码 Agent 的统一工作台：管理六个 CLI agent（Claude Code、Codex、Gemini CLI、Qwen Code、OpenCode、Kimi Code）的 API 配置，内嵌终端一键启动，git worktree 任务工作区，会话历史回放，用量统计，技能分发，以及三处 AI 辅助（提交信息/会话摘要/PR 描述）。

侧栏七个页面：**配置 / 工作区 / 终端 / 会话 / 技能 / 统计 / 设置**。侧栏底部「«」可折叠为纯图标栏。

**模块是打通的**：配置页建的 profile 在终端页一键启动；终端里跑的会话在会话页实时可见（🟢 点击跳回）；历史会话一键「在终端恢复」；工作区自动完成装依赖、起服务、评审合并；AI 按钮（◈）用你最近使用的 profile 提供辅助。典型动线：**配置 →（工作区）→ 终端 ⇄ 会话**。

## 一、配置页（⇄）：agent 与 API 配置管理

页面 = 可折叠分组列表。顶部筛选（全部/已安装/未安装）+ 搜索；每个 agent 一组（名称 + 安装状态 + 版本 + 右侧更新/安装按钮）；有配置的分组默认展开。

### 1.1 安装与更新

- 未安装的 agent 显示「**安装**」（确认框告知将执行的命令，brew 优先，自动走 TUNA 镜像）
- 已安装显示「**更新**」；过程是**实时终端**：输出滚动、可输入（`[y/n]` 在下方 `>` 行回答）、2 分钟无输出提醒、失败带诊断建议

### 1.2 创建配置（profile）

一个 profile = 一套 API 配置（端点+密钥+模型列表），一个 agent 可建多个。表单字段：

| 字段 | 说明 |
|---|---|
| Agent | CLI 类型 |
| 名称 | 自定义标记，如「Zeta 中转」 |
| Base URL | 中转地址；「从预设快速填充」可选官方/公开端点 |
| API Key | 存 `keys.json`（0600），界面只显示尾号 |
| 协议 | 仅 Qwen（openai/anthropic）与 Kimi 需要 |
| 模型列表 | **可多个**，首个默认；「获取模型」从端点拉取下拉选 |
| 附加环境变量 | 每行 `KEY=VALUE`，注入优先级最高 |

辅助：**测试连接**（验证端点+密钥，显示延迟和模型数）；**导入/导出**（JSON 备份，不含密钥）；行内操作：编辑、⋯（复制/设为全局/恢复备份/删除）。

行内还会显示：**上次使用时间**；有用量的 profile 名称旁有「**▸用量**」按钮 → 悬浮卡显示输入/输出 token 和官方价费用（按模型近似归属，跨配置共享模型会重复计入，悬停有说明）。

### 1.3 两种生效方式

- **注入模式（默认）**：终端页「启动」时配置只传给该进程，不改系统文件
- **全局模式**：「⋯ → 设为全局」写入 CLI 配置文件（如 `~/.claude/settings.json`），任何终端生效；写前自动备份（保留 5 份），「恢复备份」可还原

### 1.4 多模型切换

profile 多个模型时，启动栏下拉选一个启动；CLI 内继续切换：

| CLI | 切换方式 |
|---|---|
| Claude Code | `/model`（前 5 个已注册进选择器） |
| Codex | `/model`（自动生成 model catalog） |
| Qwen / Kimi / OpenCode | `/model`（「设为全局」后列表完整） |
| Gemini | 只能 `/model set <模型id>` 手输（CLI 限制） |

## 二、工作区页（⛁）：任务级 git worktree 隔离

解决多个 agent 在同一目录并行冲突。工作区 = 独立 worktree + 分支 + 端口段。

### 2.1 创建

「新建工作区」→ 选仓库（只列真实 git 仓库，可手输）→ 填任务名 → 自动：拉 `ccode/<任务名>` 分支（基于**本地**主分支，含未推送的提交，工作区 = 你本地项目的现状）→ 建 worktree 到 `~/ccode/workspaces/<仓库>/<任务名>/` → 复制 `.env` 类文件 → 跑 setup 脚本 → 分配端口段（4000 起 10 个）。

成功后「打开终端」自动开标签（目录、端口环境变量已预置）。

### 2.2 项目自动化（.ccode/settings.toml）

```toml
files_to_copy = [".env", ".env.local"]
run_mode = "concurrent"            # nonconcurrent 时脚本互斥
[scripts]
setup = "npm install"               # 创建时执行
archive = "docker compose down"     # 归档前执行（失败阻止归档）
[scripts.run]
web = { command = "npm run dev", default = true }
test = { command = "npm run test" }
```

配了之后行内出现 **▶**（默认脚本）/ **▾**（全部脚本），点击开 shell 标签自动执行。

### 2.3 行内信息与操作

状态 pill：**活跃**（主题强调色）/ 已归档；健康 pill：**可合并**（强调色）/ 有冲突 / 有未提交 / ↑↓领先落后。
操作：打开终端（记住上次用的 profile）、会话（跳到会话页筛选）、归档 / 恢复 / 删除（分支也删，有确认）。

### 2.4 评审与合并

- **改动面板任务视图**：worktree 里自动切换为 vs `merge-base(主分支, 任务分支)` 的累计 diff
- **合并**：「可合并」后点「合并」→ `--no-ff` 合并回主分支并自动归档。前置：主仓库在主分支且干净，否则按提示处理
- **创建 PR**：弹窗填标题，正文留空自动摘要、或点「**◈ AI 起草**」生成结构化描述（变更点/动机/测试情况，可编辑）→ 推送分支 + `gh` 建 PR（需已登录 gh）

## 三、终端页（⌨）：并行工作主界面

三带布局：**左栏（搜索+最近项目+文件树）｜ 终端标签区 ｜ 右侧面板（会话/预览/改动）**。标签栏右侧「⤢ 专注」隐藏左右栏。

### 3.1 启动与标签

启动栏：agent → profile（旁有「◈ N 技能」提示该 agent 启用的技能数）→ 模型 → 目录 → 启动。启动后启动栏**自动收缩为状态行**（点「修改」展开）。选择会记忆，每个工作区也会记住上次用的配置。

- **多标签**：「＋」开标签，各自独立进程；活跃标签为绿色下划线；关闭 × 悬停出现
- **停止/回落**：agent 退出自动回落登录 shell（「shell 模式」，提示「会话已保存，可一键恢复」）；shell 里 `exit` 彻底结束
- **打开 Shell**：纯终端标签（在展开的启动栏里）
- **⟳恢复 / ⤴对话**：收缩状态行「会话」「修改」左侧的两个按钮——⟳恢复 = 用刚才的 sessionId 接回原对话继续聊（shell 模式且可恢复时出现）；⤴对话 = 跳转到会话页打开该对话回放（可做标记/保留/归档等整理）

> **「进程 vs 会话」心智模型**：进程是标签里正在跑的活的（agent 或 shell），一次一个、不可复活；会话是写在盘上的对话记录，进程死了它还在。停止 agent = 杀进程不杀会话；shell 回落 = 进程空窗期补位；恢复 = 拿盘上的会话开新进程接着聊。
- **注意力标记**：绿点脉冲=工作中，蓝点=已完成等你输入，琥珀点=待确认（显示在标签和运行中面板）

### 3.2 会话联动

启动后启动栏出现「会话」按钮 → 右侧面板实时显示结构化对话（3 秒刷新）。Claude/Qwen 用 `--session-id` 确定性锁定，其他 agent 按（agent+目录+启动时间）探测。补充：运行中的会话在会话页带 🟢「进行中」，点击跳回终端标签；终端标签也可经 ⤴对话 跳到会话页。

### 3.3 文件树（左栏）

三段：**搜索框 → 最近项目 → 完整树**。

- **搜索框**：当前根目录内按文件名搜索（跳过隐藏目录/构建产物）；结果点击 = 树内定位+高亮
- **最近项目**：按活跃排序，点击 = 树和终端 cwd 一起切过去（真进入）；↗ 另开标签
- **树**：双击钻取；「←」返回上一级；`⌂` 回到当前项目；自动刷新（噪声过滤）；git 状态字母（M/A/?/D）
- **右键**：目录 = 打开终端/新建文件夹（内联输入）/删除；文件 = 删除。系统目录、关键用户目录、CLI 配置、.git 等**重要路径一律拒绝删除**
- **预览**：单击文件 → 右侧 Monaco 编辑器（**按扩展名语法高亮**），可编辑（脏标记 ●，保存写回；>256KB/二进制只读）

### 3.4 git 改动面板（右侧「改动」页签）

分支、领先/落后、+/- 行数（含未跟踪）、文件列表，8 秒刷新。提交信息输入框旁的「**◈**」= AI 按 diff 生成提交信息（conventional commits 风格），确认后点「提交」/「提交并推送」（无上游自动 `push -u`）。

### 3.5 终端质感

WebGL 渲染（GPU）、清瘦字形（400/600 字重、行高 1.2、零字距，向 Ghostty 锐利度靠）、盒绘字符对齐、粗体增亮、平滑滚动 150ms、细滚动条。默认字体为打包内置的 JetBrains Mono（woff2，不依赖系统安装），可在设置页换其他字体或调色板预设。后台标签输出只缓存不推流（切回补发），输出 50ms 合帧——十余个标签并行也流畅。

## 四、会话页（◔）：历史回放与整理

- **左栏分类树**：全部 / 按 agent → 按项目；顶部搜索（项目/标题/标签/工作区名）
- **列表**：标题、相对时间、agent、token 用量；Codex resume 链合并（「N 次继续」）；⚑=已保留；🟢进行中（内部启动的可点击跳回终端；**外部终端里运行的会话**也按文件活跃度自动标记，仅显示）
- **回放**：「对话 | 改动」页签切换——对话 = 结构化对话（思考折叠、工具芯片）+ 头部「**◈ 摘要**」（AI 概括，缓存）；改动 = 该会话项目的 git diff（含提交框与 ◈ AI 提交信息），**外部会话的改动也能直接提交/推送**（提交前留意「进行中」标记，避免和 agent 撞车）
- **在终端恢复**：行悬停/右键或回放头部 → 自动开标签续聊（claude `-r`、codex `resume`、kimi `-S` 等）
- **整理**：保留（pin 快照，CLI 自动删除后也能回放）、归档（默认隐藏）、自定义标题/标签、删除会话文件；项目节点右键批量删除

## 五、技能页（✦）：Skills 统一管理

技能 = 含 `SKILL.md` 的目录（开放标准）。先入库，再分发到各 CLI。

- **分类分组**：可折叠分类头（▸/▾），行内「分类: xxx」按钮内联改名（回车保存，留空归未分类）
- **应用开关**：每行六个 agent 药丸开关（claude/codex/gemini/qwen/oc/kimi），点亮即分发到对应 CLI 技能目录（symlink 优先 copy 兜底），关闭只清理由 Ccode 分发的；copy 副本与库不一致时显示「副本过期」+ 一键「重新分发」
- **导入**：本地目录 / ZIP / GitHub 仓库（`owner/repo` 或完整网址，预设 anthropics/skills）/ 「发现未纳管」（扫描各 CLI 目录收编）
- **导出**：单行或全部打包 ZIP；**查看**：右侧预览 SKILL.md；**删除**：取消应用 + 库文件备份（5 份）

## 六、统计页（◫）：用量与费用

按消息逐条解析用量、按天聚合（增量更新）。

- **卡片**：输入/输出/缓存读（含写）tokens、会话数、估算费用（官方价）
- **范围**：今日/近 7 天/近 30 天/全部；「刷新」手动重建索引
- **分布**：agent 条形图、项目排行、模型明细
- **费用口径**：官方公开价（27 项定价，供应商前缀自动剥离），标注「费用(官方价)」；含未计价模型显示 `≥`；底部有免责说明
- **$/¥ 切换**：范围旁的按钮一键换算（汇率默认 7.2，设置页可改）

## 七、设置页（⛭）

- **主题**：七套深色色卡（沉浸黑/陶土/Ayu 琥珀/Catppuccin/极简灰蓝/Dracula/灰蓝正红），各有独立强调色（CTA/选中/「活跃」「可合并」pill 同步换色），点击即时全站切换
- **终端字体**：内置 JetBrains Mono（默认）+ 常用等宽字体候选，也可填系统已装的任意字体名；**终端调色板**：VS Code Dark+（默认）等多套预设，切换即时生效
- **终端字号**：11-18，实时生效；**滚动缓冲行数**：新标签生效
- **汇率**：USD→CNY，统计页 ¥ 换算
- **brew 镜像开关**：安装/更新是否走 TUNA
- **AI 专用配置**：◈ 生成（提交信息/会话摘要/PR 描述）固定使用的 profile，建议选快模型（生成速度主要取决于它）；默认「自动」= 最近使用的 profile
- **自定义定价**：文本框编辑 pricing.json（带校验），下一次统计查询生效

## 八、AI 功能说明（◈）

三处 ◈ 按钮（git 提交信息、会话摘要、PR 描述）都通过 **headless 模式调用 agent**：把上下文（diff/会话/提交记录）发给该 CLI 的 print 模式（如 `kimi -p`、`claude -p`），纯文本生成（不依赖工具调用），不产生交互会话。profile 选择顺序：设置页「AI 专用配置」（如已选）→ 最近使用的 profile；生成慢多半是因为自动落到了大模型上，在设置页指定一个快模型即可。专用 profile 被删除时会报错提示重选，不会静默落到别的配置。失败时先检查所选 profile 是否可用。

## 九、常见问题（FAQ）

**Q：macOS 安装后打开提示「已损坏，无法打开」？**
A：不是真损坏——未签名应用从网络下载会带 quarantine 隔离标记，Gatekeeper 因此拦截。终端执行 `xattr -cr /Applications/Ccode.app` 即可。每次重新下载安装都要执行一次，做了签名公证后此问题消失。

**Q：agent 不真正执行操作（不建文件等）？**
A：中转模型不支持工具调用（实测 zetatechs 部分模型只会文字糊弄）。换真 Claude 系模型或支持工具调用的中转。

**Q：配置保存了但调用报空响应/404？**
A：Base URL 的 `/v1` 约定：OpenAI 协议（kimi/codex/qwen/opencode）**必须带** `/v1`；Anthropic 协议（claude）**不要带**。建完先点「测试连接」。

**Q：按钮点了没反应？**
A：macOS WKWebView 不支持 `window.prompt`——需要输入的地方已全部改为内联输入；如仍遇到，把位置报给开发者。

**Q：终端输出黑白？**
A：已内置修复（注入 TERM/COLORTERM、剔除 NO_COLOR）。

**Q：安装/更新卡在下载？**
A：brew 已走 TUNA 镜像（设置页可关）；npm 慢的话在 profile 附加环境变量加 `npm_config_registry=https://registry.npmmirror.com`。

**Q：改了模型列表，CLI 里 /model 没变？**
A：注入配置只在新启动的会话生效，重启该终端标签。

**Q：工作区的会话在历史里归到哪？**
A：所属仓库的项目下，带 `⎇ 任务名` 标签；工作区删除后显示为独立项目（源文件仍在）。
