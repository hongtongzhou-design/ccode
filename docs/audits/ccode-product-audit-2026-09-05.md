## 审查范围

从科研工作者、编程者、普通工作用户和软件审查专家四个角度，覆盖全部一级页面和主要功能组件：快速开聊、工作台、项目/科研流程、连接与模型、终端/聊天、会话、技能、MCP、统计、设置，以及文件树、Git、阅读器、文献雷达、定时任务、办公和编程工作区。

## 本轮直接修复

| 优先级 | 问题 | 处理 |
| --- | --- | --- |
| P1 | 快速开聊记住的连接被删除、停用或已知失效时仍静默直达 | 自动路径排除软停用、缺槽、缺网关、缺密钥、测试失败、模型未同步/失效；无可用配置时回到弹层 |
| P1 | 工作台项目/工作区加载失败与“暂无项目”混淆 | 增加局部错误提示和重试；不影响仍可用的最近会话、收件箱和快速开聊 |
| P1 | 科研模板、网关同步、连接状态、暂停决策和模型能力接口缺少回归验收记录 | 纳入本审查验收清单与既有测试命令 |
| P1 | 定时任务技能分发失败被静默吞掉，用户误以为任务可完整运行 | 日程仍可保存，但创建、编辑和运行配置修改均显示明确分发失败提示 |
| P1 | 机器验收可通过符号链接读取项目根外文件 | 对文件、目录、glob、文本和 JSON 记录验收统一 canonicalize，并用 `path_within_path` 限制在项目根内 |
| P1 | 设置页连接配置加载失败与空配置混淆 | 加载失败显示“连接配置加载失败”及重试入口，避免误操作覆盖配置 |
| P1 | 外部科研工具方案停留在备档，未进入可用技能库 | 注册 `origin-plot`、`zotero-sync`、`endnote-bridge` 为内置技能；仅 Zotero 默认挂到三套科研模板的文献检索步骤，Origin/EndNote 保持按需启用 |

## 按角色发现的风险

### 科研工作者

- 流程步骤必须同时显示“未完成、待机器验收、待人工确认”，不能只靠颜色判断。
- 文献、实验矩阵和字段验收应逐条保留失败原因、证据位置和重试入口。
- 模板变更要有版本/迁移提示，避免旧项目被新模板静默改写。

### 编程者

- 工作台、运行标签、工作区和会话必须以同一个 Project → Task → Run 归属链为准。
- 连接目录、Agent 绑定模型和全局配置属于不同来源，界面应持续显示同步/漂移状态。
- 后端调用失败不得被空 catch 吞掉；可选探测可降级，项目、工作区、连接和保存失败必须可见。

### 普通工作用户

- “网关、协议槽、绑定模型、全局生效”需要在动作附近给出下一步，而不是只给技术状态名。
- 数据清理、恢复默认、导出诊断等设置操作应显示影响范围，并在成功/失败后给出结果。
- 无项目、无流程、无会话、目录已移动等空态要提供一个明确的下一步动作。

### 软件审查

- 高风险路径重点检查：自动选择失效配置、静默失败、竞态覆盖、跨平台路径比较、密钥进入日志/命令行。
- 当前未新增依赖或改变公开存储格式。
- 完整 Rust 测试仍受本机 macOS Finder/权限沙箱影响，需在 CI 或权限完整环境复验。

## 后续优化分级

### P1

1. 统一设置页加载/保存、字体安装、诊断导出和数据清理的成功/失败反馈。
2. 连接页为 `model_unsynced`、`catalog_stale` 提供就地“同步目录/替换绑定”动作。
3. 工作台将项目、工作区、科研步骤和编码概览的局部失败拆成可重试的分区状态。

### P2

1. 为项目/流程/连接状态增加可访问性文本和键盘操作验收。
2. 为普通用户提供“基础/高级”设置解释层。
3. 对长任务的 `auto_continue / soft_pause / hard_pause` 记录决策原因和恢复入口。

### P3

1. 增加跨平台 UI 自动化验收矩阵。
2. 将审查报告中的状态机和验收证据链接到诊断导出。
