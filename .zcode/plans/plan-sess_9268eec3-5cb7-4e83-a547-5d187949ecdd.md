# 机构窗口 PDF 落盘链路重构——单一漏斗方案

## 为什么一直反复出问题（源码级结论，已查证）

1. **Tauri 2.11.5 本来就有 `WebviewWindowBuilder::on_download`**（`DownloadEvent::Requested` 可改写保存路径或拒绝，`Finished` 完成回调；wry 在 macOS/Windows/Linux 三平台都实现了对应桥接）。我此前没用它，全靠「注入脚本合成下载 + 监听 ~/Downloads」绕路——而出版商对合成请求回落地页 HTML（13:59 实测），非受控下载落点也说不清。
2. **wry 导航策略实证**：带 `download` 属性/attachment 的请求走下载通道（默认落 ~/Downloads）；**application/pdf 主框架导航会被 WKWebView 内联渲染**——内联 PDF 没有文档对象、脚本全部失效，⤓ 也消失。这就是「点下载没反应/行为各异/⤓ 不见」的底层原因。
3. ⤓ 按钮只在 DOMContentLoaded 检查**一次**，meta/链接晚出现或页面形态不同就永远不出现；且 JS 正则与 Rust 侧 `pdf_link_candidates` 口径不一致（epdf/stamp.jsp 缺失）。
4. 本地 TCP 中继（127.0.0.1 监听）已是**死代码**（页侧零调用），它的占位符替换是历次脚本语法事故的根源。
5. 「WPS 里打开」= `tauri-plugin-opener` 的「系统应用打开」路径（文件已在盘上才会发生），与登录窗口下载链路是两回事。

## 新架构：一条漏斗

```
窗口内任何下载（页面自带按钮的 attachment 响应 / ⤓ 触发 / 拦截转下载）
  → WKDownload → on_download Requested
      destination 改写为 <config>/ccode/tmp/inst-dl/<uuid>-<净化文件名>
      窗内浮条「下载中…完成后自动存进项目」
  → on_download Finished
      读暂存 → %PDF- 魔数校验（不是 PDF=诚实报错+清理，不再存 HTML 进项目）
      → 复用已验证的 stage_relayed_pdf → inst-pdf-relayed 事件 → App 监听
      → inst_save_relayed_pdf → papers/ + 资源登记 → 窗内「✓ 已存进 papers/」
```

## 具体改动（全部在 inst_access.rs + 少量前端测试/文档）

1. **登录窗 builder 链上 `.on_download`**：
   - `Requested`：destination 改写到受控暂存目录（文件名经 `sanitize_fs_name`，带 uuid 防并发）；`static` active map 记 url→path；eval 窗内「下载中」浮条；返回 true。
   - `Finished`（macOS 无落盘路径，靠 map）：读暂存 → 魔数/60MB 校验 → 走现有入库链；map miss（重定向等）时扫暂存目录近期未导入文件兜底；失败 toast 诚实报错并清理。
2. **重写 LOGIN_INIT_SCRIPT**：
   - ⤓ 改**常驻胶囊** + 每 2s 周期重检测：检测到直链=可点「⤓ 取 PDF（自动存进项目）」；未检测到=置灰「未检测到直链，用页面自带下载按钮即可，Mesa 会自动接住」。不再一次判定永久沉默。
   - `__mesaGrab` 双层传输（都在真实页上下文，服务端无法与页面自身请求区分）：先 `fetch(url, {credentials:'include'})` → blob → `a[download]` 点击（走同一 on_download 漏斗）；fetch 失败回落远端 URL 直接下载（同漏斗）。
   - 正则与 Rust `pdf_link_candidates` 对齐（补 epdf/stamp.jsp）；删 `__MESA_RELAY_PORT__` 赋值与死变量。
3. **恢复 `on_navigation` 拦截，但语义全新**：只拦高置信 pdfish 主框架导航（防被内联渲染吞掉保存能力）→ 取消导航 + `__mesaGrab` 接管；若最终拿到的是 HTML（魔数失败）→ 自动 `location.href` 放行换页**自愈**，不死路。
4. **删除死件**：本地 TCP 中继整链（relay_port / handle_relay_stream / write_relay_response / RELAY_PORT / 脚本占位符替换——连这类语法 bug 的土壤一起消灭）、`spawn_downloads_watcher`（受控下载不再经过 ~/Downloads，同时不再误捞用户其他下载）、过期注释与重复 Payload 结构。
5. **保留不动**（已验证的部分）：cookie 播种与增量捕获（免重登）、`RELAY_CONTEXT` / `stage_relayed_pdf` / `inst_save_relayed_pdf` / App.tsx 监听（12:52 端到端跑通过的入库链）。

## 风险与对策

- blob 下载的 suggested filename 可能为空 → `a.download` 显式命名 + URL 尾段兜底。
- `Finished` 的 url 与 `Requested` 不一致（重定向）→ map miss 时扫暂存目录兜底。
- 页内 fetch 也被拒（极端）→ 回落远端直链下载；再失败诚实报错，按钮 6s 后可重点。
- 三平台：`on_download` 三平台均有实现（webview2 / webkitgtk / wkwebview 源码确认），无平台裁剪。
