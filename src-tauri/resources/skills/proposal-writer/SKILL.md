# 开题报告与研究方案（proposal-writer）

本技能规定开题报告/研究方案/课题申请的写作规范。方案是立项目的文件：**每个研究内容都要能回答「为什么值得做、凭什么能做成」**。产出是草稿，采纳与修改由人定夺。

## 何时使用

- 用户要求写开题报告、研究计划书、基金/课题申请书框架
- 毕业论文流水线中「开题与文献综述」一步的开题报告部分（简报会指向本技能）

## 操作规范

### 1. 先定类型与篇幅

开题报告 / 研究方案 / 基金申请三类侧重不同（开题重技术路线与进度，基金重立项依据与创新点）；用户未说明时按开题报告处理并注明。学校/基金委有模板文件时严格按模板章节，没有模板时按下述五节结构。

### 2. 五节结构与要点

产出 `proposal/proposal.md`（用户另指定路径时从其约定）：

1. **选题依据（立项背景）**：研究问题从哪里来、为什么重要；用 `references.bib` 已有键支撑现状描述，每条现状判断都有引用，不空喊「意义重大」；
2. **研究内容**：2-4 项，每项一句话说清做什么、交付什么；内容之间相互支撑、合起来恰好回答研究问题，不多不少；
3. **研究目标与创新点**：目标可检验（写成「做到什么程度」，而非「深入研究」）；创新点 1-3 条，每条对照现有文献说清新在哪里，无法对照文献支撑的不写；
4. **技术路线**：每个研究内容的方法、数据来源、关键步骤与依赖；附一页路线示意（mermaid 或文字流程）；依赖资源不可获取的给公开替代方案，不留「待定」；
5. **可行性与进度安排**：已有基础（数据/代码/前期结果，引用项目内实际材料）；进度按阶段排到月，每阶段有可检查的标志物（文档/实验/初稿）。

### 3. 红线

- 引用只用 `references.bib` 中已存在的键，**严禁编造文献**；
- 预期成果写实（论文/系统/数据集），不夸大，不承诺「国际领先」类表述；
- 没有依据的判断标 [待核实]；未知信息（经费、合作单位等）占位「待填」。

## 完成标准

`proposal/proposal.md` 五节齐全；研究内容与研究问题闭环对应；引用键全部可在 `references.bib` 解析；进度表每阶段有标志物；[待核实]/「待填」在文末汇总。

- 写作约定：不使用彩色 emoji；强调标记用「注意：」或单色 ⚠（U+26A0 U+FE0E）。
