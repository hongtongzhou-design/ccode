# 开题报告与研究方案（proposal-writer）

本技能规定开题报告/研究方案/课题申请的写作规范。方案是立项目的文件：**每个研究内容都要能回答「为什么值得做、凭什么能做成」**。产出是草稿，采纳与修改由人定夺。

## 何时使用

- 用户要求写开题报告、研究计划书、基金/课题申请书框架
- 毕业论文流水线中「开题与文献综述」一步的开题报告部分（简报会指向本技能）

## 操作规范

### 1. 先定类型与篇幅

开题报告 / 研究方案 / 基金申请三类侧重不同（开题重技术路线与进度，基金重立项依据与创新点）；用户未说明时按开题报告处理并注明。学校/基金委有模板文件时严格按模板章节（导师意见、签名、日期等审核区一律留空不填），没有模板时按下述五节结构。

### 2. 写作前先做内容设计

动笔写正文前，先完成两件设计工作（可直接写进草稿开头小节，供人审阅取舍）：

- **缺口收束句**：选题依据末尾用一句话收束——「尽管 X 已有进展[引用]，[具体缺口] 因 [原因] 仍未解决；本课题通过 [方法] 解决它，将带来 [影响]」；
- **内容-主张-证据表**：`| 研究内容 | 关键主张 | 已有依据（文献键/项目材料）| 验证方法 | 风险（低/中/高）| 交付物 |`——逐项列出，写不出依据的项不进正文。

### 3. 五节结构与要点

产出 `proposal/proposal.md`（用户另指定路径时从其约定）：

1. **选题依据（立项背景）**：研究问题从哪里来、为什么重要；用 `references.bib` 已有键支撑现状描述，每条现状判断都有引用，不空喊「意义重大」；末尾给上节设计的缺口收束句；
2. **研究内容**：2-4 项；每项写清五要素：陈述（做什么、交付什么）/ 依据（为什么这个方向对，引文献键）/ 核心思路或工作假设 / 关键步骤 / 预期结果与失败时的退路。各项关系显式标注（独立/协同/递进）；**递进关系必须写上游失败时的降级方案**（如退回文献综述或边界确认）——递进链「一个挂全挂」，是答辩最易被攻击的结构；
3. **研究目标与创新点**：目标可检验（写成「做到什么程度」，而非「深入研究」）；创新点 1-3 条，每条对照现有文献说清新在哪里，无法对照文献支撑的不写；
4. **技术路线**：每个研究内容的方法、数据来源、关键步骤与依赖；附一页路线示意（mermaid 或文字流程）；每条关键依赖给公开替代方案 + 失败判据（什么信号说明此路不通、退回哪条线），不留「待定」；
5. **可行性与进度安排**：已有基础（数据/代码/前期结果，引用项目内实际材料）；进度按阶段排到月，每阶段有可检查的标志物（文档/实验/初稿），工作量与内容项数匹配。

### 4. 承诺分级

把「不夸大」落成写法，预期成果的动词按证据强度分三级：

- **可交付主线**（建立/确定…）：必须有文献或已有条件支撑；
- **审慎探索**（探索…的可行性/验证…是否成立）：允许不确定性，但须配失败判据；
- **边界确认**（确定…的操作窗口与 Go/No-Go 判据）：只承诺回答「能不能做」。

### 5. 红线

- 引用只用 `references.bib` 中已存在的键，**严禁编造文献**；
- 预期成果写实（论文/系统/数据集），承诺动词与证据强度匹配（见上节），不承诺「国际领先」类表述；
- 转述文献结论保留原文强度：「提示 / may indicate」不得升级为「证明 / proves」；
- 没有依据的判断标 [待核实]；未知信息（经费、合作单位等）占位「待填」。

## 完成标准

写完逐条过自检清单，不过不交差：

- `proposal/proposal.md` 五节齐全；研究内容与研究问题闭环对应；
- 引用键全部可在 `references.bib` 解析；每条事实性判断有引用键；每条创新点有文献对照；
- 承诺动词与证据强度匹配；进度每阶段有标志物且与内容工作量匹配；
- 术语缩写首次出现给全称；[待核实]/「待填」在文末汇总。

- 写作约定：不使用彩色 emoji；强调标记用「注意：」或单色 ⚠（U+26A0 U+FE0E）。
