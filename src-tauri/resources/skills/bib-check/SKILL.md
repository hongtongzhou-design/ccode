# 引用完整性校验（bib-check）

本技能规定「正文引用 ↔ references.bib ↔ 全文 PDF」三方核对的只读检查流程。**本技能只产出报告，不直接改正文和 bib**——修什么由人定夺。

## 何时使用

- 用户要求「检查引用」「核对参考文献」「bib 和正文对不对得上」
- 流水线润色/定稿/期刊格式适配步骤的一致性核对环节

## 操作规范

### 1. 确定检查范围

- 正文：优先检查报告调用方指定的稿件文件；未指定时按 `manuscript/` 下最新稿（final 优先于 draft），并在报告开头写明检查了哪个文件；
- bib：项目根 `references.bib`；缺失时在报告中说明并停止。

### 2. 引用键核对

- 从正文提取全部 `[@key]` 形式的引用键；
- 每个键必须在 `references.bib` 中存在——缺失的列入报告「未解析引用」节（含出现位置：节+行号）；
- 反向核对：bib 中从未被正文引用的条目列入「未引用条目」节（不视为错误，供用户决定去留）。

### 3. bib 条目字段核对

逐条检查：作者、年份、标题、出处（期刊/会议）、DOI 或链接五字段；缺字段或标「待补」的列入「字段缺失」节，逐条列出缺哪几项。

### 4. 全文对应核对

- 若项目存在 `papers/included.md`：bib 条目应与清单中的文献对应，清单有而 bib 无、bib 有而清单无的分别列出；
- 若项目存在 `papers/` 目录：抽查 bib 条目是否有对应 PDF（按「作者年份-短标题」命名口径匹配）；清单中标注「需自行获取」的跳过并在报告中计数说明。

### 5. 外部元数据核验（可选，联网工具可用时）

- 对含 DOI 的条目，用 Crossref（`https://api.crossref.org/works/<doi>`）取回官方元数据，逐字段核对作者/年份/标题/出处；arXiv 条目用 arXiv API 核对；
- DOI 无法解析、且按标题也检索不到任何出处的条目标 [疑似编造]，列入报告最前；
- 字段冲突（年份不符、作者对不上、标题不一致）列入「元数据存疑」节，逐条写明 bib 值与官方值；
- 联网工具不可用或条目无 DOI/标识时跳过本节，在报告中注明「未做外部核验」。

### 6. 产出报告

结果写入 `manuscript/citation-check.md`（调用方另指定路径时从其约定），结构：

```
# 引用完整性校验报告（<被检文件>，<日期>）
- 结论：通过 / N 个未解析引用 / N 个字段缺失 / N 条元数据存疑
## 疑似编造（外部核验无法证实存在，最优先处理）
## 未解析引用（正文有键、bib 无条目）
## 未引用条目（bib 有条目、正文未引用）
## 字段缺失
## 元数据存疑（外部核验字段冲突）
## 全文对应
## 建议处理项（按优先级排序，只列建议不执行）
```

## 完成标准

报告各节齐全（无问题的节写「无」；未做外部核验时相关两节写「未做外部核验」）；每条问题可定位（行号或 bib 键）；正文与 bib 一个字未改。
- 写作约定：不使用彩色 emoji；强调标记用「注意：」或单色 ⚠（U+26A0 U+FE0E）。
