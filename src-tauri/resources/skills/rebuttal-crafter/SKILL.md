# 审稿意见回复（rebuttal-crafter）

本技能规定「审稿意见 → 逐条回应 → 回复信 + 修改对照表」的操作规范。目标是让每条意见都有交代、每处修改都可回溯。**回复信是草稿，采纳与否由人定夺；不直接改稿件正文，除非用户明确要求。**

## 何时使用

- 用户粘贴或保存了审稿意见（编辑来信、reviewer comments），要求写返修回复
- 投稿与返修流水线中「审稿意见回复」一步（简报会指向本技能）

## 操作规范

### 1. 意见台账：逐条拆分编号

- 审稿意见全文默认从 `reviews/round-<n>.md` 读取（用户指定其他路径时从其约定）；文件缺失时提示用户提供并停止，**不得编造审稿意见**；
- 逐条拆分并编号：多位审稿人分节（R1.1、R1.2…、R2.1…），编辑意见单列为 E.1…；一条意见含多个诉求时拆成子条；
- **不允许遗漏任何一条**——拆完后回读原文核对数量。

### 2. 逐条定回应类型

每条意见归入三型之一，并在台账中标注：

- **接受修改**：文字/格式/补充说明类，可直接改稿解决；
- **部分接受**：方向认可但需限定范围（如只能补小规模实验、只能引用已有数据），写明限制条件；
- **礼貌反驳**：仅在审稿人存在事实性误解时使用——必须给出稿件原文位置或文献依据支撑反驳，语气对事不对人。

拿不准如何回应的一律按「部分接受」写，并标 [待确认]；需要补实验/补数据才能回应的标 [待补实验]，在回应中给出可执行的补做计划，不开空头支票。

### 3. 写回复信

产出 `rebuttal/response-letter.md`：

1. 开头一段总述：感谢编辑与审稿人 + 本次修改的要点概括（3-5 条）；
2. 逐条回应，固定结构：**意见摘要**（一两句复述，表明理解）→ **回应**（类型 + 具体处理）→ **修改位置**（稿件的节+段落，或「见修改对照表第 N 条」）；
3. 语气先谢后答；每条回应独立完整，不写「同上」。

### 4. 修改对照表与修订稿

- 产出 `rebuttal/revisions.md` 修改对照表：意见编号 → 修改点 → 修订稿中的位置（节+段落），逐条可核对；
- 用户明确要求改稿时，才在原稿基础上产出 `manuscript/revised.md`，每处修改标注对应的意见编号；未被要求时只产出回复信与对照表，稿件原样保留。

## 完成标准

回复信覆盖台账全部编号（含编辑意见）；每条回应类型明确、有修改位置或 [待补实验] 计划；修改对照表与回复信一一对应；[待确认]/[待补实验] 在回复信末尾汇总成清单。

- 写作约定：不使用彩色 emoji；强调标记用「注意：」或单色 ⚠（U+26A0 U+FE0E）。
