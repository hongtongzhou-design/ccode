# 文献精读与笔记

本技能规定综述类课题「精读 → 笔记 → 引文库」阶段的操作规范与产出格式。笔记结构固定，引文库条目齐全，保证后续大纲与写作阶段可直接引用。

## 何时使用

- 用户给出文献清单（如 `papers/included.md`），要求逐篇精读并整理笔记
- 用户要求建立或维护 BibTeX 引文库（`references.bib`）
- 综述流水线中「文献精读与笔记」一步（简报会指向本技能）

## 操作规范

### 1. 先整理人工补投，再按清单逐篇精读

精读开工前先整理 `papers/` 里人工补投的 PDF：命名不符「作者年份-短标题.pdf」的，对照 `included.md`/`to-fetch.md` 判定归属后重命名规范，并在 `to-fetch.md` 勾掉已补行；**拿不准归属的不改名，标注「待确认」**。命名整理是 agent 的职责，不要求用户按规范命名。

然后按清单逐篇处理，先读「待确认」之外的纳入项。**清单缺失或为空时，在报告中说明并停止，不要自行换题或自行补清单。**

### 2. 每篇一篇笔记

每篇产出 `notes/<序号-短标题>.md`。标题下一行先记来源锚点（机读口径，沉浸阅读区「开读」靠它认回这份笔记、不另建重复笔记）：

```
> 来源 PDF：<项目内相对路径>.pdf
```

正文固定结构：

1. **一句话总结**：不超过 50 字的大白话；压不成一句视为没读懂，重读再写
2. **研究问题**
3. **方法**：概述之后附「可复现细节」（数据集/规模/关键设置/关键参数，一句话级——写作阶段做方法对比表全靠它，事后补代价高）
4. **主要结果**：区分「实验证明」与「作者推测」，不混写；每条结果注明出处（页码 + 表/图编号，如「表 2，第 7 页」）
5. **局限**：拆两半——「作者自述的局限」与「本笔记识别的局限」，分开列，不把读者判断伪装成作者自述
6. **可引用点**（原文关键句 + 页码或段落位置）
7. **与本课题的关系**：结合项目档案卡/任务书写——这篇可用在当前课题哪一步、补上哪个空白；确实关系弱的也要明说，不硬凑
8. **疑问与待跟进**：读不懂/拿不准的点显式列出，不含糊带过；待跟进的引用同时追加到 `papers/to-fetch.md`，不只在笔记里记

**全文不可得时**，按摘要 + 可见元数据写笔记，并在笔记开头标注「仅摘要」——不得装作读过全文。

### 3. 同步引文库

每篇在 `references.bib` 追加一条 BibTeX：作者、年份、标题、出处、DOI 齐全；缺字段标「待补」，不得编造。字段齐全但未经权威源核对的标「待核」；有条件时用 CrossRef/DBLP 核对作者/出处/年份（以正式发表版为准，不用 preprint 信息），核对通过再去掉标记。

## 产出格式

- `notes/<序号-短标题>.md`：每篇一篇，固定八段结构
- `references.bib`：每篇一条 BibTeX，字段齐全或明确标「待补」/「待核」
- `papers/to-fetch.md`：精读中发现的待跟进引用追加进此清单

## 完成标准

清单中每篇都有对应笔记与 bib 条目；`notes/` 与 `references.bib` 均已提交到版本库。
- 写作约定：不使用彩色 emoji；强调标记用「注意：」或单色 ⚠（U+26A0 U+FE0E）。
