# 文献精读与笔记

本技能规定综述类课题「精读 → 笔记 → 引文库」阶段的操作规范与产出格式。笔记结构固定，引文库条目齐全，保证后续大纲与写作阶段可直接引用。

## 何时使用

- 用户给出文献清单（如 `papers/included.md`），要求逐篇精读并整理笔记
- 用户要求建立或维护 BibTeX 引文库（`references.bib`）
- 综述流水线中「文献精读与笔记」一步（简报会指向本技能）

## 操作规范

### 1. 先整理人工补投，再按清单读

项目资源中已登记的 Zotero 等外部 PDF 按绝对路径直读，来源锚点可记该绝对路径；只读，不复制、不重命名、不修改个人库附件。先查这些资源再补下载。

精读开工前先整理 **项目根 `papers/`**（见 TASK.md「项目根」，按绝对路径读，含未进本工作区的文件）里人工补投的 PDF：命名不符「作者年份-短标题.pdf」的，对照 `included.md`/`to-fetch.md` 判定归属后重命名规范，并在 `to-fetch.md` 勾掉已补行；**拿不准归属的不改名，标注「待确认」**。命名整理是 agent 的职责，不要求用户按规范命名。已有笔记先查证据版本、问题范围和全文状态，未变则复用；全文补到/更正撤稿/范围变化时标出受影响部分，保留人写内容并更新或交人处理，不因已有文件就认定有效。

然后按清单处理已确认纳入项；待确认项保留记录与状态，不伪装成已精读。**清单缺失或为空时，在报告中说明并停止，不要自行换题或自行补清单。**

### 2. 读完再写笔记

**已读完**才产出 `notes/<序号-短标题>.md`。未读完只在 `notes/index.json` 记 `reviewStatus=pending`，`notePath` 留空；禁止生成八段占位文件——文件存在会被界面标成「已读」。禁止用脚本从摘要/元数据批量生成笔记正文。上下文写不下可分批写笔记并提交；提交后立刻继续：先核心精读，再按摘要写非核心，不要每批停下来等人。pending 只留给待确认或无法按摘要写的篇。

标题下一行先记来源锚点（沉浸阅读区靠它认回笔记，不另建重复）：

```
> 来源 PDF：<项目内相对路径或已登记只读资源的绝对路径>.pdf
```

来源行下用一两句写清：全文或仅摘要、正式版或预印本、同工 DOI/重复记录、agent 草稿或已核。不要另开一节。

正文固定结构：

1. **一句话总结**：大白话当卡片标题；专有名词可留英文。压不成一句视为没读懂。不要为卡字数写成空套话。
2. **研究问题**：作者实际在问什么，不要把摘要动机段原样改写。
3. **方法**：概述之后附「可复现细节」（电解液配方/电极/loading/电流/表征，一句话级——写作阶段做方法对比表全靠它）。
4. **主要结果**：区分「观察结果及其支持范围」与「作者推测」，不混写；每条注明页码 + 表/图。看不清的数字写「原文未核清」，不要用「约 ?」混进可引用数字。
5. **局限**：拆两半——「作者自述的局限」与「本笔记识别的局限」，分开列，不把读者判断伪装成作者自述。
6. **可引用点**：每条 = 可核验论断（叙述用中文）+ 页码/图表。需要直接引述时再附原文短句。禁止只贴图表题录或摘要原句充数。
7. **与本课题的关系**：这篇在综述里支撑哪条论点；不要只写「核心/背景：××分类」。
8. **疑问与待跟进**：只写还没核清、或还要去读的下一篇/字段，不重复局限里已经下的判断；待跟进文献追加 `papers/to-fetch.md`。

**写法**：叙述用中文（把读到的内容说清楚），不要整段粘贴英文摘要或 PDF 抽取原文。材料名、离子、电解液、方法缩写、图/表编号等惯用英文原词直接写，不强翻。有 PDF 的核心篇读正文再写，页码/图表来自正文。用户确认「按摘要记」的篇根据摘要消化来写，开头标「仅摘要」——不是把摘要原文粘贴交差。

**全文不可得时**，按摘要 + 可见元数据写笔记，开头标注「仅摘要」。无实际 PDF 不伪造来源锚点，改记 DOI/URL 及访问日期。无法核实的页码、方法细节、数值和因果主张写不可核验，不凑齐八段。核心结论依赖全文时暂停该结论或缩窄范围；获取全文后复核并记录影响的大纲/稿件。

在 `notes/index.json` 写与 `papers/included.json` 全部 id 对应的记录（包括 pending）：`id`、`bibKey`、`fulltextStatus`、`reviewStatus`；已写笔记才填 `notePath`。`fulltextStatus` 为 fulltext/abstract-only/unavailable，`reviewStatus` 为 pending/blocked/reviewed；未读完不得写 reviewed。不能靠文件存在冒充读完。独立运行未有 included.json 时从清单建立稳定 id 并记录来源。

### 3. 同步引文库

每篇在 `references.bib` 检查 DOI/版本与键，复用匹配条目，缺失才追加一条 BibTeX：作者、年份、标题、出处、DOI 齐全；缺字段标「待补」，不得编造。字段齐全但未经权威源核对的标「待核」；有条件时用 CrossRef/DBLP 核对作者/出处/年份（以正式发表版为准，不用 preprint 信息），核对通过再去掉标记。

### 复核入口

文献型复现不等于重跑统计：在 notes/index.json/现有证据表记录来源版本/哈希、原文定位、提取结论与支持范围，第三人据此重建综合。来源变化或未读全文必须显式触发待复核；检索记录支持重检，不承诺动态检索结果永远相同。

### 4. 从笔记到可用证据

核心提取字段（对象、n、设计、指标、结果方向/数值、局限）回原文定位；区分质量问题和作者宣传，不以高被引或多个转述替代原始证据。跨研究综合前整理可比性、反例、偏倚风险与同一研究多报告关联。对影响主结论的提取可由人指定独立第二人/Agent 从原文核对，不先看第一份答案；分歧列证据由人裁决，不自动分派。

## 产出格式

- `notes/<序号-短标题>.md`：已读完的篇一篇，固定八段结构
- `notes/index.json`：稳定 id 与笔记/引文/全文/复核状态映射（未读完 `notePath` 可空）
- `references.bib`：每篇一条 BibTeX，字段齐全或明确标「待补」/「待核」
- `papers/to-fetch.md`：精读中发现的待跟进引用追加进此清单

## 验收入口

有 TASK.md 时沿用其中的验收摘要/质量状态合同，不重复建表；独立使用时，在本报告开头写：回答、关键证据入口、未验证、影响结论的问题、待人决定。状态为待审/有条件接受/证据通过（限定范围）/阻塞；推荐不等于人工批准。

## 完成标准

`notes/index.json` 与 `included.json` 全部 id 对齐；已写笔记符合上列写法。中途 git 提交只保存进度，不是本步完成。用户确认的核心篇有 PDF 却未写出精读、或已确认要按摘要记的非核心还没写完时，不得结束本轮等人；质量状态不得高于「已生成待审」，验收摘要写明还剩几篇。清单全有文件不等于完成。
- 写作约定：不使用彩色 emoji；强调标记用「注意：」或单色 ⚠（U+26A0 U+FE0E）。
