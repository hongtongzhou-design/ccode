# 英文综述写作

本技能规定综述写作「大纲 → 初稿 → 润色」三阶段的操作规范与红线约束。任何阶段都适用：**引用只来自引文库，严禁编造文献。**

## 何时使用

- 用户要求基于笔记与引文库（如 `notes/` 与 `references.bib`）写英文综述
- 综述流水线中「综述大纲 / 综述初稿 / 润色与定稿」各步（简报会指向本技能）

## 动笔前

- 确认综述类型：独立综述（默认本规范）/ 学位论文综述章 / 引言 mini 综述（1-3 页，CARS 三 Move：确立领域 → 指出 gap → 占据位置）；任务书未指明时按独立综述。
- 通读 `notes/` 全部笔记与 `references.bib`；笔记缺失时在报告中说明并停止，不自造内容。

## 三阶段要点

### 阶段一：大纲（outline.md）

1. 通读全部笔记，按概念/主题聚类归纳研究现状的主要线索（方法/问题/结论的异同）——**按回答问题的逻辑组织；历史演变问题可以时间为线索**。
2. 产出 `outline.md`：章节结构（引言 / 背景 / 主题各节 / 讨论 / 结论）、每节必要要点（不凑数量）、每节拟引用的 bib 键、分类框架的一句话说明。
3. 有分歧时按核心问题、证据可比性、解释力和读者需要推荐框架，待人确认，并在末尾记录取舍理由。
4. 每个主题节预设一句「综合点」：这组文献一致在哪、分歧为何（方法？样本？时代？）。
5. 讨论节必须含 gap 段：gap 归类（证据/知识/实践/方法/经验/理论，六类之一）、承认相邻工作并说清「未整合之处」；禁「有待进一步研究」式空话。
6. **只引用 `references.bib` 中存在的键，不凭记忆造引用；发现关键新文献先回检索/提取/核验，再更新大纲和库。**

### 阶段二：初稿（manuscript/draft.md）

行文规则：

1. **观点先行，引用为证**：论断在前、括号聚类引用在后（`[@a; @b]`）；禁「作者说」流水账（仅单项研究支持时应写“该研究在……条件下观察到 X”，不能改为“X 已确立”；证据整合充分才可陈述共识）；归属、争议或结论范围重要时可以明确点名研究。
2. 段落以概念开头；自检：随机抽 5 段，检查是否堆砌而非综合；必要的研究归属不机械删掉。
3. 对重要方法、分歧与适用边界作有依据的评价；没有发现问题可明确写未发现，不强迫每组批判或堆批判词。
4. 转场即论证：过渡句须承接上节论证；禁「接下来讨论…」「It is worth noting」「综上所述」式空转。
5. **去防御性套话**：论断直接说。必要局限写一次，放方法或讨论，不在摘要/段首/结论里反复道歉。真实不确定写清来源（仅摘要 / 设计不能外推 / n 过小），不要 may/might/could potentially 叠三层，也不要「这并不是说」「我们并不试图」「不是 X 而是 Y」这种先否定再立论的套式。

内容与证据：

6. 按 `outline.md` 用规范学术英文撰写。**词数不是完成标准**。项目设定或大纲里的篇幅数字只是读者预期；即使写进 TASK 也不得当成必须凑到的词数（本条优先于 TASK 配额句）。写短了不扩、写长了不删证据。标题写 `## Introduction`，不要手写 `## 1.`——Quarto `number-sections` 会再编一次号。空白编号（G1）和任务书验收编号只留在大纲「框架推演」或验收摘要，**禁止写进稿件正文或摘要**。
7. **某节显得薄，只允许加证据，禁止加字。** 顺序：① 回 `notes/` 该篇的方法 / 结果 / 可引用点 / 局限；② 笔记不是「仅摘要」且有来源 PDF（笔记头「来源 PDF」行，或 `papers/` 配对全文）时，打开该 PDF 核对该论断的原文位置，再补一句可定位的证据（条件、样本、指标、结果方向）；③ 仅摘要或 PDF 没有更多可核验细节 → 保持短，标 `[待核实]` 或留下缺口。禁止同义复述、背景铺陈、为凑词数加第三句相同意思。中心论点在引言说一次、结论收一次；各章收尾不要再复述同一对约束。
8. **证据等级写进句子，不只写在方法段。** 跟大纲「拟引用（可写）/（线索）」：全文级才写机制与定量；摘要级写成「该文摘要报告了…」，定量必须 `[待核实]`；题录级只用来定位，不写结论。方法段若声明「32 篇全文 / 其余摘要」，正文标记数必须对得上，不得只标 7 处却把摘要级写成已确立。
9. **摘要只放全文撑得住的主张。** 禁止摘要里出现 `[待核实]`、operando / 软包 / 未测步骤等近端动作。那些放结论或 outlook，并写明是建议不是本文证明。范围里点名的主题（如混合阳离子）后文必须展开，否则从范围删掉。
10. 引用一律用 `[@bib键]` 形式，且键必须能在 `references.bib` 中解析——**严禁编造文献，严禁新造键**。
11. 图表按 `outline.md` 的用图计划走 review-figures：计划写「拼」则裁图或降级为「见 [@键] Fig.n」；**禁止「待绘制」占位当产出**。撑主论点的图（如计数剪刀差）没有数据就改口，不要空图。禁止臆造图号、禁止把源 PDF 整页当图。**不虚构数据**。
12. 没有文献支撑的论断不得下；必须保留的判断在句末标 `[待核实]`。结论只写本综述实际论证了什么；把「领域下一步该做的实验」标成建议，不写成本文结论。

### 阶段三：润色与定稿（manuscript/review-final.md）

1. 语言润色：语法、用词、句式与段落衔接，保持学术语气；**只改表达，不改学术观点**。
2. 分级自检：
   - `[必须修复]`：引用断链（键不可解析）；堆砌超标（复跑阶段二第 2 条抽查）；主要结论逐项回原文核验支持范围；次要背景按风险抽查并披露覆盖范围，不符列阻塞或降级处理；摘要含 `[待核实]`；正文出现 G1 这类空白编号；「待绘制」仍当图；大纲标摘要级的定量句未降级。
   - `[建议修复]`：转场空转；防御性套话；各章重复同一立论；图表占位编号不连续；重复句式。
3. 引用闭环核对：事实性论断有适当依据；未用 bib 条目可保留，不为消除未引用条目硬塞引用。发现内容性错误标 `[待核实]`，**不得自行改写事实**。
4. 产出定稿 `manuscript/review-final.md`，并附 `manuscript/changelog.md` 逐条列出主要修改点。
5. 文末 References 节按 `references.bib` 生成完整文献列表。

## 完成标准

- 大纲：结构完整、每节要点与引用键齐全、综合点与 gap 段已预设、取舍理由已记录
- 初稿：覆盖大纲全部章节；引用键全部可在 `references.bib` 中解析；行文规则自检通过；扩写句能回溯到笔记或原文位置；不以词数判定完成；PDF 首页可读（乱码即渲染失败）；正文无 G 编号；摘要无 `[待核实]`；摘要级来源已在句中降级；「待绘制」不算图已产出；结论不超出本文论证
- 定稿：无语法硬伤、引用闭环（论断有合适依据，未用 bib 可保留）、核心论断支持性逐项通过、`[必须修复]` 项清零、`changelog.md` 已提交
- 写作约定：不使用彩色 emoji；强调标记用「注意：」或单色 ⚠（U+26A0 U+FE0E）。

## 成稿前的证据门

核心论断逐项做“论断→原文位置→支持范围→反证”核验；仅摘要材料不得支撑摘要没有报告的细节。支持性核验放入 citation-check 或现有修订记录，与 bib 元数据检查分开。final 文件名、引用键可解析、语言流畅都不是可投稿证明；核心支持性缺口需补证据、经人确认撤回/缩窄主张或保持阻塞。篇幅和发现数量依问题与证据，允许证据不足，不凑结论。上游更新后重验相关段落，保留批准范围。

## 验收入口

有 TASK.md 时沿用其中的验收摘要/质量状态合同，不重复建表；独立使用时，在本报告开头写：回答、关键证据入口、未验证、影响结论的问题、待人决定。状态为待审/有条件接受/证据通过（限定范围）/阻塞；推荐不等于人工批准。
