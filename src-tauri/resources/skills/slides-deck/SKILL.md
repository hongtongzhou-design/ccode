# 学术汇报幻灯片（slides-deck）

本技能规定「稿件/笔记 → 故事线 → 逐页内容」的幻灯片制作规范。幻灯片是讲给人听的：**一页一个信息点，图优先于字**；全部内容来自项目已有材料（`manuscript/`、`notes/`、`figures/`、`analysis/`），不虚构结果。

## 何时使用

- 用户要求做组会汇报、开题/中期/答辩、会议 talk 的幻灯片或逐页大纲
- 用户要求把 manuscript/notes 提炼成演示材料

## 操作规范

### 1. 先定场合、时长与听众

- 场合（组会/答辩/会议 talk）、时长（分钟数）、听众（本方向/跨方向）三者先确认；用户没给时按「组会 15 分钟、本方向听众」默认，并在产出开头注明假设；
- 页数预算：正文页 ≈ 时长分钟数 × 0.8-1（答辩/会议偏密，组会偏疏），另加封面/致谢与备份页。

### 2. 提炼故事线

从项目材料中提炼一条故事线：背景一句话 → 问题/空白 → 方法一句话 → 关键结果（1-3 个）→ 结论与下一步。故事线先写成 3-5 句摘要：交互场景先给用户确认，流水线/无人值守场景直接采用并继续。

### 3. 逐页大纲

产出 `slides/outline.md`，每页固定字段：

```
## 第 N 页：<页标题>
- 信息点：<本页唯一要让听众记住的一句话>
- 视觉：<用哪张图/表（引用 figures/ 路径）或文字要点；新示意图描述内容并标 [待绘制]>
- 备注：<演讲备注：展开口径、预计用时、可能被问的问题>
```

规则：一页一个信息点；能用 `figures/` 里已有的图就不用文字罗列；文字页每页不超过 6 行、每行不超过 20 字；结果页的数字必须与 `analysis/results-table.md`（或对应结果文件）一致。

### 4. 需要成品时的 HTML 形态

用户要求可直接放映的成品时，产出零依赖单文件 `slides/deck.html`：固定 16:9 页面、键盘左右翻页、无外部依赖（样式与脚本内联，不引 CDN），图片用相对路径引用 `../figures/`。

版式底线（反「AI 味」）：不用紫蓝渐变与卡片套卡片；一套 deck 内字体不超过两种、主色不超过两个；留白优先于装饰；动画只允许淡入，不用飞入飞出。

### 5. 备份页

可能被问的细节（额外实验、参数敏感性、数据口径）放正文之后的备份页，不占正文页数。

## 完成标准

`slides/outline.md` 每页信息点/视觉/备注三字段齐全；故事线与项目材料一致、数字可回溯；HTML 形态（若产出）可离线打开、翻页正常。

- 写作约定：不使用彩色 emoji；强调标记用「注意：」或单色 ⚠（U+26A0 U+FE0E）。
