# 数据清洗

本技能规定数据处理课题「清洗与整理」阶段的操作规范与产出格式。清洗规则先行、原始数据只读、产物目录承接结果，保证清洗可复现、可审计、可回溯。

## 何时使用

- 用户要求对数据集做清洗、去重、缺失值或异常值处理
- 用户要求制定可复现的清洗规则并产出清洗报告
- 数据处理流水线中「清洗与整理」一步（简报会指向本技能）

## 操作规范

### 1. 规则先写死再动手

先把全部清洗规则逐项写入 `cleaning/rules.md`，再写脚本：

- 缺失值处理：删除还是填充、填充值是什么、为什么
- 去重键：按哪几列判重、保留哪一条
- 异常值边界：阈值与依据（数据字典口径 / 业务常识 / 统计界限）
- 类型转换与格式统一：日期、编码、单位等

每条规则注明依据，**不允许出现「视情况而定」项**；拿不准的规则标 [待确认] 并在报告中单列。

### 2. 脚本只读原始数据

- 清洗脚本放入 `cleaning/`，可重复执行（从 `main` 直接重跑结果一致）
- 脚本**只读原始数据，绝不原地修改**原始文件；任何修复都发生在输出侧
- 输入数据不可读或格式损坏时在报告中说明并停止，不自行修复原始数据

### 3. 处理后数据进产物目录

处理后的数据写入项目产物目录（项目配置的产物目录；未配置时用项目根 `artifacts/`）。产物目录**不进 git**（确认已在 `.gitignore`），提交的是规则、脚本与报告，不是数据。

### 4. 每类问题给行号/计数

缺失、重复、异常、口径不一致每一类问题，处理时都要记录受影响的行号样例与总数计数，不写「少量缺失」这类无量化表述。

## 产出格式

- `cleaning/rules.md`：逐条规则 + 依据，无「视情况而定」项
- `cleaning/<清洗脚本>`：可重复执行，输入只读，输出到产物目录
- `cleaning/cleaning-report.md` 清洗报告：
  1. 规则清单（与 rules.md 一致）
  2. 处理量：每条规则影响的行数、丢弃数据清单与原因
  3. 遗留问题：[待确认] 规则与未解决的质量问题
  4. 清洗前后规模对比（行数/列数/大小）

## 完成标准

rules.md 无「视情况而定」项；脚本可从 `main` 重跑且结果一致；报告中的数字与产物目录中的实际结果一致；原始数据文件字节级未被改动。
- 写作约定：不使用彩色 emoji；强调标记用「注意：」或单色 ⚠（U+26A0 U+FE0E）。
